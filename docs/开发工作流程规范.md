# 开发工作流程规范

> **目标**: 建立标准化、可追溯、高质量的开发流程,适用于复杂Python项目的个人开发场景

---

## 📋 流程总览

```
需求/问题 → 调研分析 → 设计方案 → 编码实现 → 测试验证 → 文档更新 → 代码审查 → 提交发布
    ↓          ↓          ↓          ↓          ↓          ↓          ↓          ↓
  记录到     Memory    PLAYBOOKS  代码库     测试报告   文档同步    检查清单    Git提交
  Issue      记录       决策记录
```

---

## 🎯 阶段一: 需求分析与调研

### 1.1 问题识别
**输入**: Bug报告 / 新功能需求 / 性能优化需求

**操作清单**:
- [ ] 创建 GitHub Issue (使用GitHub MCP)
- [ ] 明确问题范围: What/Why/Who/When
- [ ] 评估风险等级: 低/中/高 (参考 [行为约束](行为约束.md))
- [ ] 设定完成标准 (DoD - Definition of Done)

**MCP工具使用**:
```python
# 使用 Sequential Thinking 分解问题
思考步骤1: 问题的根本原因是什么?
思考步骤2: 影响范围有多大? (文件/模块/系统)
思考步骤3: 有哪些已知的解决方案?
思考步骤4: 最优解的权衡是什么?
```

---

### 1.2 技术调研
**操作清单**:
- [ ] 使用 **Context7** 查询相关库文档
- [ ] 使用 **Exa** 搜索最佳实践
- [ ] 使用 **Memory** 检查是否有类似历史问题
- [ ] 使用 **Postgres MCP** 查询相关数据(如性能基线)

**示例: 添加新指标计算**
```bash
# Step 1: 查询已有计算指标的实现模式
Memory.search("计算指标实现模式")

# Step 2: 查询 pandas/numpy API
Context7.get_library_docs("/pandas/pandas", topic="data aggregation")

# Step 3: 检查数据库现有字段
Postgres.query("SELECT column_name FROM information_schema.columns
WHERE table_name='fact_measurements'")
```

**输出**: 调研报告 (写入 `docs/PLAYBOOKS/调研记录.md`)

## 🎨 阶段二: 设计方案

### 2.1 架构设计
**操作清单**:
- [ ] 确定受影响的模块 (adapters/services/models/cli)
- [ ] 绘制数据流图 (可选,复杂功能)
- [ ] 识别依赖关系
- [ ] 评估性能影响

**设计模板**:
```markdown
## 设计方案: [功能名称]

### 目标
简述1-2句

### 架构变更
- 新增模块: app/services/xxx/
- 修改模块: app/adapters/db/gateway.py
- 数据库变更: 新增表 xxx / 新增字段 xxx

### 数据流
CSV输入 → staging → 对齐 → 计算 → 结果表 → API输出

### 性能预算
- 单次计算耗时: < 100ms
- 内存占用: < 500MB
- 数据库连接: ≤ 5

### 风险评估
- 兼容性: 是否影响现有功能?
- 回滚策略: 如何快速回退?
```

- ✅ 性能权衡 (如牺牲准确性换速度)

```markdown
我们决定做什么?

- 优点: ...
- 缺点: ...
- 风险: ...
```

### 3.2 编码规范 (强制遵守)
参考 [编码规范](编码规范.md),核心要点:

#### ✅ 类型注解
```python
# 正确示例
def calculate_metric(
    value: float,
    threshold: float | None = None
) -> dict[str, Any]:
    ...

# 错误示例 (缺少类型)
def calculate_metric(value, threshold=None):
    ...
```

#### ✅ SQL 参数化
```python
# 正确示例
sql = "SELECT * FROM fact WHERE ts >= %s"
cursor.execute(sql, (start_time,))

# 错误示例 (SQL注入风险)
sql = f"SELECT * FROM fact WHERE ts >= '{start_time}'"
```

#### ✅ 异常处理
```python
# 正确示例
try:
    result = db.execute(sql)
except psycopg.OperationalError as e:
    logger.error("数据库连接失败", extra={"error": str(e)})
    raise
except ValueError as e:
    logger.warning("参数无效", extra={"param": param})
    return None

# 错误示例 (裸except)
try:
    result = db.execute(sql)
except:
    pass
```

#### ✅ 日志记录
```python
logger.info(
    "指标计算完成",
    extra={
        "event": "calc.metric.completed",
        "metric_name": "pump_efficiency",
        "rows_processed": 1234,
        "cost_ms": 567,
        "run_id": run_id
    }
)
```

### 3.3 小步提交策略
**原则**: 每个提交应该是一个完整的、可工作的单元

**推荐提交粒度**:
```
❌ 错误: 一次提交包含 10 个文件,修改 500 行
✅ 正确:
  - Commit 1: 添加数据模型 (1文件, 50行)
  - Commit 2: 实现计算逻辑 (1文件, 80行)
  - Commit 3: 添加单元测试 (1文件, 60行)
  - Commit 4: 更新文档 (1文件, 30行)
```

**提交信息格式**:
```bash
# 格式: <类型>(<范围>): <描述>
# 类型: feat|fix|refactor|docs|test|chore

git commit -m "feat(calculation): 添加泵效率计算功能

- 实现 PumpEfficiencyCalculator 类
- 支持方法A和方法B两种计算方式
- 添加参数验证和异常处理

Refs: #123"
```

### 4.2 单元测试 (必须)
**覆盖率要求**: ≥ 80%

**测试模板**:
```python
# tests/unit/services/calculation/test_pump_efficiency.py
import pytest
from app.services.calculation.metrics.pump_efficiency import PumpEfficiencyCalculator

class TestPumpEfficiencyCalculator:
    @pytest.fixture
    def calculator(self):
        return PumpEfficiencyCalculator()

    def test_calculate_normal_case(self, calculator):
        """正常情况: 流量=100, 扬程=50, 功率=60"""
        result = calculator.calculate(flow=100, head=50, power=60)
        assert result["efficiency"] == pytest.approx(0.816, rel=1e-2)
        assert result["quality"] == "GOOD"

    def test_calculate_zero_power(self, calculator):
        """边界情况: 功率为0,应抛出异常"""
        with pytest.raises(ValueError, match="功率不能为0"):
            calculator.calculate(flow=100, head=50, power=0)

    def test_calculate_negative_values(self, calculator):
        """异常情况: 负值输入"""
        with pytest.raises(ValueError):
            calculator.calculate(flow=-100, head=50, power=60)
```

**运行测试**:
```bash
# 运行所有单元测试
pytest tests/unit/ -v --cov=app --cov-report=html

# 运行特定模块
pytest tests/unit/services/calculation/ -v

# 查看覆盖率报告
open htmlcov/index.html
```

## 🎯 流程速查卡

### 快速决策树
```
是否是BUG修复?
├─ 是 → 使用"错误修复流程" (见 错误修复工作流程.md)
└─ 否 → 是否是新功能?
```
