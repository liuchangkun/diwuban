# 错误修复工作流程

> **目标**: 建立系统化的BUG修复流程,确保问题根治、经验沉淀、避免回归

---

## 🚨 流程总览

```
发现问题 → 问题分类 → 根因分析 → 修复实施 → 验证测试 → 经验沉淀 → 预防措施
    ↓          ↓          ↓          ↓          ↓          ↓          ↓
  Issue     严重等级    5-Why     小步修复   回归测试   PLAYBOOKS  自动化检测
  记录      定义        分析      验证       数据验证   记录       预防
```

### 1.2 严重等级分类

| 等级 | 标准 | 响应时间 | 示例 |
|------|------|---------|------|
| **P0 - 紧急** | 系统崩溃/数据丢失 | 立即 | 数据库连接失败、计算结果错误导致决策失误 |

## 🔍 阶段二: 根因分析

### 2.1 使用 Sequential Thinking 分解问题
```python
# 使用 Sequential Thinking MCP 工具

思考步骤1: 问题最早出现在哪个环节?
  - 数据源层? (CSV格式/数据质量)
  - ETL层? (导入/对齐/合并)
  - 计算层? (公式/参数/阈值)
  - 输出层? (格式化/日志)

思考步骤2: 有哪些相关变更?
  - 最近的代码提交
  - 配置文件修改
  - 数据库Schema变更
  - 依赖包升级

思考步骤3: 是否有类似历史问题?
  - Memory.search("类似问题")
  - 查阅 PLAYBOOKS/错误与修复记录.md

思考步骤4: 假设验证
  - 假设A: 数据格式变化 → 验证CSV样本
  - 假设B: 参数配置错误 → 检查YAML文件
  - 假设C: 数据库锁冲突 → 查询pg_stat_activity
```

---

### 2.2 5-Why 根因分析法
**原则**: 连续问5次"为什么",找到根本原因

**示例: 泵效率计算异常**
```
问题: 设备#7的泵效率计算结果为负数

Why 1: 为什么效率是负数?
→ 因为公式中分母(轴功率)为负

Why 2: 为什么轴功率为负?
→ 因为从数据库读取的power字段为NULL,被处理成了-1

Why 3: 为什么power字段为NULL?
→ 因为上游计算模块在某些情况下没有写入结果

Why 4: 为什么上游模块没有写入?
→ 因为输入数据不满足计算条件,但异常被吞掉了

Why 5: 为什么异常被吞掉?
→ 因为代码中使用了裸 except,没有记录日志

根因: 异常处理不当 + 缺少数据验证
```

### 3.2 修复实施原则

#### ✅ 最小化修改
```python
# ❌ 错误: 大范围重构
def calculate_efficiency(...):
    # 重写整个函数,改变多个逻辑

# ✅ 正确: 最小修复
def calculate_efficiency(flow, head, power):
    # 仅添加参数验证
    if power is None or power <= 0:
        raise ValueError(f"轴功率无效: {power}")
    # 原有逻辑不变
    ...
```

#### ✅ 防御式编程
```python
# ✅ 添加输入验证
def calculate_efficiency(flow: float, head: float, power: float) -> dict:
    # 参数验证
    if not all(isinstance(x, (int, float)) for x in [flow, head, power]):
        raise TypeError("所有参数必须是数值类型")

    if flow <= 0 or head <= 0 or power <= 0:
        raise ValueError(f"参数必须为正数: flow={flow}, head={head}, power={power}")

    # 正常计算
    efficiency = (flow * head * 9.81) / (3600 * power)

    # 结果验证
    if not 0 <= efficiency <= 1:
        logger.warning(
            "效率超出合理范围",
            extra={
                "efficiency": efficiency,
                "flow": flow,
                "head": head,
                "power": power
            }
        )

    return {"efficiency": efficiency, "quality": _assess_quality(efficiency)}
```

### 6.1 添加自动化检测
```python
# scripts/tools/code_quality_checks.py
"""
自动检测代码质量问题
"""
import ast
import sys

def detect_bare_except(file_path):
    """检测裸except"""
    with open(file_path) as f:
        tree = ast.parse(f.read())

    for node in ast.walk(tree):
        if isinstance(node, ast.ExceptHandler):
            if node.type is None:  # 裸except
                print(f"⚠️  {file_path}:{node.lineno} - 发现裸except")
                return False
    return True

# 集成到pre-commit hook
```

### 6.2 增强数据验证
```python
# app/services/calculation/shared/validators.py
"""
通用输入验证器
"""
from typing import Any

def validate_numeric(value: Any, name: str, min_val: float = None, max_val: float = None) -> float:
    """验证数值参数"""
    if value is None:
        raise ValueError(f"{name}不能为空")

    if not isinstance(value, (int, float)):
        raise TypeError(f"{name}必须是数值类型,实际类型: {type(value)}")

    value = float(value)

    if min_val is not None and value < min_val:
        raise ValueError(f"{name}={value}小于最小值{min_val}")

    if max_val is not None and value > max_val:
        raise ValueError(f"{name}={value}大于最大值{max_val}")

    return value

# 使用示例
def calculate_efficiency(flow, head, power):
    flow = validate_numeric(flow, "flow", min_val=0)
    head = validate_numeric(head, "head", min_val=0)
    power = validate_numeric(power, "power", min_val=0.1)
    ...

WITH before AS (
  SELECT COUNT(*) as total,
         COUNT(*) FILTER (WHERE efficiency < 0 OR efficiency > 1) as bad
  FROM calc_results_backup  -- 修复前备份
  WHERE device_id = 7

after AS (
  SELECT COUNT(*) as total,
         COUNT(*) FILTER (WHERE efficiency < 0 OR efficiency > 1) as bad
  FROM calc_results
  WHERE device_id = 7
)
SELECT
  '修复前' as status,
  b.bad as 异常数量,
  ROUND(100.0 * b.bad / b.total, 2) as 异常率
FROM before b
UNION ALL
SELECT
  '修复后',
  a.bad,
  ROUND(100.0 * a.bad / a.total, 2)
FROM after a;
```
