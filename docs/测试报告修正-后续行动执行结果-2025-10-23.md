### 任务2：修复source_hint字段写入逻辑 ✅

#### 原始建议
> 检查数据导入和计算模块中source_hint字段的写入代码  
> 确保CSV导入的数据标记为 'csv'  
> 确保计算生成的数据标记为 'calculated'

#### 执行结果
**无需修复** - source_hint字段已经正确填充，只是格式不是简单的'csv'和'calculated'。

#### 深度分析

**实际的source_hint格式**：

1. **CSV导入数据**：
   ```
   data/<相对路径>|batch=<run_id>|ver=2
   ```
   示例：
   ```
   data/二期_供水泵房_多功能电表_3#加压泵_C相电压_反馈.csv|batch=20251018T052352Z|ver=2
   ```

2. **计算生成数据**：
   ```
   calculation_{method_id}
   calculation_cyclic_{metric_key}
   calculation_orchestrator
   ```
   示例：
   ```
   calculation_pump_outlet_pressure_method_b
   calculation_main_pipeline_inlet_pressure_method_b
   ```

**数据库验证结果**：

| source_hint类型 | 记录数 | 示例 |
|----------------|--------|------|
| 计算生成（pump_outlet_pressure） | 43,200 | calculation_pump_outlet_pressure_method_b |
| 计算生成（main_pipeline_inlet_pressure） | 7,200 | calculation_main_pipeline_inlet_pressure_method_b |
| CSV导入（各种指标） | 2,400/文件 | data/...csv\|batch=...\|ver=2 |

**代码实现**：

1. **CSV导入**（`app/services/ingest/source_hint.py`）：
   ```python
   def make_source_hint(settings: Settings, base_dir: Path, csv_path: Path) -> str:
       rel = csv_path.relative_to(base_dir).as_posix()
       run_id = getattr(settings.ingest, "_runtime_run_id", None) or datetime.utcnow().strftime("%Y%m%dT%H%M%SZ")
       return f"data/{rel}|batch={run_id}|ver=2"
   ```

2. **计算生成**（`app/services/calculation/orchestrator.py`）：
   ```python
   if is_cyclic:
       source_hint = f"calculation_cyclic_{metric_key}"
   elif method_id:
       source_hint = f"calculation_{method_id}"
   else:
       source_hint = "calculation_orchestrator"
   ```

**结论**：
- source_hint字段**已经正确填充**
- 格式设计**更加详细和可追溯**
- 原始测试报告中的"source_hint字段为空"是**错误的结论**

#### 执行结果
**无需修复** - 这是正确的设计，设备类型限制确保了计算方法只在合适的设备上执行。

#### 深度分析

**设备类型配置**：

| 设备ID | 设备名称 | 设备类型 | 泵类型 |
|--------|---------|---------|--------|
| 81-86 | 二期供水泵房1-6#泵 | pump | variable_frequency |
| 87 | 二期供水泵房总管 | main_pipeline | null |
| 88 | 其他 | other | null |

**计算方法的设备类型限制**：

| 指标类型 | 允许的设备类型 | 可用方法数 |
|---------|--------------|-----------|
| pump_* 指标 | pump | 2-5个方法 |
| main_pipeline_* 指标 | main_pipeline | 3-4个方法 |

**设备与指标的匹配关系**：

| 设备类型 | 可计算的指标 | 不可计算的指标 |
|---------|------------|--------------|
| pump (81-86) | pump_flow_rate (5方法)<br>pump_head (2方法)<br>pump_outlet_pressure (4方法) | main_pipeline_inlet_pressure<br>main_pipeline_outlet_pressure |
| main_pipeline (87) | main_pipeline_inlet_pressure (4方法)<br>main_pipeline_outlet_pressure (3方法) | pump_flow_rate<br>pump_head<br>pump_outlet_pressure |

**日志中的"警告"分析**：

原始测试报告中提到的"8个指标无可用计算方法"，实际上是：
- **pump设备**尝试计算`main_pipeline_*`指标 → 正确拒绝
- **main_pipeline设备**尝试计算`pump_*`指标 → 正确拒绝

这是**设计正确的行为**，不是错误！

**设计原理**：

1. **物理意义**：
   - `pump_*`指标：单个泵的性能参数（流量、扬程、压力等）
   - `main_pipeline_*`指标：总管的性能参数（进出口压力等）

2. **计算方法**：
   - pump设备的方法：基于单泵数据计算
   - main_pipeline设备的方法：基于多泵聚合计算

3. **类型安全**：
   - `allowed_device_types`字段确保方法只在合适的设备上执行
   - 防止错误的计算逻辑应用到不匹配的设备

**结论**：
- 设备类型限制是**正确的设计**
- "无可用计算方法"是**预期的行为**
- 原始测试报告中的"问题"是**误解了设计意图**
