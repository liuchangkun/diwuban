## 📋 问题描述

### 错误信息

```
IndexError: boolean index did not match indexed array along axis 0; 
size of axis is 7200 but size of corresponding boolean axis is 3999/156
```

### 错误位置

**文件**：`app/services/calculation/orchestrator.py`  
**行号**：Lines 1514-1543（修复前）

### 错误场景

- **触发条件**：循环依赖指标的验证失败，导致 values 数组被过滤
- **影响范围**：所有循环依赖指标的计算和写入
- **错误频率**：每次验证失败时必然发生

## 🔍 根本原因分析

### 错误代码（修复前）

```python
# Line 1515: 验证（统一签名）
is_valid, mask, errors, warnings = self.validator.validate_ctx(member, values, ctx)
if not is_valid and mask is not None:
    logger.warning(f"循环依赖指标 {member} 验证失败: {errors}")
    values = values[mask]  # ❌ 过滤了 values 数组
# ...
if write_to_db:
    written = self.write_results(
        station_id=station_id,
        device_id=device_id,
        metric_key=member,
        timestamps=timestamps,  # ❌ 使用原始 timestamps（长度 = 7200）
        values=values,  # ❌ 但 values 已被过滤（长度 = 3999/156）
        quality_status=0,
        is_cyclic=True
    )
```

### 错误流程

1. **Line 1515**：调用 `validator.validate_ctx()` 验证 values 数组
2. **Line 1516-1518**：验证失败时，`values = values[mask]` 过滤了 values 数组
   - 原始 values 长度：7200
   - 过滤后 values 长度：3999 或 156（取决于有效数据比例）
3. **Line 1533-1541**：调用 `write_results()` 写入数据
   - timestamps 参数：使用原始 timestamps（长度 = 7200）
   - values 参数：使用过滤后的 values（长度 = 3999/156）
4. **Line 997-998**：`write_results()` 方法中
   ```python
   valid_mask = ~np.isnan(values)  # 长度 = 3999/156
   valid_timestamps = timestamps[valid_mask]  # ❌ 尝试用长度 3999/156 的 mask 索引长度 7200 的 timestamps
   ```
5. **结果**：IndexError - 数组长度不匹配

### 对比：非循环指标的正确处理（Lines 2042-2047）

```python
# 当过滤后长度变化时，按mask对齐timestamps
write_ts = timestamps
try:
    if mask is not None and hasattr(mask, '__len__') and len(mask) == len(timestamps):
        if len(filtered_values) != len(timestamps):
            write_ts = timestamps[mask]  # ✅ 同步过滤 timestamps
except Exception:
    write_ts = timestamps
```

**关键差异**：
- ✅ 非循环指标：在调用 write_results 前，同步过滤 timestamps
- ❌ 循环指标：没有同步过滤 timestamps，导致数组长度不匹配

## 🔧 修复方案

### 修复代码（修复后）

```python
# Line 1514-1553（修复后）
# 验证（统一签名）
is_valid, mask, errors, warnings = self.validator.validate_ctx(member, values, ctx)
if not is_valid and mask is not None:
    logger.warning(f"循环依赖指标 {member} 验证失败: {errors}")
    values = values[mask]
# 保存结果
data[member] = values
result['metrics_calculated'].append(member)
result['total_points'] += len(values)
result['valid_points'] += int(mask.sum()) if mask is not None and hasattr(mask, 'sum') else len(values)
# 可选写库
if write_to_db:
    write_start = time.time()
    # ✅ 修复：当过滤后长度变化时，按mask对齐timestamps
    # 参考 lines 2042-2047 的正确实现
    write_ts = timestamps
    try:
        if mask is not None and hasattr(mask, '__len__') and len(mask) == len(timestamps):
            if len(values) != len(timestamps):
                write_ts = timestamps[mask]
    except Exception:
        write_ts = timestamps
    
    # 设备类型校验（循环组场景）
    dtype = self._get_device_type(station_id, device_id)
    if dtype and not self._metric_allowed_for_device(member, dtype):
        logger.info(
            f"skip write: metric={member} not allowed for device_type={dtype}")
    else:
        written = self.write_results(
            station_id=station_id,
            device_id=device_id,
            metric_key=member,
            timestamps=write_ts,  # ✅ 修复：使用对齐后的 timestamps
            values=values,
            quality_status=0,
            is_cyclic=True,  # 标记为循环指标
        )
        result['written_points'] += written
        result['performance_stats']['write_time'] += time.time() - write_start
```

### 修复逻辑说明

1. **添加 timestamps 对齐逻辑**（Lines 1527-1533）：
   - 创建 `write_ts` 变量，初始值为原始 timestamps
   - 检查 mask 是否存在且长度与 timestamps 匹配
   - 如果 values 长度与 timestamps 不匹配，使用 mask 过滤 timestamps
   - 使用 try-except 确保异常情况下仍使用原始 timestamps

2. **修改 write_results 调用**（Line 1543）：
   - 将 `timestamps=timestamps` 改为 `timestamps=write_ts`
   - 确保传入的 timestamps 和 values 长度始终匹配

### 修复效果

**修复前**：
- timestamps 长度：7200
- values 长度：3999/156
- 结果：IndexError

**修复后**：
- timestamps 长度：3999/156（与 values 匹配）
- values 长度：3999/156
- 结果：✅ 正常写入数据库

## ⚠️ 潜在风险和注意事项

### 风险1：性能影响

- **风险**：添加了额外的数组过滤操作
- **影响**：可忽略（仅在验证失败时执行，且操作复杂度为 O(n)）
- **缓解措施**：无需特殊处理

### 风险2：异常处理

- **风险**：try-except 可能掩盖其他错误
- **影响**：低（仅捕获数组操作异常，其他异常会正常抛出）
- **缓解措施**：已添加，使用 try-except 确保异常情况下仍使用原始 timestamps

### 风险3：向后兼容性

- **风险**：修改了核心计算逻辑
- **影响**：无（仅修复bug，不改变正常流程）
