### 分类3：分区表（160+个）

#### mpps_w_* 系列分区表

**父表**：`metrics_presence_per_second_device`

**分区策略**：按周分区（202507-202537等）

**分区表列表**（部分）：
- mpps_w_202507（主分区表）
  - mpps_w_202507_0 ~ mpps_w_202507_15（子分区，按 device_id 哈希分区）
- mpps_w_202508（主分区表）
  - mpps_w_202508_0 ~ mpps_w_202508_15（子分区）
- ... 共约160个分区表

**是否需要外键约束**：❌ 否

**原因**：
1. **分区表继承父表的约束**：如果父表 `metrics_presence_per_second_device` 有外键，所有分区自动继承
2. **父表是统计数据表**：不需要外键约束（数据可重新生成）
3. **性能考虑**：分区表添加外键会严重影响插入性能

## 📝 遗漏原因分析

### 为什么之前的查询没有发现这些表？

**之前的查询**：
```sql
SELECT table_name, column_name
FROM information_schema.columns
WHERE column_name IN ('device_id', 'station_id')
    AND table_schema = 'public'
    AND table_name IN (
        SELECT table_name 
        FROM information_schema.tables 
        WHERE table_type = 'BASE TABLE'
    )
```

**问题**：
1. ✅ **正确排除了分区表**：之前的查询只查询了基础表，正确排除了 mpps_w_* 分区表
2. ✅ **正确排除了视图**：之前的查询只查询了 BASE TABLE，正确排除了视图
3. ✅ **正确排除了其他schema**：之前的查询只查询了 public schema，正确排除了 monitoring 和 _timescaledb_internal

**结论**：
- 之前的查询策略是正确的
- 没有遗漏任何需要添加外键约束的配置表
- "遗漏"的200+个表都是分区表或视图，不需要外键约束
