### 日志策略（6种策略）

#### 策略1：数据库操作类（25个文件）

**日志标签**：
- `[数据库-连接]` - 连接获取、释放、超时
- `[数据库-查询]` - SQL语句、参数、执行时间、影响行数
- `[数据库-事务]` - 事务开始、提交、回滚
- `[数据库-错误]` - SQL错误、连接错误、超时错误
- `[数据库-性能]` - 慢查询（>1秒）、大结果集（>10000行）

**示例**：
```python
_act.info("[数据库-查询] 执行SQL", extra={
    "SQL": sql_statement,
    "参数": params,
    "耗时ms": duration_ms,
    "影响行数": row_count,
})
```

---

#### 策略2：数据处理流程类（30个文件）

**日志标签**：
- `[流程-开始]` - 流程名称、输入参数、时间窗口
- `[流程-阶段]` - 当前阶段、进度百分比、已处理/总数
- `[流程-数据]` - 数据量、数据范围、数据质量
- `[流程-跳过]` - 跳过原因、跳过数量
- `[流程-完成]` - 总耗时、总处理量、成功/失败数

**示例**：
```python
_act.info("[流程-阶段] 当前阶段", extra={
    "阶段名称": stage_name,
    "进度": f"{processed}/{total} ({progress_pct}%)",
    "预计剩余时间": estimated_remaining,
})
```

---

#### 策略3：API接口类（8个文件）

**日志标签**：
- `[API-请求]` - 方法、路径、参数、客户端IP
- `[API-验证]` - 参数验证结果、权限检查结果
- `[API-处理]` - 业务逻辑执行、数据查询
- `[API-响应]` - 状态码、响应大小、耗时
- `[API-错误]` - 错误类型、错误消息、堆栈跟踪

**示例**：
```python
_act.info("[API-请求] 收到请求", extra={
    "方法": request.method,
    "路径": request.url.path,
    "参数": request.query_params,
    "客户端IP": request.client.host,

```

- `[任务-进度]` - 当前进度、预计剩余时间

## 🔑 关键原则

### 原则1：针对性优化

**不同类型的文件使用不同的日志策略**：
- 数据库操作 → 关注SQL、性能、事务
- 数据处理 → 关注流程、进度、数据量
- API接口 → 关注请求、响应、错误
- 任务调度 → 关注调度、执行、重试

**示例**：
```python
# 数据库操作文件
_act.info("[数据库-查询] 执行SQL", extra={"SQL": sql, "耗时ms": duration_ms})

# 数据处理文件
_act.info("[流程-阶段] 当前阶段", extra={"阶段": stage, "进度": progress})

# API接口文件
_act.info("[API-请求] 收到请求", extra={"方法": method, "路径": path})
```

---

### 原则2：完善/替换现有日志

**不是简单添加，而是**：
1. 搜索现有日志（`_act.info/warning/error/debug`、`log_db_function`）
2. 评估现有日志的质量
3. 完善不足的日志
4. 替换低质量的日志
5. 删除重复的日志

**示例**：
```python
# 原有日志（低质量）
log_db_function("sp_refresh_metric_rule_auto_baseline", args={...}, duration_ms=cost_ms)

# 替换为（高质量）
_act.info("[规则生成-完成] 自动基线计算", extra={
    "存储过程": "sp_refresh_metric_rule_auto_baseline",
    "回溯天数": lookback_days,
    "过滤条件": {"站点ID": station_id, "设备ID": device_id},
    "耗时ms": cost_ms,
    "插入行数": result.get("inserted", 0),
})
```

---

### 原则3：保持代码简洁

**在添加日志的同时**：
- 删除未使用的导入
- 删除注释掉的代码
- 删除空的异常处理
- 删除未使用的变量

**示例**：
```python
# 删除前
import time  # 只用于 log_db_function
from app.core.logging.setup import log_db_function

# old_code = do_something()
# if old_code:
#     process(old_code)

try:
    cur.execute("SET LOCAL statement_timeout TO '600000ms'")
except Exception:
    pass

# 删除后
from app.core.logging.setup import get_logger
_act = get_logger(__name__)

try:
    cur.execute("SET LOCAL statement_timeout TO '600000ms'")
except Exception as e:
    _act.debug(f"设置超时失败（忽略）: {e}")
```

---

### 原则4：结构化日志

**所有日志都使用 `extra` 参数**：
```python
# ✅ 正确
_act.info("[操作标签] 消息", extra={
    "字段1": value1,
    "字段2": value2,
})

# ❌ 错误
_act.info(f"[操作标签] 处理设备 {device_id}，耗时 {duration_ms}ms")
```

### 建议2：使用自动化工具

**可以使用的工具**：
1. **codebase-retrieval** - 搜索现有日志
2. **view + search_query_regex** - 搜索特定模式
3. **diagnostics** - 检查未使用的导入
4. **str-replace-editor** - 批量修改文件

**示例**：
```bash

# 搜索所有数据库查询

# 检查未使用的导入

```
