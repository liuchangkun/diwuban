## 🔄 prepare_dim 两阶段流程

### Stage 1（在 merge-fact 前执行）

**触发条件**: `configs/merge.yaml` 中 `prepare_dim: true`

**执行步骤**:
1. ✅ 备份手动配置表（2个）
   - dim_device_capabilities
   - dim_metric_metadata_override

2. ✅ 清空依赖表（14个）
   - fact_measurements（所有历史数据）⚠️
   - completion_runs, completion_steps
   - device_rated_params, device_running_thresholds_shadow
   - dim_device_capabilities, dim_metric_metadata_override（已备份）
   - metric_quality_rules_shadow, metric_rule_auto_baseline_shadow
   - dim_devices
   - calculation_parameters（只清空全局默认参数）
   - dim_stations
   - metric_calculation_order, dim_mapping_items
   - dim_metric_config

3. ✅ 重建维度表（3个）
   - dim_stations（从 data_mapping.v2.json）
   - dim_devices（从 data_mapping.v2.json）
   - dim_metric_config（从 dim_metric_config.sql）

4. ✅ 恢复手动配置表（2个）
   - dim_device_capabilities
   - dim_metric_metadata_override

5. ✅ 重建基础配置表（4个）
   - calculation_method_registry（从 init_methods.sql）
   - calculation_parameters（从 init_params.sql）
   - device_rated_params（从 seed_device_rated_params.sql）
   - metric_calculation_order（从 DependencyAnalyzer）

**执行命令**:
```bash
python -m app.cli.main prepare-dim configs/data_mapping.v2.json --stage 1
```

---

### Stage 2（在 merge-fact 后执行）

**触发条件**: `configs/merge.yaml` 中 `prepare_dim_stage2: true`

**前提条件**: ⚠️ fact_measurements 表必须有数据

**执行步骤**:
1. ✅ 清空规则表（6个）
   - metric_rule_auto_baseline
   - metric_rule_auto_baseline_shadow
   - metric_quality_rules
   - metric_quality_rules_shadow
   - device_running_thresholds
   - device_running_thresholds_shadow

2. ✅ 生成规则表（6个函数）
   - run_auto_baseline() → metric_rule_auto_baseline
   - run_auto_baseline_b() → metric_rule_auto_baseline_shadow
   - compute_metric_quality_rules() → metric_quality_rules
   - compute_metric_quality_rules_b() → metric_quality_rules_shadow
   - compute_device_running_thresholds() → device_running_thresholds
   - compute_device_running_thresholds_b() → device_running_thresholds_shadow

3. ✅ 生成映射表（可选）
   - dim_mapping_items（TODO）

**执行命令**:
```bash
python -m app.cli.main prepare-dim configs/data_mapping.v2.json --stage 2
```

INSERT INTO dim_device_capabilities (

## 📝 完整恢复流程

### 场景1：从零开始初始化数据库

```bash
# 步骤1：创建数据库表结构
psql -U postgres -d your_database -f scripts/create_db_and_tables.sql

# 步骤2：执行 prepare-dim stage1（重建维度表和配置表）
python -m app.cli.main prepare-dim configs/data_mapping.v2.json --stage 1

# 步骤3：手动填写 dim_device_capabilities 表
# （通过SQL或管理界面）

# 步骤4：导入数据到 fact_measurements
python -m app.cli.main run-all configs/data_mapping.v2.json --use-staging-time-range

# 步骤5：执行 prepare-dim stage2（生成规则表）
python -m app.cli.main prepare-dim configs/data_mapping.v2.json --stage 2
```

---

### 场景2：通过 run-all 流程自动执行

```yaml
# configs/merge.yaml
run_all:
  prepare_dim: true         # 阶段1：重建维度表（在 merge-fact 前）
  create_staging: true
  ingest_copy: true
  merge_fact: true
  prepare_dim_stage2: true  # 阶段2：生成规则表（在 merge-fact 后）
```

**执行命令**:
```bash
python -m app.cli.main run-all configs/data_mapping.v2.json --use-staging-time-range
```

**执行流程**:
1. prepare-dim stage1 → 备份 → 清空 → 重建维度表 → 恢复 → 重建配置表
2. create-staging → 创建暂存表
3. ingest-copy → 导入数据到暂存表
4. merge-fact → 合并数据到 fact_measurements
5. prepare-dim stage2 → 清空规则表 → 生成规则表

## 🔍 表依赖关系速查

```
dim_stations (泵站维度表)
  ↓
dim_devices (设备维度表)
  ↓
  ├─→ dim_device_capabilities (设备能力表) [手动配置]
  ├─→ device_rated_params (设备额定参数表) [SQL脚本]
  ├─→ device_running_thresholds (运行阈值表) [自动计算]
  └─→ device_running_thresholds_shadow (运行阈值影子表) [自动计算]

dim_metric_config (指标配置维度表)
  ↓
  ├─→ calculation_method_registry (计算方法注册表) [SQL脚本]
  │     ↓
  │   calculation_parameters (计算参数表) [SQL脚本]
  │
  ├─→ metric_calculation_order (指标计算顺序表) [Python生成]
  └─→ dim_metric_metadata_override (指标元数据覆盖表) [手动配置]

fact_measurements (时序事实表) ⭐⭐⭐⭐⭐
  ↓
  ├─→ metric_rule_auto_baseline (自动基线表) [自动计算]
  │     ↓
  │   metric_quality_rules (质量规则表) [自动计算]
  │
  ├─→ metric_rule_auto_baseline_shadow (自动基线影子表) [自动计算]
  │     ↓
  │   metric_quality_rules_shadow (质量规则影子表) [自动计算]
  │
  ├─→ device_running_thresholds (运行阈值表) [自动计算]
  └─→ device_running_thresholds_shadow (运行阈值影子表) [自动计算]
```
