## 🎯 关键原则

### 原则1：针对性优化

**不同类型的文件使用不同的日志策略**：
- 数据库操作 → 关注SQL、性能、事务
- 数据处理 → 关注流程、进度、数据量
- API接口 → 关注请求、响应、错误
- 任务调度 → 关注调度、执行、重试

### 原则2：完善/替换现有日志

**不是简单添加，而是**：
- 搜索现有日志（`_act.info/warning/error/debug`、`log_db_function`）
- 评估现有日志的质量
- 完善不足的日志
- 替换低质量的日志
- 删除重复的日志

### 原则3：保持代码简洁

**在添加日志的同时**：
- 删除未使用的导入
- 删除注释掉的代码
- 删除空的异常处理
- 删除未使用的变量

### 原则4：结构化日志

**所有日志都使用 `extra` 参数**：
```python
_act.info("[操作标签] 消息", extra={
    "字段1": value1,
    "字段2": value2,
})
```

**不要使用字符串拼接**：
```python
# ❌ 错误
_act.info(f"[操作标签] 处理设备 {device_id}，耗时 {duration_ms}ms")

# ✅ 正确
_act.info("[操作标签] 处理设备", extra={
    "设备ID": device_id,
    "耗时ms": duration_ms,
})
```
