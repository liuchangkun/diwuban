## 🐛 发现的代码Bug

### Bug 1: stats_collector.py - 未定义的log_biz函数

**文件位置**：`app/services/calculation/stats_collector.py`

**问题描述**：
- 代码调用了未定义的`log_biz`函数
- 影响4个位置（lines 112, 132, 155, 186）

**影响范围**：
- 统计收集器的日志记录功能
- 可能导致运行时错误

**修复方案**：
```python
# 修复前
log_biz(f"...")

# 修复后
_act.debug(f"...")
```

**修复代码**：
- Line 112: `_act.debug(f"[统计] 组 {group_name} 已存在，跳过创建")`
- Line 132: `_act.debug(f"[统计] 指标 {metric_name} 已存在于组 {group_name}，跳过创建")`
- Line 155: `_act.debug(f"[统计] 记录指标 {metric_name}={value}")`
- Line 186: `_act.debug(f"[统计] 批量记录 {len(records)} 条指标")`

### Bug 2: pool.py - update_wait_time_accurate逻辑错误

**文件位置**：`app/adapters/db/pool.py`

**问题描述**：
- `update_wait_time_accurate`方法中，先同步计数器，再计算平均值
- 导致平均值计算使用了错误的计数器值

**影响范围**：
- 连接池等待时间统计的准确性
- 可能导致统计数据不准确

**修复方案**：
```python
# 修复前（错误顺序）
self._sync_counters()  # 先同步
avg = self._wait_time_sum / max(self._wait_time_count, 1)  # 后计算

# 修复后（正确顺序）
avg = self._wait_time_sum / max(self._wait_time_count, 1)  # 先计算
self._sync_counters()  # 后同步
```

**修复代码**（lines 76-89）：
```python
def update_wait_time_accurate(self, wait_time: float) -> None:
    """更新等待时间（精确版本）"""
    with self._lock:
        self._wait_time_sum += wait_time
        self._wait_time_count += 1
        
        # 先计算平均值（使用当前计数器）
        avg = self._wait_time_sum / max(self._wait_time_count, 1)
        self._wait_time_avg = avg
        
        # 再同步计数器到原子变量
        self._sync_counters()
```

## 🎓 经验教训

### 1. API重构影响

- API重构（如`get_calculator` → `get_calculator_unified`）会影响大量测试
- 应该在重构时同步更新测试
- 使用统一签名可以简化测试

### 2. 测试隔离重要性

- `test_connection_creation_partial_failure_cleanup`在完整测试套件中失败
- 单独运行时通过
- 说明测试之间存在状态共享
- 应该使用fixture确保测试隔离

### 3. Mock设计原则

- 过度Mock内部实现会导致测试脆弱
- `test_prepare_dim_integration.py`就是典型例子
- 应该Mock外部依赖，而不是内部实现

### 4. 代码质量检查

- 通过修复测试发现了2个代码bug
- 测试是发现代码问题的有效手段
- 应该重视测试失败，而不是简单地修改测试
