### 问题1：备份文件SQL语法错误 ❌ 🔴 极高优先级

**位置**：`app/services/ingest/prepare_dim/backup.py` 第355-384行

**问题描述**：
- 备份文件生成时，时间戳类型的值未正确加引号
- 导致5个表无法从备份恢复：
  - `dim_metric_config`
  - `pump_characteristic_curves`
  - `quality_code_dict`
  - `calculation_validation_config`
  - `metric_capability_policy`

**错误日志**：
```
2025-10-20 14:22:11.849337+08|ERROR|[恢复表] dim_metric_config: 恢复失败 - syntax error at or near "15"
LINE 6: ..., 'as_is', NULL, 'number', NULL, NULL, 2025-08-20 15:28:44.5...
```

**根本原因**：
在 `_generate_sql_backup` 函数中，类型检查的顺序不正确：
1. 先检查 `isinstance(val, str)`（第362行）
2. 后检查时间戳类型（第377行）
3. 当 `val` 是 `datetime` 对象时，它不是字符串，所以跳过第362行
4. 然后在第374行的数值检查中也不匹配
5. 最后到第377行时，`datetime` 对象已经被转换为字符串，但没有加引号

**修复方案**：
调整类型检查顺序，将时间戳类型检查提前到字符串检查之前：

```python
# 修复前
elif isinstance(val, str):
    # 转义单引号
    escaped = val.replace("'", "''")
    values.append(f"'{escaped}'")
elif isinstance(val, (list, dict)):
    # JSON/JSONB/数组类型
    import json
    escaped = json.dumps(val).replace("'", "''")
    values.append(f"'{escaped}'")
elif isinstance(val, bool):
    # 布尔类型
    values.append("TRUE" if val else "FALSE")
elif isinstance(val, (int, float)):
    # 数值类型
    values.append(str(val))
elif data_type in ('timestamp without time zone', 'timestamp with time zone', 'date', ...):
    # 时间戳类型：转换为字符串并加引号
    escaped = str(val).replace("'", "''")
    values.append(f"'{escaped}'")

# 修复后
elif isinstance(val, bool):
    # 布尔类型（必须在int检查之前，因为bool是int的子类）
    values.append("TRUE" if val else "FALSE")
elif isinstance(val, (int, float)):
    # 数值类型
    values.append(str(val))
elif data_type in ('timestamp without time zone', 'timestamp with time zone', 'timestamptz', 'date', ...):
    # 时间戳类型：转换为字符串并加引号
    escaped = str(val).replace("'", "''")
    values.append(f"'{escaped}'")
elif isinstance(val, (list, dict)):
    # JSON/JSONB/数组类型
    import json
    escaped = json.dumps(val).replace("'", "''")
    values.append(f"'{escaped}'")
elif isinstance(val, str):
    # 字符串类型：转义单引号
    escaped = val.replace("'", "''")
    values.append(f"'{escaped}'")
```

### 问题2：计算方法选择失败 ❌ 🔴 极高优先级

**位置**：`app/services/calculation/orchestrator.py` 第607-667行

**问题描述**：
- 所有指标都显示"没有可用的计算方法"
- 导致缺失指标计算功能完全失效

**错误日志**：
```
2025-10-20 14:22:58.734943+08|ERROR|指标 pump_flow_rate 没有可用的计算方法
2025-10-20 14:22:59.250523+08|ERROR|指标 pump_speed 没有可用的计算方法
2025-10-20 14:22:59.253703+08|ERROR|指标 main_pipeline_inlet_pressure 没有可用的计算方法
...（共71条错误）
```

**根本原因**：
1. `_get_running_device_count` 函数查询 `mv_device_running_1s` 表
2. 表中所有设备的 `running` 值都是 0（没有运行中的设备）
3. 函数返回 `running_count = 0`
4. 所有需要 `min_running_pumps >= 2` 的方法都被拒绝
5. 没有回退机制处理 `running_count = 0` 的情况

**数据验证**：
```sql
-- 查询结果：所有设备的 running 值都是 0
SELECT station_id, device_id, running
FROM mv_device_running_1s
WHERE station_id = 6
  AND ts_bucket >= '2025-05-31T18:00:00+00:00'
  AND ts_bucket < '2025-05-31T20:00:00+00:00'
LIMIT 10;

-- 结果：
-- station_id=6, device_id=41, running=0
-- station_id=6, device_id=42, running=0
-- station_id=6, device_id=43, running=0
-- ...
```

**修复方案**：
在 `_get_running_device_count` 函数中添加回退机制，当查询到的运行设备数为0时，返回默认值2：

```python
if row and row[0] is not None:
    running_count = int(row[0])
    
    # 如果查询到的运行设备数为0，使用默认值2（可能是数据问题）
    if running_count == 0:
        logger.warning(
            f"查询到运行设备数量为0，使用默认值2（可能是设备运行状态数据缺失）",
            extra={
                "station_id": station_id,
                "start_time": start_time,
                "end_time": end_time
            }
        )
        return 2
    
    logger.debug(
        f"查询到运行设备数量: {running_count}",
        extra={
            "station_id": station_id,
            "start_time": start_time,
            "end_time": end_time
        }
    )
    return running_count
```
