## 📋 问题描述

### 问题8：曲线优化器唯一约束冲突

**错误信息**：
```
duplicate key value violates unique constraint "idx_pump_curves_unique"
DETAIL:  Key (device_id, curve_type, COALESCE(speed, '-1'::integer::numeric), COALESCE(frequency, '-1'::integer::numeric), flow_rate)=(1, Q-H, -1, -1, 50) already exists.
```

**错误位置**：
- 文件：`app/services/calculation/curve_optimizer.py`
- 函数：`_update_curve_points`
- 行号：511 (cur.execute)

**唯一约束定义**：
```sql
CREATE UNIQUE INDEX idx_pump_curves_unique 
ON public.pump_characteristic_curves 
USING btree (
    device_id, 
    curve_type, 
    COALESCE(speed, -1), 
    COALESCE(frequency, -1), 
    flow_rate
)
```

**错误原因**：
1. **重复的flow_rate值**：
   - `new_points` 列表包含重复的 `flow_rate` 值
   - 在同一个事务中，多次插入相同的 `(device_id, curve_type, speed, frequency, flow_rate)` 组合
   - 第一次INSERT成功，第二次INSERT触发唯一约束冲突

2. **ON CONFLICT未生效**：
   - 虽然代码使用了 `ON CONFLICT ... DO UPDATE`，但是在同一个事务中，第一次INSERT已经插入了记录
   - 第二次INSERT时，记录已经存在于当前事务的缓冲区中，但还未提交
   - PostgreSQL在事务内部检测到重复键，抛出错误

## 🔧 修复方案

### 修复内容：添加去重逻辑

**修改位置**：`app/services/calculation/curve_optimizer.py` lines 506-527

**修改前**：
```python
current_version = cur.fetchone()[0]
new_version = current_version + 1

# 使用UPSERT策略更新曲线点
upserted_count = 0
for flow_rate, value in new_points:
    cur.execute("""
        INSERT INTO pump_characteristic_curves
        ...
    """, (...))
    upserted_count += 1
```

**修改后**：
```python
current_version = cur.fetchone()[0]
new_version = current_version + 1

# 去重：如果有重复的flow_rate，保留最后一个
unique_points = {}
for flow_rate, value in new_points:
    unique_points[flow_rate] = value

if len(unique_points) < len(new_points):
    logger.warning(
        f"曲线点包含重复的flow_rate，已去重: {len(new_points)} -> {len(unique_points)}",
        extra={
            "device_id": device_id,
            "curve_type": curve_type,
            "original_count": len(new_points),
            "unique_count": len(unique_points)
        }
    )

# 使用UPSERT策略更新曲线点
upserted_count = 0
for flow_rate, value in unique_points.items():
    cur.execute("""
        INSERT INTO pump_characteristic_curves
        ...
    """, (...))
    upserted_count += 1
```

**关键改进**：
1. ✅ 使用字典 `unique_points` 去重，保留最后一个值
2. ✅ 记录去重操作的日志
3. ✅ 更新验证逻辑，使用 `len(unique_points)` 而不是 `len(new_points)`
4. ✅ 更新日志信息，使用 `len(unique_points)` 而不是 `len(new_points)`

## 📊 影响分析

### 正面影响

1. **消除唯一约束冲突**：
   - ✅ 去重后，不会在同一个事务中插入重复的记录
   - ✅ ON CONFLICT子句可以正常工作
   - ✅ 不会抛出唯一约束冲突错误

2. **数据质量改进**：
   - ✅ 如果有重复的flow_rate，保留最后一个值（通常是最新的）
   - ✅ 记录去重操作，便于追踪数据质量问题

3. **代码健壮性提升**：
   - ✅ 处理了边界情况（重复数据）
   - ✅ 增加了日志记录
   - ✅ 验证逻辑更加准确

### 潜在风险

1. **数据丢失**：
   - ⚠️ 如果有重复的flow_rate，只保留最后一个值，其他值会被丢弃
   - ✅ 但是，这是合理的行为，因为同一个flow_rate不应该有多个值

2. **性能影响**：
   - ⚠️ 去重操作需要遍历所有点，可能略微降低性能
   - ✅ 但是，去重的开销很小（O(n)），可以接受
