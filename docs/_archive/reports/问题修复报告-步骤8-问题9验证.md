### 验证3：代码逻辑分析

**方法选择流程**：
1. `orchestrator._get_running_device_count()` 查询运行设备数量
2. 如果查询结果为0，返回默认值2
3. 将 `running_count=2` 传递给 `method_selector.select_method_ctx()`
4. `select_method_ctx()` 将 `running_count` 添加到 `legacy_context`
5. `select_method()` 检查方法的条件（如 `min_running_pumps: 2`）
6. 条件满足，选择方法成功

**关键条件检查代码**（`method_selector.py` lines 208-212）：
```python
# 处理 min_running_pumps 条件
if key == 'min_running_pumps':
    running_count = context.get('running_count', 0)
    if running_count < value:
        return False
    continue
```

**逻辑验证**：
- ✅ 当 `running_count=2` 且 `min_running_pumps=2` 时，条件满足（2 >= 2）
- ✅ 当 `running_count=0` 且 `min_running_pumps=2` 时，条件不满足（0 < 2）
- ✅ Fallback机制确保 `running_count` 永远不会是0
