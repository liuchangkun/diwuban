## 🚨 新发现的严重问题

### 问题：事务未提交，数据未持久化

**现象**：
- 测试脚本显示 `auto_baseline_b` 插入了71行数据
- 但数据库查询显示 `metric_rule_auto_baseline_shadow` 表有0行

**数据库查询结果**：
```sql
SELECT * FROM public.metric_rule_auto_baseline_shadow LIMIT 10;
-- 结果：0行
```

**根本原因**：
1. `auto_baseline_b.py` 函数没有提交事务
2. 函数执行完毕后，连接关闭，事务回滚
3. 所有INSERT操作都被丢弃

**代码分析**：
- 函数使用 `get_conn(settings)` 获取连接
- 函数内部执行 `cur.execute(INSERT ...)`
- 函数结束时没有调用 `conn.commit()`
- 连接池可能期望 `autocommit=True`，但实际连接可能是 `autocommit=False`

---

## 🔧 解决方案

### 方案1：在规则生成函数中添加事务提交（推荐）

**修改内容**：在每个规则生成函数的最后，添加事务提交逻辑。

**示例（auto_baseline_b.py）**：
```python
def run_auto_baseline_b(settings, ...):
    with get_conn(settings) as conn:
        with conn.cursor() as cur:
            # ... 执行INSERT操作 ...

            # 提交事务
            conn.commit()  # ← 添加这一行

    return result
```

**优势**：
- ✅ 确保数据持久化
- ✅ 符合数据库最佳实践
- ✅ 修改简单，风险低

**工作量**：
- 6个文件 × 1行 = 6行代码修改
- 预计耗时：5分钟

---

### 方案2：修改连接池配置，启用autocommit

**修改内容**：在连接池创建连接时，设置 `autocommit=True`。

**劣势**：
- ❌ 可能影响其他使用连接池的代码
- ❌ 无法回滚错误的操作
- ❌ 不符合数据库最佳实践
