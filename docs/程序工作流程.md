# 程序工作流程（CLI 全链路）

## 背景与目标
- 将导入→对齐→质量标注→聚合→查询的作业流标准化、可回放。

## 作业流与时序
- 导入：staging COPY/校验
- 合并：窗口合并入事实表
- 标注：按窗口执行质量/相位标注
- 聚合/物化：刷新 MV
- 查询：API 报表与明细

## 幂等与重试
- 每步记录日志；失败可重放。

## CLI 帮助（自动块）
> 日后由 export_cli_help.py 输出

## 常见失败与排障
- 连接失败/事务冲突/索引缺失；参见“日志运维.md”。


## 记忆更新触发与异常处理（无常驻进程）
- 触发机制：
  - 每轮对话结束前由助手自动执行 `scripts/dev/scan_changes_and_update_memory.py`，无需本地守护进程。
  - 也可手动运行：`python scripts/dev/scan_changes_and_update_memory.py`。
- 写入范围与规则：
  - 仅记录 代码/数据库/配置 的新增/删除/修改；忽略 docs/** 人为文档编辑与系统输出目录（docs/PLAYBOOKS、_archive、_backup、generated、数据库设计文档本身）。
  - 数据库变更双写：`docs/PLAYBOOKS/数据库变更记录.md` 与 `docs/数据库设计文档.md` → “变更记录”。
  - 严格识别“决策/修复”，仅满足严格条件时写入 `决策记录.md` / `错误与修复记录.md`；对话摘要写入 `对话记忆.md`。
- 验证与排障：
  - 查看：`docs/PLAYBOOKS/对话记忆.md`、`改进与优化记录.md`、`数据库变更记录.md`、`配置变更记录.md`，以及 `docs/PLAYBOOKS/INDEX.md` 的 MEMORY_AUTO 块。
  - 如出现大量噪声（如 CRLF→LF 行尾差异）：建议先统一行尾或分批提交后再运行更新脚本。
- 归档策略：在 PLAYBOOKS 文档首行标注“[归档]”或“[过时]”，执行 `scripts/dev/auto_archive_playbooks.py` 自动归档并写回摘要。
- 编码与乱码预防：
  - 扫描脚本强制 `git -c core.quotepath=false` 并优先 UTF-8 解码，杜绝路径转义导致的乱码。
  - 若历史有乱码，可执行 `python scripts/dev/cleanup_dialog_memory.py` 一次性清理。
