## 一、计算方法补齐建议

### 1.1 pump_efficiency 高精度方法

**当前状态**：
- 只有1个方法（EFF_SIMPLE_V1）
- 缺少基于特性曲线的高精度方法

**建议方案**：
1. **实现 EFF_CURVE_V1 方法**（已在优先级3.3中规划）
   - 从 pump_characteristic_curves 表读取 Q-η 曲线
   - 根据当前流量插值计算效率
   - 精度等级：high

2. **实现 EFF_POWER_V1 方法**（新增）
   - 基于功率平衡计算效率
   - 公式：η = (ρ × g × Q × H) / (P_shaft × 1000)
   - 需要轴功率数据（可从电机功率和电机效率推算）
   - 精度等级：high

3. **实现 EFF_MANUFACTURER_V1 方法**（新增）
   - 从制造商提供的效率表读取
   - 根据流量和扬程查表或插值
   - 精度等级：high

**优先级**：🟢 中等（提升计算精度和容错能力）

---

### 1.2 pump_torque 备选方法

**当前状态**：
- 有2个方法（method_a 和 method_b）
- 都依赖 pump_head，缺少独立方法

**建议方案**：
1. **实现 TORQUE_POWER_V1 方法**（新增）
   - 从功率和转速计算扭矩
   - 公式：T = (P × 9550) / n
   - 依赖：pump_active_power, pump_speed
   - 精度等级：medium

2. **实现 TORQUE_CURRENT_V1 方法**（新增）
   - 从电流和电压估算扭矩
   - 适用于变频器驱动的泵
   - 依赖：pump_current, pump_voltage, pump_frequency
   - 精度等级：low

**优先级**：🟢 中等（增加备选方法）

---

### 1.3 main_pipeline_outlet_pressure 高精度方法

**当前状态**：
- 有3个方法（A/B/C）
- 缺少基于流量和管道特性的精确计算方法

**建议方案**：
1. **实现 POUT_HYDRAULIC_V1 方法**（新增）
   - 基于水力学公式计算
   - 考虑管道摩擦损失、局部损失
   - 公式：P_out = P_in + ρ × g × H_pump - ΔP_friction - ΔP_local
   - 依赖：main_pipeline_inlet_pressure, pump_head, main_pipeline_flow_rate
   - 需要管道参数：长度、直径、粗糙度
   - 精度等级：high

**优先级**：⚪ 低（当前方法已足够）

## 二、参数配置完善建议

### 2.1 建立参数配置规范

**建议**：
1. **参数分类规范**：
   - **物理常数**：P_atm, rho, g → calculation_parameters（全局）
   - **设备固有参数**：slip, pole_pairs, rated_power → device_rated_params
   - **计算系数**：a0-a5, b0-b3 → calculation_parameters（可优化）
   - **边界参数**：H_min, H_max, P_in_min, P_in_max → calculation_parameters

2. **参数命名规范**：
   - 物理常数：全小写，下划线分隔（如 `p_atm`）
   - 系数参数：字母+数字（如 `a0`, `b1`）
   - 边界参数：指标名_min/max（如 `H_min`, `H_max`）

3. **参数文档规范**：
   - 每个参数必须有注释说明
   - 必须标注单位
   - 必须标注是否可优化
   - 必须标注合理范围

**优先级**：🟡 高（提升参数管理规范性）

---

### 2.2 实施参数优化机制

**建议方案**：
1. **选择优化算法**：
   - **贝叶斯优化**：适用于参数空间较小（< 20个参数）
   - **网格搜索**：适用于参数范围明确
   - **遗传算法**：适用于参数空间较大

2. **定义优化目标**：
   - 最小化计算误差（与传感器数据对比）
   - 最大化计算成功率
   - 最小化计算时间

3. **实施步骤**：
   ```python
   # 示例：贝叶斯优化
   from skopt import gp_minimize
   from skopt.space import Real
   
   # 定义参数空间
   space = [
       Real(0.0, 100.0, name='a0'),
       Real(-1.0, 1.0, name='a1'),
       Real(-0.01, 0.01, name='a2'),
   ]
   
   # 定义目标函数
   def objective(params):
       # 使用参数计算，返回误差
       a0, a1, a2 = params
       error = calculate_error(a0, a1, a2)
       return error
   
   # 执行优化
   result = gp_minimize(objective, space, n_calls=100)
   
   # 保存优化结果
   save_optimized_params(result.x)
   ```

4. **记录优化历史**：
   - 所有优化过程记录到 optimization_history 表
   - 包含：旧值、新值、改进分数、优化方法

**优先级**：🟢 中等（提升计算精度）

### 2.3 建立参数验证机制

**建议**：
1. **参数范围验证**：
   - 检查参数值是否在 param_min 和 param_max 范围内
   - 超出范围时拒绝或警告

2. **参数一致性验证**：
   - 检查设备特定参数是否与设备类型匹配
   - 检查参数单位是否正确

3. **参数完整性验证**：
   - 检查每个方法的必需参数是否都已配置
   - 缺失参数时报警

**实施**：
```sql
-- 创建参数验证函数
CREATE OR REPLACE FUNCTION validate_calculation_parameters()
RETURNS TABLE(method_id TEXT, param_name TEXT, issue TEXT) AS $$
BEGIN
    -- 检查参数范围
    RETURN QUERY
    SELECT cp.method_id, cp.param_name, 'Value out of range' AS issue
    FROM calculation_parameters cp
    WHERE (cp.param_min IS NOT NULL AND cp.param_value < cp.param_min)
       OR (cp.param_max IS NOT NULL AND cp.param_value > cp.param_max);
    
    -- 检查参数完整性
    -- （需要根据方法定义检查必需参数）
END;
$$ LANGUAGE plpgsql;
```

**优先级**：🟡 高（防止参数配置错误）

## 三、代码逻辑优化建议

### 3.1 方法选择逻辑优化

**当前问题**：
- 方法选择逻辑较简单，只考虑优先级和依赖
- 未考虑历史成功率、执行时间等因素

**建议方案**：
1. **引入动态优先级**：
   ```python
   def calculate_dynamic_priority(method, historical_stats):
       base_priority = method['priority']
       success_rate = historical_stats.get('success_rate', 0.5)
       avg_time = historical_stats.get('avg_time_ms', 100)
       
       # 成功率权重：50%
       # 执行时间权重：30%
       # 基础优先级权重：20%
       dynamic_priority = (
           base_priority * 0.2 +
           success_rate * 100 * 0.5 +
           (100 - avg_time) * 0.3
       )
       return dynamic_priority
   ```

2. **实施方法降级机制**：
   - 如果高优先级方法连续失败N次，自动降低其优先级
   - 定期重置优先级，避免永久降级

3. **实施方法黑名单机制**：
   - 如果某个方法在特定设备上总是失败，加入黑名单
   - 黑名单定期清理

**优先级**：🟢 中等（提升方法选择智能化）

### 3.2 批量计算优化

**当前问题**：
- 批量计算时逐条处理，效率较低
- 未充分利用向量化计算

**建议方案**：
1. **实施批量参数加载**：
   ```python
   def load_parameters_batch(method_ids):
       """批量加载多个方法的参数"""
       query = """
           SELECT method_id, param_name, param_value
           FROM calculation_parameters
           WHERE method_id = ANY(%s)
       """
       results = execute_query(query, (method_ids,))
       
       # 组织成字典
       params_dict = {}
       for row in results:
           if row['method_id'] not in params_dict:
               params_dict[row['method_id']] = {}
           params_dict[row['method_id']][row['param_name']] = row['param_value']
       
       return params_dict
   ```

2. **实施向量化计算**：
   ```python
   import numpy as np
   
   def calculate_pump_head_vectorized(P_out_array, P_in_array, rho, g):
       """向量化计算泵扬程"""
       H_array = (P_out_array - P_in_array) * 1e6 / (rho * g)
       return H_array
   ```

3. **实施并行计算**：
   ```python
   from multiprocessing import Pool
   
   def calculate_missing_metrics_parallel(data_chunks, num_workers=4):
       """并行计算缺失指标"""
       with Pool(num_workers) as pool:
           results = pool.map(calculate_chunk, data_chunks)
       return results
   ```

**优先级**：🟡 高（显著提升计算性能）

### 3.3 缓存机制实施

**建议方案**：
1. **方法注册缓存**：
   ```python
   from functools import lru_cache
   
   @lru_cache(maxsize=128)
   def get_methods_for_metric(metric_key):
       """缓存方法查询结果"""
       query = """
           SELECT * FROM calculation_method_registry
           WHERE metric_key = %s AND is_enabled = true
           ORDER BY priority DESC
       """
       return execute_query(query, (metric_key,))
   ```

2. **参数缓存**（使用内存缓存）：
   ```python
   from cachetools import TTLCache, cached
   from cachetools.keys import hashkey
   import threading

   # 创建TTL缓存（1小时过期）
   _param_cache = TTLCache(maxsize=1000, ttl=3600)
   _param_cache_lock = threading.RLock()

   @cached(cache=_param_cache, lock=_param_cache_lock,
           key=lambda method_id, device_id: hashkey(method_id, device_id or 0))
   def get_parameters_cached(method_id, device_id=None):
       """从内存缓存读取参数"""
       # 从数据库加载
       params = load_parameters_from_db(method_id, device_id)
       return params
   ```

3. **计算结果缓存**（使用内存缓存）：
   ```python
   from cachetools import TTLCache, cached
   from cachetools.keys import hashkey
   import threading

   # 创建TTL缓存（10分钟过期）
   _calc_cache = TTLCache(maxsize=10000, ttl=600)
   _calc_cache_lock = threading.RLock()

   @cached(cache=_calc_cache, lock=_calc_cache_lock,
           key=lambda device_id, metric_key, ts: hashkey(device_id, metric_key, ts))
   def get_calculated_value_cached(device_id, metric_key, ts):
       """从内存缓存读取计算结果"""
       # 计算
       value = calculate_metric(device_id, metric_key, ts)
       return value
   ```

   **注意**：
   - 使用 `cachetools.TTLCache` 实现TTL缓存
   - 线程安全（使用RLock）
   - 自动过期（TTL机制）
   - 无需外部依赖（如Redis）

**优先级**：🟡 高（显著提升查询性能）

   ```sql
   ON fact_measurements USING GIN (calculation_metadata);
   ```

2. **calculation_method_registry 表增加统计字段**：
   ```sql
   ALTER TABLE calculation_method_registry
   ADD COLUMN total_executions BIGINT DEFAULT 0,
   ADD COLUMN total_successes BIGINT DEFAULT 0,
   ADD COLUMN avg_execution_time_ms NUMERIC DEFAULT 0;
   
   -- 定期更新统计
   CREATE OR REPLACE FUNCTION update_method_statistics()
   RETURNS void AS $$
   BEGIN
       UPDATE calculation_method_registry cmr
       SET total_executions = stats.total,
           total_successes = stats.successes,
           avg_execution_time_ms = stats.avg_time
       FROM (
           SELECT 
               method_id,
               COUNT(*) AS total,
               SUM(CASE WHEN success THEN 1 ELSE 0 END) AS successes,
               AVG(execution_time_ms) AS avg_time
           FROM calculation_performance_metrics
           WHERE created_at >= NOW() - INTERVAL '7 days'
           GROUP BY method_id
       ) stats
       WHERE cmr.method_id = stats.method_id;
   END;
   $$ LANGUAGE plpgsql;
   ```

**优先级**：🟢 中等（提升可追溯性和统计能力）
