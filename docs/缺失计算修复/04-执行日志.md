#### 发现5：参数加载使用"全有或全无"逻辑（问题3.9）

**现状**：
- 当前 load_parameters() 方法：
  - 如果设备有任何参数 → 只使用设备级参数
  - 如果设备没有参数 → 只使用全局级参数
- 无法实现部分参数覆盖

**影响**：
- 如果设备只配置了3个参数，其他7个参数会缺失
- 导致计算失败或使用硬编码默认值

#### 发现6：参数优化器未使用额定参数作为约束（问题3.8）

**现状**：
- parameter_optimizer.py 使用RLS算法优化参数
- 支持参数约束（上下界）
- 但**未使用设备额定参数作为约束**
- 未在额定工况点添加约束

**影响**：
- 优化后的参数可能偏离设备实际特性
- 在额定工况点精度可能降低

   - 影响：无法存储P矩阵，无法监控优化效果

**RLS算法原理深度分析**：

递归最小二乘法(RLS)是一种**在线学习算法**，核心特点：

**更新公式**（第252-254行注释）：
```
K(k) = P(k-1) * φ(k) / [λ + φ(k)ᵀ * P(k-1) * φ(k)]  # 增益矩阵
θ(k) = θ(k-1) + K(k) * [y(k) - φ(k)ᵀ * θ(k-1)]      # 参数更新
P(k) = [P(k-1) - K(k) * φ(k)ᵀ * P(k-1)] / λ          # 协方差更新
```

**关键点**：
- P(k) **必须**基于 P(k-1) 更新（第319行）
- P矩阵包含参数估计的不确定性信息
- 随着数据增多，P矩阵的迹（trace）逐渐减小
- **如果每次都重置 P = I * 1000，就完全失去了递归特性**

**当前实现的严重矛盾**：
- apply_rls() 方法正确实现了P矩阵的递归更新（第319行）
- 但 optimize_parameters() 方法每次都重新初始化P（第129行）
- 导致 apply_rls() 计算出的 P_new 完全被浪费
- 这就是用户说的"每次优化都从0开始"的根本原因
