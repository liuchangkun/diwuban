### 1.2 核心设计原则

1. **数据库驱动**: 所有方法、参数、依赖关系都存储在数据库中
2. **动态加载**: 运行时从数据库加载方法和参数，无需重启
3. **优先级选择**: 根据优先级、依赖、条件自动选择最佳方法
4. **参数分层**: 支持设备级 → 站级 → 全局默认的参数覆盖
5. **可扩展性**: 新增方法只需注册到数据库和CALCULATOR_REGISTRY

### 2.2 方法签名规范

所有计算方法必须遵循统一的签名：

```python
def calculate_xxx_method_y(
    data: Dict[str, Any],
    params: Dict[str, float],
    device_info: Optional[Dict[str, Any]] = None
) -> Optional[float]:
    """
    计算xxx指标的方法Y
    
    Args:
        data: 包含所有依赖指标的数据字典
              例如: {'pump_active_power': 100.0, 'pump_frequency': 45.0}
        params: 方法所需的参数字典
                例如: {'alpha': 1.0, 'beta': 1.0, 'f_thr': 3.0}
        device_info: 设备信息（可选）
                     例如: {'device_id': 1, 'device_type': 'pump'}
    
    Returns:
        计算结果（float）或 None（计算失败）
    """
    pass
```

### 2.3 注册新方法的步骤

1. **在 calculators.py 中实现计算函数**
2. **将函数添加到 CALCULATOR_REGISTRY**
3. **在数据库中注册方法** (calculation_method_registry表)
4. **配置方法参数** (calculation_parameters表)
5. **更新计算顺序** (metric_calculation_order表)

## 三、参数加载机制

### 3.1 参数加载优先级

**位置**: `app/services/calculation/orchestrator.py` (lines 682-720)

```python
def load_parameters(
    self,
    method_id: str,
    device_id: Optional[int] = None,
    station_id: Optional[int] = None
) -> Dict[str, float]:
    """
    加载计算方法的参数
    
    优先级（从高到低）：
    1. 设备级参数 (device_id 指定)
    2. 站级参数 (station_id 指定)
    3. 全局默认参数 (device_id=NULL, station_id=NULL)
    4. 代码中的硬编码默认值（仅作为后备）
    """
```

**优先级示例**:

```sql
-- 1. 设备级参数（最高优先级）
SELECT param_name, param_value
FROM calculation_parameters
WHERE method_id = 'pump_flow_rate_method_a'
  AND device_id = 1;

-- 2. 站级参数
SELECT param_name, param_value
FROM calculation_parameters
WHERE method_id = 'pump_flow_rate_method_a'
  AND station_id = 1
  AND device_id IS NULL;

-- 3. 全局默认参数（最低优先级）
SELECT param_name, param_value
FROM calculation_parameters
WHERE method_id = 'pump_flow_rate_method_a'
  AND device_id IS NULL
  AND station_id IS NULL;
```

### 3.2 参数类型

1. **物理常数** (is_optimizable=false)
   - rho (水密度): 1000.0 kg/m³
   - g (重力加速度): 9.80665 m/s²
   - P_atm (大气压): 0.101325 MPa

2. **可优化参数** (is_optimizable=true)
   - alpha, beta (权重指数)
   - f_thr, p_thr (阈值)
   - slip (转差率)
   - eta_motor (电机效率)

3. **设备特定参数** (从device_rated_params表读取)
   - pole_pairs (极对数)
   - rated_power (额定功率)
   - rated_flow (额定流量)
   - rated_head (额定扬程)

## 四、方法选择机制

### 4.1 选择流程

**位置**: `app/services/calculation/method_selector.py` (lines 246-368)

```
1. 从数据库加载所有可用方法
   ↓
2. 按优先级排序（priority DESC）
   ↓
3. 对每个方法依次检查：
   a. 设备类型是否匹配 (allowed_device_types)
   b. 依赖项是否满足 (check_dependencies)
   c. 条件是否满足 (check_conditions)
   ↓
4. 返回第一个通过所有检查的方法
   ↓
5. 如果没有方法通过，返回None
```

### 4.2 依赖检查

**位置**: `app/services/calculation/method_selector.py` (lines 109-168)

```python
def check_dependencies(
    self,
    method: Dict[str, Any],
    available_data: Dict[str, Any]
) -> Tuple[bool, Optional[str]]:
    """
    检查方法的依赖项是否满足
    
    检查内容：
    1. 所有依赖的指标是否存在于available_data中
    2. 依赖的指标值是否有效（非None、非NaN）
    
    Returns:
        (是否满足, 失败原因)
    """
```

### 4.3 条件检查

**位置**: `app/services/calculation/method_selector.py` (lines 170-244)

```python
def check_conditions(
    self,
    method: Dict[str, Any],
    device_info: Dict[str, Any],
    available_data: Dict[str, Any]
) -> Tuple[bool, Optional[str]]:
    """
    检查方法的条件是否满足

    1. min_running_pumps: 最少运行泵数

    3. min/max: 数值范围
    4. has_sensor: 是否有传感器
    5. requires_training: 是否需要训练数据
    6. requires_cumulative_flow: 是否需要累计流量
    
    Returns:
        (是否满足, 失败原因)
    """
```

## 五、依赖关系处理机制

### 5.1 依赖关系定义

**数据库表**: `metric_calculation_order`

```sql
SELECT metric_key, depends_on, priority, order_index
FROM metric_calculation_order
ORDER BY order_index;
```

**示例**:
```
pump_flow_rate: []  -- 无依赖，可直接计算
pump_head: [pump_outlet_pressure, pump_inlet_pressure]
pump_efficiency: [pump_flow_rate, pump_head, pump_active_power]
pump_torque: [pump_flow_rate, pump_head, pump_speed]
```

### 5.2 拓扑排序

系统使用拓扑排序确定计算顺序，确保：
1. 被依赖的指标先计算
2. 避免循环依赖
3. 最大化并行计算机会

### 5.3 循环依赖检测

如果检测到循环依赖，系统会：
1. 记录错误日志
2. 拒绝执行计算
3. 返回明确的错误信息

## 六、错误处理和日志

### 6.1 错误分类

1. **配置错误**: 方法未注册、参数缺失
2. **依赖错误**: 依赖项不满足、数据无效
3. **计算错误**: 除零、溢出、数值异常
4. **数据库错误**: 连接失败、查询超时

### 6.2 日志记录

所有计算过程都会记录到以下表：
- `calculation_failures_log`: 计算失败日志
- `calculation_performance_metrics`: 性能指标
- `optimization_history`: 优化历史

## 七、性能优化

### 7.1 批量计算

支持批量计算多个时间点的数据，减少数据库查询次数。

### 7.2 参数缓存

参数在内存中缓存，避免重复查询数据库。

### 7.3 并行计算

对于无依赖关系的指标，可以并行计算。
