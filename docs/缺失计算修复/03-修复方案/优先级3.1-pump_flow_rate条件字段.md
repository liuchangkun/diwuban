# 优先级3.1：pump_flow_rate 条件字段不一致

## 📋 问题描述

### 具体表现
1. **数据库层面**：
   - pump_flow_rate_method_d 的 conditions 使用 `min_running_pumps`
   - pump_flow_rate_method_e 的 conditions 使用 `running_count`
   - 两个字段名不一致，但含义相同

2. **代码层面**：
   - `check_conditions()` 函数可能只识别其中一个字段名
   - 导致条件检查逻辑不一致

### 根本原因
- **命名不统一**：不同开发者使用了不同的字段名
- **缺乏规范**：没有明确的条件字段命名规范

### 影响范围
- pump_flow_rate_method_d 或 method_e 的条件检查可能失败
- 方法选择逻辑不一致

### 严重程度
🟢 **中等**（影响有限，但应修复以保持一致性）

---

## 🔧 修复步骤

### 步骤1：统一字段名为 running_count

```sql
-- 修改 method_d 的 conditions
UPDATE calculation_method_registry
SET conditions = jsonb_set(
    conditions - 'min_running_pumps',
    '{running_count}',
    conditions->'min_running_pumps'
),
    updated_at = NOW(),
    updated_by = 'manual_fix_3.1'
WHERE method_id = 'pump_flow_rate_method_d'
  AND conditions ? 'min_running_pumps';

-- 验证修改
SELECT method_id, conditions
FROM calculation_method_registry
WHERE method_id IN ('pump_flow_rate_method_d', 'pump_flow_rate_method_e');
```

**预期结果**：
- method_d: `{"description": "功率分摊，中等精度", "running_count": {"min": 2}}`
- method_e: `{"description": "频率分摊，低-中等精度", "running_count": {"min": 2}}`

**注意**：两个方法都需要至少2台泵运行（min_running_pumps=2），不是 exact=1

## 🔄 回滚方案

```sql
UPDATE calculation_method_registry
SET conditions = jsonb_set(
    conditions - 'running_count',
    '{min_running_pumps}',
    conditions->'running_count'
),
    updated_at = NOW(),
    updated_by = 'rollback_3.1'
WHERE method_id = 'pump_flow_rate_method_d';
```
