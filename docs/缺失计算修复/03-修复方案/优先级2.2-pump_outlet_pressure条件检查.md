# 优先级2.2：pump_outlet_pressure 方法A条件检查问题

## 📋 问题描述

### 具体表现
1. **数据库层面**：
   - `calculation_method_registry` 表中 pump_outlet_pressure_method_a 的 conditions 字段包含 `has_sensor` 条件
   - conditions: `{"has_sensor": true, "description": "直接从传感器读取"}`

2. **代码层面**：
   - `method_selector.py` 的 `check_conditions()` 函数无法在运行时检查 `has_sensor` 条件
   - `has_sensor` 是设备配置信息，不是运行时数据
   - 导致条件检查逻辑不完整

3. **运行时表现**：
   - method_a 的条件检查总是失败或被跳过
   - 即使传感器数据可用，也可能选择其他优先级较低的方法

### 根本原因
- **条件类型混淆**：将设备配置条件（has_sensor）与运行时数据条件（running_count）混在一起
- **检查逻辑缺失**：`check_conditions()` 函数未实现设备配置条件的检查
- **设计不一致**：其他方法使用数据可用性判断，而 method_a 使用配置条件

### 影响范围

#### 直接影响
- pump_outlet_pressure_method_a 可能无法被正确选择
- 传感器数据可用时，可能使用计算方法而非直接读取

#### 间接影响
- 计算精度下降（计算方法精度低于传感器直接读取）
- 计算资源浪费（有传感器数据却进行计算）

### 严重程度
🟡 **严重**（影响方法选择逻辑，应尽快修复）

## 🔧 修复步骤

### 方案A：移除 has_sensor 条件，改用数据可用性判断（推荐）

#### 步骤1：修改 conditions 字段
```sql
-- 移除 has_sensor 条件
UPDATE calculation_method_registry
SET conditions = '{"description": "直接从传感器读取（如果数据可用）"}'::jsonb,
    updated_at = NOW(),
    updated_by = 'manual_fix_2.2'
WHERE method_id = 'pump_outlet_pressure_method_a'
  AND metric_key = 'pump_outlet_pressure';
```

**说明**：
- 移除 `has_sensor` 条件后，方法选择器将依赖 `check_dependencies()` 函数
- `check_dependencies()` 会检查 `pump_outlet_pressure` 是否在 `available_data` 中
- 如果传感器数据可用，`available_data` 中会包含 `pump_outlet_pressure`
- 如果传感器数据不可用，依赖检查失败，自动选择其他方法

#### 步骤2：验证修改
```sql
SELECT method_id, conditions, dependencies
FROM calculation_method_registry
WHERE method_id = 'pump_outlet_pressure_method_a';
```

**预期结果**：
```json
{
  "method_id": "pump_outlet_pressure_method_a",
  "conditions": {"description": "直接从传感器读取（如果数据可用）"},
  "dependencies": ["pump_outlet_pressure"]
}
```

### 方案B：实现 has_sensor 条件检查（备选）

#### 步骤1：扩展 dim_device_capabilities 表
```sql
-- 创建设备能力表（如果不存在）
CREATE TABLE IF NOT EXISTS dim_device_capabilities (
    id              BIGSERIAL PRIMARY KEY,
    device_id       BIGINT NOT NULL,
    metric_key      TEXT NOT NULL,
    has_sensor      BOOLEAN NOT NULL DEFAULT false,
    sensor_type     TEXT,
    created_at      TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at      TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    
    UNIQUE(device_id, metric_key)
);

-- 插入设备能力数据
INSERT INTO dim_device_capabilities (device_id, metric_key, has_sensor, sensor_type)
SELECT DISTINCT 
    device_id,
    'pump_outlet_pressure',
    true,
    'pressure_sensor'
FROM fact_measurements
WHERE metric_id = (SELECT id FROM dim_metric_config WHERE metric_key = 'pump_outlet_pressure')
  AND source = 'sensor'
ON CONFLICT (device_id, metric_key) DO UPDATE
SET has_sensor = true, updated_at = NOW();
```

#### 步骤2：修改 check_conditions() 函数
```python
# 在 app/services/calculation/method_selector.py 中修改

def check_conditions(method, device_id, **kwargs):
    """检查方法的执行条件"""
    conditions = method.get('conditions', {})
    
    # 检查 has_sensor 条件
    if 'has_sensor' in conditions:
        required_has_sensor = conditions['has_sensor']
        actual_has_sensor = _check_device_capability(
            device_id, 
            method['metric_key'], 
            'has_sensor'
        )
        if actual_has_sensor != required_has_sensor:
            return False
    
    # 检查其他条件...
    return True

def _check_device_capability(device_id, metric_key, capability_name):
    """查询设备能力"""
    from app.db import get_db_connection
    
    conn = get_db_connection()
    cursor = conn.cursor()
    
    query = f"""
        SELECT {capability_name}
        FROM dim_device_capabilities
        WHERE device_id = %s AND metric_key = %s
    """
    cursor.execute(query, (device_id, metric_key))
    result = cursor.fetchone()
    
    return result[0] if result else False
```
