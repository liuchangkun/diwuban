# 优先级4.2：metric_capability_policy 表中 compute_flag 设置不一致

## 📋 问题描述

### 具体表现
1. **数据库层面**：
   - `metric_capability_policy` 表中 pump_inlet_pressure 的 compute_flag='不需要'
   - 但实际上 pump_inlet_pressure 没有传感器数据，必须通过计算获得

2. **逻辑矛盾**：
   - compute_flag 标记为"不需要"，但实际需要计算
   - 可能导致计算流程跳过此指标

### 根本原因
- **配置错误**：初始配置时假设有传感器数据
- **未及时更新**：发现没有传感器数据后未更新配置

### 影响范围
- 计算流程可能跳过 pump_inlet_pressure
- 与实际需求不符

### 严重程度
⚪ **轻微**（如果计算流程未使用此字段，则无影响）

---

## 🔧 修复步骤

### 步骤1：更新 compute_flag

```sql
-- 修改 pump_inlet_pressure 的 compute_flag
UPDATE metric_capability_policy
SET compute_flag = '需要',
    updated_at = NOW()
WHERE metric_key = 'pump_inlet_pressure';

-- 验证修改
SELECT metric_key, acquisition_status, compute_flag
FROM metric_capability_policy
WHERE metric_key = 'pump_inlet_pressure';
```

**预期结果**：
```
metric_key            | acquisition_status | compute_flag
----------------------|-------------------|-------------
pump_inlet_pressure   | 未采集            | 需要
```

---

### 步骤2：检查其他指标的 compute_flag

```sql
-- 查询所有"未采集"但标记为"不需要"的指标
SELECT metric_key, acquisition_status, compute_flag
FROM metric_capability_policy
WHERE acquisition_status = '未采集'
  AND compute_flag = '不需要';

```

## 📊 参数来源

### compute_flag 定义
| 值 | 说明 | 适用场景 |
|----|------|---------|
| 需要 | 必须计算 | 无传感器数据，必须通过计算获得 |
| 不需要 | 不需要计算 | 有传感器数据，直接采集 |
| 可选 | 可选计算 | 有传感器数据，但可以通过计算验证或补充 |

## ✅ 验证方案

```sql
-- 检查所有指标的配置一致性
SELECT 
    mcp.metric_key,
    mcp.acquisition_status,
    mcp.compute_flag,
    COUNT(cmr.method_id) AS method_count
FROM metric_capability_policy mcp
LEFT JOIN calculation_method_registry cmr 
    ON mcp.metric_key = cmr.metric_key 
    AND cmr.is_enabled = true
GROUP BY mcp.metric_key, mcp.acquisition_status, mcp.compute_flag
ORDER BY mcp.metric_key;

-- 预期：compute_flag='需要' 的指标应该有 method_count > 0
```

## 🔄 回滚方案

```sql
UPDATE metric_capability_policy
SET compute_flag = '不需要',
    updated_at = NOW()
WHERE metric_key = 'pump_inlet_pressure';
```
