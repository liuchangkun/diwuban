# 优先级5.2：计算任务调度机制

## 📋 问题分析

### 问题描述

**具体表现**：
- 计算任务需要手动触发（通过CLI命令 `python -m app.cli.calculate_metrics`）
- 无法自动定时执行计算任务
- 无法根据数据更新自动触发计算
- 无法管理多个计算任务的优先级和依赖关系

**根本原因**：
- 系统缺少任务调度框架
- 没有定时任务配置机制
- 没有任务队列和任务管理

**影响范围**：
- 需要人工定期执行计算任务
- 无法实现实时计算（数据到达后立即计算）
- 无法实现分布式计算（多个worker并行处理）
- 运维成本高，容易遗漏

**严重程度**：🟢 **中等**（影响自动化程度，但不阻塞功能）

---

## 🎯 修复目标

1. **实现定时任务调度**：支持cron表达式配置计算频率
2. **实现事件驱动计算**：数据更新后自动触发计算
3. **实现任务优先级管理**：高优先级任务优先执行
4. **实现任务依赖管理**：自动处理任务之间的依赖关系
5. **实现任务失败重试**：自动重试失败的任务
6. **实现任务监控告警**：任务失败时发送告警

---

## 🔧 修复方案

### 方案选择

**推荐方案**：使用 **APScheduler** + **Celery** 组合

**理由**：
- **APScheduler**：轻量级，适合定时任务，易于集成
- **Celery**：成熟的分布式任务队列，支持优先级、重试、监控
- **组合优势**：APScheduler负责定时触发，Celery负责任务执行和管理

**备选方案**：
- 方案B：只使用Celery Beat（Celery的定时任务组件）
- 方案C：使用Airflow（适合复杂的DAG工作流，但过于重量级）

        # 使用现有的数据库连接配置
        return f"db+postgresql://{self.DB_USER}:{self.DB_PASSWORD}@{self.DB_HOST}:{self.DB_PORT}/{self.DB_NAME}"

    @property
    def celery_result_backend(self) -> str:
        """动态生成Celery result backend URL"""
        return f"db+postgresql://{self.DB_USER}:{self.DB_PASSWORD}@{self.DB_HOST}:{self.DB_PORT}/{self.DB_NAME}"
```

**注意**：
- 使用 `db+postgresql://` 前缀表示数据库broker
- Celery会自动创建所需的表（celery_taskmeta, celery_tasksetmeta）
- 无需额外的Redis或RabbitMQ服务

# -*- coding: utf-8 -*-
"""Celery应用配置"""
from celery import Celery
from app.core.config import settings

# 创建Celery应用
celery_app = Celery(
    'pump_station_tasks',
    broker=settings.celery_broker_url,  # 数据库URL（PostgreSQL）
    backend=settings.celery_result_backend  # 数据库URL（PostgreSQL）
)

# Celery配置
celery_app.conf.update(
    # 任务序列化
    task_serializer='json',
    accept_content=['json'],
    result_serializer='json',
    timezone='Asia/Shanghai',
    enable_utc=True,
    
    # 任务路由
    task_routes={
        'app.tasks.calculation.*': {'queue': 'calculation'},
        'app.tasks.data_import.*': {'queue': 'data_import'},
    },
    
    # 任务优先级
    task_queue_max_priority=10,
    task_default_priority=5,
    
    # 任务重试
    task_acks_late=True,
    task_reject_on_worker_lost=True,
    
    # 任务超时
    task_soft_time_limit=300,  # 5分钟软超时
    task_time_limit=600,  # 10分钟硬超时
    
    # 结果过期时间
    result_expires=3600,  # 1小时
)

# 自动发现任务
celery_app.autodiscover_tasks(['app.tasks'])
```

# -*- coding: utf-8 -*-
"""计算任务"""
from celery import Task
from app.tasks.celery_app import celery_app
from app.services.calculation.orchestrator import CalculationOrchestrator
from app.core.logging import get_logger
from typing import List, Optional
import traceback

logger = get_logger(__name__)


class CalculationTask(Task):
    """计算任务基类（支持自动重试）"""
    autoretry_for = (Exception,)
    retry_kwargs = {'max_retries': 3, 'countdown': 60}
    retry_backoff = True
    retry_backoff_max = 600
    retry_jitter = True


@celery_app.task(
    base=CalculationTask,
    name='app.tasks.calculation.calculate_device_metrics',
    priority=7
)
def calculate_device_metrics(
    device_id: int,
    start_time: Optional[str] = None,
    end_time: Optional[str] = None,
    metrics: Optional[List[str]] = None
) -> dict:
    """
    计算单个设备的指标
    
    Args:
        device_id: 设备ID
        start_time: 开始时间（ISO格式）
        end_time: 结束时间（ISO格式）
        metrics: 指标列表（None表示所有指标）
    
    Returns:
        计算结果字典
    """
    try:
        logger.info(
            f"[Celery任务] 开始计算设备{device_id}的指标",
            extra={"device_id": device_id, "metrics": metrics}
        )
        
        orchestrator = CalculationOrchestrator()
        result = orchestrator.calculate_metrics(
            device_id=device_id,
            start_time=start_time,
            end_time=end_time,
            metrics=metrics
        )
        
        logger.info(
            f"[Celery任务] 设备{device_id}计算完成",
            extra={"device_id": device_id, "success_count": len(result.get('success', []))}
        )
        
        return {
            'status': 'success',
            'device_id': device_id,
            'result': result
        }
        
    except Exception as e:
        logger.error(
            f"[Celery任务] 设备{device_id}计算失败: {str(e)}",
            extra={"device_id": device_id, "error": str(e), "traceback": traceback.format_exc()}
        )
        raise


@celery_app.task(
    name='app.tasks.calculation.calculate_all_devices',
    priority=5
)
def calculate_all_devices(
    start_time: Optional[str] = None,
    end_time: Optional[str] = None,
    metrics: Optional[List[str]] = None
) -> dict:
    """
    计算所有设备的指标（并行执行）
    
    Args:
        start_time: 开始时间（ISO格式）
        end_time: 结束时间（ISO格式）
        metrics: 指标列表（None表示所有指标）
    
    Returns:
        计算结果字典
    """
    from app.models.device import Device
    
    try:
        # 获取所有设备
        devices = Device.query.filter_by(is_active=True).all()
        device_ids = [d.id for d in devices]
        
        logger.info(f"[Celery任务] 开始计算所有设备的指标，共{len(device_ids)}个设备")
        
        # 并行触发每个设备的计算任务
        tasks = []
        for device_id in device_ids:
            task = calculate_device_metrics.apply_async(
                args=(device_id, start_time, end_time, metrics),
                priority=7
            )
            tasks.append(task)
        
        # 等待所有任务完成
        results = [task.get(timeout=600) for task in tasks]
        
        success_count = sum(1 for r in results if r['status'] == 'success')
        
        logger.info(f"[Celery任务] 所有设备计算完成，成功{success_count}/{len(device_ids)}个")
        
        return {
            'status': 'success',
            'total': len(device_ids),
            'success': success_count,
            'results': results
        }
        
    except Exception as e:
        logger.error(f"[Celery任务] 计算所有设备失败: {str(e)}")
        raise


@celery_app.task(
    name='app.tasks.calculation.optimize_device_parameters',

### 步骤4：创建定时任务调度器

**文件**：`app/tasks/scheduler.py`

```python
# -*- coding: utf-8 -*-
"""定时任务调度器"""
from apscheduler.schedulers.background import BackgroundScheduler
from apscheduler.triggers.cron import CronTrigger
from apscheduler.triggers.interval import IntervalTrigger
from app.tasks.calculation_tasks import calculate_all_devices, optimize_device_parameters
from app.core.logging import get_logger
from app.core.config import settings

logger = get_logger(__name__)

# 创建调度器
scheduler = BackgroundScheduler(
    timezone='Asia/Shanghai',
    job_defaults={
        'coalesce': True,  # 合并错过的任务
        'max_instances': 1,  # 同一任务最多1个实例
        'misfire_grace_time': 300  # 错过任务的宽限时间（5分钟）
    }
)


def init_scheduler():
    """初始化调度器"""
    
    # 任务1：每小时计算一次所有设备的指标
    scheduler.add_job(
        func=lambda: calculate_all_devices.delay(),
        trigger=CronTrigger(minute=0),  # 每小时的0分
        id='hourly_calculation',
        name='每小时计算所有设备指标',
        replace_existing=True
    )
    
    # 任务2：每天凌晨2点计算前一天的数据
    scheduler.add_job(
        func=lambda: calculate_all_devices.delay(
            start_time='yesterday 00:00:00',
            end_time='yesterday 23:59:59'
        ),
        trigger=CronTrigger(hour=2, minute=0),
        id='daily_calculation',
        name='每天计算前一天数据',
        replace_existing=True
    )
    
    # 任务3：每周日凌晨3点优化参数
    scheduler.add_job(
        func=lambda: optimize_all_device_parameters(),
        trigger=CronTrigger(day_of_week='sun', hour=3, minute=0),
        id='weekly_optimization',
        name='每周优化设备参数',
        replace_existing=True
    )
    
    # 启动调度器
    scheduler.start()
    logger.info("[调度器] 定时任务调度器已启动")


def optimize_all_device_parameters():
    """优化所有设备的参数"""
    from app.models.device import Device
    
    devices = Device.query.filter_by(is_active=True).all()
    for device in devices:
        # 为每个设备的每个方法创建优化任务
        methods = ['HEAD_COEF_V1', 'PIN_COEF_V1', 'pump_flow_rate_method_a']
        for method_id in methods:
            optimize_device_parameters.apply_async(
                args=(device.id, method_id),
                priority=3
            )


def shutdown_scheduler():
    """关闭调度器"""
    scheduler.shutdown()
    logger.info("[调度器] 定时任务调度器已关闭")
```

## 🚨 风险评估

### 风险1：数据库broker性能

**风险描述**：使用数据库作为Celery消息代理，性能略低于Redis

**缓解措施**：
- 定期清理已完成的任务记录
- 为Celery相关表添加索引
- 监控数据库连接数和查询性能
- 如果任务量增大，考虑迁移到RabbitMQ

**注意**：
- 当前任务量不大，数据库broker性能足够
- 避免了Redis依赖，简化了部署

### 风险2：任务堆积

**风险描述**：如果worker处理速度慢于任务产生速度，会导致任务堆积

**缓解措施**：
- 监控队列长度，超过阈值时告警
- 动态调整worker数量
- 设置任务过期时间

### 风险3：任务失败

**风险描述**：任务执行失败可能导致数据缺失

**缓解措施**：
- 配置自动重试（已实现）
- 记录失败任务到数据库
- 发送告警通知
