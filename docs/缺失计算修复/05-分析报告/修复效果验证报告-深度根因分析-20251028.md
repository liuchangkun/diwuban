#### 根本原因

**数据加载与计算的时间轴不一致**：

1. **数据加载阶段**（`orchestrator.py` lines 228-263）：
   - 当 `filter_running=True` 时，查询使用 `INNER JOIN mv_device_running_1s` 并且 `dr.running = 1`
   - `timestamp_set` 只包含**有数据的时间点**（line 263）
   - `timestamps` 数组长度 = 有数据的时间点数量（line 306）
   - 所有指标数组初始化为 `len(timestamps)`（line 309）

2. **pump_flow_rate 的数据特征**：
   - pump_flow_rate 只在设备运行时有数据（3999秒）
   - 停止时没有数据（3201秒）
   - 这是合理的，因为停止时流量为0或无效

3. **pump_head 的计算特征**：
   - pump_head 依赖 pump_outlet_pressure 和 pump_inlet_pressure
   - pump_outlet_pressure 在所有时间点都有数据（7200秒）
   - pump_inlet_pressure 在所有时间点都有数据（7200秒）
   - 因此 pump_head 在所有时间点都被计算（7200秒）
   - **关键**：pump_head 的计算没有考虑运行状态，在停止时也计算了扬程

4. **数组长度不匹配的产生**：
   - 数据加载时，`timestamps` 长度 = 3999（只包含运行时的时间点）
   - pump_flow_rate 数组长度 = 3999（只在运行时有数据）
   - pump_head 在本次计算中被重新计算，但是：
     - pump_outlet_pressure 和 pump_inlet_pressure 在所有7200秒都有数据
     - pump_head 的计算方法没有过滤非运行时的数据
     - 计算结果可能有7200个数据点
   - 当计算 pump_efficiency 或 pump_torque 时：
     - 尝试使用 pump_flow_rate[3999] 和 pump_head[7200]
     - 导致 `ValueError: operands could not be broadcast together with shapes (3999,) (7200,)`

#### 代码分析

**pump_torque 计算器**（`calculators.py` lines 554-607）：
```python
def calculate_pump_torque_method_a(data: Dict[str, np.ndarray], params: Dict[str, float]) -> np.ndarray:
    Q_m3h = data['pump_flow_rate']  # m³/h
    H = data['pump_head']  # m
    n = data['pump_speed']  # rpm

    # 创建有效数据掩码
    valid_mask = ~np.isnan(Q_m3h) & ~np.isnan(H) & ~np.isnan(n) & (n > 0)

    # 计算扭矩（初始化为NaN）
    T = np.full_like(Q_m3h, np.nan)  # ❌ 如果 Q_m3h 长度=3999，H 长度=7200，这里会失败

    # 单位转换
    Q_m3s = Q_m3h[valid_mask] / 3600.0  # ❌ 如果 valid_mask 长度与 Q_m3h 不匹配，会失败
    omega = 2.0 * np.pi * n[valid_mask] / 60.0

    # 计算水力功率（kW）
    P_shaft = rho * g * Q_m3s * H[valid_mask]  # ❌ 如果 H 长度与 Q_m3h 不匹配，valid_mask 无法正确索引

    return T
```

**问题**：
- `valid_mask` 的长度取决于输入数组的长度
- 如果 `Q_m3h`, `H`, `n` 长度不一致，`valid_mask` 的计算会失败
- 即使 `valid_mask` 计算成功，索引操作 `H[valid_mask]` 也会失败

**pump_efficiency 计算器**（`methods/eff_simple_v1.py` lines 6-37）：
```python
def calculate_eff_simple_v1(data: Dict[str, np.ndarray], params: Dict[str, float]) -> np.ndarray:
    Q = data.get('pump_flow_rate')        # m3/s
    H = data.get('pump_head')             # m
    P_e = data.get('pump_active_power')   # kW

    # 确定数组长度
    n = 0
    for arr in (Q, H, P_e):
        if isinstance(arr, np.ndarray):
            n = len(arr)  # ❌ 如果 Q, H, P_e 长度不一致，n 会取第一个非None数组的长度
            break

    def nz(x):
        return x if isinstance(x, np.ndarray) else np.full(n, np.nan)

    Q = nz(Q)  # ❌ 如果原始 Q 长度 != n，这里会保留原始数组，不会扩展
    H = nz(H)  # ❌ 如果原始 H 长度 != n，这里会保留原始数组，不会扩展
    P_e = nz(P_e)

    denom = P_e * eta_motor  # ❌ 如果 P_e 长度与 Q, H 不一致，会失败
    mask_valid = (~np.isnan(Q)) & (~np.isnan(H)) & (~np.isnan(P_e)) & (denom > 1e-6)  # ❌ 数组长度不一致
    eta = np.full(n, np.nan)
    eta[mask_valid] = (rho * g * Q[mask_valid] * H[mask_valid]) / (denom[mask_valid] * 1000.0)  # ❌ 索引失败

    return eta
```

**问题**：
- `nz()` 函数的逻辑有缺陷：`return x if isinstance(x, np.ndarray) else np.full(n, np.nan)`
- 如果 `x` 是数组但长度 != n，不会扩展或截断，直接返回原始数组
- 导致后续运算时数组长度不一致
