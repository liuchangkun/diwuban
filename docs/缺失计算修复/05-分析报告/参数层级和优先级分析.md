## 📂 参数类型分类

### 分类标准

根据参数的性质和用途，将所有参数分为3类：

#### 1. 物理常数（Physical Constants）

**定义**：普遍适用的物理常数，所有设备通用

| 参数名 | 典型值 | 单位 | 说明 | 使用方法 |
|--------|--------|------|------|---------|
| rho | 1000.0 | kg/m³ | 水密度 | HEAD_COEF_V1, PIN_COEF_V1, EFF_SIMPLE_V1 |
| g | 9.80665 | m/s² | 重力加速度 | HEAD_COEF_V1, PIN_COEF_V1, EFF_SIMPLE_V1 |
| P_atm | 0.101325 | MPa | 大气压 | pump_head_method_main, pump_inlet_pressure_method_b |

**特点**：
- ✅ 所有设备使用相同值
- ✅ 应配置为全局参数（device_id=NULL）
- ✅ 不需要设备级覆盖
- ⚠️ 但在特殊情况下可能需要调整（如高海拔地区的P_atm）

**当前配置**：
```sql
-- 查询物理常数配置
SELECT method_id, param_name, param_value, param_unit
FROM calculation_parameters
WHERE param_name IN ('rho', 'g', 'P_atm') AND device_id IS NULL
ORDER BY method_id, param_name;
```

**配置建议**：
- 物理常数应配置为全局参数
- 除非有特殊需求（如高海拔、高温环境），否则不应设置设备级覆盖
- 建议添加 `is_physical_constant` 标记字段，防止误修改

#### 2. 方法系数（Method Coefficients）

**定义**：特定计算方法的拟合系数，可能因设备而异

| 参数名 | 典型值 | 说明 | 使用方法 | 是否因设备而异 |
|--------|--------|------|---------|--------------|
| a0-a5 | 变化 | HEAD_COEF_V1的扬程系数 | HEAD_COEF_V1 | ⚠️ 可能 |
| b0-b3 | 变化 | PIN_COEF_V1的压力系数 | PIN_COEF_V1 | ⚠️ 可能 |
| alpha | 1.0 | pump_flow_rate_method_a的功率指数 | pump_flow_rate_method_a | ⚠️ 可能 |
| beta | 1.0 | pump_flow_rate_method_a的频率指数 | pump_flow_rate_method_a | ⚠️ 可能 |
| calibration_a | 30.0 | pump_speed_method_c的斜率 | pump_speed_method_c | ⚠️ 可能 |
| calibration_b | 0.0 | pump_speed_method_c的截距 | pump_speed_method_c | ⚠️ 可能 |

**特点**：
- ⚠️ 可能因设备而异（如不同型号的泵特性曲线不同）
- ✅ 应提供全局默认值（device_id=NULL）
- ✅ 允许设备级覆盖（device_id=X）
- ✅ 可通过参数优化器自动优化

**当前配置**：
```sql
-- 查询方法系数配置
SELECT method_id, param_name, param_value, device_id
FROM calculation_parameters
WHERE param_name IN ('a0', 'a1', 'a2', 'a3', 'a4', 'a5', 'b0', 'b1', 'b2', 'b3', 'alpha', 'beta')
ORDER BY method_id, device_id NULLS FIRST, param_name;
```

**配置建议**：
- 为每个方法提供全局默认系数
- 允许为特定设备优化系数
- 记录优化历史（optimization_history字段）
- 设置置信度阈值（confidence_score > 0.7才使用优化值）

#### 3. 阈值参数（Threshold Parameters）

**定义**：用于条件判断的阈值，可能因设备或泵站而异

| 参数名 | 典型值 | 单位 | 说明 | 使用方法 | 是否因设备而异 |
|--------|--------|------|------|---------|--------------|
| f_thr | 3.0 | Hz | 频率阈值 | pump_flow_rate_method_e | ⚠️ 可能 |
| p_thr | 0.5 | kW | 功率阈值 | pump_flow_rate_method_d | ⚠️ 可能 |
| H_min | 0.0 | m | 最小扬程 | HEAD_COEF_V1 | ⚠️ 可能 |
| H_max | 100.0 | m | 最大扬程 | HEAD_COEF_V1 | ⚠️ 可能 |
| P_in_min | 0.0 | MPa | 最小进口压力 | PIN_COEF_V1 | ⚠️ 可能 |
| P_in_max | 1.0 | MPa | 最大进口压力 | PIN_COEF_V1 | ⚠️ 可能 |

**特点**：
- ⚠️ 可能因设备或泵站而异
- ✅ 应提供全局默认值
- ✅ 允许设备级或泵站级覆盖
- ⚠️ 需要根据实际运行情况调整

**当前配置**：
```sql
-- 查询阈值参数配置
SELECT method_id, param_name, param_value, device_id, station_id
FROM calculation_parameters
WHERE param_name LIKE '%_thr' OR param_name LIKE '%_min' OR param_name LIKE '%_max'
ORDER BY method_id, device_id NULLS FIRST, param_name;
```

**配置建议**：
- 根据设备额定参数设置阈值（如 H_max = 1.5 * rated_head）
- 允许泵站级覆盖（同一泵站的设备使用相同阈值）
- 定期审查阈值合理性（基于实际运行数据）

### 分类汇总

| 参数类型 | 参数数量 | 应全局配置 | 允许设备级覆盖 | 允许优化 |
|---------|---------|-----------|--------------|---------|
| 物理常数 | 3 | ✅ 是 | ⚠️ 特殊情况 | ❌ 否 |
| 方法系数 | 12+ | ✅ 是 | ✅ 是 | ✅ 是 |
| 阈值参数 | 6+ | ✅ 是 | ✅ 是 | ⚠️ 谨慎 |

## 🏗️ 参数层级设计

### 当前设计（3层级）

根据 calculation_parameters 表的设计，参数支持3个层级：

```
全局级（device_id=NULL, station_id=NULL）
    ↓ 被覆盖
泵站级（device_id=NULL, station_id=X）
    ↓ 被覆盖
设备级（device_id=X, station_id=NULL）
```

**表结构**：
```sql
CREATE TABLE calculation_parameters (
    id SERIAL PRIMARY KEY,
    method_id VARCHAR(100),
    param_name VARCHAR(100),
    param_value REAL,
    device_id INTEGER,  -- NULL表示全局或泵站级
    station_id INTEGER, -- NULL表示全局或设备级
    ...
);
```

### 改进设计（4层级）

**加上设备额定参数后，应该是4个层级**：

```
全局级计算参数（calculation_parameters, device_id=NULL）
    ↓ 被覆盖
设备额定参数（device_rated_params, device_id=X）
    ↓ 被覆盖
泵站级计算参数（calculation_parameters, station_id=X）
    ↓ 被覆盖
设备级计算参数（calculation_parameters, device_id=X）
```

**优先级规则**：
1. **最低优先级**：全局级计算参数（适用于所有设备的默认值）
2. **次低优先级**：设备额定参数（设备的物理特性参数）
3. **次高优先级**：泵站级计算参数（同一泵站的设备共享）
4. **最高优先级**：设备级计算参数（特定设备的优化参数）

## ⚙️ 当前 load_parameters() 的问题

### 当前实现

**代码位置**：`app/services/calculation/orchestrator.py:682-720`

```python
def load_parameters(self, device_id: int, method_id: str) -> Dict[str, float]:
    """加载计算参数"""
    with get_connection() as conn:
        with conn.cursor() as cur:
            # 先尝试加载设备特定参数
            query = """
                SELECT param_name, param_value
                FROM calculation_parameters
                WHERE device_id = %s AND method_id = %s
            """
            cur.execute(query, (device_id, method_id))
            rows = cur.fetchall()
            
            if not rows:
                # 如果没有设备特定参数，加载全局默认参数
                query = """
                    SELECT param_name, param_value
                    FROM calculation_parameters
                    WHERE device_id IS NULL AND method_id = %s
                """
                cur.execute(query, (method_id,))
                rows = cur.fetchall()
            
            params = {row[0]: float(row[1]) for row in rows}
    
    return params
```

### 问题分析

| 问题 | 描述 | 影响 |
|------|------|------|
| ❌ 问题1 | 完全忽略 device_rated_params 表 | 设备额定参数无法使用 |
| ❌ 问题2 | 忽略泵站级参数（station_id） | 无法为泵站配置共享参数 |
| ❌ 问题3 | 使用"全有或全无"逻辑 | 无法实现部分参数覆盖 |
| ❌ 问题4 | 缺少参数来源日志 | 无法追踪参数来自哪个层级 |

**"全有或全无"逻辑的问题**：

**场景**：设备129的HEAD_COEF_V1方法
- 全局参数：rho, g, a0, a1, a2, a3, a4, a5, H_min, H_max（10个参数）
- 设备级参数：a0, a1, H_max（3个参数）

**当前行为**：
- 如果设备有任何参数 → 只使用设备级参数（3个）
- 结果：缺少 rho, g, a2, a3, a4, a5, H_min（7个参数）
- 后果：计算失败或使用硬编码默认值

**期望行为**：
- 使用设备级参数覆盖全局参数
- 结果：a0, a1, H_max来自设备级，其他7个来自全局级
- 后果：所有参数都可用

## ✅ 正确的优先级实现

### 实现代码

```python
def load_parameters(
    self, 
    device_id: int, 
    method_id: str, 
    station_id: Optional[int] = None
) -> Dict[str, float]:
    """
    加载计算参数（支持4层级优先级）
    
    优先级（从低到高）：
    1. 全局级计算参数（最低优先级）
    2. 设备额定参数
    3. 泵站级计算参数
    4. 设备级计算参数（最高优先级）
    
    Args:
        device_id: 设备ID
        method_id: 计算方法ID
        station_id: 泵站ID（可选）
    
    Returns:
        参数字典 {param_name: param_value}
    """
    params = {}
    param_sources = {}  # 记录每个参数的来源
    
    with get_connection() as conn:
        with conn.cursor() as cur:
            # 层级1：加载全局计算参数
            query = """
                SELECT param_name, param_value
                FROM calculation_parameters
                WHERE device_id IS NULL AND station_id IS NULL AND method_id = %s
            """
            cur.execute(query, (method_id,))
            for row in cur.fetchall():
                params[row[0]] = float(row[1])
                param_sources[row[0]] = 'global'
            logger.debug(f"[参数加载] 全局参数: {len(params)}个")
            
            # 层级2：加载设备额定参数（新增！）
            query = """
                SELECT param_key, value_numeric
                FROM device_rated_params
                WHERE device_id = %s AND value_numeric IS NOT NULL
            """
            cur.execute(query, (device_id,))
            rated_count = 0
            for row in cur.fetchall():
                params[row[0]] = float(row[1])
                param_sources[row[0]] = 'rated'
                rated_count += 1
            logger.debug(f"[参数加载] 设备额定参数: {rated_count}个")
            
            # 层级3：加载泵站级计算参数（如果提供了station_id）
            if station_id is not None:
                query = """
                    SELECT param_name, param_value
                    FROM calculation_parameters
                    WHERE device_id IS NULL AND station_id = %s AND method_id = %s
                """
                cur.execute(query, (station_id, method_id))
                station_count = 0
                for row in cur.fetchall():
                    params[row[0]] = float(row[1])
                    param_sources[row[0]] = 'station'
                    station_count += 1
                logger.debug(f"[参数加载] 泵站级参数: {station_count}个")
            
            # 层级4：加载设备级计算参数（最高优先级）
            query = """
                SELECT param_name, param_value
                FROM calculation_parameters
                WHERE device_id = %s AND method_id = %s
            """
            cur.execute(query, (device_id, method_id))
            device_count = 0
            for row in cur.fetchall():
                params[row[0]] = float(row[1])
                param_sources[row[0]] = 'device'
                device_count += 1
            logger.debug(f"[参数加载] 设备级参数: {device_count}个")
    
    # 记录参数来源统计
    source_stats = {}
    for source in param_sources.values():
        source_stats[source] = source_stats.get(source, 0) + 1
    
    logger.info(
        f"[参数加载完成] device_id={device_id}, method_id={method_id}, "
        f"total_params={len(params)}, sources={source_stats}"
    )
    
    # 详细日志（DEBUG级别）
    if logger.isEnabledFor(logging.DEBUG):
        for param_name, param_value in sorted(params.items()):
            source = param_sources.get(param_name, 'unknown')
            logger.debug(
                f"  {param_name} = {param_value} (来源: {source})"
            )
    
    return params
```

## ⚠️ 参数冲突处理

### 潜在冲突场景

**场景1**：设备额定参数的 eta_motor 与计算参数的 eta_motor

- device_rated_params: `eta_motor = 0.93`
- calculation_parameters (device_id=129, method_id='EFF_SIMPLE_V1'): `eta_motor = 0.92`

**解决方案**：
- **优先级规则**：设备级计算参数 > 设备额定参数
- **最终使用**：`eta_motor = 0.92`（来自calculation_parameters）
- **理由**：计算参数可能是经过优化的值，应优先使用

**实现**：
```python
# 在load_parameters()中，设备级计算参数最后加载，会覆盖额定参数
# 层级2：加载设备额定参数
params['eta_motor'] = 0.93  # 来自device_rated_params

# 层级4：加载设备级计算参数
params['eta_motor'] = 0.92  # 覆盖上面的值
```

**日志记录**：
```python
if 'eta_motor' in params and 'eta_motor' in rated_params:
    logger.warning(
        f"[参数冲突] eta_motor 同时存在于计算参数和额定参数中，"
        f"使用设备级计算参数值 {params['eta_motor']} "
        f"（额定参数值 {rated_params['eta_motor']} 被覆盖）"
    )
```

### 冲突避免策略

**策略1**：命名规范（不推荐）
- 设备额定参数：`eta_motor_rated`
- 计算参数：`eta_motor`
- 问题：破坏现有命名规范，需要大量代码修改

**策略2**：优先级规则（推荐）
- 使用明确的优先级规则
- 记录冲突日志
- 允许用户选择使用哪个值

**策略3**：参数类型标记
- 在calculation_parameters表中添加 `param_type` 字段
- 类型：'physical_constant', 'method_coefficient', 'threshold', 'rated_override'
- 'rated_override' 类型的参数优先级高于设备额定参数
