### 缺陷1：load_parameters() 完全没有加载 device_rated_params 表

**验证方法**：查看 `app/services/calculation/orchestrator.py` lines 682-720

**验证结果**：✅ **准确**

**证据**：
```python
def load_parameters(self, device_id: int, method_id: str) -> Dict[str, float]:
    """加载计算参数"""
    with get_connection() as conn:
        with conn.cursor() as cur:
            # 先尝试加载设备特定参数
            query = """
                SELECT param_name, param_value
                FROM calculation_parameters
                WHERE device_id = %s AND method_id = %s
            """
            cur.execute(query, (device_id, method_id))
            rows = cur.fetchall()

            if not rows:
                # 如果没有设备特定参数，加载全局默认参数
                query = """
                    SELECT param_name, param_value
                    FROM calculation_parameters
                    WHERE device_id IS NULL AND method_id = %s
                """
                cur.execute(query, (method_id,))
                rows = cur.fetchall()

            params = {row[0]: float(row[1]) for row in rows}

    return params
```

**确认**：
- ✅ 只查询 `calculation_parameters` 表
- ✅ 完全没有查询 `device_rated_params` 表
- ✅ 使用"全有或全无"逻辑（if not rows）

**严重程度评估**：✅ **准确**（🔴 阻塞性）

- 需要降级策略（使用全局默认值）

### 数据问题2：设备135只有4条额定参数（应该有7条）

**验证方法**：查询数据库

**验证结果**：⚠️ **需要修正**

**证据**：
```sql
SELECT 
    d.id AS device_id,
    d.name AS device_name,
    COUNT(drp.id) AS rated_params_count,
    STRING_AGG(drp.param_key, ', ' ORDER BY drp.param_key) AS param_keys
FROM dim_devices d
LEFT JOIN device_rated_params drp ON d.id = drp.device_id
WHERE d.id = 135
GROUP BY d.id, d.name;

-- 结果：
-- device_id=135
-- device_name="二期供水泵房总管"
-- rated_params_count=4
-- param_keys="C_hazen, pipe_diameter, pipe_length, roughness_rel"
```

**修正**：
- 原描述："设备135只有4条额定参数（应该有7条）" - **不准确**
- 正确描述："设备135有4条管道参数，缺少3条泵参数（rated_flow, rated_head, rated_efficiency）"
- 原因：设备135是"总管"，不是泵，所以不需要泵参数
- **这不是数据问题，而是正常的设备类型差异**

**结论**：
- ❌ 这不是数据问题
- ✅ 设备135的参数配置是正确的（总管只需要管道参数）
- ✅ 不同设备类型需要不同的额定参数
