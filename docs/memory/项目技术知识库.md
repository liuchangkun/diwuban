## 🗄️ 核心数据表结构

### 事实表 (Fact Tables)
#### `fact_measurements` - 核心时序测量数据表
- **表类型**: TimescaleDB Hypertable
- **分区策略**: 按 ts_bucket 时间分区 + device_id 空间分区
- **主键**: `id`
- **唯一约束**: `(station_id, device_id, metric_id, ts_bucket)`
- **时间对齐**: 支持秒级数据对齐，时间窗口采用半开区间 [start,end)
- **质量标注**: 包含质量状态和运行相位标注列
- **用途**: 存储所有设备的时序测量数据，是系统的核心数据表

### 维度表 (Dimension Tables)
#### `dim_stations` - 泵站维度表
- **主键**: `id`
- **核心字段**: `name`、`extra(jsonb)`、`created_at`
- **扩展信息**: `extra` 字段建议包含时区信息
- **关联关系**: 与 `dim_devices` 表通过 `station_id` 关联

#### `dim_devices` - 设备维度表
- **主键**: `id`
- **外键**: `station_id` (关联 dim_stations)
- **核心字段**: 设备名称、类型、泵类型等信息
- **特殊字段**: `pump_type` 字段区分变频泵和软启动泵
- **用途**: 存储设备元数据，支持设备级别的配置和管理

#### `dim_metric_config` - 指标配置维度表
- **主键**: `id`
- **唯一键**: `metric_key`
- **配置内容**: 单位、显示单位、小数策略、有效范围等
- **功能**: 支持指标的标准化和单位转换
- **扩展性**: 为新增指标提供配置支持

## 🏛️ 数据库架构 (Schemas)

### `reporting` Schema - 报表数据架构
- **物化视图**: 
  - `mv_measurements_hourly` - 按小时聚合数据
  - `mv_measurements_daily` - 按日聚合数据
- **查询函数**: 
  - `get_metrics_daily` - 日级数据查询
  - `get_metrics_hourly` - 小时级数据查询
  - `get_metrics_multi` - 多维度数据查询
- **性能优化**: 提升大时间窗口查询性能

### `api` Schema - API数据操作架构
- **存储过程**: 
  - `upsert_measurement` - 数据插入/更新
  - `delete_measurement` - 数据删除
- **特点**: 支持批量操作和条件过滤
- **用途**: 为应用层提供统一的数据访问接口

### `monitoring` Schema - 性能监控架构
- **监控表**: `pgss_snapshot` (存储 pg_stat_statements 快照)
- **监控视图**: `v_mv_hit_audit` (监控物化视图命中率)
- **功能**: 支持数据库性能分析和优化

## ⚙️ 核心业务服务

### 数据导入服务 (`app/services/data_import.py`)
- **CSV解析**: 支持多种编码和分隔符配置
- **预处理**: 使用 staging 表进行数据清洗
- **高性能导入**: 采用 COPY 命令的批量导入机制
- **质量检查**: 内置数据质量检查和错误处理机制
- **背压控制**: 支持动态调整导入速度

### 质量控制服务
- **质量码支持**: 越界、跳变、平台期、噪声等多种质量码
- **两层验证机制**: 
  - L1: 质量窗口 + 物理约束验证
  - L2: 特性曲线验证
- **存储过程**: 使用 `sp_mark_quality_window` 进行质量标注
- **诊断功能**: 支持详细的质量诊断和问题定位

## 🧮 算法模块详解

### 自动基线计算
#### 方案A (robust) - `app/services/rules/auto_baseline.py`
- **算法**: 基于分位数和MAD的稳健估计
- **数据筛选**: 仅使用质量=0且稳态(phase=1)的数据
- **输出**: 写入正式的 `metric_rule_auto_baseline` 表

#### 方案B (STL) - `app/services/rules/auto_baseline_b.py`
- **算法**: 基于STL时间序列分解的残差稳健估计
- **数据筛选**: 优先使用 phase=1 的稳态片段，缺失时回退 running=1
- **输出**: 写入影子表 `metric_rule_auto_baseline_shadow`，不影响正式表
- **优势**: 更适合处理季节性和趋势性数据

### 运行状态判定 (`scripts/sql/m1/fn_running_state_1s.sql`)
- **多指标综合**: 基于电流A/B/C、有功功率、频率的综合标准分数
- **时间粒度**: 按1秒粒度判断设备是否"运行中"
- **阈值配置**: 支持运行阈值的动态调整
- **状态保持**: 支持状态保持和回退机制

### 特性曲线拟合 (`app/services/pump_group_curve_fitting.py`)
- **拟合算法**: 支持多项式拟合和科学计算库集成
- **数据清洗**: 自动检测和过滤补齐数据，确保原始数据优先
- **曲线类型**: 支持 H-Q、η-Q、P-Q 等多种水泵特性曲线
- **质量评估**: 提供拟合质量评估和 R² 计算
- **增强补齐**: 基于特性曲线的智能数据补齐

## 🌐 API接口系统

### 路由模块
- **`data_admin`**: 站点设备管理接口
- **`data_timeseries`**: 时序数据查询接口  
- **`monitoring`**: 系统健康检查和性能监控接口

### 核心端点
- **站点管理**: `GET /api/v1/data/stations` - 获取站点列表
- **设备管理**: `GET /api/v1/data/stations/{id}/devices` - 获取设备列表
- **时序数据**: `GET /api/v1/data/devices/{id}/raw` - 原始数据查询
- **指标配置**: `GET /api/v1/data/metrics` - 指标清单

### 查询特性
- **分页支持**: limit/offset 分页查询
- **时间过滤**: start_time/end_time 时间窗口
- **格式切换**: wide/long 两种数据格式
- **聚合查询**: 按小时/日的聚合数据

## ⚙️ 配置管理系统

### 配置文件结构
- **`database.yaml`**: 数据库连接配置 (严格限制，不允许ENV覆盖)
- **`web.yaml`**: Web服务配置 (FastAPI应用参数)
- **`system.yaml`**: 系统通用配置 (目录、时区、编码等)
- **`ingest.yaml`**: 数据导入配置 (支持CLI/ENV覆盖)
- **`logging.yaml`**: 日志系统配置 (输出、格式、级别等)

### 配置加载机制
- **类型安全**: 基于 dataclass 的类型安全配置
- **优先级**: CLI > ENV > YAML > 默认值
- **安全限制**: 数据库配置严格限制在YAML文件中
- **配置验证**: 启动时进行配置验证和错误提示
