# 智能助手执行规则（始终遵守）

目的：确保在任何会话/重启后，我都严格按统一规则工作，且无需后台常驻进程。

## 全局必遵
- 语言：始终使用中文沟通。
- 收尾自动：每轮对话结束前，自动执行一次“更新PLAYBOOKS”，无需你提醒；若你说“跳过更新”，则本轮不执行。
- 无守护进程：不启动本地常驻进程或计划任务。
- 范围：仅记录 代码/数据库/配置 的新增/删除/修改 + 本轮对话摘要；不记录 docs/** 的人为文档编辑；忽略系统输出目录（docs/PLAYBOOKS、docs/_archive、docs/_backup、generated、docs/数据库设计文档.md）。
- 数据库双写：数据库变更同时写入 docs/PLAYBOOKS/数据库变更记录.md 与 docs/数据库设计文档.md→“变更记录”。
- 严格识别：仅在严格命中“决策/修复”条件时，写入 决策记录.md / 错误与修复记录.md。
- 新增/删除：对新增与删除都要记录，并说明兼容性/迁移窗口/回滚策略。
- 表达模板：
  - 代码/配置：动机→变更→验证→影响→风险
  - 修复：现象→根因→修复→验证→预防
  - 决策（ADR）：Context→Decision→Consequences→Status
  - DB：对象→DDL概要→兼容与迁移→验证

## 对话生命周期钩子
- 会话开始：
  1) 遵循本文件与以下文档：docs/智能助手行为控制.md、docs/行为约束.md、docs/编码规范.md、docs/个人工作守则.md、docs/严格模式-核对清单.md、docs/测试指南.md、docs/程序工作流程.md、docs/MCP工具使用指南.md。
  2) 若用户有新的明确指示，以用户最新指示为最高优先级。
- 会话收尾（自动）：
  1) 运行 scripts/dev/scan_changes_and_update_memory.py（不安装依赖、不做外部变更）。
  2) 写入对话摘要（问题/结论/决策/行动）。
  3) 报告执行结果；如失败，给出修复建议。

## 变更路由策略（摘要）
- 代码→docs/PLAYBOOKS/改进与优化记录.md（修复类→错误与修复记录.md；涉及方案/兼容性/破坏性→同步 决策记录.md）
- 配置→docs/PLAYBOOKS/配置变更记录.md
- 数据库→docs/PLAYBOOKS/数据库变更记录.md + docs/数据库设计文档.md（“变更记录”）
- 对话→docs/PLAYBOOKS/对话记忆.md（仅摘要，不堆流水账）

## 质量闸与降噪
- 严格过滤：忽略 docs/** 人为编辑和系统输出路径。
- 模板化写入：确保每条记录包含动机/影响/验证等关键要素。
- 去重合并：同一文件同日多次记录合并为一条（按最高价值保留）。

## 执行与验证边界
- 可以：运行安全的本地脚本、测试、静态检查；读网络资料（只读）。
- 不可以：擅自安装依赖、改配置、部署、写生产数据、付费外部调用（除非你明确授权）。
- 包管理：变化一律通过包管理器命令实施，并先征求同意。
- 测试：如修改代码，会主动补/跑最小范围单测，确保通过。

## 临时例外与指令
- 你可随时说“跳过更新”跳过当轮收尾更新。
- 你可说“仅记录数据库”/“仅记录代码”等缩小范围，我按指示执行。
