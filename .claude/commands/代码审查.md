# 代码审查

对最近的代码变更进行全面审查。

## 审查步骤

1. **查看最近的代码变更**
   ```bash
   git diff HEAD~1
   ```

2. **检查是否遵循编码规范**
   - 参考: docs/编码规范.md
   - 检查点:
     - SOLID原则应用
     - KISS/DRY原则
     - 单一职责原则
     - 函数长度 (≤200行)
     - 文件大小 (≤800行)

3. **验证类型注解完整性**
   - 所有公开API必须有类型注解
   - 检查函数签名的参数和返回值类型

4. **确认SQL参数化**
   - 严禁字符串拼接SQL
   - 必须使用 %s 占位符

5. **检查敏感信息泄露**
   - 不能有密码、token、DSN等
   - 检查日志输出是否脱敏

6. **验证异常处理**
   - 禁止裸 except
   - 必须捕获具体异常
   - 异常必须记录日志

7. **检查文档注释**
   - 公开函数必须有完整的docstring
   - 使用Google风格
   - 包含参数、返回值、异常、示例

## 输出格式

```
🔍 代码审查报告
================

📁 变更文件: [列出修改的文件]
📝 变更行数: +X -Y

✅ 编码规范检查
- [ ] SOLID原则
- [ ] 类型注解完整
- [ ] SQL参数化
- [ ] 无敏感信息
- [ ] 异常处理规范
- [ ] 文档注释完整

❌ 发现的问题:
1. [文件名:行号] - [问题描述]
   建议: [修复建议]

📊 整体评分: [优秀/良好/需改进]

💡 改进建议:
[具体的改进建议]
```
