# 性能分析

分析数据库和应用性能,识别瓶颈并提供优化建议。

## 分析步骤

1. **连接PostgreSQL数据库 (只读模式)**

2. **查询慢查询TOP10**
   ```sql
   SELECT
     query,
     calls,
     mean_exec_time,
     total_exec_time,
     stddev_exec_time,
     min_exec_time,
     max_exec_time
   FROM pg_stat_statements
   ORDER BY mean_exec_time DESC
   LIMIT 10;
   ```

3. **检查分区裁剪是否生效**
   ```sql
   -- 示例: 检查查询是否使用了分区裁剪
   EXPLAIN ANALYZE
   SELECT * FROM fact_measurements
   WHERE ts_bucket >= '2025-01-01'::timestamptz
     AND ts_bucket < '2025-01-02'::timestamptz;
   ```

4. **分析索引命中率**
   ```sql
   SELECT
     schemaname,
     tablename,
     indexrelname,
     idx_scan,
     idx_tup_read,
     idx_tup_fetch
   FROM pg_stat_user_indexes
   WHERE schemaname = 'public'
   ORDER BY idx_scan DESC
   LIMIT 20;
   ```

5. **查看连接池使用情况**
   ```sql
   SELECT
     datname,
     numbackends,
     xact_commit,
     xact_rollback,
     blks_read,
     blks_hit,
     tup_returned,
     tup_fetched
   FROM pg_stat_database
   WHERE datname = current_database();
   ```

6. **检查锁等待**
   ```sql
   SELECT
     pid,
     usename,
     application_name,
     state,
     wait_event_type,
     wait_event,
     query
   FROM pg_stat_activity
   WHERE wait_event IS NOT NULL;
   ```

7. **检查表膨胀**
   ```sql
   SELECT
     schemaname,
     tablename,
     pg_size_pretty(pg_total_relation_size(schemaname||'.'||tablename)) as total_size,
     n_live_tup,
     n_dead_tup,
     ROUND(100 * n_dead_tup / NULLIF(n_live_tup + n_dead_tup, 0), 2) as dead_ratio
   FROM pg_stat_user_tables
   WHERE n_dead_tup > 1000
   ORDER BY n_dead_tup DESC
   LIMIT 10;
   ```
