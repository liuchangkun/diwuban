## 📋 修订说明

### 问题1：历史数据可用性限制

**原计划问题**: 假设所有设备都有7天历史数据可用

**修订方案**:
1. **最少数据要求**: 
   - 设备类型识别: 最少3天数据，推荐7天
   - 运行模式识别: 最少3天数据，推荐7天
   - 阈值学习: 最少1天数据（现有逻辑已支持）

2. **降级处理策略**:
   ```
   数据充足度评估:
   - 7天+ 数据 → 高质量识别 (quality='high')
   - 3-7天数据 → 中等质量识别 (quality='medium')
   - 1-3天数据 → 低质量识别 (quality='low')，使用保守策略
   - <1天数据 → 无法识别 (quality='insufficient')，使用默认值
   ```

3. **新增字段**: `data_days_available` (INTEGER) - 记录实际可用数据天数

---

### 问题2：设备类型数据来源不明确

**原计划问题**: 未考虑dim_devices表中已有pump_type字段

**修订方案**:
1. **dim_devices表已有字段**:
   - `pump_type` (TEXT): 'variable_frequency' (变频泵) 或 'soft_start' (软启动泵)
   - 数据来源: configs/dimensions.yaml配置文件

2. **优先级策略**: "人工设置优先，自动识别作为fallback"
   ```
   IF dim_devices.pump_type IS NOT NULL THEN
     -- 使用配置文件中的pump_type
     device_type = CASE pump_type
       WHEN 'variable_frequency' THEN 'vfd'
       WHEN 'soft_start' THEN 'soft_start'
       ELSE 'unknown'
     END
     device_type_source = 'config'  -- 新增字段
   ELSE
     -- 使用自动识别
     device_type = 自动识别结果
     device_type_source = 'auto'  -- 新增字段
   END IF
   ```

3. **新增字段**: `device_type_source` (TEXT) - 'config' 或 'auto'

4. **sp_detect_device_type_simple修改**:
   - 先检查dim_devices.pump_type
   - 如果pump_type不为NULL，直接使用
   - 如果pump_type为NULL，才执行自动识别

### 问题3：维度表ID变化的自适应处理

**原计划问题**: 未考虑dim_devices表ID可能变化的情况

**修订方案**:
1. **当前系统状态**:
   - ✅ dim_devices表使用**固定ID**（从配置文件读取）
   - ✅ 已执行迁移脚本: `scripts/sql/migration/migrate_dim_ids_to_fixed.sql`
   - ✅ 设备ID范围: 1-8（固定不变）
   - ✅ 序列已删除: `dim_devices_id_seq` 不存在

2. **外键约束状态**:
   - ❌ **当前缺失**: device_running_thresholds表没有外键约束
   - ✅ **必须添加**: 在阶段1迁移脚本中添加外键约束

3. **外键约束策略**:
   ```sql
   ALTER TABLE public.device_running_thresholds
   ADD CONSTRAINT device_running_thresholds_device_id_fkey
   FOREIGN KEY (device_id) REFERENCES dim_devices(id)
   ON UPDATE CASCADE ON DELETE CASCADE;
   ```

4. **预期效果**:
   - ✅ 如果device_id变化，device_running_thresholds表自动更新
   - ✅ 如果设备被删除，device_running_thresholds表自动清理
   - ✅ 防止孤立记录

5. **风险评估**: **极低**
   - 当前系统使用固定ID，ID不会变化
   - 外键约束只是额外的安全保障
   - 即使未来ID变化，外键约束会自动处理

### 问题4：与prepare_dim流程的兼容性

**原计划问题**: 未说明如何与prepare_dim流程集成

**修订方案**:
1. **prepare_dim流程概述**:
   ```
   阶段1（在merge-fact前执行）:
   1. 备份21个表（包括device_running_thresholds）
   2. 清空非备份表
   3. 重建维度表（dim_stations, dim_devices, dim_metric_config）
   4. 恢复手动配置表
   5. 重建基础配置表（dim_device_capabilities等）
   
   阶段2（在merge-fact后执行）:
   1. 清空规则表
   2. 生成规则表（device_running_thresholds等）
   3. 生成映射表
   ```

2. **device_running_thresholds表的分类**:
   - **类别**: D类规则表（自适应SQL脚本生成）
   - **备份**: ✅ 已纳入prepare_dim备份机制
   - **恢复**: ❌ 不从备份恢复，而是重新生成

3. **阶段1迁移脚本的执行时机**:
   ```
   prepare_dim阶段1完成后，手动执行一次:
   1. 执行 060_alter_device_running_thresholds_phase1.sql（添加新字段）
   2. 执行 060_add_foreign_key_constraint.sql（添加外键约束）
   3. 不影响prepare_dim流程的正常运行
   ```

4. **prepare_dim流程对device_running_thresholds表的处理**:
   - **阶段1**: 备份 → 不清空 → 不恢复（保持原有数据）
   - **阶段2**: 清空 → 重新生成（调用sp_refresh_device_running_thresholds_*）

5. **新增字段的初始化**:
   ```sql
   -- 在prepare_dim阶段2之前，手动执行一次
   UPDATE device_running_thresholds
   SET 
       device_type = CASE 
           WHEN EXISTS (
               SELECT 1 FROM dim_devices d 
               WHERE d.id = device_running_thresholds.device_id

           WHEN EXISTS (
               SELECT 1 FROM dim_devices d 
               WHERE d.id = device_running_thresholds.device_id 
                 AND d.pump_type = 'soft_start'
           ) THEN 'soft_start'
           ELSE 'unknown'
       END,
       device_type_source = CASE 
           WHEN EXISTS (
               SELECT 1 FROM dim_devices d 
               WHERE d.id = device_running_thresholds.device_id 
                 AND d.pump_type IS NOT NULL
           ) THEN 'config'
           ELSE 'unknown'
       END,
       running_mode = 'unknown',
       startup_window_secs_effective = 30,
       shutdown_window_secs_effective = 20,
       startup_inrush_multiplier = 6.0,
       startup_inrush_duration_secs = 3,
       use_weighted_fusion = FALSE,
       signal_weight_current = 0.5,
       signal_weight_power = 0.3,
       signal_weight_frequency = 0.2,
       threshold_quality = 'unknown'
   WHERE device_type IS NULL;
   ```

6. **与现有流程的兼容性保证**:
   - ✅ 不修改prepare_dim流程的代码
   - ✅ 不修改备份/恢复逻辑
   - ✅ 新增字段都有默认值，不影响现有查询
   - ✅ 外键约束不影响prepare_dim流程的清空/重建操作

### 1.3 外键约束添加（新增）

**文件路径**: `scripts/sql/migrations/060_add_foreign_key_constraint.sql`

```sql
-- =====================================================================
-- 迁移脚本: 060_add_foreign_key_constraint.sql
-- 用途: 为device_running_thresholds表添加外键约束
-- 创建日期: 2025-10-31
-- 依赖: 009_device_running_thresholds.sql
-- 理由: 确保device_id与dim_devices表保持一致，支持级联更新和删除
-- =====================================================================

BEGIN;

-- ========== 检查孤立记录 ==========
DO $$
DECLARE
    v_orphan_count INTEGER;
BEGIN
    SELECT COUNT(*) INTO v_orphan_count
    FROM public.device_running_thresholds drt
    LEFT JOIN public.dim_devices d ON d.id = drt.device_id
    WHERE d.id IS NULL;
    
    IF v_orphan_count > 0 THEN
        RAISE WARNING '发现 % 个孤立记录（device_id不存在于dim_devices表）', v_orphan_count;
        RAISE EXCEPTION '请先清理孤立记录，再添加外键约束';
    ELSE
        RAISE NOTICE '✅ 无孤立记录，可以安全添加外键约束';
    END IF;
END $$;

-- ========== 添加外键约束 ==========
DO $$
BEGIN
    -- 检查外键是否已存在
    IF NOT EXISTS (
        SELECT 1
        FROM information_schema.table_constraints
        WHERE constraint_name = 'device_running_thresholds_device_id_fkey'
            AND table_name = 'device_running_thresholds'
            AND table_schema = 'public'
    ) THEN
        -- 添加外键约束
        ALTER TABLE public.device_running_thresholds
        ADD CONSTRAINT device_running_thresholds_device_id_fkey
        FOREIGN KEY (device_id)
        REFERENCES public.dim_devices(id)
        ON UPDATE CASCADE
        ON DELETE CASCADE;
        
        RAISE NOTICE '✅ 成功为 device_running_thresholds.device_id 添加外键约束';
    ELSE
        RAISE NOTICE '⚠️ device_running_thresholds.device_id 的外键约束已存在，跳过';
    END IF;
END $$;

COMMIT;

-- =====================================================================
-- 验证脚本
-- =====================================================================
DO $$
DECLARE
    v_constraint_exists BOOLEAN;
BEGIN
    SELECT EXISTS (
        SELECT 1
        FROM information_schema.table_constraints
        WHERE constraint_name = 'device_running_thresholds_device_id_fkey'
            AND table_name = 'device_running_thresholds'
            AND table_schema = 'public'
    ) INTO v_constraint_exists;
    
    IF v_constraint_exists THEN
        RAISE NOTICE '[验证成功] 外键约束已存在';
    ELSE
        RAISE WARNING '[验证失败] 外键约束不存在';
    END IF;
END $$;
```

### 2.1 sp_detect_device_type_simple（修订版）

**修改内容**: 优先使用dim_devices.pump_type，如果为NULL才自动识别

**算法伪代码（修订版）**:
```
1. 读取dim_devices.pump_type
   IF pump_type IS NOT NULL THEN
     -- 使用配置文件中的pump_type
     device_type = CASE pump_type
       WHEN 'variable_frequency' THEN 'vfd'
       WHEN 'soft_start' THEN 'soft_start'
       ELSE 'unknown'
     END
     device_type_source = 'config'
     device_type_auto_detected = FALSE
     
     -- 根据device_type设置enable_f和权重
     IF device_type = 'vfd' THEN
       enable_f = TRUE
       weights = (0.4, 0.3, 0.3)
     ELSIF device_type = 'soft_start' THEN
       enable_f = FALSE
       weights = (0.6, 0.4, 0.0)
     END IF
     
     -- 更新device_running_thresholds表
     -- 记录日志
     RETURN
   END IF

2. 如果pump_type为NULL，执行自动识别:
   -- 读取最近7天的频率数据（如果不足7天，使用可用天数）
   -- 计算data_days_available
   
   IF data_days_available < 1 THEN
     -- 数据不足，无法识别
     device_type = 'unknown'
     device_type_source = 'unknown'
     threshold_quality = 'insufficient'
     RETURN
   END IF
   
   -- 计算频率统计特征
   mean_freq = AVG(frequency)
   std_freq = STDDEV(frequency)
   freq_cv = std_freq / mean_freq
   freq_range = MAX(frequency) - MIN(frequency)
   
   -- 判定设备类型
   IF freq_cv > 0.02 AND freq_range > 3.0 THEN
     device_type = 'vfd'
     enable_f = TRUE
     weights = (0.4, 0.3, 0.3)
   ELSIF freq_cv < 0.01 AND freq_range < 1.0 THEN
     device_type = 'soft_start'
     enable_f = FALSE
     weights = (0.6, 0.4, 0.0)
   ELSE
     device_type = 'unknown'
     保持原有配置
   END IF
   
   device_type_source = 'auto'
   device_type_auto_detected = TRUE
   
   -- 根据data_days_available设置threshold_quality
   IF data_days_available >= 7 THEN
     threshold_quality = 'high'
   ELSIF data_days_available >= 3 THEN
     threshold_quality = 'medium'
   ELSE
     threshold_quality = 'low'
   END IF

3. 更新device_running_thresholds表
4. 记录日志
```
