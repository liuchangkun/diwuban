### 三种验证方法

#### 1. 日志分析验证
**目标**: 通过分析日志文件确认命令执行过程和结果

**日志文件位置**:
- `logs/app.log` - 应用主日志
- `logs/error.log` - 错误日志
- `logs/sql.log` - SQL执行日志
- `logs/anomaly_diagnosis.log` - 异常诊断日志
- `logs/db_pool.log` - 数据库连接池日志

**关键日志模式**:
```
[流程-开始] [流程名称]
[流程-完成] [流程名称]
[流程-错误] [错误描述]
[进度] 阶段名称 开始/完成
```

**验证点**:
- 检查是否有ERROR级别日志
- 检查是否有WARNING级别日志(需分析是否正常)
- 检查流程开始和完成日志是否配对
- 检查耗时是否合理
- 检查统计数据是否正确

#### 2. 数据库验证
**目标**: 通过SQL查询验证数据库状态变化

**验证策略**:
- 执行前快照: 记录关键表的行数、时间范围、关键字段值
- 执行后快照: 再次记录相同指标
- 差异分析: 对比前后差异，验证是否符合预期

**关键SQL查询模板**:
```sql
-- 表行数统计
SELECT COUNT(*) FROM {table_name};

-- 时间范围查询
SELECT MIN(ts_bucket), MAX(ts_bucket) FROM fact_measurements;

-- 数据分布查询
SELECT station_id, device_id, COUNT(*) 
FROM fact_measurements 
GROUP BY station_id, device_id;

-- 质量状态统计
SELECT quality_status, COUNT(*) 
FROM fact_measurements 
GROUP BY quality_status;
```

#### 3. 代码逻辑验证
**目标**: 追踪代码执行流程，验证数据库状态变化符合代码逻辑

**验证方法**:
- 阅读关键函数源代码
- 理解数据处理逻辑
- 根据代码逻辑推断预期结果
- 对比实际结果与预期结果

**关键代码路径**:
- `app/cli/main.py` - CLI命令入口
- `app/services/run_all/orchestrator.py` - run-all编排器
- `app/services/ingest/prepare_dim/__init__.py` - 维表准备
- `app/services/ingest/create_staging.py` - staging表创建
- `app/services/ingest/copy_workers.py` - CSV导入
- `app/services/ingest/merge_service.py` - 数据合并
