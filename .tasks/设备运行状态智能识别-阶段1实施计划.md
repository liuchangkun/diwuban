# 设备运行状态智能识别 - 阶段1实施计划

**创建时间**: 2025-10-31  
**计划类型**: 技术实施计划 - 阶段1（快速修复）  
**目标**: 解决device_id=5的运行识别率问题（从2.2%提升到90%+）  
**开发周期**: 2周  
**风险等级**: 低（保留原有逻辑作为fallback）  

---

## 📋 计划概述

### 核心目标
1. **解决持续运行场景的阈值学习问题**: 改进Otsu双峰法，支持单峰分布
2. **实现设备类型自动识别**: 区分变频泵 vs 软启动泵
3. **实现信号加权融合**: 替代OR逻辑，提高判定可靠性
4. **实现自适应启动/停止窗口**: 替代固定10秒窗口
5. **处理启动电流冲击**: 识别并标记启动电流冲击，避免误判

### 实施策略
- **向后兼容**: 所有新功能通过开关控制，默认关闭
- **渐进式启用**: 先在测试设备上验证，再逐步推广
- **性能优先**: 避免引入性能瓶颈，优化SQL查询

#### 2.1.1 sp_detect_device_type_simple

**文件路径**: `scripts/sql/migrations/061_create_sp_detect_device_type_simple.sql`

**函数签名**:
```sql
CREATE OR REPLACE PROCEDURE sp_detect_device_type_simple(
    p_device_id BIGINT DEFAULT NULL
)
LANGUAGE plpgsql
```

**功能描述**:
- 自动识别设备类型(变频泵 vs 软启动泵)
- 基于频率变异系数(CV)和频率范围判定
- 自动调整enable_f和信号权重

**算法伪代码**:
```
1. 读取最近7天的频率数据(只使用quality_status=0的数据)
2. 计算频率统计特征:
   - mean_freq = AVG(frequency)
   - std_freq = STDDEV(frequency)
   - freq_cv = std_freq / mean_freq
   - freq_range = MAX(frequency) - MIN(frequency)
3. 判定设备类型:
   IF freq_cv > 0.02 AND freq_range > 3.0 THEN
     device_type = 'vfd'  -- 变频泵
     enable_f = TRUE
     weights = (0.4, 0.3, 0.3)  -- 电流、功率、频率
   ELSIF freq_cv < 0.01 AND freq_range < 1.0 THEN
     device_type = 'soft_start'  -- 软启动泵
     enable_f = FALSE
     weights = (0.6, 0.4, 0.0)
   ELSE
     device_type = 'unknown'
     保持原有配置
   END IF
4. 更新device_running_thresholds表
5. 记录日志
```

**依赖关系**:
- 读取: `fact_measurements`, `dim_metric_config`
- 更新: `device_running_thresholds`

**性能考虑**:
- 只使用最近7天数据,避免全表扫描
- 使用索引: `fact_measurements(device_id, ts_bucket, metric_id)`

#### 2.1.2 sp_detect_running_mode_simple

**文件路径**: `scripts/sql/migrations/062_create_sp_detect_running_mode_simple.sql`

```sql
CREATE OR REPLACE PROCEDURE sp_detect_running_mode_simple(
    p_device_id BIGINT DEFAULT NULL
)
LANGUAGE plpgsql
```

**功能描述**:
- 识别设备运行模式(持续运行/频繁启停/偶尔运行)
- 基于运行时长比例判定

**算法伪代码**:
```
1. 读取最近7天的运行状态数据(mv_device_running_1s)
2. 计算运行时长比例:
   running_ratio = SUM(running=1) / COUNT(*)
3. 判定运行模式:
   IF running_ratio > 0.8 THEN
     running_mode = 'continuous'  -- 持续运行
   ELSIF running_ratio < 0.2 THEN
     running_mode = 'occasional'  -- 偶尔运行
   ELSE
     running_mode = 'frequent'  -- 频繁启停
   END IF
4. 更新device_running_thresholds表
5. 记录日志
```

**依赖关系**:
- 读取: `mv_device_running_1s`
- 更新: `device_running_thresholds`

**性能考虑**:
- 只使用最近7天数据
- 使用索引: `mv_device_running_1s(device_id, ts_bucket)`

#### 2.2.1 sp_refresh_device_running_thresholds_current

**文件路径**: `scripts/sql/migrations/052_create_sp_refresh_device_running_thresholds_current.sql`

**修改位置**: 第112-133行(final_thresholds CTE之后)

**修改内容**: 添加运行模式自适应逻辑

**修改伪代码**:
```
在final_thresholds CTE之后,UPDATE语句之前,插入新的CTE:

final_thresholds_adaptive AS (
    SELECT
        ft.device_id,
        ft.threshold AS base_threshold,
        ft.mad,
        drt.running_mode,
        -- 根据运行模式调整i_off
        CASE drt.running_mode
            WHEN 'continuous' THEN 
                (SELECT PERCENTILE_CONT(0.10) FROM current_data WHERE device_id = ft.device_id)
            WHEN 'occasional' THEN 
                (SELECT PERCENTILE_CONT(0.05) FROM current_data WHERE device_id = ft.device_id)
            ELSE ft.threshold - ft.mad * 2.0  -- frequent模式使用原有逻辑
        END AS i_off_adjusted,
        -- 根据运行模式调整i_on
        CASE drt.running_mode
            WHEN 'continuous' THEN 
                (SELECT PERCENTILE_CONT(0.30) FROM current_data WHERE device_id = ft.device_id)
            WHEN 'occasional' THEN 
                (SELECT PERCENTILE_CONT(0.50) FROM current_data WHERE device_id = ft.device_id)
            ELSE ft.threshold + ft.mad * 2.0
        END AS i_on_adjusted
    FROM final_thresholds ft
    JOIN device_running_thresholds drt ON ft.device_id = drt.device_id
)

修改UPDATE语句,使用final_thresholds_adaptive:
UPDATE device_running_thresholds t
SET 
    enable_i = TRUE,
    i_on = fta.i_on_adjusted,
    i_off = fta.i_off_adjusted,
    threshold_quality = CASE
        WHEN ft.sample_count >= 1000 THEN 'high'
        WHEN ft.sample_count >= 500 THEN 'medium'
        WHEN ft.sample_count >= 50 THEN 'low'
        ELSE 'insufficient'
    END,
    updated_at = NOW(),
    updated_by = 'sp_refresh_device_running_thresholds_current_v2'
FROM final_thresholds_adaptive fta
JOIN final_thresholds ft ON fta.device_id = ft.device_id
WHERE t.device_id = fta.device_id;
```

**理由**: 根据运行模式选择不同的阈值学习策略,解决持续运行场景的问题

**影响范围**: 只影响阈值计算逻辑,不影响其他功能

#### 2.2.2 fn_running_state_1s

**文件路径**: `scripts/sql/m1/011_fn_running_state_1s.sql`

**修改位置**: 第27-35行(DECLARE部分)和第80-106行(判定逻辑部分)

**修改内容**: 添加加权融合逻辑

**修改伪代码**:
```
1. 在DECLARE部分添加新变量:
   v_use_weighted boolean;
   v_w_i double precision; v_w_p double precision; v_w_f double precision;
   v_score_i double precision; v_score_p double precision; v_score_f double precision;
   v_composite double precision;

2. 在读取阈值时,同时读取融合策略参数(第37-44行之后):
   SELECT ..., use_weighted_fusion, signal_weight_current, signal_weight_power, signal_weight_frequency
     INTO ..., v_use_weighted, v_w_i, v_w_p, v_w_f
   FROM device_running_thresholds
   WHERE device_id = p_device_id;

3. 修改判定逻辑(第82-105行):
   IF v_use_weighted THEN
     -- 加权融合逻辑
     v_score_i := CASE WHEN v_ei AND v_i_on > v_i_off 
                       THEN GREATEST(0, LEAST(1, (r_max_i - v_i_off) / (v_i_on - v_i_off)))
                       ELSE 0 END;
     v_score_p := CASE WHEN v_ep AND v_p_on > v_p_off 
                       THEN GREATEST(0, LEAST(1, (r_p - v_p_off) / (v_p_on - v_p_off)))
                       ELSE 0 END;
     v_score_f := CASE WHEN v_ef AND v_f_on > v_f_off 
                       THEN GREATEST(0, LEAST(1, (r_f - v_f_off) / (v_f_on - v_f_off)))
                       ELSE 0 END;
     
     v_composite := v_w_i * v_score_i + v_w_p * v_score_p + v_w_f * v_score_f;
     
     IF v_state IS NULL THEN
       v_state := (v_composite > 0.5);
     ELSE
       IF v_state THEN
         IF v_composite < 0.4 THEN v_state := false; END IF;  -- 滞回带0.1
       ELSE
         IF v_composite > 0.6 THEN v_state := true; END IF;
       END IF;
     END IF;
   ELSE
     -- 原有OR逻辑(保持不变)
     v_state := ((v_ei AND r_max_i >= v_i_on) OR (v_ep AND r_p >= v_p_on) OR (v_ef AND r_f >= v_f_on));
     ...
   END IF;
```

**理由**: 加权融合比OR逻辑更稳健,但通过开关控制,默认关闭保持向后兼容

**影响范围**: 只影响运行状态判定逻辑,不影响其他功能
