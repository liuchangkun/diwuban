```python
def run_missing_metrics_compute(plan: BatchPlan, report_dir: Path) -> Dict[str, Any]:
    """
    批量计算缺失指标
    
    Args:
        plan: 批处理计划（包含设备列表、时间窗口、并发度等）
    """
    # 为每个线程创建独立的orchestrator
    def worker(args: Tuple[int, int, datetime, datetime]) -> Dict[str, Any]:
        sid, did, ws, we = args
        orch = CalculationOrchestrator()  # ← 每个线程独立的orchestrator
        
        try:
            # 1. 获取指标列表
            if plan.use_presence_table:
                metrics_for_window = _fetch_metrics_for_device_window(sid, did, ws, we)
            else:
                metrics_for_window = plan.metrics or []
            
            # 2. 按设备类型过滤指标
            dtype = device_type_map.get((sid, did))
            if dtype:
                metrics_for_device = [m for m in metrics_for_window if dtype in (allowed_map.get(m) or set())]
            else:
                metrics_for_device = metrics_for_window
            
            # 3. 执行计算
            res = _run_one(
                orch, sid, did, ws, we, metrics_for_device,
                plan.filter_running, plan.filter_quality, write=(not plan.dry_run)
            )
            return {"station_id": sid, "device_id": did, "success": True, "result": res}
        except Exception as e:
            return {"station_id": sid, "device_id": did, "success": False, "error": str(e)}
    
    # 构造任务列表
    tasks: List[Tuple[int, int, datetime, datetime]] = []
    for sid, did in plan.devices:
        windows = list(_datetime_range(plan.start, plan.end, plan.window_hours))
        for ws, we in windows:
            tasks.append((sid, did, ws, we))
    
    # 并发执行
    with cf.ThreadPoolExecutor(max_workers=plan.concurrency) as ex:
        for out in ex.map(worker, tasks):
            results.append(out)
```

**关键特性**：
- ✅ 每个线程创建独立的CalculationOrchestrator实例
- ✅ 使用ThreadPoolExecutor进行并发计算
- ✅ 任务粒度：(station_id, device_id, time_window)
- ✅ 并发度可配置（plan.concurrency）

### 2. 智能并行策略

**代码位置**：`app/services/calculation/orchestrator.py:2466-2565`

```python
def calculate_missing_metrics_batch(
    self,
    devices: List[Tuple[int, int]],
    start_time: str,
    end_time: str,
    metrics: List[str],
    write_to_db: bool = True,
    max_workers: int = 4,
    auto_parallel: bool = True
) -> Dict[str, Any]:
    """
    批量计算多个设备的缺失指标
    
    智能并行策略：
    - 总数据点 > 10000 且 设备数 > 2 → 并行
    - 单设备数据点 > 5000 → 并行
    - 否则 → 串行（避免线程开销）
    """
    # 估算数据点数量
    total_estimated_points = estimated_points_per_device * len(devices)
    
    if auto_parallel:
        if total_estimated_points > 10000 and len(devices) > 2:
            use_parallel = True
            parallel_reason = f"总数据点({total_estimated_points}) > 10000 且 设备数({len(devices)}) > 2"
        elif estimated_points_per_device > 5000:
            use_parallel = True
            parallel_reason = f"单设备数据点({estimated_points_per_device}) > 5000"
        else:
            use_parallel = False
            parallel_reason = f"数据量较小，使用串行计算以避免线程开销"
    
    # 定义单设备计算函数
    def calculate_device(station_id: int, device_id: int):
        try:
            result = self.calculate_missing_metrics(
                station_id=station_id,
                device_id=device_id,
                start_time=start_time,
                end_time=end_time,
                metrics=metrics,
                write_to_db=write_to_db
            )
            return station_id, device_id, result
        except Exception as e:
            logger.error(f"设备 (station={station_id}, device={device_id}) 计算失败: {e}")
            return station_id, device_id, {'success': False, 'errors': [str(e)]}
    
    # 根据策略选择串行或并行计算
    if use_parallel:
        # 并行计算
        with ThreadPoolExecutor(max_workers=max_workers) as executor:
            futures = {
                executor.submit(calculate_device, station_id, device_id): (station_id, device_id)
                for station_id, device_id in devices
            }
            
            for future in as_completed(futures):
                station_id, device_id = futures[future]
                station_id, device_id, result = future.result()
                results[(station_id, device_id)] = result
    else:
        # 串行计算
        for station_id, device_id in devices:
            station_id, device_id, result = calculate_device(station_id, device_id)
            results[(station_id, device_id)] = result
```

**关键特性**：
- ✅ 智能判断是否使用并行（基于数据量和设备数）
- ✅ 并行时使用ThreadPoolExecutor
- ✅ 串行时按设备列表顺序执行
- ✅ 每个设备的计算是独立的

## 🔥 设备3的pump_flow_rate错误原因分析

### 假设1：计算顺序导致权重总和不完整

**场景**：串行模式下，设备按顺序计算

```
假设设备列表顺序：[1, 2, 3, 4, 5, 6]

时间点：2025-10-23 10:48:08+08

设备1计算pump_flow_rate:
  - 查询mv_device_running_1s表 → 只有设备1的running=1（其他设备尚未修改）
  - 查询fact_measurements表 → 只有设备1的数据
  - weight_totals = 设备1的权重
  - 设备1的份额 = 100%
  - pump_flow_rate = 3344.907 × 100% = 3344.907 m³/h ❌

设备2计算pump_flow_rate:
  - 查询mv_device_running_1s表 → 设备1和设备2的running=1
  - 查询fact_measurements表 → 设备1和设备2的数据
  - weight_totals = 设备1的权重 + 设备2的权重
  - 设备2的份额 = 设备2权重 / weight_totals
  - pump_flow_rate = 3344.907 × 份额 ✅

设备3计算pump_flow_rate:
  - 查询mv_device_running_1s表 → 设备1、2、3的running=1
  - 查询fact_measurements表 → 设备1、2、3的数据
  - weight_totals = 设备1 + 设备2 + 设备3的权重
  - 设备3的份额 = 设备3权重 / weight_totals
  - pump_flow_rate = 3344.907 × 份额 ✅
```

**结论**：❌ 这个假设不成立，因为：
- 用户已经手动修改了所有设备的running=1
- 查询时应该能看到所有设备的数据

### 假设2：并行模式导致数据竞争

**场景**：并行模式下，多个设备同时计算

```
设备2、3、6同时计算pump_flow_rate（并行）

设备3的计算线程：
  - 查询mv_device_running_1s表 → 所有设备running=1 ✅
  - 查询fact_measurements表 → 获取所有设备的power和freq
  - 计算权重总和：
```

**证据**：
- 每个线程创建独立的CalculationOrchestrator实例
- weight_totals是_prepare_flow_rate_share方法的局部变量
- 不同线程的weight_totals不共享

## 📌 总结

### 批处理机制特性

| 特性 | 描述 | 影响 |
|------|------|------|
| 线程隔离 | 每个线程独立的CalculationOrchestrator | 数据不共享 |
| 智能并行 | 基于数据量自动选择串行/并行 | 计算顺序不确定 |
| 任务粒度 | (station_id, device_id, time_window) | 设备级并发 |
| 数据查询 | 每个设备独立查询fact_measurements | 可能看到不完整的数据 |

### 设备3的pump_flow_rate错误的可能原因

**最可能的原因**：并行计算时，设备3查询fact_measurements表时，设备2和设备6的数据尚未写入

**次要可能原因**：
1. mv_device_running_1s表在设备3计算时状态不完整
2. SQL查询的时间窗口不匹配
3. 数据库事务隔离级别导致的可见性问题
