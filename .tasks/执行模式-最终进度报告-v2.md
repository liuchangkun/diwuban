## 🔧 已修复的问题列表

### 问题1：嵌套聚合函数错误 ✅ 已修复

**错误信息**：
```
aggregate function calls cannot be nested
```

**根本原因**：
在计算 MAD（中位数绝对偏差）时，嵌套了两个 PERCENTILE_CONT 函数。

**解决方案**：
将 `device_thresholds` CTE 拆分为两个 CTE：
1. `device_medians`：计算中位数
2. `device_thresholds`：使用中位数计算 MAD

**修复文件**：
- 052_create_sp_refresh_device_running_thresholds_current.sql（第91-111行）
- 053_create_sp_refresh_device_running_thresholds_power.sql（第78-98行）
- 054_create_sp_refresh_device_running_thresholds_frequency.sql（第78-98行）

### 问题2：CTE 作用域错误 ✅ 已修复

**错误信息**：
```
relation "device_list" does not exist
LINE 1: SELECT COUNT(*) FROM device_list
```

**根本原因**：
在 CTE 作用域外尝试查询 CTE 中定义的 `device_list` 临时表。

**解决方案**：
删除所有在 CTE 作用域外引用 CTE 的 RAISE NOTICE 语句。

**修复文件**：
- 052_create_sp_refresh_device_running_thresholds_current.sql（第135-141行 → 第135-137行）
- 053_create_sp_refresh_device_running_thresholds_power.sql（第122-133行 → 第122-129行）
- 054_create_sp_refresh_device_running_thresholds_frequency.sql（第122-133行 → 第122-129行）
- 055_create_sp_refresh_device_running_thresholds_timing.sql（第76-81行 → 第76-78行）

### 问题3：device_list CTE 数据源错误 ✅ 已修复

**错误信息**：
无错误，但表为空

**根本原因**：
`device_list` CTE 从 `device_running_thresholds` 表中选择设备，但在 `_clear_rule_tables` 之后该表是空的，导致没有设备被处理。

**解决方案**：
将 `device_list` CTE 的数据源从 `device_running_thresholds` 改为 `dim_devices`。

**修复文件**：
- 052_create_sp_refresh_device_running_thresholds_current.sql（第62-67行）
- 053_create_sp_refresh_device_running_thresholds_power.sql（第59-64行）
- 054_create_sp_refresh_device_running_thresholds_frequency.sql（第59-64行）
- 055_create_sp_refresh_device_running_thresholds_timing.sql（第59-64行）

**修复前**：
```sql
WITH device_list AS (
    SELECT device_id
    FROM device_running_thresholds  -- ❌ 表为空
    WHERE ...
),
```

**修复后**：
```sql
WITH device_list AS (
    SELECT id as device_id
    FROM dim_devices  -- ✅ 从设备表选择
    WHERE ...
),
```
