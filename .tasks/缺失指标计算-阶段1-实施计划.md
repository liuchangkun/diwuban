```

├── __init__.py

│   ├── __init__.py

│   ├── pump_head.py         # pump_head计算函数
│   └── pump_outlet_pressure.py  # pump_outlet_pressure计算函数（4种方案）

    ├── __init__.py
    └── physics_validator.py  # 物理验证器

app/cli/
├── calculation_cli.py        # 计算相关CLI命令

scripts/sql/calculation/
├── create_tables.sql         # 创建6个数据库表
├── init_methods.sql          # 初始化计算方法
└── init_params.sql           # 初始化计算参数
```

### 数据流程

```
1. CLI命令触发
   ↓
2. CalculationOrchestrator编排
   ↓
3. 读取metrics_presence_per_second_device（需要计算的指标）
   ↓
4. DependencyAnalyzer分析依赖关系，拓扑排序
   ↓
5. MethodSelector选择最佳计算方法
   ↓
6. DataLoader批量加载所需指标数据
   ↓
7. 按拓扑顺序逐层计算（调用calculators）
   ↓
8. PhysicsValidator验证计算结果
   ↓
9. BatchWriter批量写入fact_measurements
   ↓
10. 更新metrics_presence_per_second_device
```

## 📝 详细更改计划

### 更改1：创建数据库表结构

**文件**: `scripts/sql/calculation/create_tables.sql`

**理由**: 需要6个核心表来支持计算功能的元数据管理、参数配置、验证配置、失败日志和优化历史。

**具体更改**:
1. 创建`metric_calculation_order`表 - 存储指标计算顺序和依赖关系
2. 创建`calculation_method_registry`表 - 存储所有计算方法的定义
3. 创建`calculation_parameters`表 - 存储计算参数（支持设备级和全局级）
4. 创建`calculation_validation_config`表 - 存储验证器的配置参数
5. 创建`calculation_failures_log`表 - 记录所有计算和验证失败的情况
6. 创建`optimization_history`表 - 记录参数优化的历史

**涉及的表**:
- metric_calculation_order (主键: metric_key)
- calculation_method_registry (主键: method_id)
- calculation_parameters (唯一约束: device_id, metric_key, method_id, param_name)
- calculation_validation_config (唯一约束: device_id, metric_key, validator_type, param_name)
- calculation_failures_log (主键: id, 索引: device_id, ts_second, metric_key)
- optimization_history (主键: id, 索引: device_id, metric_key, created_at)

**依赖关系**:
- 依赖`dim_metric_config`表（外键引用）
- 依赖`dim_stations`表（外键引用）
- 依赖`dim_devices`表（外键引用）
