### 当前问题

❌ **存储过程执行失败**

**错误信息**：
```
relation "device_list" does not exist
LINE 1: SELECT COUNT(*) FROM device_list
```

**根本原因**：
存储过程中的 CTE（WITH 子句）定义的 `device_list` 临时表，在后续的 RAISE NOTICE 语句中被引用，但 PostgreSQL 不允许在 CTE 外部引用 CTE 中定义的表。

**影响**：
- 电流阈值学习存储过程执行失败
- 后续的功率、频率、时间参数学习存储过程因事务中止而全部失败
- device_running_thresholds 表仍然为空
- 36个指标仍然缺失

## 🔧 需要修复的问题

### 问题1：存储过程中的 RAISE NOTICE 引用 CTE

**位置**：所有4个存储过程

**问题代码示例**（052_create_sp_refresh_device_running_thresholds_current.sql）：
```sql
WITH device_list AS (
    SELECT device_id
    FROM device_running_thresholds
    WHERE ...
),
...

-- 后续的 RAISE NOTICE 尝试查询 device_list
RAISE NOTICE '[电流阈值学习] 总设备数: %', (SELECT COUNT(*) FROM device_list);
```

**解决方案**：
1. 将 CTE 改为临时表（CREATE TEMP TABLE）
2. 或者，将统计信息在 CTE 中计算好，存储到变量中
3. 或者，删除这些 RAISE NOTICE 语句（最简单）

**推荐方案**：删除引用 CTE 的 RAISE NOTICE 语句，保留其他日志输出。

### 问题2：存储过程的日志输出过于详细

**问题**：
存储过程中有很多 RAISE NOTICE 语句尝试查询 CTE 来获取统计信息，这些语句会导致错误。

**解决方案**：
简化日志输出，只保留关键的执行步骤日志，删除所有需要查询 CTE 的统计日志。
