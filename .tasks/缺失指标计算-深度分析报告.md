### 1️⃣ CalculationOrchestrator（主流程编排器）

#### 📌 核心职责
- 协调所有组件完成计算流程
- 数据加载（时间对齐）
- 批量计算和写入
- 并行计算支持

#### 🔄 工作流程

```python
def calculate_missing_metrics(station_id, device_id, start_time, end_time, metrics):
    # 步骤1：加载数据（时间对齐）
    data, timestamps = load_data(...)
    
    # 步骤2：分析依赖关系，生成计算顺序
    calculation_order = dependency_analyzer.get_calculation_order(metrics)
    
    # 步骤3：按顺序计算每个指标
    for metric in calculation_order:
        # 3.1 选择计算方法
        method = method_selector.select_method(metric, available_metrics, data)
        
        # 3.2 加载参数
        params = load_parameters(method_id, device_id)
        
        # 3.3 执行计算
        calculator = get_calculator(method_id)
        result = calculator(data, params)
        
        # 3.4 验证结果
        is_valid, errors = validator.validate(metric, result, data)
        
        # 3.5 更新数据字典
        if is_valid:
            data[metric] = result
            available_metrics.add(metric)
    
    # 步骤4：批量写入数据库
    write_to_database(data, timestamps, station_id, device_id)
    
    # 步骤5：记录失败日志
    log_failures(...)
```

```python
def get_calculation_order(metrics):
    # 步骤1：构建依赖图
    graph = build_graph(metrics)
    # graph = {'pump_efficiency': ['pump_flow_rate', 'pump_head'], ...}
    
    # 步骤2：检测循环依赖
    cycle = detect_circular_dependency(graph)
    if cycle:
        raise CircularDependencyError(f"检测到循环依赖: {cycle}")
    
    # 步骤3：拓扑排序
    order = topological_sort(graph)
    # order = ['pump_flow_rate', 'pump_head', 'pump_efficiency']
    
    return order
```

### 3️⃣ MethodSelector（方法选择器）

#### 📌 核心职责
- 检查方法的依赖是否满足
- 检查方法的条件是否满足
- 按优先级选择最佳方法

#### 🔄 工作流程

```python
def select_method(metric_key, available_metrics, data=None, context=None):
    # 步骤1：获取该指标的所有方法（按优先级排序）
    methods = _method_registry[metric_key]
    
    # 步骤2：遍历方法，找到第一个满足条件的
    for method in methods:
        # 2.1 检查依赖是否满足
        if not check_dependencies(method['dependencies'], available_metrics, data):
            continue
        
        # 2.2 检查条件是否满足
        if not check_conditions(method['conditions'], context):
            continue
        
        # 2.3 找到合适的方法
        return method
    
    # 步骤3：没有找到合适的方法
    return None
```

#### ✅ 已实现的功能
1. ✅ **依赖检查**：检查依赖指标是否在可用列表中
2. ✅ **数据有效性检查**：检查数据是否为空、是否全是NaN、是否有非零值
3. ✅ **条件检查**：检查JSONB格式的条件（如min_running_pumps）
4. ✅ **优先级排序**：按priority DESC排序，选择优先级最高的方法

#### ✅ 验证结果
- ✅ 所有新增指标都能选择到合适的方法
- ✅ 优先级设置合理（100 > 90 > 80）

#### ⚠️ 发现的问题

**问题1：条件检查不够完善**
- **要求**：根据已有指标和设备运行状态，选择最合适、精度最高的计算方法
- **现状**：只检查了`min_running_pumps`等简单条件

**问题2：未实现规则引擎**

#### 🔄 函数签名规范

```python
def calculate_xxx_method_y(
    data: Dict[str, np.ndarray],
    params: Dict[str, float]
) -> np.ndarray:
    """
    方法Y：方法名称
    
    公式:
        result = f(input1, input2, ...)
    
    Args:
        data: 包含 input1, input2, ...
        params: 包含 param1, param2, ...
    
    Returns:
        计算得到的结果数组
    """
    # 1. 提取输入数据
    input1 = data['input1']
    input2 = data['input2']
    
    # 2. 提取参数（带默认值）
    param1 = params.get('param1', default_value)
    
    # 3. 创建有效数据掩码
    valid_mask = ~np.isnan(input1) & ~np.isnan(input2) & (input1 > 0)
    
    # 4. 初始化结果数组为NaN
    result = np.full_like(input1, np.nan)
    
    # 5. 对有效数据进行计算
    result[valid_mask] = formula(input1[valid_mask], input2[valid_mask], param1)
    
    # 6. 返回结果
    return result
```

#### ✅ 已实现的功能
1. ✅ **23个计算函数**：9个指标，23种方法
2. ✅ **函数式架构**：每个方法一个独立函数
3. ✅ **参数化配置**：从params字典读取参数
4. ✅ **NaN处理**：正确处理NaN值
5. ✅ **向量化计算**：使用NumPy向量化操作
6. ✅ **注册表模式**：CALCULATOR_REGISTRY字典

#### ✅ 验证结果
- ✅ 所有23个方法都已正确注册
- ✅ 简单计算测试通过（pump_speed, pump_torque）

- **建议**：统一pump_speed的单位为rpm，或在pump_torque计算时判断单位并转换

**问题2：pump_cumulative_flow_method_a性能问题**

```python
def validate(metric_key, values, data=None, context=None):
    # 步骤1：获取验证配置
    validators = _validation_config.get(metric_key, [])
    
    # 步骤2：执行所有验证器
    all_valid = np.ones(len(values), dtype=bool)
    errors = []
    
    for validator_config in validators:
        validator_type = validator_config['validator_type']
        params = validator_config['params']
        
        # 2.1 执行验证
        if validator_type == 'range':
            mask, errs = validate_range(values, params['min'], params['max'])
        elif validator_type == 'non_negative':
            mask, errs = validate_non_negative(values)
        # ... 其他验证器
        
        # 2.2 合并结果
        all_valid &= mask
        errors.extend(errs)
    
    # 步骤3：返回结果
    return all_valid, errors
```

#### ✅ 已实现的功能
1. ✅ **范围验证**：检查值是否在[min, max]范围内
2. ✅ **非负验证**：检查值是否为非负数
3. ✅ **NaN验证**：检查值是否为NaN

## 四、数据流程分析

### 🔄 完整数据流程

```
1. CLI命令触发
   ↓
2. 初始化组件（Orchestrator, DependencyAnalyzer, MethodSelector, Validator）
   ↓
3. 加载数据（load_data）
   ├─ 查询fact_measurements表
   ├─ 使用ts_bucket作为时间基准
   ├─ 时间对齐（缺失时间点填充NaN）
   └─ 返回：data字典 + timestamps数组
   ↓
4. 分析依赖关系（dependency_analyzer.get_calculation_order）
   ├─ 从calculation_method_registry表读取依赖关系
   ├─ 构建依赖图
   ├─ 检测循环依赖
   ├─ 拓扑排序
   └─ 返回：计算顺序列表
   ↓
5. 按顺序计算每个指标
   ├─ 5.1 选择计算方法（method_selector.select_method）
   │   ├─ 检查依赖是否满足
   │   ├─ 检查条件是否满足
   │   └─ 返回：method字典
   │
   ├─ 5.2 加载参数（load_parameters）
   │   ├─ 查询calculation_parameters表
   │   ├─ 优先使用设备级参数
   │   ├─ 回退到全局参数
   │   └─ 返回：params字典
   │
   ├─ 5.3 执行计算（calculator(data, params)）
   │   ├─ 从CALCULATOR_REGISTRY获取计算函数
   │   ├─ 执行计算
   │   └─ 返回：result数组
   │
   ├─ 5.4 验证结果（validator.validate）
   │   ├─ 范围验证
   │   ├─ 非负验证
   │   ├─ NaN验证
   │   └─ 返回：(is_valid, errors)
   │
   └─ 5.5 更新数据字典
       ├─ data[metric] = result
       └─ available_metrics.add(metric)
   ↓
6. 批量写入数据库（write_to_database）
   ├─ 构建INSERT语句
   ├─ 批量插入fact_measurements表
   └─ 关联：station_id, device_id, ts_bucket, metric_id, value
   ↓
7. 记录失败日志（log_failures）
   └─ 插入calculation_failures_log表
```

## 六、发现的问题和偏离

#### 1. 缺少运行状态过滤

- **影响**：异常数据可能影响计算精度

- **影响**：无法计算需要泵站级数据的指标（如总管流量分摊）
- **建议**：实现load_station_data方法

- **影响**：计算性能差，可能成为瓶颈
- **建议**：使用NumPy的cumsum函数优化

- **影响**：多泵并联时，结果不准确

```python
    data: Dict[str, np.ndarray],
    params: Dict[str, float]
) -> np.ndarray:
    """方法A：相对转速法"""
    f = data['pump_frequency']  # Hz
    f_ref = params.get('f_ref', 50.0)  # Hz

    # 创建有效数据掩码
    valid_mask = ~np.isnan(f) & (f > 0)

    # 计算相对转速（初始化为NaN）
    n_star = np.full_like(f, np.nan)
    n_star[valid_mask] = f[valid_mask] / f_ref

    return n_star
```

**问题**:
- ⚠️ 输出是相对转速（无量纲），不是绝对转速（rpm）
- ⚠️ pump_torque_method_a依赖pump_speed，如果使用方法A的结果，计算会出错

**建议修复**:
```python
def calculate_pump_speed_method_a(
    data: Dict[str, np.ndarray],
    params: Dict[str, float]
) -> np.ndarray:
    """方法A：相对转速法（修正版）"""
    f = data['pump_frequency']  # Hz
    f_ref = params.get('f_ref', 50.0)  # Hz
    n_ref = params.get('n_ref', 1500.0)  # rpm，额定转速

    # 创建有效数据掩码
    valid_mask = ~np.isnan(f) & (f > 0)

    n[valid_mask] = (f[valid_mask] / f_ref) * n_ref  # ✅ 输出绝对转速
```

## 附录C：性能优化建议

### C1. pump_cumulative_flow_method_a优化

**当前实现（性能差）**:
```python
def calculate_pump_cumulative_flow_method_a(data, params):
    Q = data['pump_flow_rate']  # m³/h
    initial_value = params.get('initial_value', 0.0)
    time_interval = params.get('time_interval', 1.0)

    valid_mask = ~np.isnan(Q) & (Q >= 0)
    V = np.full_like(Q, np.nan)

    # ❌ 使用for循环逐点累加，性能差
    cumsum = initial_value
    for i in range(len(Q)):
        if valid_mask[i]:
            cumsum += Q[i] * time_interval / 3600.0
            V[i] = cumsum
        else:
            V[i] = np.nan

    return V
```

**优化后（性能好）**:
```python
def calculate_pump_cumulative_flow_method_a(data, params):
    Q = data['pump_flow_rate']  # m³/h
    initial_value = params.get('initial_value', 0.0)
    time_interval = params.get('time_interval', 1.0)

    valid_mask = ~np.isnan(Q) & (Q >= 0)

    # ✅ 使用NumPy的cumsum函数，性能好
    Q_filled = np.where(valid_mask, Q, 0)  # 将NaN替换为0
    V = initial_value + np.cumsum(Q_filled * time_interval / 3600.0)

    # 将无效位置设置为NaN
    V = np.where(valid_mask, V, np.nan)

    return V
```

**性能对比**:
- for循环版本：O(n)，但有Python循环开销
- cumsum版本：O(n)，但是C语言实现，快10-100倍
