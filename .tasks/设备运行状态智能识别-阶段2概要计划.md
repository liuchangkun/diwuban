## 📋 计划概述

### 核心目标
在阶段1的基础上,增强以下功能:
1. **启动/停止过渡特征学习**: 从历史数据中学习启动/停止过程的信号特征
2. **自适应时间参数学习**: 自动学习每个设备的启动/停止持续时间
3. **启动电流冲击倍数学习**: 从历史数据中学习启动电流峰值倍数
4. **异常检测**: 识别异常的启动/停止过程
5. **多算法切换**: 根据数据质量自动选择最优阈值学习算法

### 实施策略
- **依赖阶段1**: 必须在阶段1完成并验证效果后才能开始
- **可选实施**: 如果阶段1已经解决问题,阶段2可以推迟或取消
- **渐进式增强**: 每个功能独立开发和测试,互不影响

## 📝 存储过程和函数计划

### 2.1 新增存储过程清单

#### 2.1.1 sp_learn_transition_features

**功能描述**: 从历史数据中学习启动/停止过程的信号特征

**算法概要**:
```
1. 识别所有启动/停止边沿(0→1, 1→0)
2. 提取每个边沿前后的信号序列(电流、功率)
3. 计算信号特征:
   - 上升/下降斜率(线性回归)
   - 信号方差
   - 启动电流冲击峰值倍数
   - 启动电流冲击持续时间
4. 使用P95作为阈值(排除异常值)
5. 更新device_running_thresholds表
```

**输入参数**:
- p_device_id: 设备ID(NULL表示所有设备)
- p_start_ts: 开始时间
- p_end_ts: 结束时间

**输出**: 更新device_running_thresholds表的特征字段

---

#### 2.1.2 sp_select_threshold_algorithm

**功能描述**: 根据数据质量自动选择最优阈值学习算法

**算法概要**:
```
1. 评估数据质量:
   - 样本数量
   - 数据完整性(缺失率)
   - 信号稳定性(方差)
   - 运行模式(continuous/frequent/occasional)
2. 选择算法:
   - continuous + 高质量 → robust_quantile
   - frequent + 高质量 → otsu
   - occasional + 高质量 → gmm (Gaussian Mixture Model)
   - 低质量 → adaptive (自适应降级)
3. 更新device_running_thresholds表
```

**输入参数**:
- p_device_id: 设备ID(NULL表示所有设备)

**输出**: 更新device_running_thresholds表的threshold_algorithm字段

---

#### 2.1.3 sp_detect_anomalies

**功能描述**: 识别异常的启动/停止过程

**算法概要**:
```
1. 读取最近7天的启动/停止事件
2. 对每个事件计算特征:
   - 启动/停止持续时间
   - 电流/功率变化率
   - 启动电流峰值
3. 使用3-sigma规则识别异常:
   - 持续时间异常(过长或过短)
   - 变化率异常(过快或过慢)
   - 峰值异常(过高或过低)
4. 记录异常事件到日志表
5. 更新device_running_thresholds表的last_anomaly_detection_ts
```

**输入参数**:
- p_device_id: 设备ID(NULL表示所有设备)
- p_start_ts: 开始时间
- p_end_ts: 结束时间

**输出**: 插入异常事件到日志表

---

### 2.2 修改现有存储过程

#### 2.2.1 sp_refresh_device_running_thresholds_current

**修改内容**: 根据threshold_algorithm字段选择不同的算法

**算法伪代码**:
```
1. 读取device_running_thresholds.threshold_algorithm
2. 根据算法类型调用不同的计算逻辑:
   - 'otsu': 使用原有Otsu双峰法
   - 'robust_quantile': 使用P05/P95分位数法
   - 'gmm': 使用高斯混合模型(需要Python集成)
   - 'adaptive': 根据数据质量动态选择
3. 更新阈值
```

---

#### 2.2.2 sp_refresh_mv_running_phase

**修改内容**: 使用学习到的过渡特征增强phase识别

**算法伪代码**:
```
1. 读取学习到的过渡特征(斜率、方差阈值)
2. 在phase标记时,额外检查:
   - 信号变化率是否符合学习到的斜率
   - 信号方差是否符合学习到的阈值
3. 如果不符合,标记为异常(phase_type='anomaly')
```

## 🗄️ 新增数据库表

### 2.3.1 device_transition_anomalies 表

**用途**: 记录异常的启动/停止事件

**表结构**:
```sql
CREATE TABLE IF NOT EXISTS public.device_transition_anomalies (
    id                  BIGSERIAL PRIMARY KEY,
    station_id          INTEGER NOT NULL,
    device_id           BIGINT NOT NULL,
    ts_start            TIMESTAMPTZ NOT NULL,
    ts_end              TIMESTAMPTZ NOT NULL,
    transition_type     TEXT NOT NULL CHECK (transition_type IN ('startup', 'shutdown')),
    anomaly_type        TEXT NOT NULL CHECK (anomaly_type IN ('duration', 'slope', 'peak', 'variance')),
    expected_value      DOUBLE PRECISION,
    actual_value        DOUBLE PRECISION,
    deviation_sigma     DOUBLE PRECISION,  -- 偏离标准差的倍数
    detected_at         TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    FOREIGN KEY (device_id) REFERENCES dim_devices(id)
);

CREATE INDEX idx_device_transition_anomalies_device_ts 
    ON public.device_transition_anomalies(device_id, ts_start);
```

## 📊 风险评估

### 7.1 技术风险

**风险1**: 过渡特征学习可能不准确(数据质量差)
- **缓解措施**: 使用P95排除异常值,设置最小样本数要求

**风险2**: GMM算法需要Python集成,增加复杂度
- **缓解措施**: 先实现otsu和robust_quantile,GMM作为可选功能

**风险3**: 异常检测可能产生大量误报
- **缓解措施**: 使用3-sigma规则,设置合理的阈值

### 7.2 性能风险

**风险1**: sp_learn_transition_features可能耗时过长
- **缓解措施**: 只使用最近7天数据,优化SQL查询

**风险2**: 异常检测增加存储开销
- **缓解措施**: 定期清理旧的异常记录(保留30天)

### 7.3 业务风险

**风险1**: 阶段2可能不是必需的(阶段1已经解决问题)
- **缓解措施**: 在阶段1完成后评估是否需要阶段2

**风险2**: 用户可能不需要异常检测功能
- **缓解措施**: 异常检测作为可选功能,默认关闭
