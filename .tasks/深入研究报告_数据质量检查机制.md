## 🔍 质量状态定义

### quality_status字段

**代码位置**：`.memory/业务层/质量检查规则.md:114-122`

```
quality_status字段：
- 0 = GOOD（正常）：无质量问题
- 1 = SUSPECT（可疑）：有质量问题但可能是正常波动
- 2 = BAD（异常）：明确的质量问题
- 3 = COMPLETED（补全）：通过计算补全的数据
- 4 = MISSING（缺失）：数据缺失
```

**数据库定义**：`fact_measurements.quality_status`
- 类型：smallint
- 默认值：0
- 注释：数据质量状态码：0=正常；>0 为异常码

## 📊 质量码定义

### 7个核心质量码

| 质量码 | 标签 | 类别 | 严重度 | 描述 |
|--------|------|------|--------|------|
| 101 | 物理越界 | physical | 高 | 数值超出物理有效范围 |
| 111 | 异常跳变 | statistical | 中 | 相邻数据点变化过大 |
| 121 | 平台期 | statistical | 低 | 连续N个点值相同 |
| 401 | 状态矛盾 | logical | 中 | 运行状态与指标值矛盾 |
| 701 | 功率因数异常 | electrical | 中 | power_factor < 0 OR > 1 |
| 702 | 三相不平衡 | electrical | 中 | 三相电流不平衡度过大 |
| 751 | 计数器单调性 | logical | 高 | 累计量出现回退 |

## 🔄 质量检查流程

### 检查顺序

**代码位置**：`.memory/业务层/质量检查规则.md:127-159`

```
1. 物理越界检查（101） - 最高优先级
2. 计数器单调性检查（751） - 仅适用于累计量
3. 异常跳变检查（111）
4. 平台期检查（121）
5. 状态矛盾检查（401）
6. 功率因数异常检查（701）
7. 三相不平衡检查（702）
```

### 检查逻辑

```python
quality_codes = []

# 1. 物理越界
if value < valid_min or value > valid_max:
    quality_codes.append(101)
    quality_status = 2  # BAD

# 2. 异常跳变
if abs(value - prev_value) > jump_threshold:
    quality_codes.append(111)
    quality_status = max(quality_status, 1)  # SUSPECT

# 3. 平台期
if count_same_values >= plateau_threshold:
    quality_codes.append(121)
    quality_status = max(quality_status, 1)  # SUSPECT

# 4. 状态矛盾
if running_state == 0 and power > 0:
    quality_codes.append(401)
    quality_status = max(quality_status, 1)  # SUSPECT
```

**完整的数据加载SQL**：

```sql
SELECT 
    fm.ts_bucket,
    fm.value,
    mc.metric_key
FROM fact_measurements fm
JOIN dim_metric_config mc ON mc.id = fm.metric_id
LEFT JOIN mv_device_running_1s dr 
    ON fm.station_id = dr.station_id 
    AND fm.device_id = dr.device_id 
    AND fm.ts_bucket = dr.ts_bucket
WHERE fm.station_id = %s
  AND fm.device_id = %s
  AND fm.ts_bucket >= %s
  AND fm.ts_bucket < %s
  AND mc.metric_key = ANY(%s)
  AND dr.running = 1              -- 运行状态过滤
  AND fm.quality_status = 0       -- 质量过滤（只使用正常数据）
ORDER BY fm.ts_bucket, mc.metric_key
```

- ✅ 计算引擎只使用quality_status=0的数据
- ✅ 质量问题数据（quality_status > 0）被自动排除
- ✅ 确保计算结果的可靠性

## 🔥 质量检查的关键表

### metric_quality_rules表

**用途**：存储每个指标的质量检查规则

**关键字段**：

- valid_min：最小有效值
- valid_max：最大有效值

## 📊 质量检查的执行机制

### 存储过程：sp_mark_quality_window

**用途**：对指定时间窗口的数据执行质量检查

**输入参数**：
- p_station_id：泵站ID
- p_device_id：设备ID（可选）
- p_start_ts：开始时间
- p_end_ts：结束时间

**执行流程**：
```
1. 读取质量规则（metric_quality_rules表）
2. 读取待检查数据（fact_measurements表）
3. 执行质量检查（物理越界、异常跳变、平台期等）
4. 更新quality_codes数组和quality_status字段
5. 记录诊断日志（quality_diagnosis_log表）
6. 更新质量评估（quality_eval_by_device_metric表）
```

## 🔍 质量检查的详细规则

### 101 - 物理越界

**检查公式**：`value < valid_min OR value > valid_max`

**示例**：
- 有功功率 < 0 或 > 10000kW
- 流量 < 0 或 > 1000m³/h
- 扬程 < 0 或 > 200m
- 效率 < 0 或 > 1.0

**处理建议**：标记为BAD（quality_status=2），不参与统计和计算

---

### 111 - 异常跳变

**检查公式**：`abs(value - prev_value) > jump_threshold`

**阈值设置**：
- 动态阈值：threshold = 3 × σ（标准差）
- 静态阈值：根据指标类型设置
  - 流量：50 m³/h
  - 扬程：20 m
  - 功率：500 kW
  - 电流：50 A

**处理建议**：标记为SUSPECT（quality_status=1），需人工确认

---

### 121 - 平台期

**检查公式**：`count_same_values >= plateau_threshold`

**阈值设置**：
- 通常为连续10个点值相同

**处理建议**：标记为SUSPECT（quality_status=1），可能是传感器故障

---

### 401 - 状态矛盾

**检查公式**：`running_state == 0 AND power > 0`

**示例**：
- 设备标记为停机，但功率 > 0
- 设备标记为运行，但功率 = 0

**处理建议**：标记为SUSPECT（quality_status=1），需检查运行状态判断逻辑

## 📌 总结

### 质量检查机制的优势

| 优势 | 描述 |
|------|------|
| 多层检查 | 7个质量码覆盖物理、统计、逻辑、电气等多个维度 |
| 自动化 | 通过存储过程自动执行质量检查 |
| 可追溯 | 诊断日志记录所有质量问题 |
| 可配置 | 质量规则可按指标配置 |

### 质量过滤的关键点

1. **数据加载**：只使用quality_status=0的数据
2. **计算结果**：当前未设置quality_status（使用默认值0）
3. **质量检查**：通过存储过程sp_mark_quality_window执行
4. **质量评估**：按设备和指标统计质量分数

### 潜在改进点

1. **计算结果质量状态**：根据验证结果设置quality_status
2. **质量传播**：如果输入数据有质量问题，计算结果也应标记
3. **质量阈值**：支持设备级和泵站级的质量阈值配置
