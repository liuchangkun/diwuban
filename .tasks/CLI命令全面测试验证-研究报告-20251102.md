## 🎯 run-all 命令深度分析

### 命令签名
```bash
python -m app.cli.main run-all [mapping_file] [options]
```

### 核心编排器
- **文件**: `app/services/run_all/orchestrator.py` (1493行)
- **函数**: `run_all()`
- **配置**: `configs/merge.yaml`

### 执行流程 (9个阶段)

```
1. prepare-dim stage1 (默认开启)
   ↓ 重建维度表: dim_stations, dim_devices, dim_metric_config
   
2. create-staging (默认开启)
   ↓ 创建staging表: staging_raw, staging_rejects
   
3. ingest-copy (默认开启)
   ↓ CSV导入到staging_raw
   
4. merge-fact (默认开启)
   ↓ 合并到fact_measurements (时间对齐)
   
5. prepare-dim stage2 (默认开启)
   ↓ 生成规则表: metric_quality_rules, metric_rule_auto_baseline
   
6. calculation (默认开启)
   ↓ 缺失指标计算: pump_flow_rate, pump_head等10个指标
   
7. device_running (默认开启)
   ↓ 设备运行状态计算: mv_device_running_1s
   
8. presence (默认开启)
   ↓ 存在性统计: mv_presence_1s_any, mv_presence_60s_stats
   
9. quality_mark (默认关闭)
   ↓ 质量标注: fact_measurements.quality_codes
```

### 配置开关 (configs/merge.yaml)
```yaml
run_all:
  prepare_dim: true              # 阶段1
  create_staging: true           # 阶段2
  ingest_copy: true              # 阶段3
  merge_fact: true               # 阶段4
  prepare_dim_stage2: true       # 阶段5
  enable_calculation: true       # 阶段6
  device_running: true           # 阶段7
  presence: true                 # 阶段8
  quality_mark: false            # 阶段9 (默认关闭)
  reset_db: false                # 是否清空数据库
  reset_logs: true               # 是否清空日志
```

### 关键特性
1. **时间窗口**: 支持自动探测staging时间范围或手动指定
2. **并行执行**: quality_mark支持并行(默认4个worker)
3. **错误处理**: 每个阶段都有try-except包裹
4. **日志记录**: 结构化日志记录每个步骤的耗时和统计
5. **执行摘要**: 支持生成JSON格式的执行摘要
