### 核心问题

**device_running_thresholds 表完全为空，导致整个运行状态生成和指标计算流程失败。**

### 影响范围

| 影响项 | 状态 | 说明 |
|--------|------|------|
| device_running_thresholds 表 | ❌ 完全为空（0行） | 缺少所有设备的阈值配置 |

### 根本原因

1. **设计缺陷**：prepare-dim 阶段2 的规则生成不完整

2. **数据迁移问题**：设备更新后配置未同步
   - 2025-10-23 修复时为设备 89-94 创建了阈值配置
   - 后续 prepare-dim 将设备更新为 105-110
   - 阈值配置未自动迁移到新设备

3. **缺少验证**：没有完整性检查机制
   - 阈值表为空时没有报错
   - device_running 步骤静默失败
   - 指标计算静默失败

## 📊 第二部分：计算逻辑层面的深度分析

### 2.1 fn_running_state_1s 函数的阈值依赖

**函数实现**（`scripts/sql/m1/011_fn_running_state_1s.sql`）：

```sql
-- 第37-43行：从 device_running_thresholds 表读取阈值
SELECT COALESCE(enable_i,false), COALESCE(enable_p,false), COALESCE(enable_f,false),
       i_on, i_off, p_on, p_off, f_on, f_off,
       grace_hold_secs
  INTO v_ei, v_ep, v_ef,
       v_i_on, v_i_off, v_p_on, v_p_off, v_f_on, v_f_off,
       v_grace
FROM public.device_running_thresholds
WHERE device_id = p_device_id;

-- 第82-84行：运行判断逻辑
v_state := ( (v_ei AND r_max_i >= v_i_on)
          OR (v_ep AND r_p     >= v_p_on)
          OR (v_ef AND r_f     >= v_f_on) );
```

**问题分析**：
- 如果 device_running_thresholds 表为空，SELECT 返回 NULL
- enable_i/p/f 被 COALESCE 为 false
- i_on, i_off 等阈值为 NULL
- 判断逻辑：`(false AND NULL >= NULL) OR ... OR ...` = **false**
- **结果**：所有秒都被判定为 NOT running

### 2.2 sp_refresh_mv_running_phase 存储过程

**存储过程实现**（`scripts/sql/migrations/040_mv_running_phase.sql`）：

```sql
-- 第116行：调用 fn_running_state_1s
WITH s AS (
  SELECT * FROM public.fn_running_state_1s(p_station_id, p_device_id, p_start_ts, p_end_ts)
)
...
-- 第151-160行：插入到 mv_device_running_1s
INSERT INTO public.mv_device_running_1s(station_id, device_id, ts_bucket, running, phase, phase_type)
SELECT p_station_id, p_device_id, m.ts_bucket,
       CASE WHEN m.is_running THEN 1 ELSE 0 END,
       m.phase,
       NULL::text
FROM mark m
ON CONFLICT (station_id, device_id, ts_bucket)
DO UPDATE SET running = EXCLUDED.running, ...
```

**问题分析**：
- 即使阈值表为空，存储过程也会执行
- 但所有 is_running 都是 false
- 插入的 running 列都是 0
- **没有报错，静默失败**

### 3.3 根本原因总结

**设计缺陷**：
1. `run_running_thresholds()` 函数职责不完整
   - 只负责计算 pf_min/pf_max
   - 不负责初始化核心阈值
   - 假设核心阈值已经存在

2. prepare-dim 阶段2 缺少阈值初始化步骤
   - 清空规则表后，只调用 run_running_thresholds()
   - 没有调用阈值初始化函数
   - 导致核心阈值缺失

**数据迁移问题**：
1. 设备更新后，阈值配置未自动迁移
2. 备份恢复机制无法处理设备 ID 变化
3. 缺少设备变更检测和配置同步机制

**缺少验证**：
1. 没有检查阈值表完整性
2. 没有检查核心阈值是否为 NULL
3. device_running 步骤静默失败
4. 指标计算静默失败

## 🔍 第五部分：错误处理和验证机制分析

### 5.1 当前系统的错误处理

**问题1：阈值表为空时没有报错**
- `run_running_thresholds()` 成功执行
- 报告"inserted X rows"
- 但这些行只有 device_id，核心阈值为 NULL
- **没有验证阈值完整性**

**问题2：device_running 步骤静默失败**
- `fn_running_state_1s` 正常执行
- 返回所有秒的 is_running=false
- `sp_refresh_mv_running_phase` 正常执行
- 插入 running=0 的数据
- **没有检查是否所有秒都是 NOT running**

**问题3：指标计算静默失败**
- `load_data()` 返回空数据
- 计算方法因依赖缺失而跳过
- 报告"metrics_failed"
- **但没有明确说明是因为运行状态数据缺失**

### 5.2 缺少的验证机制

**应该添加的验证**：

1. **prepare-dim 阶段2 完成后**：
   - 检查 device_running_thresholds 表是否为空
   - 检查每个设备的核心阈值是否为 NULL
   - 如果发现问题，明确报错并停止流程

2. **device_running 步骤执行前**：
   - 检查阈值表是否完整
   - 检查是否所有需要处理的设备都有完整的阈值配置
   - 如果发现问题，明确报错并停止流程

3. **device_running 步骤执行后**：
   - 检查生成的数据是否合理
   - 如果所有秒都是 NOT running，发出警告
   - 检查是否为所有设备生成了数据

4. **指标计算执行前**：
   - 检查 mv_device_running_1s 表是否有对应设备的数据
   - 如果使用 filter_running=True，检查是否有 running=1 的数据
   - 如果发现问题，明确报错或建议禁用 filter_running
