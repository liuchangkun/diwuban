### 阶段1：问题1修复（metric_quality_rules数据生成）

**根因分析**：
- 存储过程 `sp_refresh_metric_rule_auto_baseline` 和 `sp_refresh_metric_rule_auto_baseline_win` 从 `fact_measurements` 表查找 `device_phase` 指标
- 但 `device_phase` 数据实际存储在 `mv_device_running_1s.phase` 列中
- 导致无法找到稳态数据（phase=1），baseline表为空

**解决方案**：
- 修改两个存储过程，从 `mv_device_running_1s` 表 JOIN 获取 phase 数据
- 使用 `INNER JOIN mv_device_running_1s ON (station_id, device_id, ts_bucket) WHERE phase=1`
- 添加兼容逻辑：`phase=1 OR (phase IS NULL AND running=1)`

**迁移文件**：
- `scripts/sql/migrations/069_alter_sp_refresh_metric_rule_auto_baseline_use_mv.sql`
- `scripts/sql/migrations/070_alter_sp_refresh_metric_rule_auto_baseline_win_use_mv.sql`

**验证结果**：
- ✅ metric_rule_auto_baseline：36行数据
- ✅ metric_quality_rules：36行数据

## 🔧 技术亮点

### 1. 表达式索引处理NULL值
```sql
CREATE UNIQUE INDEX uq_device_rated_params_3tier 
ON device_rated_params (
    COALESCE(station_id, 0), 
    COALESCE(device_id, 0), 
    param_key, 
    COALESCE(effective_from, '1970-01-01'::timestamptz)
);
```

### 2. 6层参数优先级系统
```python
# 层级1：全局计算参数
# 层级2：全局默认额定参数
# 层级3：设备额定参数
# 层级3.5：泵站级额定参数（新增）
# 层级4：泵站级计算参数
# 层级5：设备级计算参数
```

### 3. 存储过程优化
```sql
-- 从物化视图获取稳态数据
INNER JOIN public.mv_device_running_1s mvr
  ON mvr.station_id = f.station_id 
 AND mvr.device_id = f.device_id 
 AND mvr.ts_bucket = f.ts_bucket
 AND (mvr.phase = 1 OR (mvr.phase IS NULL AND mvr.running = 1))
```
