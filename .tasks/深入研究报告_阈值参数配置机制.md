### 2. 参数加载机制

**代码位置**：`app/services/calculation/orchestrator.py:675-812`

**6层参数优先级**（从低到高）：

| 层级 | 来源表                        | 条件                                      | 优先级 |
|------|-------------------------------|-------------------------------------------|--------|
| 1    | calculation_parameters        | device_id=NULL, station_id=NULL           | 最低   |
| 2    | global_default_rated_params   | 设备无额定参数时使用                      | 低     |
| 3    | device_rated_params           | device_id=X                               | 中     |
| 3.5  | device_rated_params           | station_id=X, device_id=NULL              | 中高   |
| 4    | calculation_parameters        | station_id=X, device_id=NULL              | 高     |
| 5    | calculation_parameters        | device_id=X                               | 最高   |

**加载逻辑**：
```python
def load_parameters(self, device_id: int, method_id: str, station_id: Optional[int] = None) -> Dict[str, any]:
    params = {}
    param_sources = {}
    
    # 层级1: 全局计算参数
    SELECT param_name, param_value FROM calculation_parameters
    WHERE device_id IS NULL AND station_id IS NULL AND method_id = %s
    
    # 层级2: 全局默认额定参数（如果设备无额定参数）
    if not has_rated_params:
        SELECT param_key, default_value FROM global_default_rated_params
    
    # 层级3: 设备额定参数
    SELECT param_key, value_numeric FROM device_rated_params WHERE device_id = %s
    
    # 层级3.5: 泵站级额定参数
    if station_id:
        SELECT param_key, value_numeric FROM device_rated_params
        WHERE station_id = %s AND device_id IS NULL
    
    # 层级4: 泵站级计算参数
    if station_id:
        SELECT param_name, param_value FROM calculation_parameters
        WHERE station_id = %s AND device_id IS NULL AND method_id = %s
    
    # 层级5: 设备级计算参数（最高优先级）
    SELECT param_name, param_value FROM calculation_parameters
    WHERE device_id = %s AND method_id = %s
    
    return params
```

### 4. 阈值参数的使用位置

**代码位置1**：`orchestrator.py:1668-1681` - `_prepare_flow_rate_share()` 方法

```python
params_cfg = self.load_parameters(device_id, method.method_id)
alpha = float(params_cfg.get("alpha", 1.0))
beta = float(params_cfg.get("beta", 1.0))
f_thr = float(params_cfg.get("f_thr", 3.0))  # ← 阈值参数
p_thr = float(params_cfg.get("p_thr", 0.5))  # ← 阈值参数

weight_i = np.zeros_like(power, dtype=float)
valid_mask = (
    ~np.isnan(power)
    & ~np.isnan(freq)
    & (freq >= f_thr)      # ← 频率阈值过滤
    & (power >= p_thr)     # ← 功率阈值过滤
)
```

**代码位置2**：`orchestrator.py:1768-1780` - 权重总和计算

```python
for ts_bucket, dev_id, power_val, freq_val in rows:
    if power_val is None or freq_val is None:
        continue
    p_val = float(power_val)
    f_val = float(freq_val)
    
    if f_val < f_thr or p_val < p_thr:  # ← 阈值过滤
        continue
    
    weight = (p_val ** alpha) * (f_val ** beta)
    if np.isfinite(weight) and weight > 0:
        weight_totals[ts_bucket] += weight
```

## 📊 总结

### ✅ 已验证的事实

1. **参数来源明确**：
   - f_thr=3.0 Hz 和 p_thr=0.5 kW 存储在 `calculation_parameters` 表
   - 当前为全局配置（device_id=NULL, station_id=NULL）

2. **配置机制完善**：
   - 支持6层参数优先级
   - 支持设备级别、泵站级别、全局级别的参数配置
   - 高优先级参数会覆盖低优先级参数

3. **使用位置清晰**：
   - 在 `_prepare_flow_rate_share()` 方法中使用
   - 用于过滤低频率、低功率的设备
   - 防止停机或低负荷设备参与流量分配

### ❓ 待解决的问题

1. **阈值合理性**：
   - f_thr=3.0 Hz 是否合理？（设备3的频率=4.90 Hz，刚好超过阈值）
   - p_thr=0.5 kW 是否合理？（设备3的功率=3.2 kW，远超阈值）

2. **设备3的特殊情况**：
   - 设备3的频率和功率都满足阈值要求
   - 但权重很小（15.68），份额只有0.071%
   - 是否需要为低负荷运行的设备设置不同的阈值？
