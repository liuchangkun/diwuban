## 📊 逐个指标分析

### 1. pump_flow_rate（根源失败）

**计算方法**：pump_flow_rate_method_a（优先级100）

**依赖**：
- main_pipeline_flow_rate ✅
- pump_active_power ✅ (值为0)
- pump_frequency ✅ (值为0)

**计算逻辑**：
```python
# orchestrator.py:1676-1681
valid_mask = (
    ~np.isnan(power)
    & ~np.isnan(freq)
    & (freq >= f_thr)      # 0 >= 3.0 ❌
    & (power >= p_thr)     # 0 >= 0.5 ❌
)
```

**失败原因**：
- ❌ freq=0 < f_thr=3.0
- ❌ power=0 < p_thr=0.5
- 不满足阈值条件 → valid_mask=False → weight=0 → share=NaN → 无法计算

**失败类型**：**阈值过滤失败**（不是依赖缺失，而是数据不满足计算条件）

### 2. pump_speed（独立失败）

**计算方法**：pump_speed_method_a（优先级100）

**依赖**：
- pump_frequency ✅ (值为0)

**计算逻辑**：
```python
# calculators.py:476-480
valid_mask = ~np.isnan(f) & (f > 0)  # 0 > 0 ❌

n = np.full_like(f, np.nan)

```

**失败原因**：
- ❌ freq=0，不满足 `f > 0` 条件
- valid_mask=False → n=NaN → 无法写入数据库

**失败类型**：**零值过滤失败**（计算方法主动过滤了freq=0的情况）

**验证**：
- 设备2的pump_frequency=48.44 Hz → pump_speed=1453.125 rpm ✅
- 计算公式：n = (48.44 / 50) × 1500 = 1453.125 ✅

## 🎯 失败模式总结

### 失败类型分类

| 指标 | 失败类型 | 根本原因 | 是否依赖链断裂 |
|------|---------|---------|---------------|
| pump_flow_rate | 阈值过滤失败 | freq=0, power=0不满足阈值条件 | ❌ 否（根源失败） |
| pump_speed | 零值过滤失败 | freq=0不满足f>0条件 | ❌ 否（独立失败） |
| pump_cumulative_flow | 依赖链断裂 | pump_flow_rate缺失 | ✅ 是 |
| pump_efficiency | 依赖链断裂 | pump_flow_rate缺失 | ✅ 是 |
| pump_torque | 依赖链断裂 | pump_flow_rate和pump_speed都缺失 | ✅ 是 |

### 依赖关系图

```
根源失败:
  pump_flow_rate (阈值过滤失败: freq=0, power=0)
    ├─→ pump_cumulative_flow (依赖链断裂)
    ├─→ pump_efficiency (依赖链断裂)
    └─→ pump_torque (依赖链断裂)

独立失败:
  pump_speed (零值过滤失败: freq=0)
    └─→ pump_torque (依赖链断裂)
```

## 📌 关键发现

### 发现1：两种不同的失败模式

1. **阈值/零值过滤失败**（主动过滤）：
   - pump_flow_rate: 硬编码阈值 `freq>=3.0, power>=0.5`
   - pump_speed: 硬编码条件 `f > 0`
   - 这些是计算方法**主动设计**的过滤逻辑，用于排除无效数据

2. **依赖链断裂**（被动失败）：
   - pump_cumulative_flow、pump_efficiency、pump_torque
   - 这些是因为上游指标失败导致的**连锁反应**

### 发现2：pump_speed的零值过滤是合理的

**代码位置**：`calculators.py:476`

```python
valid_mask = ~np.isnan(f) & (f > 0)
```

**设计意图**：
- 频率为0意味着电机停止，转速应该为0
- 但转速为0可能被误解为"数据缺失"
- 因此计算方法选择返回NaN，而不是0

**问题**：
- 这导致停机设备的pump_speed无法被记录
- 如果需要记录停机状态，应该允许写入0值

### 发现3：5个缺失指标中，3个是依赖链断裂

**统计**：
- 根源失败：1个（pump_flow_rate）
- 独立失败：1个（pump_speed）
- 依赖链断裂：3个（pump_cumulative_flow、pump_efficiency、pump_torque）

**结论**：
- 60%的失败是由于依赖链断裂
- 40%的失败是由于阈值/零值过滤
