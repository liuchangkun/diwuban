## 问题1: 物化视图表未填充

### 根本原因分析

#### mv_device_running_1s 表填充流程

**预期流程**:
1. `prepare_dim_stage2` → `_generate_rule_tables()`
2. 阶段A: `run_running_thresholds()` 生成 `device_running_thresholds` 表
3. 阶段B: `DeviceRunningJob.run()` 填充 `mv_device_running_1s` 表
4. 阶段C: (已删除)

**实际代码位置**:
- 文件: `app/services/ingest/prepare_dim/__init__.py`
- 函数: `_generate_rule_tables()` (第770-1050行)
- 阶段B代码: 第974-1048行

**关键发现**:
```python
# 第974行开始
if cfg_device_running:  # 配置开关控制
    # 调用 DeviceRunningJob
    job = DeviceRunningJob(settings, _job_cfg)
    job.run(start_ts=start_time, end_ts=end_time)
```

**填充机制**:
- `DeviceRunningJob.run()` → `run_device()` → `upsert_mv_running_phase_slice()`
- `upsert_mv_running_phase_slice()` 调用存储过程 `sp_refresh_mv_running_phase`
- 存储过程将数据写入 `mv_device_running_1s` 表

**实际验证结果**:
```sql
-- 配置验证
configs/merge.yaml: device_running: true  ✓ 配置已启用

-- 数据验证
SELECT COUNT(*) FROM device_running_thresholds;  -- 结果: 6 ✓ 有数据
SELECT COUNT(*) FROM fact_measurements WHERE metric_id IN (SELECT id FROM dim_metric_config WHERE metric_key = 'device_running');  -- 结果: 0 ✗ 无数据

-- 物化视图验证
SELECT COUNT(*) FROM mv_device_running_1s;  -- 结果: 0 ✗ 空表
```

**根本原因确认**:
❌ **fact_measurements 表中没有 device_running 指标的数据！**

这是核心问题：
1. `device_running_thresholds` 表有6条记录（阈值已学习）
2. 但 `fact_measurements` 表中没有 `device_running` 指标的数据
3. `DeviceRunningJob.run()` 的职责是**计算并写入** device_running 数据到 fact_measurements
4. `sp_refresh_mv_running_phase` 存储过程从 fact_measurements 读取 device_running=1 的记录写入 mv_device_running_1s
5. 由于 fact_measurements 中无 device_running 数据，mv_device_running_1s 表自然为空

**DeviceRunningJob 的实际职责**:
- 文件: `app/services/device_running_job.py`
- 第239行: `upsert_mv_running_phase_slice()` 调用 `sp_refresh_mv_running_phase`
- 但这个存储过程**不是**从原始数据计算 device_running，而是从已有的 device_running 数据填充物化视图
- **真正的问题**: 缺少将原始指标（电流/功率/频率）计算为 device_running 并写入 fact_measurements 的步骤

### mv_metric_60s_stats 表填充流程

**预期填充方式**:
- 调用存储过程 `sp_refresh_mv_metric_60s_stats`
- 从 `fact_measurements` 表聚合60秒统计数据

**问题**: 在 `_generate_rule_tables()` 中未找到调用此存储过程的代码

## 问题3: 阈值配置不完整警告

### 警告来源

**验证函数**: `app/services/rules/validate_thresholds.py`
**函数**: `validate_device_running_thresholds()` (第28-272行)

**检查内容**:
1. 表是否为空
2. 核心字段是否为 NULL:
   - `i_on`, `i_off` (电流阈值)
   - `grace_hold_secs`, `min_run_secs`, `min_stop_secs`, `smoothing_secs` (时间参数)

**实际数据验证**:
```sql
SELECT device_id, i_on, i_off, grace_hold_secs, min_run_secs, min_stop_secs, smoothing_secs
FROM device_running_thresholds;

-- 结果: 所有6个设备的时间参数都是 0
device_id | i_on   | i_off  | grace_hold_secs | min_run_secs | min_stop_secs | smoothing_secs
----------|--------|--------|-----------------|--------------|---------------|---------------
1         | 541.12 | 265.28 | 0               | 0            | 0             | 0
2         | 470.08 |-156.48 | 0               | 0            | 0             | 0
3         | 0.17   | 0.15   | 0               | 0            | 0             | 0
4         | 376.16 | 305.76 | 0               | 0            | 0             | 0
5         | 0.17   | 0.15   | 0               | 0            | 0             | 0
6         | 530.08 | 237.60 | 0               | 0            | 0             | 0
```

**根本原因确认**:
❌ **时间参数学习存储过程未正确执行或逻辑有问题！**

**时间参数学习流程**:
1. 调用位置: `app/services/rules/running_thresholds.py` 第305-320行
2. 存储过程: `sp_refresh_device_running_thresholds_timing`
3. 定义位置: `scripts/sql/migrations/055_create_sp_refresh_device_running_thresholds_timing.sql`

**存储过程逻辑分析**:
```sql
-- 第66-75行: 更新条件
UPDATE device_running_thresholds t
SET
    grace_hold_secs = COALESCE(t.grace_hold_secs, v_default_grace_hold),
    min_run_secs = COALESCE(t.min_run_secs, v_default_min_run),
    min_stop_secs = COALESCE(t.min_stop_secs, v_default_min_stop),
    smoothing_secs = COALESCE(t.smoothing_secs, v_default_smoothing),
    ...
WHERE t.device_id IN (SELECT device_id FROM device_list)
  AND (t.grace_hold_secs = 0 OR t.min_run_secs = 0 OR t.min_stop_secs = 0 OR t.smoothing_secs = 0);
```

**问题分析**:
- `COALESCE(t.grace_hold_secs, v_default_grace_hold)` 的逻辑是：如果字段为 NULL，使用默认值
- 但实际数据中，字段值是 **0**（不是 NULL）
- `COALESCE(0, 30)` 返回 0（因为 0 不是 NULL）
- 虽然 WHERE 条件匹配（grace_hold_secs = 0），但 SET 语句不会更新值

**用户提到的"对齐后的数据"问题**:
- 用户说"时间参数应该根据对齐后的数据计算"
- 当前存储过程（第49-54行）注释说明："当前版本使用默认值策略（未来可从历史数据学习）"
- 存储过程没有从 mv_device_running_1s 表分析运行状态持续时间
- 需要实现从对齐后的 device_running 数据中学习时间参数

## 研究结论（已更正）

### 问题1: mv_device_running_1s 表为空

**架构理解（用户澄清）**:
1. ✅ `device_running` 指标**不再**存储在 `fact_measurements` 表中
2. ✅ `mv_device_running_1s` 表**专门**存储设备运行状态

**正确的数据流**:
```
原始指标（电流/功率/频率）
  ↓ (存储在 fact_measurements)
fn_running_state_1s() 函数
  ↓ (根据 device_running_thresholds 阈值计算)
sp_refresh_mv_running_phase 存储过程
  ↓ (写入)
mv_device_running_1s 表
```

**DeviceRunningJob 的实际职责**:
- 文件: `app/services/device_running_job.py`
- 第239行: 调用 `upsert_mv_running_phase_slice()`
- 该函数调用 `sp_refresh_mv_running_phase` 存储过程
- 存储过程内部:
  1. 调用 `fn_running_state_1s()` 函数从原始指标计算运行状态
  2. 识别启动/停止边沿
  3. 标记 phase (0=停止, 1=运行, 2=启动中, 3=停止中)
  4. 写入 `mv_device_running_1s` 表

**执行验证**:
```sql
-- DeviceRunningJob 已执行 ✓
SELECT COUNT(*) FROM completion_runs WHERE code_version = 'device_running:v1';  -- 6条记录

-- 所有设备都执行了，但 rows_read = 0 ✗
SELECT run_id, device_id, rows_read, duration_ms FROM completion_runs
WHERE code_version = 'device_running:v1' ORDER BY run_id DESC LIMIT 6;
-- 结果：所有设备的 rows_read = 0, duration_ms = 0

-- 原始指标数据充足 ✓
SELECT COUNT(*) FROM fact_measurements WHERE device_id = 1;  -- 1,089,815 条记录
时间范围：2025-10-22 08:00:00 到 2025-10-23 07:19:37
```

**根本原因确认**:
❌ **fn_running_state_1s() 函数有 SQL 错误！**

**错误详情**:
```sql
-- 测试函数调用
SELECT COUNT(*) FROM fn_running_state_1s(1, 1, '2025-10-22T08:00:00Z', '2025-10-22T09:00:00Z');
-- 错误：column f.quality_status does not exist

-- 函数定义中的问题代码（数据库中的实际版本）：
SELECT ... FROM fact_measurements f
WHERE ...
  AND f.quality_status = 0  -- ❌ 此列不存在！
```

**fact_measurements 表结构验证**:
```sql
SELECT column_name FROM information_schema.columns
WHERE table_name = 'fact_measurements' AND table_schema = 'public';

-- 实际列：id, station_id, device_id, metric_id, ts_raw, ts_bucket, value, source_hint, inserted_at
-- ❌ 没有 quality_status 列！
```

**问题影响**:
1. `fn_running_state_1s()` 函数执行失败
2. `sp_refresh_mv_running_phase` 存储过程调用该函数时失败
3. `DeviceRunningJob` 执行完成但没有写入任何数据（rows_read = 0）
4. `mv_device_running_1s` 表保持为空

**修复方案**:
需要更新 `fn_running_state_1s()` 函数，删除 `AND f.quality_status = 0` 这一行
