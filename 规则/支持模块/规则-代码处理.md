# 代码处理指南

## 代码块结构

根据不同编程语言的注释语法选择适当的格式：

### 风格语言（C、C++、Java、JavaScript、Go、Python、Vue等前后端语言）

```language:file_path
// ... existing code ...
{{ modifications, e.g., using + for additions, - for deletions }}
// ... existing code ...
```

**示例**：
```python:utils/calculator.py
# ... existing code ...
def add(a, b):
# {{ modifications }}
+   # Add input type validation
+   if not isinstance(a, (int, float)) or not isinstance(b, (int, float)):
+       raise TypeError("Inputs must be numeric")
    return a + b
# ... existing code ...
```

### 通用格式（语言类型不确定时）

```language:file_path
[... existing code ...]
{{ modifications }}
[... existing code ...]
```

## 编辑指南

### 基本原则

- **仅显示必要的修改上下文**：不要显示整个文件，只显示修改的部分及其上下文
- **包括文件路径和语言标识符**：每个代码块都要指定语言和文件路径
- **提供上下文注释**：如需要，添加注释说明修改的目的
- **考虑对代码库的影响**：思考修改对其他部分的影响
- **验证与请求的相关性**：确保修改与用户请求相关
- **保持范围合规性**：不要修改不相关的代码
- **避免不必要的更改**：只做必要的修改

### 注释和日志规范

**除非另有说明，否则所有生成的注释和日志输出必须使用中文。**

**示例**：
```python
# 正确：使用中文注释
def process_data(data):
    """处理数据并返回结果"""
    if not data:
        logger.warning("数据为空，跳过处理")
        return None
    # 验证数据格式
    if not isinstance(data, list):
        raise TypeError("数据必须是列表类型")
    return data

# 错误：使用英文注释（除非用户明确要求）
def process_data(data):
    """Process data and return result"""
    if not data:
        logger.warning("Data is empty, skip processing")
        return None
    # Validate data format
    if not isinstance(data, list):
        raise TypeError("Data must be list type")
    return data
```

## 禁止行为

### 严格禁止

1. **使用未经验证的依赖项**
   - 不要添加未经验证的第三方库
   - 不要使用过时或不安全的依赖

2. **留下不完整的功能**
   - 不要留下半成品代码
   - 不要留下TODO注释而不实现

3. **包含未测试的代码**
   - 不要提交未经测试的代码
   - 不要假设代码会正常工作

4. **使用过时的解决方案**
   - 不要使用已弃用的API
   - 不要使用过时的编程模式

5. **在未明确要求时使用项目符号**
   - 在代码注释中避免使用项目符号
   - 使用自然的段落描述

6. **跳过或简化代码部分（除非是计划的一部分）**
   - 不要省略错误处理
   - 不要简化关键逻辑

7. **修改不相关的代码**
   - 不要"顺便"修改其他代码
   - 保持修改范围在计划内

8. **使用代码占位符（除非是计划的一部分）**
   - 不要使用 `# TODO: implement this`
   - 不要使用 `pass` 或空函数体
   - 不要使用 `...` 作为占位符

## 代码质量标准

### 命名规范

- **变量名**：使用描述性名称，避免单字母变量（除了循环计数器）
- **函数名**：使用动词开头，清晰描述功能
- **类名**：使用名词，首字母大写
- **常量名**：全大写，使用下划线分隔

**示例**：
```python
# 正确
user_count = 10
def calculate_total_price(items):
    pass
class UserManager:
    pass
MAX_RETRY_COUNT = 3

# 错误
uc = 10
def calc(i):
    pass
class um:
    pass
max = 3
```

### 错误处理

- **始终处理可能的错误**
- **提供清晰的错误信息**
- **使用适当的异常类型**
- **不要吞掉异常**

**示例**：
```python
# 正确
def read_file(file_path):
    """读取文件内容"""
    try:
        with open(file_path, 'r', encoding='utf-8') as f:
            return f.read()
    except FileNotFoundError:
        logger.error(f"文件不存在: {file_path}")
        raise
    except PermissionError:
        logger.error(f"没有权限读取文件: {file_path}")
        raise
    except Exception as e:
        logger.error(f"读取文件时发生错误: {file_path}, 错误: {e}")
        raise

# 错误
def read_file(file_path):
    try:
        with open(file_path, 'r') as f:
            return f.read()
    except:
        pass  # 吞掉异常
```

### 代码注释

- **使用中文注释**（除非另有说明）
- **注释应该解释"为什么"，而不是"是什么"**
- **复杂逻辑必须有注释**
- **函数必须有文档字符串**

**示例**：
```python
# 正确
def calculate_discount(price, user_level):
    """
    根据用户等级计算折扣价格
    
    Args:
        price: 原价
        user_level: 用户等级 (1-5)
    
    Returns:
        折扣后的价格
    """
    # 使用二次函数计算折扣，确保高等级用户获得更大折扣
    discount_rate = 0.05 * (user_level ** 2)
    return price * (1 - discount_rate)

# 错误
def calculate_discount(price, user_level):
    # Calculate discount
    discount_rate = 0.05 * (user_level ** 2)  # Multiply by 0.05
    return price * (1 - discount_rate)  # Return discounted price
```

### 代码格式

- **使用一致的缩进**（Python: 4空格，JavaScript: 2空格）
- **每行不超过80-120字符**
- **函数之间空一行**
- **类之间空两行**
- **运算符两边加空格**

## 代码显示规范

当向用户展示现有文件中的代码时，不要用普通的 markdown ``` 包裹。

相反，**始终**将要展示给用户的代码包裹在 `<augment_code_snippet>` 和 `</augment_code_snippet>` XML 标签中。

提供 `path=` 和 `mode="EXCERPT"` 属性。

使用四个反引号（````）而不是三个。

**示例**：
```xml
<augment_code_snippet path="foo/bar.py" mode="EXCERPT">
````python
class AbstractTokenizer():
    def __init__(self, name):
        self.name = name
    ...
````
</augment_code_snippet>
```

**简洁性**：只提供 <10 行代码。如果你提供正确的 XML 结构，它将被解析为可点击的代码块，用户可以随时点击查看完整文件。

## 包管理

**始终使用适当的包管理器进行依赖管理，而不是手动编辑包配置文件。**

### 使用正确的包管理器命令

| 语言/框架 | 包管理器 | 安装命令 | 卸载命令 |
|----------|---------|---------|---------|
| JavaScript/Node.js | npm | `npm install <package>` | `npm uninstall <package>` |
| JavaScript/Node.js | yarn | `yarn add <package>` | `yarn remove <package>` |
| JavaScript/Node.js | pnpm | `pnpm add <package>` | `pnpm remove <package>` |
| Python | pip | `pip install <package>` | `pip uninstall <package>` |
| Python | poetry | `poetry add <package>` | `poetry remove <package>` |
| Python | conda | `conda install <package>` | `conda remove <package>` |
| Rust | cargo | `cargo add <package>` | `cargo remove <package>` |
| Go | go | `go get <package>` | `go mod tidy` |
| Ruby | gem | `gem install <package>` | `gem uninstall <package>` |
| Ruby | bundler | `bundle add <package>` | `bundle remove <package>` |
| PHP | composer | `composer require <package>` | `composer remove <package>` |
| C#/.NET | dotnet | `dotnet add package <package>` | `dotnet remove package <package>` |

### 为什么使用包管理器

- **自动解析正确版本**
- **处理依赖冲突**
- **更新锁文件**
- **维护环境一致性**

### 例外情况

只有在以下情况下才能手动编辑包文件：
- 复杂的配置更改（如自定义脚本、构建配置）
- 包管理器命令无法完成的操作
