# RIPER-5 协议规则系统 - 使用说明

## 📋 概述

这是 RIPER-5 + Multidimensional Thinking + Agent Execution Protocol 的模块化规则系统。

**版本**：v3.0 - 模块化分层架构  
**更新日期**：2025-09-30

---

## 🎯 设计理念

### 问题
原始的 `规则.md` 文件有 1075 行，超过了 Augment Rules 的文件大小限制，导致无法添加到 Rules 中。

### 解决方案
采用**分层按需加载架构**：
- **主控文件**（150-200行）：添加到 Augment Rules，包含核心框架和强制加载机制
- **详细模块**（按需加载）：AI 在需要时通过 `view` 工具读取

### 优势
✅ 保留全部功能和效果  
✅ 解决文件大小限制  
✅ 按需加载，节省 token  
✅ 模块化，易于维护和扩展  
✅ 更清晰的职责划分

## 🚀 使用步骤

### 步骤1: 在 Augment Rules 中添加主控文件

1. 打开 Augment 设置
2. 找到 "Rules" 或 "Custom Rules" 选项
3. 添加文件：`规则/规则-主控.md`
4. 保存设置

**重要**：只需要添加主控文件，不要添加其他文件！

### 步骤2: 验证配置

开始一个新对话，发送测试消息：
```
你好，请确认你已加载 RIPER-5 协议。
```

AI 应该：
1. 声明当前模式（如 `[MODE: 研究]`）
2. 读取核心原则文件
3. 展示上下文状态报告

### 步骤3: 正常使用

AI 会自动：
- 根据任务类型判断需要进入的模式
- 在进入模式前读取对应的详细规则文件
- 严格遵循协议执行任务

## ⚙️ 强制加载机制

主控文件中包含强制加载机制，确保 AI 会读取必要的详细规则：

### 协议初始化
在处理任何用户请求前，AI 必须：
1. 读取核心原则文件
2. 根据任务类型判断模式
3. 读取对应模式的详细规则文件

### 模式执行前自检
进入任何模式前，AI 必须确认：
- [ ] 已读取核心原则文件
- [ ] 已读取当前模式的详细规则文件
- [ ] 已读取记忆系统文件（如涉及记忆操作）
- [ ] 已理解当前模式的允许/禁止事项

## 🛠️ 维护和更新

### 更新某个模式的规则
1. 编辑对应的模式文件（如 `规则-模式1-研究.md`）
2. 保存文件
3. 无需重新配置 Augment Rules
4. AI 会在下次进入该模式时读取最新内容

### 添加新的规则模块
1. 在对应目录下创建新文件
2. 在主控文件的"支持文件索引"中添加引用
3. 在需要的模式中添加读取指令

### 更新主控文件
1. 编辑 `规则-主控.md`
2. 保存文件
3. Augment 会自动重新加载

## ❓ 常见问题

### Q: AI 会自动读取详细规则文件吗？
A: 是的，主控文件中包含强制加载机制，AI 必须在进入模式前读取对应的详细规则文件。

### Q: 如果 AI 没有读取详细文件怎么办？
A: 提醒 AI："请先读取对应的详细规则文件，然后再继续。"

### Q: 可以只添加主控文件吗？
A: 是的，只需要添加主控文件到 Augment Rules。其他文件通过 `view` 工具按需读取。

### Q: 如何确认 AI 已加载规则？
A: 检查 AI 的响应是否包含模式声明和上下文状态报告。

### Q: 可以自定义规则吗？
A: 可以，直接编辑对应的规则文件即可。建议先备份原文件。
