# 阶段1：现状调研报告

- 版本：v0.1
- 日期：2025-09-28
- 负责人：Augment Agent

## 一、执行摘要
本报告调研现有数据库对象与接口，目标是为“水泵设备缺失指标计算系统”的后续实现提供依据。在不修改 fact_measurements 结构的前提下，复用现有函数/视图/过程，确保逐点按 ts_bucket 秒级对齐与 [start,end) 窗口口径。
- 统一口径声明：时间/DST/窗口对齐、单位归一与 RunContext 最小字段以《阶段2_核心计算引擎设计.md》§6/§8/§13 为准；L1=质量窗口+物理/机理（L1a/L1b），L2=特性曲线。

## 二、系统/技术栈概览
- PostgreSQL + TimescaleDB（fact_measurements 为 Hypertable）
- 应用层有 get_*_by_time_range 的封装，底层走 reporting.get_metrics_*_multi 系列
- 运行态/相位物化：mv_device_running_1s + sp_refresh_mv_running_phase
- 指标在场性：metrics_presence_per_second 函数、metrics_presence_per_second_device 表、兼容视图 mv_presence_1s_any
- 质量打标：sp_mark_quality_window（含 vfast 与 diag 包装），结果写回 fact_measurements 质量字段

## 三、核心对象与要点
### 1) fact_measurements（Hypertable）
- 时间列 ts_bucket，空间维度 device_id，唯一覆盖 (station_id, device_id, metric_id, ts_bucket)
- 索引：BRIN(ts_bucket)、复合(s,d,m,t)
- 口径：逐点按秒对齐；写回时通过上述复合键冲突 UPSERT

### 2) 运行态/相位：mv_device_running_1s
- 表结构含 running、phase 字段；过程 sp_refresh_mv_running_phase 支持按设备+窗口幂等刷新
- 查询按半开区间 [start,end)；对高频窗口查询有索引

### 3) 指标在场性/缺失：metrics_presence_per_second / _device
- 函数按秒输出 need_compute_metrics 与 available_metrics（以 metric_key 表达），可结合 _device 表进行设备×秒维度统计
- 兼容视图 mv_presence_1s_any 将 presence 信息映射到 metric_id

### 4) 时间窗聚合读取：get_device_metrics_by_time_range / get_station_devices_metrics_by_time_range
- 应用层封装统一了参数与返回结构；数据库端由 reporting.get_metrics_*_multi 选择小时/日粒度

### 5) 质量打标：sp_mark_quality_window / _vfast / _vfast_diag
- 覆盖越界/跳变/平台期/非单调/噪声/传感器故障/602等；提供剖析与诊断日志
- 在计算写回前后均可调用以保障输入/输出可靠性

## 四、存在问题识别
- 缺失指标推导尚无统一配置与方法登记，难以管控“何时算/如何算/参数何在/如何验证”
- 大窗口批量计算的调度/并发策略需在应用层统一编排
- 计算与验证留痕缺失，影响可追溯性与版本化对比

## 五、改进需求
- 引入四张配置/方法/标定/验证表，收敛治理“计算开关、方法可用性、参数来源、验证留痕”
- 采用应用层编排（Python），数据库存储配置与结果留痕，复用既有视图/过程，保证口径统一
- 批处理+并发策略，确保>10万点场景的性能与资源控制

## 5+. 统一口径与治理补充（文档建议）
- 维表/映射来源（占位）：device→model/series/vendor 的映射来源于维表或配置中心；具体来源名在阶段2 §9 引用；缺失映射时 L2 直接跳过并留痕
- 单位治理口径：单位归一/映射失败的处理与 unit_map_version/单位因子摘要以阶段2 §6/§8/§13 为准；缺映射拒绝计算并留痕
- Timescale 运维建议（简）：chunk_interval 建议 1–3 天；mv_device_running_1s 定时刷新+手动补刷；例行 VACUUM/ANALYZE 与锁/膨胀监控


## 七、补充设计（按用户最新要求）
- 设备级参数成套：新增 rls_parameter_set（每设备可多套，支持唯一激活 is_active），rls_parameter_calibration 以 set_id 关联归属
- 特性曲线接口：新增 characteristic_curve_library（H-Q/η-Q/P-Q），用于第二层验证/优化；基础计算不直接依赖
- 原则：优化引擎（RLS/特性曲线）仅用于优化参数与结果评估，不参与基础计算过程，避免掩耳盗铃

- 特性曲线回退：先尝试设备专属激活曲线；若无则回退至机型/系列/厂家通用；若仍无或性能评分不足，则仅运行第一层（物理/机理）验证，跳过第二层


## 六、结论
- 现状与项目约束高度匹配：无需变更 fact_measurements 结构即可落地
- 复用对象清单：mv_device_running_1s、metrics_presence_per_second(_device)、get_*_by_time_range、sp_mark_quality_window
- 建议按本报告的改进需求推进阶段2/3/4 的实现
