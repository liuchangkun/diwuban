# 阶段2：核心计算引擎设计（轻量但完整的实现约定）

- 版本：v0.2
- 日期：2025-09-28
- 负责人：Augment Agent


本文为阶段2的设计与实现约定，目标是以“最小可运行骨架 + 明确契约”的方式，快速落地引擎并可扩展到新增设备/指标。严格遵循阶段1已定口径：不改 fact_measurements 结构，按 ts_bucket 逐点计算，复用 get_*_by_time_range、mv_device_running_1s、sp_mark_quality_window，窗口口径 [start, end)。

---

## 1. 目标与范围
- 输出一个可运行的最小引擎骨架：identify_missing_metrics → select_optimal_method → compute → 两层验证 → upsert → run_context 留痕
- 明确模块职责、接口契约与数据模型；给出并发/批量、幂等、异常与观测约定
- 支持后续“自适应扩展”（新增设备/指标）无需改引擎代码，只补元数据与配置

## 2. 模块结构与目录（建议）
- src/core_engine/
  - pipeline.py（编排主流程，组织各模块调用）
  - identify_missing_metrics.py（缺失识别）
  - selector.py（CalculationMethodSelector）
  - calculator.py（MetricCalculator）
  - validators/
    - quality_window.py（封装 sp_mark_quality_window 调用）
    - curve_validator.py（曲线验证与回退链）
  - writeback.py（UPSERT 与幂等）
  - run_context.py（留痕 API 与字段校验）

## 3. 数据模型与类型约定
- 时间：严格秒级 ts_bucket，对齐 [start, end) 半开区间
- 设备/指标：以 device_id、metric_id 为主键（统一对齐 dim_metric_config）
- 数据帧 frame_by_ts_bucket：字典/二维结构，key=ts_bucket，value=所需输入指标列（NaN 允许）
- 段 Segment：{device_id, metric_id, segment_start, segment_end}（保证段内按 ts_bucket 连续，且 running=1）
- Series：计算输出序列（按 ts_bucket 对齐）；允许 NaN
- 结果行 Row：{station_id, device_id, metric_id, ts_bucket, value}
- 掩码/质量：presence & running 掩码；质量窗口在验证层处理

## 4. 时序与端到端流程（Mermaid）
```mermaid
flowchart LR
  A[Identify Missing]-->B[Select Method]
  B-->C[Compute]
  C-->D1[Validate L1: Quality Window]
  D1-->D2{Curve Available & Score>=Min?}
  D2 -- Yes --> E[Validate L2: Curve]
  D2 -- No  --> F[Skip L2]
  E-->G[WriteBack UPSERT]
  F-->G[WriteBack UPSERT]
  G--Async-->H[Optimizer (RLS/Curve) 自动激活并记录]
  G-->I[RunContext Record]
```

## 5. 接口契约（入参/出参/异常）
- identify_missing_metrics(device_ids|station_id, target_metrics, start, end, tz, coverage_threshold=0.95) → List[Segment]
  - 步骤：presence 判定 need_compute ∧ mv_device_running_1s.running=1 → 连续段聚合（最小段长可配置）
  - 异常：参数校验错误（ValueError）；DB 访问异常（DataAccessError）
  - 口径：入参时间均按本地时区 tz 接收→统一转换为 UTC → 按 UTC 对齐到秒级 ts_bucket；界面展示再按 tz 转回
  - DST：夏令时重复秒/缺秒时，重复秒取第一条，缺秒按无数据处理（不插值），该决策写入 run_context
  - 掩码：presence 掩码 ∧ mv_device_running_1s.running=1；仅保留运行态=1的秒点
  - 连段：对秒点掩码进行连段聚合，默认最小段长 min_segment_seconds=60（可配置）；
    - 断裂合并：允许 ≤ gap_merge_seconds=2 的小缺口粘连合并，避免碎片化（可配置）
  - 输出：List[Segment]，按设备×指标×时间段聚合；每段记录来源与规则摘要到 run_context

- select_optimal_method(target_metric, available_inputs, device_id) → method_id | None
  - 候选：calculation_method_selector.applicable_metrics 包含 target_metric
  - 过滤：required_inputs 存在率≥阈值（阈值从 remark(JSON) 读取；优先设备/指标粒度）
  - 排序：设备级优先 → accuracy_level 降序 → priority_level 升序 → method_name 字典序；取 Top1
  - 阈值：从 metric_calculation_config.remark 或 calculation_method_selector.remark(JSON) 读取 coverage_threshold、required_inputs_presence_min、min_segment_seconds 等；未配置则落回全局默认
  - 降阈：若无候选，则一次性将 coverage_threshold 降至 0.8 再评估；仍无则返回 None 并记录原因
  - 记录：run_context 记录 method_id、候选数、过滤原因（按 required_inputs 缺失/存在率不足等分类）、排序因子与最终选择；写 thresholds_hash（阈值配置 JSON 归一化后哈希）

- compute(method_id, frame_by_ts_bucket, env) → Series

- validate_physical(series) → result, stats（物理/机理约束校验，L1b）

  - env：包含单位映射版本 unit_map_version、ρ/g/温度/海拔/黏度来源与取值、VFD 标定、假设说明
  - 单位归一：按 dim_metric_config.unit→SI；记录转换因子摘要（unit_factors_digest）
  - 保护：运行态=0、输入缺失→对应点 NaN；越界→NaN 待验证器判定；不做时间插值与跨断点连接
  - 记录：run_context 写入 unit_map_version、unit_factors_digest、env 常数、越界点计数

- validate_quality(series) → result, stats（封装 sp_mark_quality_window）
- validate_curve(series, device_id, target_metric) → result, residual_stats, curve_meta
  - 回退链：设备专属→机型/系列→厂家通用；无/低质（performance_score<min_curve_score）则直接“仅第一层”
- upsert_results(rows, source_tag, calculation_id) → stats（批量、重试等）
- run_context.log(calculation_id, context_dict) → None

## 6. 数据获取封装（DB 复用）
- 函数：get_device_metrics_by_time_range / get_station_devices_metrics_by_time_range
- 规则：
  - 时区与对齐：入参按 tz 接收，统一转 UTC 对齐到秒级 ts_bucket；界面展示再按 tz 转回；对 DST 重复秒/缺秒按“重复取第一、缺失不插值”处理
  - 对齐 [start, end)、按 ts_bucket 秒级；将原始窗口与对齐后的窗口写入 run_context（window_original/window_aligned_utc）
  - mv 刷新水位：计算前查询/刷新 mv_device_running_1s，确保覆盖至 end；记录 last_refreshed_ts 与是否达标（covered=true/false）到 run_context；若不达标可降级为仅按 presence 掩码过滤或延后执行
- 示例（remark JSON 片段）：{"coverage_threshold":0.95,"required_inputs_presence_min":0.9,"min_segment_seconds":60}

  - presence：使用 metrics_presence_per_second(_device) 判定 available/need_compute；presence 与 running 掩码取交集
  - 单位归一：按 dim_metric_config 与项目映射；记录 unit_map_version 与转换因子摘要（unit_factors_digest）到 run_context

## 7. 方法选择策略（阈值配置与回退）
- 阈值来源：metric_calculation_config.remark 或 calculation_method_selector.remark（JSON）
  - 优先读取设备/指标定制阈值；其次全局默认
- 回退：无候选→一次降阈值到 0.8 重评；仍无→跳过并记录原因（run_context）
- 记录：run_context 写入 method_id、阈值、候选数、过滤原因、排序因子

## 8. 物理计算器（公式族与保护）
- 典型公式（详见 docs/计算原理和公式.md）：
  - H = ΔP / (ρ g)
  - P_out = ρ g Q H，η = P_out / P_in
  - 其他派生见指标对照表
- 工况与常数：ρ、g、黏度/温度/海拔、VFD 相似定律缩放；若无环境数据，记录采用常数与假设
- 记录：run_context 写入常数取值、假设、越界点计数；若使用 VFD 缩放，记录转速/频率口径与缩放因子

- 缺失/异常边界：不做插值与跨断点连接；NaN 保持 NaN

## 9. 两层验证（质量窗口 + 物理/机理 + 曲线）
- 第一层（L1）：
  - L1a（质量窗口）：封装调用 sp_mark_quality_window；入库前仅对 required_inputs 校验；入库后对输出抽样/变化量校验
  - L1b（物理/机理）：validate_physical(series) 校验范围/单调/越界；越界点保持为 NaN 并统计
  - 冷静期与最短保持期：为避免频繁切换，激活/回滚需满足最短保持期（如≥3批/7天）与冷静期（如≥24h）；写入 remark 与 run_context

- 第二层（L2，特性曲线）：CurveValidator
  - 回退链：设备专属→机型/系列→厂家通用（记录 curve_fallback_level）
  - min_curve_score：不足则仅第一层验证、跳过第二层；默认阈值与计算口径：
    - score 由拟合残差/相对误差/时间稳定性综合得到；设最小样本量 N_min（如 ≥300 点）
    - 默认 min_curve_score 与 N_min 可写入 characteristic_curve_library.remark，并在 run_context 记录采用值
  - 记录：curve_id、min_curve_score、residual_stats、N_used 写入 run_context / calculation_result_validation

  - 数据源映射：model/series/vendor 的来源字段需在维表或配置中给出映射口径；若缺失映射，直接跳过 L2（仅第一层），并记录到 run_context

## 10. 写回与幂等
- 写回流程（推荐）：事务内 临时表批量导入 → 单条 MERGE/ON CONFLICT 语句进行批量 UPSERT → 删除临时表
  - 优点：减少逐行往返与锁竞争；便于统计失败与重试
- 事务与隔离级别：写回使用短事务，推荐 READ COMMITTED；单批失败回滚不影响其他批
- Chunk 亲和：尽量按 device×时间顺序写入，减少跨 chunk 冲突；必要时按 station 分桶并限制同站并发≤2

- UPSERT 目标：ON CONFLICT (station_id, device_id, metric_id, ts_bucket) DO UPDATE SET value, source, updated_at
- 批量与窗口：每批 ≤ 2000~5000 行；写回前对输入做质量窗口校验、写回后对输出做抽样/变化量校验（见 §9）
- 监控与报警：记录并上报成功率、吞吐、P50/P95 延迟、重试/死锁比、写回失败率、NaN 比例、L2 跳过率、降级事件；为关键指标配置报警阈值；关键统计写入 run_context 以便溯源
- 幂等：calculation_id = hash(device_id, metric_id, [start,end)_alignedUTC, method_signature, method_version, thresholds_hash, unit_map_version)
  - 命中幂等：若存在相同 calculation_id 的 run_context → 跳过或 compare-only 模式；compare-only 若差异>ε（可配置）则记录告警与原因，不直接覆盖
  - 记录：run_context 记录幂等命中/跳过原因、compare-only 差异统计（diff_rate、max_abs_diff 等）
- compare-only 策略：命中幂等后进入只比对模式，不写回；若 |new-old|/max(ε,value_range) > δ（默认 δ=1%）触发告警并记录，建议触发重算；阈值可按指标配置

- 重试与退避：冲突/死锁/锁等待按指数退避（100→200→400→800ms，上限 1s 加抖动±50ms），单批最多 3 次；段级最多 5 次，超过则降并发与批量
- 重算策略：当上游数据或 presence/mv 水位线发生变更时，对最近 N 天（可配置）触发重算；新 calculation_id 将包含输入版本哈希；RunContext 记录重算原因与影响范围
  - 触发源（枚举）：presence/mv 刷新水位线变化；数据修正/回补；单位映射或阈值配置变更；方法版本升级；物理常数口径变更；compare-only 异常告警
  - 规模上限：单次重算的最大设备数与总窗口时长可配置，避免资源暴冲；run_context 写入重算批次ID


## 11. 并发与切片
- 切片：5~15 分钟窗口按设备切片批处理
- 并发：设备并发 4~8、同站 ≤ 2；优化作业并发 ≤ 计算并发 1/2
- 公平与回压：按设备/站点令牌桶限速，跨站轮询提升公平性；当死锁/冲突/延迟报警触发时动态下调并发与批量（回压），事件记录 run_context
- 指标命名统一：成功率(success_rate)、吞吐(tps)、P95延迟(p95_latency_ms)、重试比(retry_rate)、死锁比(deadlock_rate)、NaN比例(nan_ratio)、L2跳过率(l2_skip_rate)、降级事件(degrade_events)

- 观测指标与报警：成功率、吞吐、P50/P95 延迟、重试/死锁比、写回失败率、NaN 比例、L2 跳过率、降级事件；为关键指标设置报警阈值并记录到 run_context 以便溯源。
- 观测：run_context 写实际并发/批量/重试次数/降级事件；用于SLA与离线调优

## 12. 自适应扩展（新增设备/指标）

### 12.1 新增指标操作清单
**完整流程（3个关键步骤）：**
1) **指标注册**：在 dim_metric_config 注册 metric_id/metric_key/unit/si_conversion
   - 确保 metric_key 唯一性，unit 字段符合项目单位规范
   - si_conversion 因子必须准确，用于单位归一化
   - 记录指标的物理含义和计算用途

2) **方法注册**：在 calculation_method_selector 注册可用方法
   - applicable_metrics 字段必须包含新指标的 metric_key
   - 设置 required_inputs（所需输入指标）、accuracy_level（精度等级）、priority（优先级）
   - remark(JSON) 中写入默认阈值策略与物理边界约束

3) **验证器配置**：在相关配置的 remark(JSON) 写入阈值策略与物理边界
   - Validators 增补该指标的物理约束（范围、单调性、符号等）
   - 设置质量窗口的阈值参数（coverage_threshold、required_inputs_presence_min等）
   - 配置特性曲线验证的相关参数（如适用）

### 12.2 新增设备操作清单
**完整流程（3个关键步骤）：**
1) **参数集准备**：在 rls_parameter_set 为 device_id 新建 set_id
   - 可空先占位，确保 device 级唯一激活约束（is_active=true 唯一）
   - 必要时在 rls_parameter_calibration 补充参数项
   - 若暂不标定则沿用通用参数/默认物理常数

2) **计算配置**：在 metric_calculation_config 为 device_id×目标指标建立行
   - calculation_enabled=true 开启计算
   - 设置 priority_level 与阈值策略
   - remark(JSON) 中配置设备专属的阈值参数（coverage_threshold等）

3) **特性曲线配置**：处理设备专属特性曲线
   - 若有设备专属曲线，写入 characteristic_curve_library 并设置 is_active=true
   - 若无专属曲线，则依赖回退链（机型/系列/厂家通用）
   - 确保曲线的 performance_score 满足 min_curve_score 要求

### 12.3 回退与跳过策略
**无方法回退**：
- 一次性降阈值到0.8复评：当无候选方法时，将 coverage_threshold 从默认值降至0.8重新评估
- 仍无则跳过该段：降阈值后仍无可用方法，跳过该时间段并写入 run_context
- 记录详细原因：在 run_context 中记录无方法的具体原因（输入不足、阈值过严等）

**无/低质曲线回退**：
- 仅执行第一层验证：当无可用曲线或 performance_score < min_curve_score 时
- 跳过第二层验证：不执行特性曲线验证，仅依赖物理/机理验证
- 记录跳过原因：在 run_context 中记录 L2 跳过的具体原因和曲线状态

**其他回退情况**：
- 缺失单位映射→拒绝计算并记录到 run_context
- 数据质量不足→跳过并记录质量问题详情
- 物理约束违反→标记为 NaN 并统计越界情况



## 13. RunContext 字段清单（最小必填）

### 13.1 核心必填字段
**方法与配置**：
- method_id：选择的计算方法标识符
- set_id：使用的参数集标识符（来自 rls_parameter_set）
- curve_id：使用的特性曲线标识符（如适用）
- min_curve_score：特性曲线的最小评分要求

**阈值与边界**：
- coverage_threshold：覆盖率阈值（如0.95）
- required_inputs_presence_min：输入指标存在率最小要求
- thresholds_hash：阈值配置的哈希值，用于幂等判断
- 物理边界：各指标的物理约束范围（从 remark(JSON) 读取）

**单位与常数**：
- unit_map_version：单位映射版本标识
- unit_factors_digest：单位换算因子摘要
- 物理常数口径：ρ（密度）、g（重力加速度）、温度、海拔、VFD口径等
- 假设说明：当环境数据缺失时采用的常数与假设

### 13.2 运维与监控字段
**批量与并发统计**：
- batch_size：实际批处理大小
- concurrency：实际并发数
- retries：重试次数统计
- 降级事件：自动降级的触发次数和原因

**mv刷新覆盖范围**：
- last_refreshed_ts：mv_device_running_1s 最后刷新时间
- covered：是否覆盖到目标时间窗口结束时间
- refresh_coverage_range：实际刷新覆盖的时间范围

**版本与来源**：
- version_tag：计算引擎版本标签
- source：数据来源标识（如 'calculation_engine_v2.1'）

### 13.3 时间与窗口字段
- tz：时区信息
- window_original：原始时间窗口
- window_aligned_utc：UTC对齐后的时间窗口

### 13.4 质量与验证字段
- method_version：方法版本号
- applicable_methods_count：候选方法总数
- filter_reasons：方法过滤原因分类
- curve_fallback_level：曲线回退级别（device/model/series/vendor）
- N_used：实际使用的样本数量

### 13.5 幂等与比对字段
- calculation_id：计算任务的唯一标识符
- compare_only：是否为仅比对模式
- diff_rate：差异率统计
- max_abs_diff：最大绝对差异

### 13.6 错误与异常字段
- nan_ratio：NaN值比例
- nan_distribution_digest：NaN分布摘要
- 错误码枚举（文档级建议）：
  - E.PARAM（参数/口径错误）
  - E.DB.NET（数据库连接/网络异常）
  - E.DB.DEADLOCK（死锁）
  - E.DB.CONFLICT（写入冲突/唯一冲突）
  - E.DB.TIMEOUT（锁等待/超时）
  - E.PIPE.RETRY_EXCEEDED（重试超限）
  - E.VAL.FAIL（验证失败）

## 14. 错误分类与处理
- 重试上限与退避：DataAccessError/Conflict/Deadlock/LockWait 单批≤3、段级≤5；退避 100→200→400→800ms（上限 1s，抖动±50ms），超过进入降级/失败

- 参数/口径错误（ValueError）：立即失败并记录 run_context
- 数据访问错误（DataAccessError）：有限重试；失败记录并跳过当前段
- 监控与报警：对成功率/延迟/重试/死锁/写回失败/NaN 比例/L2 跳过率/降级事件设置报警阈值（建议默认：成功率<99%、P95>2s、死锁>0.5% 等），并在 run_context 打点便于溯源

- 资源/锁竞争（Conflict/Deadlock/LockWait）：指数退避与降级策略
- 验证失败（ValidationFail）：不写回，并记录 calculation_result_validation 详情

## 15. 验收标准与测试计划
- 单元测试：
  - 选择器：阈值读取/降阈/排序稳定性；remark(JSON) 解析与 thresholds_hash 一致性
  - 计算器：单位归一（unit_map_version 与 unit_factors_digest）、越界/NaN 保护、VFD 缩放记录
  - 曲线验证：回退链顺序与缺省处理、min_curve_score 门槛/样本量 N_min、生效与跳过
  - 幂等：calculation_id 组成（包含 method_version/thresholds_hash/unit_map_version）与 compare-only 差异阈值
- 小型集成测试：
  - 数据：2 台设备×2 指标，含停机与缺失；一台无曲线、一台低质曲线
  - 流程：识别→选法→计算→L1（输入）→写回→L1（输出抽样）→L2（有/无/低质）→run_context
  - 断言：
    - L2 在无曲线或低 score 时被跳过且 run_context 记录清晰
