## 📖 文档说明

本文档定义项目的质量标准，涵盖代码质量、测试、文档、审查、性能等方面。所有开发人员必须严格遵守本标准。

**标准级别**：
- `[强制]`：必须遵守，违反将导致代码审查不通过

- `[参考]`：可选遵守，作为最佳实践参考

## 1. 代码质量标准

### 1.1 文件大小 [强制]

- **单文件行数**：不超过 **600行**（不包含注释和空行）
- **超过限制**：必须拆分为多个文件
- **检查方法**：
  ```bash
  # 统计代码行数（不含注释和空行）
  find app -name "*.py" -exec grep -v '^\s*#' {} \; -exec grep -v '^\s*$' {} \; | wc -l
  ```

### 1.2 函数复杂度 [强制]

- **圈复杂度**：单个函数不超过 **10**（建议 ≤ 6）
- **函数长度**：不超过 **50行**（不含注释和空行）
- **参数数量**：不超过 **5个**（超过则使用对象封装）
- **嵌套深度**：不超过 **4层**

**检查工具**：
```bash
# 使用 radon 检查圈复杂度
pip install radon
radon cc app/ -a -nb

# 使用 pylint 检查
pylint app/ --disable=all --enable=too-many-arguments,too-many-locals
```

**示例**：
```python
# ❌ 圈复杂度过高（>10）
def process_data(data):
    if condition1:
        if condition2:
            if condition3:
                if condition4:
                    if condition5:
                        # 嵌套过深
                        pass

# ✅ 降低圈复杂度
def process_data(data):
    if not _validate_data(data):
        return None

    result = _transform_data(data)
    return _save_data(result)

def _validate_data(data):
    return condition1 and condition2

def _transform_data(data):
    # 转换逻辑
    pass

def _save_data(data):
    # 保存逻辑
    pass
```

### 1.3 类大小 [推荐]

- **类长度**：不超过 **500行**（不含注释和空行）
- **方法数量**：不超过 **20个公共方法**
- **职责单一**：一个类只负责一个领域

### 1.4 重复代码 [强制]

- **重复次数**：相同代码块不超过 **3处**
- **处理方式**：必须提取为公共函数/类
- **检查工具**：
  ```bash
  # 使用 pylint 检查重复代码
  pylint app/ --disable=all --enable=duplicate-code

  # 使用 ruff 检查
  ruff check app/ --select=R0801
  ```

### 1.5 代码覆盖率 [强制]

- **单元测试覆盖率**：≥ **80%**
- **集成测试覆盖率**：≥ **60%**
- **关键路径覆盖率**：≥ **90%**

**检查方法**：
```bash
# 使用 pytest-cov
pytest --cov=app --cov-report=html --cov-report=term

# 查看覆盖率报告
open htmlcov/index.html
```

### 1.6 类型注解 [强制]

- **公共API**：必须有完整的类型注解
- **内部函数**：可推断的类型可省略
- **关键模块**：启用 mypy strict 模式

**示例**：
```python
# ✅ 完整的类型注解
from typing import List, Optional, Dict, Any

async def import_data(
    file_path: str,
    station_id: int,
    options: Optional[Dict[str, Any]] = None
) -> ImportResult:
    """导入数据"""
    pass

# ❌ 缺少类型注解
async def import_data(file_path, station_id, options=None):
    pass
```

## 2. 测试标准

### 2.1 单元测试 [强制]

**必须测试**：
- 所有公共函数/方法
- 所有业务逻辑
- 所有边界条件

**测试命名**：
```python
def test_函数名_场景_期望结果():
    pass

# 示例
def test_import_data_valid_csv_success():
    """测试导入有效CSV文件成功"""
    pass

def test_import_data_invalid_format_raises_error():
    """测试导入无效格式文件抛出异常"""
    pass

def test_import_data_empty_file_returns_zero():
    """测试导入空文件返回0条记录"""
    pass
```

**必须覆盖的场景**：
1. **正常流程**：输入有效数据，验证输出正确
2. **边界条件**：空值、最大值、最小值、边界值
3. **异常情况**：无效输入、网络错误、数据库错误

**使用Mock隔离依赖**：
```python
from unittest.mock import Mock, patch

@patch('app.adapters.db.gateway.get_conn')
async def test_import_data_db_error(mock_get_conn):
    """测试数据库错误处理"""
    mock_get_conn.side_effect = DatabaseError("连接失败")

    with pytest.raises(DatabaseError):
        await import_data("test.csv", 1001)
```

**必须测试**：
- 关键业务流程（端到端）
- 数据库操作（使用测试数据库）
- 外部API调用（使用Mock或测试环境）

## 3. 文档标准

### 3.1 代码文档 [强制]

**所有公共API必须有docstring**：
```python
def import_data(file_path: str, station_id: int) -> ImportResult:
    """
    从CSV文件导入测量数据

    读取指定的CSV文件，验证数据格式，然后批量导入到数据库。

    Args:
        file_path: CSV文件的完整路径
        station_id: 泵站ID，用于关联导入的数据

    Returns:
        ImportResult: 导入结果对象，包含：
            - success_count: 成功导入的数据条数
            - failed_count: 失败的数据条数
            - error_messages: 错误消息列表

    Raises:
        FileNotFoundError: 当文件不存在时
        InvalidDataFormatError: 当数据格式不符合要求时
        DatabaseError: 当数据库操作失败时

    Example:
        >>> result = await import_data("/data/measurements.csv", 1001)
        >>> print(f"导入成功: {result.success_count} 条")

    Note:
        - 大文件导入可能耗时较长，建议使用异步调用
        - 导入过程中会自动创建事务，失败时会回滚
    """
    pass
```

**docstring格式**：使用 **Google风格**

**必须包含**：
- 功能描述
- 参数说明（Args）
- 返回值说明（Returns）
- 异常说明（Raises）
- 使用示例（Example）
- 注意事项（Note）

## 4. 代码审查标准

### 4.1 审查清单 [强制]

在代码审查时，必须检查以下项目：

**编码规范**：
- [ ] 是否符合编码规范（命名、格式、注释）？
- [ ] 是否遵循六大设计原则（SOLID + LoD）？
- [ ] 文件行数是否超过600行？
- [ ] 函数长度是否超过50行？
- [ ] 圈复杂度是否超过10？

**功能正确性**：
- [ ] 是否实现了需求的所有功能？
- [ ] 是否处理了所有边界条件？
- [ ] 是否有完整的错误处理？

**测试覆盖**：
- [ ] 是否有单元测试？
- [ ] 测试覆盖率是否达标（≥80%）？
- [ ] 是否测试了边界条件和异常情况？

**性能考虑**：
- [ ] 是否有性能问题（N+1查询、大循环等）？
- [ ] 是否有内存泄漏风险？
- [ ] 数据库查询是否优化？

**安全性**：
- [ ] 是否有SQL注入风险？
- [ ] 是否在日志中输出了敏感信息？
- [ ] 是否验证了用户输入？

**文档完整性**：
- [ ] 是否有完整的docstring？
- [ ] 是否更新了相关文档？
- [ ] 是否更新了API文档？

### 4.2 审查流程 [强制]

- **所有代码必须经过至少1人审查**
- **关键代码必须经过2人审查**
- **审查意见必须全部解决才能合并**

### 4.3 审查工具 [推荐]

```bash
# 静态代码检查
pylint app/
ruff check app/
mypy app/

# 代码格式检查
black --check app/
isort --check app/

# 安全检查
bandit -r app/

# 复杂度检查
radon cc app/ -a -nb
```

## 5. 性能标准

### 5.1 响应时间 [强制]

| 类型 | P95 | P99 | 说明 |
|------|-----|-----|------|
| API接口 | < 1秒 | < 3秒 | 普通查询接口 |
| 数据库查询 | < 2秒 | < 5秒 | 单次查询 |
| 页面加载 | < 2秒 | < 4秒 | 首屏加载 |
| 批量操作 | < 10秒 | < 30秒 | 批量导入/导出 |

**测量方法**：
```python
import time
from app.core.logging.setup import log_activity

async def api_endpoint():
    with log_activity("API调用", params={"endpoint": "/api/data"}):
        # 自动记录耗时
        result = await process_request()
        return result
```

### 5.2 资源使用 [推荐]

- **CPU使用率**：< 70%（平均）
- **内存使用率**：< 80%（平均）
- **数据库连接数**：< 最大连接数的60%
- **磁盘IO**：< 80%（峰值）

**监控方法**：
```python
import psutil

def check_resource_usage():
    cpu_percent = psutil.cpu_percent(interval=1)
    memory_percent = psutil.virtual_memory().percent

    if cpu_percent > 70:
        logger.warning(f"CPU使用率过高: {cpu_percent}%")

    if memory_percent > 80:
        logger.warning(f"内存使用率过高: {memory_percent}%")
```

### 5.3 并发能力 [推荐]

- **支持并发用户数**：≥ 100
- **无明显性能衰减**：并发增加时响应时间增长 < 20%

**压力测试**：
