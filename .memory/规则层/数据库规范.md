## 📖 文档说明

## 第一部分：通用数据库规范

### 1. 连接管理规范

#### 1.1 连接池使用 [强制]

- **必须使用连接池**：禁止直接创建数据库连接
- **连接复用**：使用完毕后必须归还连接池
- **超时设置**：所有连接操作必须设置超时
- **连接验证**：从连接池获取连接后必须验证连接有效性

**示例**：
```python
# ✅ 正确：使用连接池
from app.adapters.db import get_connection

with get_connection() as conn:
    # 使用连接
    pass
# 连接自动归还

# ❌ 错误：直接创建连接
import psycopg
conn = psycopg.connect("postgresql://...")  # 禁止
```

#### 1.2 连接生命周期 [强制]

- **短连接原则**：尽快释放连接，避免长时间占用
- **事务边界**：事务应尽可能短，避免长事务
- **连接泄漏检测**：必须使用上下文管理器（with语句）

#### 1.3 连接配置 [强制]

- **配置集中管理**：所有连接配置必须在 `configs/database.yaml` 中
- **禁止硬编码**：禁止在代码中硬编码连接信息
- **禁止环境变量覆盖**：禁止使用环境变量覆盖数据库配置

### 2. 查询优化规范

#### 2.1 SQL编写规范 [强制]

- **禁止字符串拼接SQL**：必须使用参数化查询
- **防止SQL注入**：所有用户输入必须使用占位符
- **查询超时**：所有查询必须设置超时时间

**示例**：
```python
# ✅ 正确：参数化查询
sql = "SELECT * FROM fact_measurements WHERE device_id = %s AND ts_bucket >= %s"
cur.execute(sql, (device_id, start_time))

# ❌ 错误：字符串拼接
sql = f"SELECT * FROM fact_measurements WHERE device_id = {device_id}"  # 禁止
```

#### 2.2 查询性能优化 [推荐]

- **时间范围过滤**：时序数据查询必须包含时间范围
- **索引覆盖**：查询字段应尽量被索引覆盖
- **避免SELECT ***：明确指定需要的列
- **分页查询**：大结果集必须分页

**示例**：
```python
# ✅ 正确：包含时间范围和分页
sql = """
    SELECT station_id, device_id, ts_bucket, value
    FROM fact_measurements
    WHERE device_id = %s
      AND ts_bucket >= %s AND ts_bucket < %s
    ORDER BY ts_bucket
    LIMIT %s OFFSET %s
"""

# ❌ 错误：无时间范围，无分页
sql = "SELECT * FROM fact_measurements WHERE device_id = %s"  # 可能扫描全表
```

#### 2.3 JOIN优化 [推荐]

- **小表驱动大表**：JOIN时小表在前
- **索引JOIN列**：JOIN的列必须有索引
- **避免笛卡尔积**：必须有JOIN条件

### 3. 事务处理规范

#### 3.1 事务边界 [强制]

- **明确事务边界**：使用事务上下文管理器
- **事务尽可能短**：减少锁持有时间
- **异常回滚**：异常时必须回滚事务

**示例**：
```python
# ✅ 正确：使用事务上下文管理器
from app.adapters.db.transaction import transaction

with get_connection() as conn:
    with transaction(conn) as tx_conn:
        # 数据库操作
        cur.execute("INSERT ...")
        cur.execute("UPDATE ...")
        # 自动提交或回滚
```

#### 3.2 事务隔离级别 [推荐]

- **默认隔离级别**：READ COMMITTED
- **特殊场景**：需要更高隔离级别时必须说明理由
- **避免死锁**：按固定顺序访问资源

#### 3.3 嵌套事务 [推荐]

- **使用SAVEPOINT**：嵌套事务使用保存点
- **部分回滚**：支持回滚到保存点

### 4. 索引设计规范

#### 4.1 索引创建原则 [推荐]

- **高选择性列**：为高选择性列创建索引
- **复合索引顺序**：等值查询列在前，范围查询列在后
- **覆盖索引**：常用查询考虑使用INCLUDE子句

**示例**：
```sql
-- ✅ 正确：复合索引，等值在前，范围在后
CREATE INDEX idx_measurements ON fact_measurements (station_id, device_id, metric_id, ts_bucket);

-- ✅ 正确：覆盖索引
CREATE INDEX idx_measurements_covering ON fact_measurements (station_id, device_id, ts_bucket) INCLUDE (value);
```

#### 4.2 索引维护 [推荐]

- **定期分析**：定期执行ANALYZE更新统计信息
- **索引重建**：膨胀严重时重建索引
- **监控索引使用**：定期检查未使用的索引

### 5. Schema设计规范

#### 5.1 表设计原则 [推荐]

- **规范化设计**：避免数据冗余
- **主键设计**：每个表必须有主键
- **外键约束**：维护数据完整性
- **字段类型**：选择合适的数据类型

#### 5.2 表命名规范 [强制]

**基本规则**：
- **格式**：小写字母 + 下划线（snake_case）
- **语言**：使用英文单词
- **复数形式**：表名使用复数（如 `measurements`、`devices`）

**前缀规范**：
- `fact_`：事实表（如 `fact_measurements`）
- `dim_`：维度表（如 `dim_stations`、`dim_devices`）
- `staging_`：暂存表（如 `staging_raw`、`staging_rejects`）
- `mv_`：物化视图（如 `mv_measurements_hourly`）
- `v_`：普通视图（如 `v_training_timeseries_1s`）

**示例**：
```sql
-- ✅ 正确：事实表
CREATE TABLE fact_measurements (...);

-- ✅ 正确：维度表
CREATE TABLE dim_stations (...);
CREATE TABLE dim_devices (...);

-- ✅ 正确：暂存表
CREATE TABLE staging_raw (...);

-- ❌ 错误：大写字母
CREATE TABLE FactMeasurements (...);  -- 禁止

-- ❌ 错误：单数形式
CREATE TABLE fact_measurement (...);  -- 应使用复数
```

#### 5.3 字段命名规范 [强制]

**基本规则**：
- **格式**：小写字母 + 下划线（snake_case）
- **语言**：使用英文单词
- **语义化**：字段名应清晰表达含义

**常用后缀**：
- `_id`：ID字段（如 `station_id`、`device_id`、`metric_id`）
- `_at`：时间字段（如 `created_at`、`updated_at`、`inserted_at`）
- `_ts`：时间戳字段（如 `start_ts`、`end_ts`）
- `_utc`：UTC时间（如 `ts_utc`）
- `_raw`：原始数据（如 `ts_raw`）
- `_bucket`：时间桶（如 `ts_bucket`）
- `_count`：计数字段（如 `success_count`、`failed_count`）
- `_ms`：毫秒（如 `duration_ms`、`timeout_ms`）
- `_sec`：秒（如 `max_gap_sec`）

**外键命名**：
- 外键字段名应与引用表的主键名一致
- 格式：`引用表名_id`（如 `station_id` 引用 `dim_stations.id`）

**布尔字段**：
- 使用 `is_`、`has_`、`enable_` 前缀（如 `is_running`、`has_error`、`enable_i`）

**示例**：
```sql
-- ✅ 正确：清晰的字段命名
CREATE TABLE fact_measurements (
    id BIGSERIAL PRIMARY KEY,
    station_id BIGINT NOT NULL,           -- 外键，引用 dim_stations.id
    device_id BIGINT NOT NULL,            -- 外键，引用 dim_devices.id
    metric_id BIGINT NOT NULL,            -- 外键，引用 dim_metric_config.id
    ts_raw TIMESTAMPTZ NOT NULL,          -- 原始时间戳
    ts_bucket TIMESTAMPTZ NOT NULL,       -- 对齐时间戳
    value NUMERIC NOT NULL,               -- 测量值
    source_hint TEXT,                     -- 来源提示
    inserted_at TIMESTAMPTZ DEFAULT NOW() -- 插入时间
);

-- ❌ 错误：大写字母
CREATE TABLE measurements (
    StationID BIGINT  -- 禁止
);

-- ❌ 错误：不清晰的命名
CREATE TABLE measurements (
    s_id BIGINT,  -- 应使用 station_id
    val NUMERIC   -- 应使用 value
);
```

#### 5.4 索引命名规范 [强制]

**基本规则**：
- **格式**：`idx_表名_列名1_列名2`
- **唯一索引**：`uq_表名_列名`
- **主键**：`pk_表名`（通常自动生成）

**示例**：
```sql
-- ✅ 正确：复合索引
CREATE INDEX idx_measurements_station_device_metric_ts
ON fact_measurements (station_id, device_id, metric_id, ts_bucket);

-- ✅ 正确：覆盖索引
CREATE INDEX idx_measurements_device_ts_covering
ON fact_measurements (device_id, ts_bucket) INCLUDE (value);

-- ✅ 正确：唯一索引
CREATE UNIQUE INDEX uq_measurements_station_device_metric_ts
ON fact_measurements (station_id, device_id, metric_id, ts_bucket);

-- ❌ 错误：不清晰的命名
CREATE INDEX idx1 ON fact_measurements (device_id);  -- 禁止
```

#### 5.5 约束命名规范 [推荐]

**基本规则**：
- **主键**：`pk_表名`
- **外键**：`fk_表名_引用表名`
- **检查约束**：`chk_表名_约束描述`
- **唯一约束**：`uq_表名_列名`

**示例**：
```sql
-- ✅ 正确：外键约束
ALTER TABLE fact_measurements
ADD CONSTRAINT fk_measurements_stations
FOREIGN KEY (station_id) REFERENCES dim_stations(id);

-- ✅ 正确：检查约束
ALTER TABLE fact_measurements
ADD CONSTRAINT chk_measurements_value_positive
CHECK (value >= 0);

-- ✅ 正确：唯一约束
ALTER TABLE dim_stations
ADD CONSTRAINT uq_stations_name
UNIQUE (name);
```

#### 5.6 函数命名规范 [强制]

**基本规则**：
- **格式**：小写字母 + 下划线（snake_case）
- **前缀**：`fn_`（函数）、`sp_`（存储过程）
- **语义化**：函数名应清晰表达功能

**参数命名**：
- **前缀**：`p_`（如 `p_device_id`、`p_start_ts`）
- **格式**：小写字母 + 下划线

**示例**：
```sql
-- ✅ 正确：函数命名
CREATE OR REPLACE FUNCTION fn_training_timeseries_1s(
    p_station_id BIGINT,
    p_device_id BIGINT,
    p_metric_id BIGINT,
    p_start_ts TIMESTAMPTZ,
    p_end_ts TIMESTAMPTZ
) RETURNS TABLE(...) AS $$
...
$$ LANGUAGE sql;

-- ✅ 正确：存储过程命名
CREATE OR REPLACE FUNCTION sp_mark_quality_window(
    p_device_id BIGINT,
    p_start_ts TIMESTAMPTZ,
    p_end_ts TIMESTAMPTZ
) RETURNS VOID AS $$
...
$$ LANGUAGE plpgsql;

-- ❌ 错误：大写字母
CREATE FUNCTION GetTrainingData(...) ...  -- 禁止

-- ❌ 错误：无前缀
CREATE FUNCTION training_timeseries(...) ...  -- 应使用 fn_ 前缀
```

### 6. 注释与备注规范

#### 6.1 表注释规范 [强制]

**基本要求**：
- **所有表必须有注释**
- **注释语言**：必须使用中文
- **注释内容**：简要说明表的用途

**格式**：
```sql
COMMENT ON TABLE schema_name.table_name IS '表的用途说明';
```

**示例**：
```sql
-- ✅ 正确：简洁的表注释
COMMENT ON TABLE public.fact_measurements IS '时序事实（秒对齐）';
COMMENT ON TABLE public.dim_stations IS '泵站维表';
COMMENT ON TABLE public.dim_devices IS '设备维表';
COMMENT ON TABLE public.dim_metric_config IS '指标配置';

-- ✅ 正确：详细的表注释
COMMENT ON TABLE public.device_running_thresholds IS
'设备秒级运行判断的集中阈值配置表。用于统一管理每台设备启用的信号、开关滞回阈值、缺报延续与防抖参数。';

-- ❌ 错误：英文注释
COMMENT ON TABLE fact_measurements IS 'Measurement fact table';  -- 必须使用中文
```

#### 6.2 列注释规范 [强制]

**基本要求**：
- **关键列必须有注释**（主键、外键、业务字段）
- **注释语言**：必须使用中文
- **注释内容**：说明字段的含义、单位、取值范围

**格式**：
```sql
COMMENT ON COLUMN schema_name.table_name.column_name IS '字段说明';
```

**示例**：
```sql
-- ✅ 正确：清晰的列注释
COMMENT ON COLUMN public.fact_measurements.station_id IS '泵站ID（外键）';
COMMENT ON COLUMN public.fact_measurements.device_id IS '设备ID（外键）';
COMMENT ON COLUMN public.fact_measurements.metric_id IS '指标ID（外键）';
COMMENT ON COLUMN public.fact_measurements.ts_raw IS '原始时间戳（timestamptz，建议UTC）';
COMMENT ON COLUMN public.fact_measurements.ts_bucket IS '对齐后的时间（整秒）';
COMMENT ON COLUMN public.fact_measurements.value IS '测量数值';
COMMENT ON COLUMN public.fact_measurements.source_hint IS '数据来源线索（如文件路径/批次/版本）';
COMMENT ON COLUMN public.fact_measurements.inserted_at IS '插入时间（timestamptz）';

-- ✅ 正确：包含单位和范围的注释
COMMENT ON COLUMN public.device_running_thresholds.i_on_thr IS '电流开启阈值（A，大于此值判定为运行）';
COMMENT ON COLUMN public.device_running_thresholds.i_off_thr IS '电流关闭阈值（A，小于此值判定为停机）';
COMMENT ON COLUMN public.device_running_thresholds.missing_continue_sec IS '缺报延续时间（秒，缺报时保持上一状态的最大时长）';

-- ❌ 错误：英文注释
COMMENT ON COLUMN fact_measurements.value IS 'Measurement value';  -- 必须使用中文

-- ❌ 错误：不清晰的注释
COMMENT ON COLUMN fact_measurements.value IS '值';  -- 应说明是什么值
```

#### 6.3 视图注释规范 [强制]

**基本要求**：
- **所有视图必须有注释**
- **注释内容**：包含用途、字段说明、使用示例
- **使用 $DOC$ 标记**：多行注释使用 $DOC$ 包裹

**格式**：
```sql
COMMENT ON VIEW schema_name.view_name IS $DOC$
用途: 视图的用途说明
字段: 字段列表和说明
示例:
-- SQL示例
SELECT ...
$DOC$;
```

**示例**：
```sql
-- ✅ 正确：完整的视图注释
COMMENT ON VIEW public.v_training_timeseries_1s IS $DOC$
用途: 统一 1s 读取口径（训练/分析）。
字段: ts_bucket, station_id, station_name, device_id, device_name, metric_id, metric_key, unit_display, value。
示例:
-- 单设备单指标 1 小时明细
SELECT ts_bucket, value
FROM public.v_training_timeseries_1s
WHERE station_id=1 AND device_id=1 AND metric_id=101
  AND ts_bucket BETWEEN '2025-09-01 00:00+00' AND '2025-09-01 01:00+00'
ORDER BY ts_bucket
LIMIT 1000;
-- 按小时聚合
SELECT date_trunc('hour', ts_bucket) AS ts_hour, avg(value) AS avg_v
FROM public.v_training_timeseries_1s
WHERE station_id=1 AND device_id=1 AND metric_id=101
  AND ts_bucket >= now() - interval '24 hours'
GROUP BY 1 ORDER BY 1;
$DOC$;
```

#### 6.4 函数注释规范 [强制]

**基本要求**：
- **所有函数必须有注释**
- **注释内容**：包含用途、参数说明、返回值说明、使用示例
- **使用 $DOC$ 标记**：多行注释使用 $DOC$ 包裹

**格式**：
```sql
COMMENT ON FUNCTION schema_name.function_name(参数类型列表) IS $DOC$
用途: 函数的用途说明
参数: 参数列表和说明
返回: 返回值说明
示例:
-- SQL示例
SELECT ...
$DOC$;
```

**示例**：
```sql
-- ✅ 正确：完整的函数注释
COMMENT ON FUNCTION public.fn_training_timeseries_1s(bigint,bigint,bigint,timestamptz,timestamptz) IS $DOC$
用途: 统一 1s 训练口径（长表返回）。
参数: p_station_id, p_device_id, p_metric_id, p_start_ts, p_end_ts。
返回: ts_bucket, value, station_id, device_id, metric_id。
示例:
SELECT ts_bucket, value
FROM public.fn_training_timeseries_1s(1,1,101, now()-interval '10 minutes', now());
$DOC$;

-- ✅ 正确：详细的函数注释
COMMENT ON FUNCTION public.fn_running_state_1s(bigint,bigint,timestamptz,timestamptz) IS $DOC$
用途: 逐秒运行判定（按 device_running_thresholds 阈值，on/off 滞回 + 缺报延续）。
参数:
  - p_station_id: 泵站ID
  - p_device_id: 设备ID
  - p_start_ts: 开始时间（UTC）
  - p_end_ts: 结束时间（UTC）
返回: ts_bucket, is_running, max_i, p, f, source。
示例:
SELECT * FROM public.fn_running_state_1s(1,1,'2025-09-01 00:00+00','2025-09-01 02:00+00')
ORDER BY ts_bucket;
$DOC$;
```

#### 6.5 注释维护规范 [强制]

**基本要求**：
- **创建对象时必须添加注释**
- **修改对象时必须同步更新注释**
- **删除对象时注释自动删除**

**注释更新流程**：
1. 修改表结构 → 更新表注释和列注释
2. 修改函数签名 → 更新函数注释
3. 修改视图定义 → 更新视图注释

**示例**：
```sql
-- 修改表结构后更新注释
ALTER TABLE fact_measurements ADD COLUMN quality_codes SMALLINT[];
COMMENT ON COLUMN fact_measurements.quality_codes IS '质量码数组（多个质量问题）';

-- 修改函数后更新注释
CREATE OR REPLACE FUNCTION fn_training_timeseries_1s(...) ...
COMMENT ON FUNCTION fn_training_timeseries_1s(...) IS $DOC$
用途: [更新后的用途说明]
...
$DOC$;
```

### 7. 安全规范

#### 7.1 权限管理 [强制]

- **最小权限原则**：应用账号只授予必要权限
- **禁止超级用户**：应用禁止使用超级用户连接
- **密码管理**：密码必须加密存储

#### 7.2 数据安全 [强制]

- **敏感数据加密**：敏感字段必须加密
- **审计日志**：关键操作必须记录审计日志
- **数据脱敏**：日志中禁止输出敏感信息

### 8. 连接池配置（项目实现）

#### 8.1 连接池参数 [强制]

项目使用 **psycopg3 连接池**，配置在 `configs/database.yaml`：

```yaml
pool:
  min_size: 1          # 最小连接数
  max_size: 10         # 最大连接数
  max_inactive_connection_lifetime: 3600  # 非活跃连接生存时间（秒）

timeouts:
  connect_timeout_ms: 5000      # 连接超时
  statement_timeout_ms: 30000   # 语句超时
  query_timeout_ms: 60000       # 查询超时
  connection_acquire_timeout_ms: 10000   # 获取连接超时
  connection_validation_timeout_ms: 1000 # 连接验证超时
  pool_shutdown_timeout_ms: 30000        # 连接池关闭超时

retry:
  max_retries: 3               # 最大重试次数
  retry_delay_ms: 1000         # 重试延迟
  backoff_multiplier: 2.0      # 退避倍数
```

#### 8.2 连接池使用 [强制]

**获取连接**：
```python
from app.adapters.db import get_connection

# 使用默认超时
with get_connection() as conn:
    # 使用连接
    pass

# 使用自定义超时
with get_connection(timeout=5.0) as conn:
    # 使用连接
    pass
```

**连接池初始化**：

from app.adapters.db import init_database

### 9. Schema分层架构（项目实现）

项目使用 **多Schema分层架构**，不同Schema承担不同职责：

#### 9.1 Schema职责划分 [强制]

| Schema | 职责 | 对象类型 | 使用场景 |
|--------|------|---------|---------|
| **api** | 数据操作接口 | 存储过程 | 所有CRUD操作 |
| **reporting** | 报表查询 | 物化视图、查询函数 | 聚合查询、报表生成 |
| **monitoring** | 性能监控 | 监控表、监控视图 | 性能分析、监控 |
| **public** | 核心数据 | 事实表、维度表 | 数据存储 |

#### 9.2 Schema使用规范 [强制]

**数据写入**：
- 必须通过 `api` schema 的存储过程
- 禁止在应用代码中直接写SQL的INSERT/UPDATE/DELETE

```python
# ✅ 正确：调用存储过程
sql = "SELECT api.upsert_measurement(%s, %s, %s, %s)"
cur.execute(sql, (device_id, metric_id, ts_utc, value))

# ❌ 错误：直接写SQL
sql = "INSERT INTO fact_measurements ..."  # 禁止
```

**数据查询**：
- 聚合查询优先使用 `reporting` schema 的物化视图或函数
- 明细查询可直接查询 `public` schema 的表

```python
# ✅ 正确：使用reporting函数
sql = "SELECT * FROM reporting.get_metrics_hourly(%s, %s, %s, %s, %s)"

# ✅ 正确：查询物化视图
sql = "SELECT * FROM reporting.mv_measurements_hourly WHERE ..."
```

### 10. TimescaleDB Hypertable使用（项目实现）

项目使用 **TimescaleDB** 管理时序数据，核心表为 Hypertable。

#### 10.1 Hypertable配置 [强制]

**fact_measurements表**：
- **表类型**：TimescaleDB Hypertable
- **时间分区列**：`ts_bucket`（秒级时间戳）
- **空间分区列**：`device_id`（设备ID）
- **分区数量**：8个空间分区
- **Chunk时间间隔**：1天

**创建Hypertable**：
```sql
SELECT create_hypertable(
    relation => 'public.fact_measurements',
    time_column_name => 'ts_bucket',
    partitioning_column => 'device_id',
    number_partitions => 8,
    chunk_time_interval => INTERVAL '1 day',
    if_not_exists => true
);
```

#### 10.2 时序数据查询优化 [强制]

- **必须包含时间范围**：所有查询必须过滤时间范围
- **利用分区裁剪**：查询条件应包含分区键
- **避免跨分区JOIN**：尽量在同一分区内查询

```python
# ✅ 正确：包含时间范围和设备ID
sql = """
    SELECT * FROM fact_measurements
    WHERE device_id = %s
      AND ts_bucket >= %s AND ts_bucket < %s
"""

# ❌ 错误：无时间范围
sql = "SELECT * FROM fact_measurements WHERE device_id = %s"  # 扫描所有分区
```

### 13. 数据库日志规范（项目实现）

#### 13.1 SQL日志记录 [强制]

项目使用 `log_sql` 记录所有SQL执行：

```python
from app.core.logging.setup import log_sql
import time

start_time = time.time()
try:
    cur.execute(sql, params)
    rows = cur.fetchall()
    duration_ms = int((time.time() - start_time) * 1000)
    log_sql(sql, params=params, duration_ms=duration_ms, rows=len(rows))
except Exception as e:
    duration_ms = int((time.time() - start_time) * 1000)
    log_sql(sql, params=params, duration_ms=duration_ms, error=str(e))
    raise
```

#### 13.2 数据库函数日志 [强制]

调用数据库函数时使用 `log_db_function`：

```python
from app.core.logging.setup import log_db_function

log_db_function(
    name="api.upsert_measurement",
    args={"device_id": device_id, "metric_id": metric_id},
    duration_ms=duration_ms,
    rows=1
)
```
