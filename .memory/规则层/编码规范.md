## 0. 文件大小限制 [强制]

### 0.1 单文件行数限制

**强制规则**：
- 单个文件代码行数不能超过 **600行**（不包含注释和空行）
- 超过600行必须拆分为多个文件

**拆分原则**：
- 按职责拆分：将不同职责的代码拆分到不同文件
- 按层次拆分：将不同抽象层次的代码分离
- 按功能模块拆分：将相关功能组织到独立模块

**示例**：
```python
# ❌ 不良示例：单文件800行
# app/services/data_processor.py (800行)
class DataProcessor:
    # 包含导入、验证、转换、存储等所有逻辑

# ✅ 良好示例：拆分为多个文件
# app/services/data_import/
#   __init__.py
#   importer.py (200行) - 导入逻辑
#   validator.py (150行) - 验证逻辑
#   transformer.py (180行) - 转换逻辑
#   storage.py (120行) - 存储逻辑
```

**检查方法**：
```bash
# 查找超过600行的文件
find app -name "*.py" -exec wc -l {} \; | awk '$1 > 600 {print $0}'
```

## 1. 面向对象设计六大原则 [强制]

本项目严格遵循**SOLID + LoD（迪米特法则）**六大面向对象设计原则，作为评审/实现的强约束与落地清单。

### 1.1 单一职责原则（SRP - Single Responsibility Principle）

**定义**：一个模块/类/函数仅有一个引起其变化的原因（职责单一、聚焦领域）

**要点**：
- 文件/类过大、函数>200行、混合IO/业务/汇总逻辑 → 必拆分
- 入口层不写业务；跨层交互经网关（adapters）
- 公共API以"动词+对象"表达单一动作

**本项目落地**：
- 目录分层：`app/{adapters, services, core, cli}`
- Docstring明确职责/依赖/示例
- 公开API全量类型标注

**示例**：
```python
# ❌ 违反SRP：一个类做太多事
class DataHandler:
    def read_csv(self): pass
    def validate_data(self): pass
    def transform_data(self): pass
    def save_to_db(self): pass
    def send_notification(self): pass

# ✅ 遵循SRP：职责分离
class CSVReader:
    def read(self): pass

class DataValidator:
    def validate(self): pass

class DataTransformer:
    def transform(self): pass

class DataRepository:
    def save(self): pass

class NotificationService:
    def send(self): pass
```

### 1.2 开闭原则（OCP - Open-Closed Principle）

**定义**：对扩展开放，对修改封闭；新增能力优先"加实现/配置"，而非"改老代码"

**要点**：
- 以抽象（Protocol/接口）+ 策略（Strategy）承载变化点
- 避免if-else硬编码分支，改为"注册表/工厂/策略映射"
- 用配置驱动可变参数与阈值

**本项目落地**：
- 新增导入模式/合并策略：新增策略类并注册到工厂，而不是修改调用方
- 外部扩展点暴露最小稳定接口；内部实现可替换

**示例**：
```python
# ❌ 违反OCP：每次新增类型都要修改代码
def process_data(data, data_type):
    if data_type == "csv":
        return process_csv(data)
    elif data_type == "json":
        return process_json(data)
    elif data_type == "xml":  # 新增类型需要修改此函数
        return process_xml(data)

# ✅ 遵循OCP：使用策略模式
from typing import Protocol

class DataProcessor(Protocol):
    def process(self, data): ...

class CSVProcessor:
    def process(self, data): ...

class JSONProcessor:
    def process(self, data): ...

# 注册表
PROCESSORS = {
    "csv": CSVProcessor(),
    "json": JSONProcessor(),
}

def process_data(data, data_type):
    processor = PROCESSORS.get(data_type)
    if not processor:
        raise ValueError(f"不支持的数据类型: {data_type}")
    return processor.process(data)
```

### 1.3 里氏替换原则（LSP - Liskov Substitution Principle）

**定义**：子类型必须能够替换其基类型而不破坏正确性（行为兼容）

**要点**：
- 不加强前置条件/不放宽后置条件
- 返回值/异常契约一致
- 输入输出类型与语义保持父类/协议契约

**本项目落地**：
- 适配器实现（DbGateway/SqlGateway）可替换
- 测试以协议为准，不依赖具体类

**示例**：
```python
# ❌ 违反LSP：子类改变了行为契约
class Rectangle:
    def set_width(self, w): self.width = w
    def set_height(self, h): self.height = h
    def area(self): return self.width * self.height

class Square(Rectangle):
    def set_width(self, w):
        self.width = w
        self.height = w  # 违反了父类的行为契约

# ✅ 遵循LSP：使用组合而非继承
class Shape(Protocol):
    def area(self) -> float: ...

class Rectangle:
    def __init__(self, width, height):
        self.width = width
        self.height = height
    def area(self): return self.width * self.height

class Square:
    def __init__(self, side):
        self.side = side
    def area(self): return self.side * self.side
```

### 1.4 接口隔离原则（ISP - Interface Segregation Principle）

**定义**：客户端不应被迫依赖其不使用的方法；接口应当小而专

**要点**：
- 禁止"胖接口"，分解为聚焦的多个小接口/协议
- 组合优于继承：通过组合小接口获得所需能力

**本项目落地**：
- 将db/logging/fs接口按操作场景拆分
- 服务层仅依赖所需协议方法

**示例**：
```python
# ❌ 违反ISP：胖接口
class Worker(Protocol):
    def work(self): ...
    def eat(self): ...
    def sleep(self): ...

class Robot(Worker):  # 机器人不需要eat和sleep
    def work(self): pass
    def eat(self): pass  # 被迫实现不需要的方法
    def sleep(self): pass

# ✅ 遵循ISP：接口隔离
class Workable(Protocol):
    def work(self): ...

class Eatable(Protocol):
    def eat(self): ...

class Sleepable(Protocol):
    def sleep(self): ...

class Human:
    # 实现所有接口
    def work(self): pass
    def eat(self): pass
    def sleep(self): pass

class Robot:
    # 只实现需要的接口
    def work(self): pass
```

### 1.5 依赖倒置原则（DIP - Dependency Inversion Principle）

**定义**：高层模块不依赖低层实现，二者都依赖抽象；细节依赖抽象

**要点**：
- 通过构造注入/工厂注入依赖
- 禁止在业务内直接new具体实现
- 配置集中在settings，依赖由入口组装注入

**本项目落地**：
- services依赖adapters的协议（Protocol）
- 实例由cli/main组装注入

**示例**：
```python
# ❌ 违反DIP：高层依赖低层具体实现
class EmailService:
    def send(self, message): ...

class UserService:
    def __init__(self):
        self.email = EmailService()  # 直接依赖具体实现

    def register(self, user):
        # ...
        self.email.send("欢迎注册")

# ✅ 遵循DIP：依赖抽象
class MessageSender(Protocol):
    def send(self, message: str): ...

class EmailService:
    def send(self, message): ...

class SMSService:
    def send(self, message): ...

class UserService:
    def __init__(self, message_sender: MessageSender):
        self.message_sender = message_sender  # 依赖抽象

    def register(self, user):
        # ...
        self.message_sender.send("欢迎注册")

# 在入口组装
email_service = EmailService()
user_service = UserService(email_service)
```

### 1.6 迪米特法则（LoD - Law of Demeter，最少知识原则）

**定义**：只与"直接朋友"通信，避免深层对象链条（a.b.c.d）

**要点**：
- 提供合适的领域方法，避免暴露内部结构
- 减少链式穿透
- 限制跨层访问，统一通过网关/服务接口交互

**本项目落地**：
- 严禁在业务层直接操作底层连接/游标
- 通过DbGateway统一访问

**示例**：
```python
# ❌ 违反LoD：链式调用
class Customer:
    def __init__(self):
        self.wallet = Wallet()

class Wallet:
    def __init__(self):
        self.money = 100

# 违反LoD的调用
customer = Customer()
if customer.wallet.money >= 50:  # 知道了太多内部细节
    customer.wallet.money -= 50

# ✅ 遵循LoD：封装内部细节
class Customer:
    def __init__(self):
        self._wallet = Wallet()

    def pay(self, amount):
        return self._wallet.deduct(amount)

class Wallet:
    def __init__(self):
        self._money = 100

    def deduct(self, amount):
        if self._money >= amount:
            self._money -= amount
            return True
        return False

# 遵循LoD的调用
customer = Customer()
customer.pay(50)  # 只与Customer交互，不知道Wallet的存在
```

### 1.7 评审自检清单

在代码审查时，请检查以下项目：

- [ ] **职责单一**：模块/类/函数是否仅一个变化原因？是否存在混杂IO/业务/汇总？
- [ ] **扩展优先**：新增需求是否通过"新增实现/配置"而非"改老逻辑"？
- [ ] **可替换**：实现是否完全满足协议契约（类型/异常/语义）？
- [ ] **小接口**：是否为调用方裁剪了最小必要接口？
- [ ] **依赖注入**：高层是否仅依赖抽象？实例由入口装配？
- [ ] **最少知识**：是否消除了a.b.c级联访问与跨层直连？

## 2. 注释规范

### 1.1 文件头注释 [强制]

每个源代码文件必须包含文件头注释，说明模块用途。

**Python示例**：
```python
"""
数据导入服务模块

本模块负责从CSV文件导入测量数据到数据库，支持自动编码检测和数据验证。

主要功能：
- CSV文件解析（支持UTF-8、GBK编码）
- 数据格式验证
- 批量数据导入
- 导入进度跟踪

作者：张三
创建日期：2025-01-15
最后修改：2025-09-30
"""
```

**SQL示例**：
```sql
-- ============================================
-- 数据导入存储过程
--
-- 功能：批量插入或更新测量数据
-- 作者：张三
-- 创建日期：2025-01-15
-- 最后修改：2025-09-30
-- ============================================
```

### 1.2 类注释 [强制]

每个类必须包含类注释，说明类的职责、使用场景、关键属性。

**示例**：
```python
class DataImporter:
    """
    数据导入器

    负责从外部数据源导入数据到系统数据库。支持多种数据格式和导入策略。

    主要职责：
    - 解析外部数据文件
    - 验证数据格式和完整性
    - 执行数据导入操作
    - 记录导入日志和错误

    使用场景：
    - 定时批量数据导入
    - 手动触发的数据导入
    - 数据迁移和初始化

    关键属性：
        db_pool: 数据库连接池
        batch_size: 批量导入的批次大小
        max_retries: 失败重试次数

    示例：
        >>> importer = DataImporter(db_pool, batch_size=1000)
        >>> result = await importer.import_from_csv("data.csv")
        >>> print(f"成功导入 {result.success_count} 条数据")
    """
```

### 1.3 函数注释 [强制]

所有公共函数必须包含函数注释，说明参数、返回值、异常、使用示例。

**示例（Google风格）**：
```python
async def import_measurements(
    file_path: str,
    station_id: int,
    skip_validation: bool = False
) -> ImportResult:
    """
    从CSV文件导入测量数据

    读取指定的CSV文件，验证数据格式，然后批量导入到数据库。
    支持自动编码检测和数据去重。

    Args:
        file_path: CSV文件的完整路径
        station_id: 泵站ID，用于关联导入的数据
        skip_validation: 是否跳过数据验证，默认False

    Returns:
        ImportResult: 导入结果对象，包含以下字段：
            - success_count: 成功导入的数据条数
            - failed_count: 失败的数据条数
            - error_messages: 错误消息列表

    Raises:
        FileNotFoundError: 当文件不存在时
        InvalidDataFormatError: 当数据格式不符合要求时
        DatabaseError: 当数据库操作失败时

    Example:
        >>> result = await import_measurements(
        ...     "/data/measurements.csv",
        ...     station_id=1001
        ... )
        >>> print(f"导入成功: {result.success_count} 条")

    Note:
        - 大文件导入可能耗时较长，建议使用异步调用
        - 导入过程中会自动创建事务，失败时会回滚
    """
```

### 1.4 行内注释 [推荐]

复杂逻辑、业务规则、算法思路必须添加行内注释。

**良好示例**：
```python
# 计算自动基线：使用最近30天的P10分位数作为基线值
baseline = np.percentile(recent_data, 10)

# 特殊处理：当设备离线时间超过24小时，重置累计值
if offline_duration > timedelta(hours=24):
    cumulative_value = 0
```

**不良示例**：
```python
# 计算基线
baseline = np.percentile(recent_data, 10)  # ❌ 注释没有说明为什么是P10

# 处理离线
if offline_duration > timedelta(hours=24):  # ❌ 注释过于简单
    cumulative_value = 0
```

### 1.6 注释语言 [强制]

- **必须使用中文**
- **禁止中英混杂**（专业术语除外）
- **禁止使用拼音**

**良好示例**：
```python
# 使用Redis缓存查询结果，TTL设置为300秒
```

**不良示例**：

- 代码修改时**必须同步更新注释**

- 注释应该解释"为什么"而不是"是什么"

## 2. 日志规范（基于项目实际实现）

本项目使用自研的异步日志系统（`app/core/logging/setup.py`），配置文件为`configs/logging.yaml`。

### 2.1 日志系统架构 [参考]

**核心特性**：
- 基于标准logging，异步写入（QueueHandler + QueueListener）
- 多目标输出：控制台、文件（支持按时间/大小轮换）
- 上下文注入：request_id/trace_id/user_id/tenant等
- 输出格式：管道分隔固定字段 + extra_json（严格JSON）
- 提供log_activity上下文管理器与辅助事件API

**日志文件分类**：
- `logs/app.log` - 应用日志（INFO级别）
- `logs/error.log` - 错误日志（ERROR级别）
- `logs/sql.log` - SQL执行日志
- `logs/anomaly_diagnosis.log` - 异常诊断日志
- `logs/db_pool.log` - 数据库连接池日志

### 2.2 日志级别使用 [强制]

| 级别 | 使用场景 | 示例 |
|------|---------|------|
| **DEBUG** | 详细的调试信息，仅在开发环境使用 | 函数参数值、中间计算结果 |
| **INFO** | 关键业务流程节点 | 开始导入数据、完成质量检查 |
| **WARNING** | 潜在问题，但不影响功能 | 数据格式异常但已修正 |
| **ERROR** | 错误但不影响系统运行 | 单条数据导入失败 |
| **CRITICAL** | 严重错误，需要立即处理 | 数据库连接失败、系统崩溃 |

**示例**：
```python
import logging

logger = logging.getLogger(__name__)

logger.debug("开始处理文件", extra={"extra_data": {"file_path": file_path}})
logger.info("数据导入完成", extra={"extra_data": {"成功": success_count, "失败": failed_count}})
logger.warning("设备数据格式异常", extra={"extra_data": {"device_id": device_id}})
logger.error("导入数据失败", extra={"extra_data": {"错误": str(e)}}, exc_info=True)
logger.critical("数据库连接失败")
```

### 2.3 上下文字段 [强制]

项目支持以下上下文字段，通过`set_context()`设置：

| 字段 | 说明 | 示例 |
|------|------|------|
| `request_id` | 请求ID | `req-1234567890` |
| `trace_id` | 追踪ID（分布式追踪） | `trace-abc123` |
| `span_id` | 当前跨度ID | `span-def456` |
| `parent_span_id` | 父跨度ID | `span-abc123` |
| `span_depth` | 跨度深度 | `2` |
| `timeline_id` | 时间线ID | `timeline-xyz` |
| `timeline_seq` | 时间线序号 | `5` |
| `user_id` | 用户ID | `u-42` |
| `tenant` | 租户ID | `t-1` |

**使用示例**：
```python
from app.core.logging.setup import set_context, clear_context

# 在请求开始时设置上下文
set_context(
    request_id="req-123",
    trace_id="trace-abc",
    user_id="u-42",
    tenant="t-1"
)

# 业务逻辑...
logger.info("处理用户请求")  # 自动包含上下文字段

# 请求结束时清理上下文
clear_context()
```

### 2.4 日志格式 [强制]

**输出格式**：管道分隔（pipe）格式
```
timestamp|pid|processName|threadId|线程名|filename|module|funcName|lineno|level|message|extra_json
```

**extra_json结构**：
```json
{
  "类型": "进入",
  "event": "enter",
  "参数": {"file_path": "/data/test.csv"},
  "request_id": "req-123",
  "trace_id": "trace-abc",
  "user_id": "u-42"
}
```

**字段中文化**：
项目支持字段中文化（通过`localize_map`配置），常用映射：
- `type` → `类型`
- `event` → `事件`
- `params` → `参数`
- `duration_ms` → `耗时ms`
- `error` → `错误信息`
- `sql` → `SQL语句`
- `rows` → `行数`

### 2.5 日志API使用 [强制]

项目提供以下日志辅助API，**必须优先使用**：

#### 2.5.1 log_activity - 过程日志

用于记录函数/方法的进入、退出、耗时、异常。

**使用方法**：
```python
from app.core.logging.setup import log_activity

async def import_data(file_path: str, station_id: int):
    with log_activity("数据导入", params={"file_path": file_path, "station_id": station_id}):
        # 自动记录进入日志
        result = await _do_import(file_path, station_id)
        # 自动记录退出日志（包含耗时）
        return result
    # 如果发生异常，自动记录错误日志
```

```python
class ClassA:
```

## 5. 错误处理规范

### 5.1 异常捕获 [强制]

- 捕获具体异常，避免使用裸 `except`
- 必须记录异常日志
- 必须包含异常堆栈信息

**良好示例**：
```python
try:
    result = await import_data(file_path)
except FileNotFoundError as e:
    logger.error(f"文件不存在: {file_path}", exc_info=True)
    raise
except ValidationError as e:
    logger.error(f"数据验证失败: {e}", exc_info=True)
    raise
except Exception as e:
    logger.critical(f"未知错误: {e}", exc_info=True)
    raise
```

**不良示例**：
```python
try:
    result = await import_data(file_path)
except:  # ❌ 裸except
    pass  # ❌ 吞掉异常

try:
    result = await import_data(file_path)
except Exception as e:
    print(e)  # ❌ 使用print而非logger
```

### 5.2 异常传播 [强制]

- 底层函数抛出异常
- 上层函数捕获并处理
- 不要在底层吞掉异常

**示例**：
```python
# 底层函数：抛出异常
async def read_file(file_path: str) -> str:
    if not os.path.exists(file_path):
        raise FileNotFoundError(f"文件不存在: {file_path}")
    return open(file_path).read()

# 上层函数：捕获并处理
async def import_data(file_path: str):
    try:
        content = await read_file(file_path)
        # 处理数据...
    except FileNotFoundError as e:
        logger.error(f"导入失败: {e}")
        return ImportResult(success=False, error=str(e))
```

### 5.3 自定义异常 [推荐]

业务异常应该自定义异常类型，便于区分和处理。

**示例**：
```python
class DataImportError(Exception):
    """数据导入异常基类"""
    pass

class FileFormatError(DataImportError):
    """文件格式错误"""
    pass

class ValidationError(DataImportError):
    """数据验证错误"""
    pass

# 使用
if not is_valid_format(file):
    raise FileFormatError(f"不支持的文件格式: {file.suffix}")
```

### 5.4 资源清理 [强制]

使用 `with` 语句或 `try-finally` 确保资源释放。

**良好示例**：
```python
# ✅ 使用with语句
with open(file_path, 'r') as f:
    content = f.read()

# ✅ 使用try-finally
connection = await db_pool.acquire()
try:
    result = await connection.execute(sql)
finally:
    await db_pool.release(connection)
```

**不良示例**：
```python
# ❌ 没有资源清理
f = open(file_path, 'r')
content = f.read()
# 忘记关闭文件
```

## 6. 代码示例

### 6.1 完整示例：数据导入函数

```python
"""
数据导入服务模块

负责从CSV文件导入测量数据到数据库。
"""
import logging
from pathlib import Path
from typing import List, Optional
from datetime import datetime

from app.models import ImportResult, MeasurementData
from app.database import DatabasePool
from app.exceptions import FileFormatError, ValidationError

logger = logging.getLogger(__name__)


class DataImporter:
    """
    数据导入器

    负责从CSV文件导入测量数据到数据库，支持自动编码检测和数据验证。

    Attributes:
        db_pool: 数据库连接池
        batch_size: 批量导入的批次大小，默认1000
        max_retries: 失败重试次数，默认3
    """

    # 支持的文件格式
    SUPPORTED_FORMATS = ['.csv', '.xlsx']

    # 最大文件大小（100MB）
    MAX_FILE_SIZE = 100 * 1024 * 1024

    def __init__(
        self,
        db_pool: DatabasePool,
        batch_size: int = 1000,
        max_retries: int = 3
    ):
        """
        初始化数据导入器

        Args:
            db_pool: 数据库连接池
            batch_size: 批量导入的批次大小
            max_retries: 失败重试次数
        """
        self.db_pool = db_pool
        self.batch_size = batch_size
        self.max_retries = max_retries
        logger.info(f"数据导入器初始化完成: batch_size={batch_size}")

    async def import_from_csv(
        self,
        file_path: str,
        station_id: int,
        skip_validation: bool = False
    ) -> ImportResult:
        """
        从CSV文件导入测量数据

        Args:
            file_path: CSV文件的完整路径
            station_id: 泵站ID
            skip_validation: 是否跳过数据验证，默认False

        Returns:
            ImportResult: 导入结果，包含成功/失败数量和错误消息

        Raises:
            FileNotFoundError: 文件不存在
            FileFormatError: 文件格式不支持
            ValidationError: 数据验证失败
        """
        logger.info(
            f"开始导入数据: file_path={file_path}, station_id={station_id}"
        )
        start_time = datetime.now()

        try:
            # 验证文件
            self._validate_file(file_path)

            # 读取数据
            data = await self._read_csv(file_path)
            logger.info(f"读取到 {len(data)} 条数据")

            # 验证数据
            if not skip_validation:
                data = self._validate_data(data)
                logger.info(f"数据验证通过: {len(data)} 条")

            # 批量导入
            result = await self._batch_import(data, station_id)

            # 记录结果
            duration = (datetime.now() - start_time).total_seconds()
            logger.info(
                f"数据导入完成: 成功={result.success_count}, "
                f"失败={result.failed_count}, 耗时={duration:.2f}秒"
            )

            return result

        except FileNotFoundError as e:
            logger.error(f"文件不存在: {file_path}", exc_info=True)
            raise
        except FileFormatError as e:
            logger.error(f"文件格式错误: {e}", exc_info=True)
            raise
        except ValidationError as e:
            logger.error(f"数据验证失败: {e}", exc_info=True)
            raise
        except Exception as e:
            logger.critical(f"导入过程发生未知错误: {e}", exc_info=True)
            raise

    def _validate_file(self, file_path: str) -> None:
        """
        验证文件是否存在且格式正确

        Args:
            file_path: 文件路径

        Raises:
            FileNotFoundError: 文件不存在
            FileFormatError: 文件格式不支持或文件过大
        """
        path = Path(file_path)

        # 检查文件是否存在
        if not path.exists():
            raise FileNotFoundError(f"文件不存在: {file_path}")

        # 检查文件格式
        if path.suffix not in self.SUPPORTED_FORMATS:
            raise FileFormatError(
                f"不支持的文件格式: {path.suffix}, "
                f"支持的格式: {self.SUPPORTED_FORMATS}"
            )

        # 检查文件大小
        file_size = path.stat().st_size
        if file_size > self.MAX_FILE_SIZE:
            raise FileFormatError(
                f"文件过大: {file_size / 1024 / 1024:.2f}MB, "
                f"最大支持: {self.MAX_FILE_SIZE / 1024 / 1024:.2f}MB"
            )

        logger.debug(f"文件验证通过: {file_path}")

    # ... 其他方法 ...
```
