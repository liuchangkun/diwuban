## 一、数据导入流程

### 流程步骤
1. **文件上传** → 用户通过API上传CSV文件
2. **文件验证** → 编码检测（UTF-8、GBK）、格式验证
3. **数据解析** → 读取CSV、验证必需列（ts、tag、value）
4. **数据验证** → 时间戳、标签映射、数值范围验证
5. **写入暂存表** → 有效数据→staging表，拒绝数据→rejects表
6. **数据合并** → 调用merge_window，从staging→fact_measurements
7. **返回结果** → 成功数量、拒绝数量、错误信息

### 关键节点
- **API接口**：POST /api/v1/import/csv
- **暂存表**：staging（临时存储）
- **事实表**：fact_measurements（最终存储）
- **存储过程**：api.upsert_measurement

## 二、数据质量检查流程

### 流程步骤
1. **获取质量规则** → 从metric_quality_rules表读取规则
2. **读取待检查数据** → 指定时间窗口、站点/设备
3. **执行质量检查** → 物理越界、异常跳变、平台期、状态矛盾等
4. **标注质量问题** → 更新quality_codes数组、quality_status字段
5. **记录诊断日志** → 写入quality_diagnosis_log表
6. **更新质量评估** → 更新quality_eval_by_device_metric表

### 质量检查项
- **物理越界**（101）：value < valid_min OR value > valid_max
- **异常跳变**（111）：abs(value - prev_value) > jump_threshold
- **平台期**（121）：连续N个点值相同
- **状态矛盾**（401）：运行状态与指标值矛盾
- **功率因数异常**（701）：power_factor < 0 OR > 1
- **三相不平衡**（702）：max(A,B,C) - min(A,B,C) > threshold
- **计数器单调性**（751）：累计量出现回退

### 关键节点
- **质量规则表**：metric_quality_rules
- **诊断日志表**：quality_diagnosis_log
- **存储过程**：sp_mark_quality_window

## 三、特性曲线拟合流程

### 流程步骤
1. **获取运行数据** → 指定设备、时间范围（30-90天）
2. **数据筛选** → 过滤质量码=0、稳态数据（phase=1）
3. **数据清洗** → 异常值处理（3σ原则）、缺失值处理
4. **曲线拟合** → Q-H、η-Q、P-Q曲线拟合
5. **拟合质量评估** → 计算R²、RMSE、数据点数量
6. **存储拟合结果** → 写入dim_curves表
7. **曲线应用** → 数据验证、数据补全、异常检测

### 曲线类型
- **Q-H曲线**（流量-扬程）：H = a₀ + a₁Q + a₂Q²
- **η-Q曲线**（效率-流量）：η = b₀ + b₁Q + b₂Q²
- **P-Q曲线**（功率-流量）：P = c₀ + c₁Q + c₂Q²

### 关键节点
- **曲线表**：dim_curves
- **拟合方法**：POLYNOMIAL、LINEAR、EXPONENTIAL
- **质量阈值**：R² > 0.85

## 四、运行优化流程

### 流程步骤
1. **获取当前运行状态** → 读取站点设备、当前运行数据
2. **设定优化目标** → 能效优化、成本优化、性能优化
3. **选择优化算法** → 遗传算法、粒子群算法、梯度下降等
4. **生成优化方案** → 泵组合优化、频率调节、阀门开度
5. **方案评估** → 计算优化后能耗、节能效果、成本节约
6. **存储优化结果** → 写入optimizations表

### 优化目标
- **能效优化**（ENERGY_EFFICIENCY）：最小化能耗
- **成本优化**（COST_REDUCTION）：最小化运行成本
- **性能优化**（PERFORMANCE_OPTIMIZATION）：最大化性能

### 关键节点
- **优化表**：optimizations
- **物理计算**：PhysicsBasedCalculator
- **特性曲线**：dim_curves

## 五、设备运行状态计算流程

### 流程步骤
1. **获取运行阈值** → 从device_running_thresholds表读取
2. **读取运行数据** → 指定设备、时间范围
3. **计算综合标准分数** → 电流、功率、频率加权平均
4. **状态判定** → 运行/停止/待机
5. **状态保持和回退** → 避免频繁切换
6. **统计计算** → 运行时长、开停机次数
7. **存储结果** → 更新running_state字段、写入device_running_slices表

### 状态判定规则
- **运行**（RUNNING）：综合分数 > 运行阈值
- **停止**（STOPPED）：综合分数 < 停止阈值
- **待机**（STANDBY）：其他情况

### 关键节点
- **阈值表**：device_running_thresholds
- **切片表**：device_running_slices
- **存储过程**：sp_refresh_device_running_thresholds_otsu

## 六、自动基线计算流程

### 流程步骤
1. **获取历史数据** → 指定回溯天数（7-30天）
2. **数据筛选** → 过滤质量码=0、稳态数据
3. **基线计算** → robust方法或STL方法
4. **基线验证** → 检查合理性、与历史对比
5. **存储基线** → 写入metric_rule_auto_baseline表
6. **基线应用** → 质量检查、异常检测、趋势分析

### 计算方法
- **方案A（robust）**：基于分位数和MAD的稳健估计
- **方案B（STL）**：基于STL时间序列分解

### 关键节点
- **基线表**：metric_rule_auto_baseline
- **存储过程**：sp_refresh_metric_rule_auto_baseline

## 七、数据补全流程

### 流程步骤
1. **识别缺失指标** → 扫描fact_measurements表
2. **检查补全条件** → 输入指标、特性曲线、物理模型
3. **选择补全方法** → 物理模型、特性曲线、历史数据
4. **执行补全** → 计算缺失值、计算置信度
5. **存储补全结果** → 更新fact_measurements、标记quality_status=3
6. **补全质量评估** → 计算准确率、不确定性分析

### 补全方法
- **基于物理模型**：流量=f(扬程,转速)、功率=f(流量,扬程)
- **基于特性曲线**：根据Q-H、η-Q、P-Q曲线预测
- **基于历史数据**：线性插值、样条插值、时间序列预测

### 关键节点
- **物理计算**：PhysicsBasedCalculator
- **特性曲线**：dim_curves
- **补全标记**：quality_status=3
