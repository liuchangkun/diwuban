## 一、质量码定义

### 101 - 物理越界
**说明**：数值超出物理有效范围
**检查公式**：value < valid_min OR value > valid_max
**示例**：
- 有功功率 < 0 或 > 10000kW
- 流量 < 0 或 > 1000m³/h
- 扬程 < 0 或 > 200m
- 效率 < 0 或 > 1.0

**处理建议**：标记为BAD，不参与统计和计算

---

### 111 - 异常跳变
**说明**：相邻数据点变化过大
**检查公式**：abs(value - prev_value) > jump_threshold
**阈值设置**：
- 动态阈值：threshold = 3 × σ（标准差）
- 静态阈值：根据指标类型设置
  - 流量：50 m³/h
  - 扬程：20 m
  - 功率：500 kW
  - 电流：50 A

**示例**：
- 流量从100突变到500（变化400 > 50）
- 扬程从50突变到10（变化40 > 20）

**处理建议**：标记为SUSPECT，需人工审核

---

### 121 - 平台期
**说明**：连续多个相同值
**检查公式**：连续N个点值相同
**阈值设置**：
- N通常设置为10-20
- 对于快速变化的指标（如电流），N可设置为5-10
- 对于缓慢变化的指标（如温度），N可设置为20-30

**示例**：
- 流量连续20个点都是100.0
- 扬程连续15个点都是50.0

**处理建议**：标记为SUSPECT，可能是传感器故障

---

### 401 - 状态矛盾
**说明**：运行状态与指标值矛盾
**检查公式**：
- running_state = 0（停止）但 power > 0
- running_state = 1（运行）但 power = 0

**示例**：
- 设备显示停止但电流不为0
- 设备显示运行但功率为0

**处理建议**：标记为SUSPECT，需检查状态判定逻辑

---

### 701 - 功率因数异常
**说明**：功率因数超出合理范围
**检查公式**：power_factor < 0 OR power_factor > 1
**合理范围**：0.7-1.0
**示例**：
- 功率因数 = 1.2（超出1.0）
- 功率因数 = -0.5（小于0）

**处理建议**：标记为BAD，可能是计算错误

---

### 702 - 三相不平衡
**说明**：三相电流不平衡度过大
**检查公式**：
- 不平衡度 = (max(A,B,C) - min(A,B,C)) / avg(A,B,C)
- 不平衡度 > threshold（通常0.2，即20%）

**示例**：
- A相电流 = 100A，B相电流 = 80A，C相电流 = 60A
- 不平衡度 = (100-60)/80 = 0.5 > 0.2

**处理建议**：标记为SUSPECT，需检查电气系统

---

### 751 - 计数器单调性
**说明**：累计量出现回退
**检查公式**：current_value < previous_value
**适用指标**：
- 累计电量
- 累计流量
- 累计运行时长

**示例**：
- 累计电量从1000kWh回退到900kWh

**处理建议**：标记为BAD，可能是计数器复位或故障

## 二、质量状态定义

### quality_status字段
- **0 = GOOD（正常）**：无质量问题
- **1 = SUSPECT（可疑）**：有质量问题但可能是正常波动
- **2 = BAD（异常）**：明确的质量问题
- **3 = COMPLETED（补全）**：通过计算补全的数据
- **4 = MISSING（缺失）**：数据缺失

---

## 三、质量检查流程

### 3.1 检查顺序
1. **物理越界检查**（101） - 最高优先级
2. **计数器单调性检查**（751） - 仅适用于累计量
3. **异常跳变检查**（111）
4. **平台期检查**（121）
5. **状态矛盾检查**（401）
6. **功率因数异常检查**（701）
7. **三相不平衡检查**（702）

### 3.2 检查逻辑
```python
# 伪代码
quality_codes = []

# 1. 物理越界
if value < valid_min or value > valid_max:
    quality_codes.append(101)
    quality_status = 2  # BAD

# 2. 异常跳变
if abs(value - prev_value) > jump_threshold:
    quality_codes.append(111)
    quality_status = max(quality_status, 1)  # SUSPECT

# 3. 平台期
if count_same_values >= plateau_threshold:
    quality_codes.append(121)
    quality_status = max(quality_status, 1)  # SUSPECT

# 4. 状态矛盾
if running_state == 0 and power > 0:
    quality_codes.append(401)
    quality_status = max(quality_status, 1)  # SUSPECT

# 5. 功率因数异常
if power_factor < 0 or power_factor > 1:
    quality_codes.append(701)
    quality_status = 2  # BAD

# 6. 三相不平衡
if imbalance_ratio > 0.2:
    quality_codes.append(702)
    quality_status = max(quality_status, 1)  # SUSPECT

# 7. 计数器单调性
if is_counter and value < prev_value:
    quality_codes.append(751)
    quality_status = 2  # BAD
```

## 四、质量规则表结构

### metric_quality_rules表
**字段**：
- station_id：站点ID
- device_id：设备ID
- metric_id：指标ID
- valid_min：最小有效值
- valid_max：最大有效值
- jump_threshold：跳变阈值
- plateau_threshold：平台期阈值
- method：计算方法（robust、STL等）
- version：规则版本

**示例**：
```sql
SELECT * FROM metric_quality_rules
WHERE station_id = 1 AND device_id = 101 AND metric_id = 1;

-- 结果：
-- station_id | device_id | metric_id | valid_min | valid_max | jump_threshold | plateau_threshold | method | version
-- 1          | 101       | 1         | 0         | 1000      | 50             | 10                | robust | 1
```

## 六、质量评估统计

### quality_eval_by_device_metric表
**字段**：
- station_id：站点ID
- device_id：设备ID
- metric_id：指标ID
- start_ts：开始时间
- end_ts：结束时间
- total_count：总数据点数
- good_count：正常数据点数
- suspect_count：可疑数据点数
- bad_count：异常数据点数
- missing_count：缺失数据点数
- good_rate：正常率
- suspect_rate：可疑率
- bad_rate：异常率

**计算公式**：
- good_rate = good_count / total_count
- suspect_rate = suspect_count / total_count
- bad_rate = bad_count / total_count
