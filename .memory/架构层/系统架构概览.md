## 一、技术栈

### 后端技术
- **语言**：Python 3.11+
- **Web框架**：FastAPI
- **数据验证**：Pydantic
- **数据库驱动**：psycopg 3.x
- **科学计算**：numpy、scipy、scikit-learn
- **任务调度**：APScheduler

### 数据库技术
- **数据库**：PostgreSQL 16
- **时序扩展**：TimescaleDB 2.11+
- **Schema设计**：
  - `public` - 核心业务表
  - `api` - 数据操作存储过程
  - `reporting` - 查询函数和物化视图

### 基础设施
- **连接池**：自定义连接池（支持健康检查、租约管理）
- **日志系统**：结构化日志（管道格式）
- **错误处理**：熔断器、重试机制、错误分析
- **监控**：系统健康检查、性能指标、数据质量监控

## 三、核心组件

### 3.1 API层组件

#### 时序数据API（data_timeseries.py）
- **职责**：提供时序数据查询接口
- **端点**：
  - GET /api/v1/stations/{id}/measurements
  - GET /api/v1/devices/{id}/measurements
  - GET /api/v1/stations/{id}/raw
- **特性**：支持多粒度聚合、宽表格式、分页查询

#### 管理API（data_admin.py）
- **职责**：提供系统管理接口
- **端点**：
  - GET /api/v1/stations
  - GET /api/v1/stations/{id}/devices
  - GET /api/v1/metrics
  - POST /api/v1/import/csv
  - GET /api/v1/stats/import
- **特性**：站点设备管理、数据导入、统计查询

#### 监控API（monitoring.py）
- **职责**：提供系统监控接口
- **端点**：
  - GET /api/v1/monitoring/health
  - GET /api/v1/monitoring/db-health
  - GET /api/v1/monitoring/pool-stats
  - GET /api/v1/monitoring/performance
  - GET /api/v1/monitoring/devices
  - GET /api/v1/monitoring/devices/{id}
- **特性**：健康检查、性能监控、设备状态

---

### 3.2 服务层组件

#### 数据导入服务（DataImportService）
- **文件**：app/services/data_import.py
- **职责**：CSV文件导入和数据验证
- **核心方法**：
  - import_csv_file() - 导入CSV文件
  - get_import_statistics() - 获取导入统计
  - cleanup_old_staging_data() - 清理旧数据
- **依赖**：数据库适配器、文件系统适配器

#### 曲线拟合服务（CurveFittingService）
- **文件**：app/services/curve_fitting.py
- **职责**：设备特性曲线拟合（Q-H、η-Q、P-Q等）
- **核心方法**：fit_curve()、_fit_with_scipy()、_fit_simplified()
- **依赖**：numpy、scipy、数据库适配器

#### 优化服务（OptimizationService）
- **文件**：app/services/optimization.py
- **职责**：泵站运行优化计算
- **核心方法**：optimize()、_optimize_pump_configuration()
- **依赖**：算法适配器、数据库适配器

#### 质量检查服务
- **文件**：app/services/quality/
- **职责**：数据质量检查和标注
- **核心方法**：run_quality_full_pass()、mark_quality_window()
- **依赖**：数据库适配器、质量规则

#### 报表服务
- **文件**：app/services/reporting/
- **职责**：数据报表生成
- **核心方法**：generate_report()、export_window_code_distribution()
- **依赖**：数据库适配器、reporting schema

#### 规则服务
- **文件**：app/services/rules/
- **职责**：规则计算和管理
- **核心方法**：run_auto_baseline()、run_running_thresholds()
- **依赖**：数据库适配器、统计算法

## 五、关键设计决策

### 5.1 为什么使用TimescaleDB？
- 时序数据量大，需要高效存储和查询
- 自动分区、高效压缩、连续聚合

### 5.2 为什么使用存储过程？
- 数据操作逻辑集中管理
- 保证数据一致性
- 减少网络往返，提高性能

### 5.3 为什么自定义连接池？
- 需要精细的连接管理和监控
- 健康检查、连接租约、内存泄漏诊断

## 六、性能优化策略

### 6.1 数据库层
- 按周分区（fact_measurements表）
- 复合索引（station_id, device_id, metric_id, ts）
- 物化视图预聚合

### 6.2 应用层
- 批量操作（COPY命令，每批1000行）
- 连接池复用
- 异步处理长时间任务

### 6.3 查询优化
- 时间范围过滤
- 物化视图优先
- 分页查询（默认100条/页）
