## 📊 表结构设计

### 1. fact_measurements（现有表）

**用途**：存储所有指标的测量值

**表结构**：
```sql
CREATE TABLE fact_measurements (
    id BIGSERIAL PRIMARY KEY,
    device_id INT NOT NULL,
    metric_key VARCHAR(100) NOT NULL,
    value DOUBLE PRECISION,
    timestamp TIMESTAMP NOT NULL,
    quality_code SMALLINT DEFAULT 0,
    created_at TIMESTAMP DEFAULT NOW(),
    updated_at TIMESTAMP DEFAULT NOW()
);

-- 索引
CREATE INDEX idx_fm_device_metric_time ON fact_measurements(device_id, metric_key, timestamp DESC);
CREATE INDEX idx_fm_timestamp ON fact_measurements(timestamp DESC);
CREATE INDEX idx_fm_metric_time ON fact_measurements(metric_key, timestamp DESC);

-- 分区（按月）
CREATE TABLE fact_measurements_y2025m01 PARTITION OF fact_measurements
    FOR VALUES FROM ('2025-01-01') TO ('2025-02-01');
```

**字段说明**：

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGSERIAL | 主键 |
| device_id | INT | 设备ID |
| metric_key | VARCHAR(100) | 指标键（如pump_flow_rate） |
| value | DOUBLE PRECISION | 指标值 |
| timestamp | TIMESTAMP | 时间戳 |
| quality_code | SMALLINT | 质量码（0=正常，1=可疑，2=错误） |
| created_at | TIMESTAMP | 创建时间 |
| updated_at | TIMESTAMP | 更新时间 |

**pump_flow_rate相关指标**：
- `pump_flow_rate`：泵流量（m³/h）
- `main_pipeline_flow_rate`：总管流量（m³/h）
- `pump_active_power`：泵有功功率（kW）
- `pump_frequency`：泵频率（Hz）
- `pump_cumulative_flow`：泵累计流量（m³）
- `pump_inlet_pressure`：泵进口压力（MPa）
- `pump_outlet_pressure`：泵出口压力（MPa）

**查询示例**：
```sql
-- 查询设备105在指定时间范围的pump_flow_rate
SELECT timestamp, value
FROM fact_measurements
WHERE device_id = 105
  AND metric_key = 'pump_flow_rate'
  AND timestamp BETWEEN '2025-01-01 00:00:00' AND '2025-01-01 01:00:00'
ORDER BY timestamp;

-- 查询多个指标（用于DataLoader）
SELECT device_id, metric_key, timestamp, value
FROM fact_measurements
WHERE device_id IN (105, 106, 107)
  AND metric_key IN ('pump_active_power', 'pump_frequency', 'main_pipeline_flow_rate')
  AND timestamp BETWEEN '2025-01-01 00:00:00' AND '2025-01-01 01:00:00'
ORDER BY device_id, metric_key, timestamp;
```

### 3. calculation_parameters（新增表）

**用途**：存储计算参数配置（三级配置）

**表结构**：
```sql
CREATE TABLE calculation_parameters (
    id SERIAL PRIMARY KEY,
    metric_key VARCHAR(100) NOT NULL,
    method_id VARCHAR(100),
    parameter_name VARCHAR(100) NOT NULL,
    parameter_value DOUBLE PRECISION NOT NULL,

    -- 三级配置
    station_id INT,  -- NULL表示全局配置
    device_id INT,   -- NULL表示泵站级配置

    -- 元数据
    description TEXT,
    is_optimizable BOOLEAN DEFAULT FALSE,
    created_at TIMESTAMP DEFAULT NOW(),
    updated_at TIMESTAMP DEFAULT NOW(),
    created_by VARCHAR(100),

    -- 约束
    CONSTRAINT chk_level CHECK (
        (station_id IS NULL AND device_id IS NULL) OR  -- 全局
        (station_id IS NOT NULL AND device_id IS NULL) OR  -- 泵站
        (station_id IS NOT NULL AND device_id IS NOT NULL)  -- 设备
    ),
    UNIQUE(metric_key, method_id, parameter_name, station_id, device_id)
);

-- 索引
CREATE INDEX idx_cp_metric_method ON calculation_parameters(metric_key, method_id);
CREATE INDEX idx_cp_station ON calculation_parameters(station_id) WHERE station_id IS NOT NULL;
CREATE INDEX idx_cp_device ON calculation_parameters(device_id) WHERE device_id IS NOT NULL;
```

**字段说明**：

| 字段 | 类型 | 说明 |
|------|------|------|
| id | SERIAL | 主键 |
| metric_key | VARCHAR(100) | 指标键（如pump_flow_rate） |
| method_id | VARCHAR(100) | 方法ID（如method_a），NULL表示全局参数 |
| parameter_name | VARCHAR(100) | 参数名（如alpha、beta） |
| parameter_value | DOUBLE PRECISION | 参数值 |
| station_id | INT | 泵站ID（NULL=全局） |
| device_id | INT | 设备ID（NULL=泵站级） |
| description | TEXT | 参数描述 |
| is_optimizable | BOOLEAN | 是否可优化 |

**配置示例**：
```sql
-- 全局配置（所有泵站、所有设备）
INSERT INTO calculation_parameters (metric_key, method_id, parameter_name, parameter_value, station_id, device_id, description, is_optimizable)
VALUES
    ('pump_flow_rate', 'method_a', 'alpha', 1.0, NULL, NULL, '功率指数（全局默认）', TRUE),
    ('pump_flow_rate', 'method_a', 'beta', 1.0, NULL, NULL, '频率指数（全局默认）', TRUE);

-- 泵站级配置（14号泵站）
INSERT INTO calculation_parameters (metric_key, method_id, parameter_name, parameter_value, station_id, device_id, description, is_optimizable)
VALUES
    ('pump_flow_rate', 'method_a', 'alpha', 1.2, 14, NULL, '功率指数（14号泵站优化后）', TRUE),
    ('pump_flow_rate', 'method_a', 'beta', 0.9, 14, NULL, '频率指数（14号泵站优化后）', TRUE);

-- 设备级配置（14号泵站105号设备）
INSERT INTO calculation_parameters (metric_key, method_id, parameter_name, parameter_value, station_id, device_id, description, is_optimizable)
VALUES
    ('pump_flow_rate', 'method_a', 'alpha', 1.3, 14, 105, '功率指数（105号设备特殊配置）', TRUE);
```

**查询优先级**（设备 > 泵站 > 全局）：
```sql
-- ParameterManager查询逻辑
WITH param_hierarchy AS (
    SELECT
        parameter_name,
        parameter_value,
        CASE
            WHEN device_id IS NOT NULL THEN 1  -- 设备级
            WHEN station_id IS NOT NULL THEN 2  -- 泵站级
            ELSE 3  -- 全局级
        END AS priority
    FROM calculation_parameters
    WHERE metric_key = 'pump_flow_rate'
      AND method_id = 'method_a'
      AND (
          (station_id = 14 AND device_id = 105) OR  -- 设备级
          (station_id = 14 AND device_id IS NULL) OR  -- 泵站级
          (station_id IS NULL AND device_id IS NULL)  -- 全局级
      )
)
SELECT parameter_name, parameter_value
FROM param_hierarchy
WHERE priority = (SELECT MIN(priority) FROM param_hierarchy)
ORDER BY parameter_name;
```

## 🔍 索引优化策略

### 1. fact_measurements索引优化

**核心查询模式**：
```sql
-- 模式1：单设备单指标时间范围查询（最常见）
SELECT timestamp, value
FROM fact_measurements
WHERE device_id = ? AND metric_key = ? AND timestamp BETWEEN ? AND ?;

-- 模式2：多设备多指标时间范围查询（DataLoader）
SELECT device_id, metric_key, timestamp, value
FROM fact_measurements
WHERE device_id IN (?, ?, ?) AND metric_key IN (?, ?, ?) AND timestamp BETWEEN ? AND ?;

-- 模式3：泵站级聚合查询
SELECT device_id, AVG(value) as avg_value
FROM fact_measurements
WHERE metric_key = ? AND timestamp BETWEEN ? AND ?
GROUP BY device_id;
```

**推荐索引**：
```sql
-- 主索引（覆盖模式1和模式2）
CREATE INDEX idx_fm_device_metric_time ON fact_measurements(device_id, metric_key, timestamp DESC);

-- 辅助索引（覆盖模式3）
CREATE INDEX idx_fm_metric_time ON fact_measurements(metric_key, timestamp DESC);

-- 时间索引（用于分区裁剪）
CREATE INDEX idx_fm_timestamp ON fact_measurements(timestamp DESC);
```

**索引大小估算**：
- 假设每天1000万条记录
- 每个索引约占表大小的30%
- 3个索引总计约占90%
- 建议定期VACUUM和REINDEX

## 📦 分区策略

### 1. fact_measurements分区

**分区方式**：按月分区（RANGE分区）

**原因**：
- ✅ 查询通常按时间范围
- ✅ 历史数据可以归档
- ✅ 分区裁剪提高查询性能

**实现**：
```sql
-- 创建分区表
CREATE TABLE fact_measurements (
    id BIGSERIAL,
    device_id INT NOT NULL,
    metric_key VARCHAR(100) NOT NULL,
    value DOUBLE PRECISION,
    timestamp TIMESTAMP NOT NULL,
    quality_code SMALLINT DEFAULT 0,
    created_at TIMESTAMP DEFAULT NOW(),
    updated_at TIMESTAMP DEFAULT NOW()
) PARTITION BY RANGE (timestamp);

-- 创建分区（2025年1月）
CREATE TABLE fact_measurements_y2025m01 PARTITION OF fact_measurements
    FOR VALUES FROM ('2025-01-01') TO ('2025-02-01');

-- 创建分区（2025年2月）
CREATE TABLE fact_measurements_y2025m02 PARTITION OF fact_measurements
    FOR VALUES FROM ('2025-02-01') TO ('2025-03-01');

-- 自动创建未来分区（使用pg_partman扩展）
SELECT partman.create_parent(
    p_parent_table := 'public.fact_measurements',
    p_control := 'timestamp',
    p_type := 'native',
    p_interval := '1 month',
    p_premake := 3  -- 提前创建3个月的分区
);
```

### 2. calculation_logs分区

**分区方式**：按天分区（RANGE分区）

**原因**：
- ✅ 日志数据量大

- ✅ 历史日志可以定期清理

```sql
SELECT partman.create_parent(

UPDATE partman.part_config
```

## ⚡ 查询优化建议

### 1. DataLoader查询优化

**优化前**（多次查询）：
```python
# 不推荐：每个指标单独查询
for metric_key in ['pump_active_power', 'pump_frequency', 'main_pipeline_flow_rate']:
    data = query(f"SELECT timestamp, value FROM fact_measurements WHERE device_id = {device_id} AND metric_key = '{metric_key}' AND timestamp BETWEEN '{start}' AND '{end}'")
```

**优化后**（单次查询 + 透视）：
```python
# 推荐：一次查询所有指标，然后在Python中透视
sql = """
    SELECT device_id, metric_key, timestamp, value
    FROM fact_measurements
    WHERE device_id IN %s
      AND metric_key IN %s
      AND timestamp BETWEEN %s AND %s
    ORDER BY device_id, timestamp, metric_key
"""
data = query(sql, [device_ids, metric_keys, start_time, end_time])

# 透视操作（Pandas）
pivot_data = data.pivot_table(
    index=['device_id', 'timestamp'],
    columns='metric_key',
    values='value'
).reset_index()
```

## 📊 数据量估算

### fact_measurements

**假设**：
- 设备数量：1000台
- 指标数量：50个/设备
- 采样频率：1秒
- 数据保留：1年

**计算**：
- 每秒记录数：1000 × 50 = 50,000
- 每天记录数：50,000 × 86,400 = 43.2亿
- 每年记录数：43.2亿 × 365 = 1.58万亿

**存储估算**：
- 每条记录：约80字节
- 每年数据：1.58万亿 × 80字节 ≈ 126 TB
- 加上索引：126 TB × 1.9 ≈ 240 TB

**建议**：
- ✅ 使用TimescaleDB（时序数据库扩展）
- ✅ 启用压缩（可节省70-90%空间）
- ✅ 历史数据归档到对象存储

### calculation_logs

**假设**：
- 每次计算产生6条日志（6个阶段）
- 每天计算1000次

**计算**：

- 每年日志数：6,000 × 365 = 219万

**存储估算**：
- 每条日志：约500字节（含JSONB）

**建议**：
