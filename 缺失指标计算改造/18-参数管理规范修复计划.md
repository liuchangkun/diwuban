### 3. 代码违规修复

根据之前的审查报告，发现了 **78个代码违规**：

#### 修复策略

**阶段1：修复 Validator 类（优先级最高）**
- 原因：Validator 的默认值直接影响数据质量
- 范围：9个指标的 validator.py 文件
- 预计违规数：~20个

**阶段2：修复 DataFilter 类**
- 原因：DataFilter 的默认值影响数据过滤
- 范围：9个指标的 data_filter.py 文件
- 预计违规数：~15个

**阶段3：修复 Calculator/Methods 类**
- 原因：Calculator 的默认值影响计算结果
- 范围：9个指标的 methods/*.py 文件
- 预计违规数：~30个

**阶段4：修复 ParameterManager**
- 原因：ParameterManager 的 default_params 是根本问题
- 范围：app/services/calculation/shared/parameter_manager.py
- 预计违规数：1个（但影响最大）

#### 修复模板

**修复前**：
```python
max_power = params.get('max_power', 500.0)  # ❌ 硬编码默认值
```

**修复后**：
```python
max_power = params.get('max_power')
if max_power is None:
    self.logger.error(
        f"[参数错误] 缺少必需参数 'max_power'",
        extra={
            'station_id': station_id,
            'device_id': device_id,
            'metric_key': 'pump_shaft_power',
            'missing_param': 'max_power',
            'fix': '请在 calculation_parameters 表中添加该参数'
        }
    )
    raise ValueError(f"缺少必需参数 'max_power'")
```
