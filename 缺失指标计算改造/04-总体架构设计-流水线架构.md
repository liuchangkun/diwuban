## 架构概述

### 设计理念

**核心思想**：将缺失指标计算流程设计为一个**流水线（Pipeline）架构**，每个阶段是一个独立的、可组合的处理单元。

**关键特性**：
- ✅ **按指标顺序计算**：先完成所有设备的 pump_flow_rate，再进行下一个指标
- ✅ **指标间串行，设备间并行**：确保指标依赖关系正确，同时提高计算效率
- ✅ **共用模块全局唯一**：调度器、数据写入、参数优化全局只有一个实例
- ✅ **指标专用模块独立实现**：每个指标有自己的数据获取、过滤、计算逻辑
- ✅ **三级参数配置**：支持全局、泵站、设备三个级别的参数配置
- ✅ **三级参数优化**：支持全局、泵站、设备三个级别的独立优化（基于物理自洽性）

### 架构分层

### 与现有系统的对比

| 维度 | 现有系统 | 新架构 |
|------|---------|--------|
| **配置方式** | 数据库表驱动（calculation_method_registry） | 代码配置（Python字典/类） |
| **计算顺序** | 不明确（依赖DependencyAnalyzer） | 明确的指标顺序（METRIC_ORDER） |
| **模块复用** | 所有指标共享一个Orchestrator | 共用模块 + 指标专用模块 |
| **代码复杂度** | 单文件2659行 | 多文件，每个<600行 |
| **扩展性** | 需要修改注册表和Orchestrator | 只需添加新的指标目录 |
| **可测试性** | 难以单独测试某个阶段 | 每个阶段可独立测试 |
| **可维护性** | 逻辑分散，难以理解 | 逻辑清晰，易于理解 |

### 核心优势

1. **清晰的计算顺序**：
   - 指标顺序在代码中明确定义（METRIC_ORDER）
   - 指标间串行，确保依赖关系正确
   - 设备间并行，提高计算效率

2. **模块化设计**：
   - 共用模块全局唯一，避免重复实现
   - 指标专用模块独立实现，易于扩展
   - 每个模块职责单一，易于测试

3. **灵活的参数管理**：
   - 三级配置（全局 > 泵站 > 设备）
   - 参数存储在数据库，支持动态调整
   - 支持参数优化（基于物理自洽性）

4. **完整的日志链路**：
   - 每个阶段都记录详细日志
   - 使用 task_id 关联同一任务的所有日志
   - 支持并行任务的日志区分

5. **渐进式迁移**：
   - 先迁移 pump_flow_rate，验证无误后再迁移其他指标
   - 新旧系统可以并行运行，对比结果
   - 支持回滚

        self,

        2. 再计算所有设备的 pump_head

        Args:

        Returns:
            所有指标的执行结果汇总
        """
        all_results = {}

        # 按指标顺序依次执行
        for metric_key in self.METRIC_ORDER:
            logger.info(f"[调度] 开始计算指标: {metric_key}")

            # 计算当前指标的所有设备
            metric_result = self.schedule_single_metric(
                metric_key=metric_key,
                devices=devices,
                start_time=start_time,
                end_time=end_time,
                window_hours=window_hours,
                max_workers=max_workers
            )

            all_results[metric_key] = metric_result

            logger.info(
                f"[调度] 指标 {metric_key} 计算完成 - "
                f"成功: {metric_result['success_count']}, "
                f"失败: {metric_result['failure_count']}"
            )

        return all_results

    def schedule_single_metric(
        self,
        metric_key: str,
        devices: List[Tuple[int, int]],
        start_time: datetime,
        end_time: datetime,
        window_hours: int = 1,
        max_workers: int = 4
    ) -> Dict:
        """
        调度单个指标的计算（所有设备）

        Args:
            metric_key: 指标键（如 'pump_flow_rate'）
            devices: 设备列表
            start_time: 开始时间
            end_time: 结束时间
            window_hours: 时间窗口大小
            max_workers: 最大并行工作线程数

        Returns:
            当前指标的执行结果汇总
        """
        # 1. 生成任务列表（按时间窗口和设备分片）
        tasks = self._generate_tasks(
            metric_key, devices, start_time, end_time, window_hours
        )

        logger.info(
            f"[调度] 指标 {metric_key} - 任务总数: {len(tasks)}, "
            f"设备数: {len(devices)}, "
            f"时间窗口: {window_hours}小时"
        )

        # 2. 并行执行任务
        results = []
        with ThreadPoolExecutor(max_workers=max_workers) as executor:
            futures = {
                executor.submit(self._execute_task, task): task
                for task in tasks
            }

            # 3. 收集结果
            for future in as_completed(futures):
                task = futures[future]
                try:
                    result = future.result()
                    results.append(result)
                except Exception as e:
                    logger.error(
                        f"[调度] 任务执行失败 - "
                        f"指标: {task['metric_key']}, "
                        f"设备: {task['device_id']}, "
                        f"错误: {e}"
                    )
                    results.append({
                        'success': False,
                        'error': str(e),
                        'task': task
                    })

        # 4. 汇总结果
        return self._summarize_results(metric_key, results)
```

**关键特性**：
- ✅ **指标间串行**：等待一个指标的所有设备计算完成，再进行下一个指标
- ✅ **设备间并行**：同一指标的不同设备可以并行计算（max_workers控制并发度）
- ✅ **时间窗口并行**：同一设备的不同时间窗口可以并行计算
- ✅ **错误隔离**：单个任务失败不影响其他任务

### 3. DataWriter（数据写入）

**职责**：
- 批量写入计算结果
- 自适应批量大小管理

**接口定义**：

```python
class DataWriter:
    """数据写入模块（共用）"""

    def __init__(self):
        # 初始化自适应批量管理器
        self.adaptive_batch = AdaptiveBatchManager(config={
            'enabled': True,
            'initial_size': 10000,
            'min_size': 1000,
            'max_size': 50000,
            'memory_limit_mb': 1000,
            'target_throughput': 10000,
        })

        logger.info("[数据写入] 初始化完成")

    def write_batch(
        self,
        metric_key: str,
        results: List[Tuple],
        station_id: int,
        device_id: int,
        task_id: str
    ) -> Dict:
        """
        批量写入计算结果

        Args:
            metric_key: 指标键
            results: 计算结果列表 [(ts_bucket, value), ...]
            station_id: 泵站ID
            device_id: 设备ID
            task_id: 任务ID（用于日志关联）

        Returns:
            写入结果统计
        """
        if not results:
            logger.warning(
                f"[数据写入] [task_id={task_id}] 没有数据需要写入",
                extra={'task_id': task_id, 'metric_key': metric_key}
            )
            return {'written_count': 0}

        # 准备插入语句
        insert_query = """
            INSERT INTO fact_measurements (
                station_id, device_id, ts_bucket, metric_key, value,
                quality_status, is_calculated, created_at
            ) VALUES (
                %s, %s, %s, %s, %s,
                'GOOD', TRUE, NOW()
            )
            ON CONFLICT (station_id, device_id, ts_bucket, metric_key)
            DO UPDATE SET
                value = EXCLUDED.value,
                is_calculated = TRUE,
                updated_at = NOW()
        """

        # 获取初始批量大小
        batch_size = self.adaptive_batch.get_initial_size()

        written_count = 0
        batch_number = 0

        logger.info(
            f"[数据写入] [task_id={task_id}] 开始写入 - "
            f"总行数: {len(results)}, 初始批量: {batch_size}",
            extra={'task_id': task_id, 'total_rows': len(results)}
        )

        try:
            write_start = time.time()

            with get_connection() as conn:
                with conn.cursor() as cur:
                    # 分批写入
                    i = 0
                    while i < len(results):
                        batch_number += 1
                        batch_start = time.time()

                        # 准备批次数据
                        batch = results[i:i + batch_size]
                        batch_data = [
                            (station_id, device_id, ts, metric_key, value)
                            for ts, value in batch
                        ]

                        # 批量插入
                        cur.executemany(insert_query, batch_data)
                        written_count += len(batch)

                        batch_time = time.time() - batch_start
                        throughput = len(batch) / batch_time if batch_time > 0 else 0

                        logger.info(
                            f"[数据写入] [task_id={task_id}] 批次 {batch_number} 完成 - "
                            f"行数: {len(batch)}, 耗时: {batch_time:.2f}s, "
                            f"吞吐量: {throughput:.0f}行/秒",
                            extra={
                                'task_id': task_id,
                                'batch_number': batch_number,
                                'batch_size': len(batch),
                                'duration_s': batch_time,
                                'throughput': throughput
                            }
                        )

                        # 自适应调整批量大小
                        if self.adaptive_batch.is_enabled():
                            performance = {
                                'throughput': throughput,
                                'duration_ms': batch_time * 1000,
                                'memory_mb': 0,  # TODO: 实际内存监控
                            }
                            new_batch, reason = self.adaptive_batch.adjust(
                                batch_size, performance
                            )

                            if new_batch != batch_size:
                                logger.info(
                                    f"[数据写入] [task_id={task_id}] 调整批量大小: "
                                    f"{batch_size} → {new_batch}, 原因: {reason}",
                                    extra={'task_id': task_id, 'reason': reason}
                                )
                                batch_size = new_batch

                        i += batch_size

                    # 提交事务
                    conn.commit()

            total_time = time.time() - write_start
            avg_throughput = written_count / total_time if total_time > 0 else 0

            logger.info(
                f"[数据写入] [task_id={task_id}] 写入完成 - "
                f"总行数: {written_count}, 总耗时: {total_time:.2f}s, "
                f"平均吞吐量: {avg_throughput:.0f}行/秒",
                extra={
                    'task_id': task_id,
                    'written_count': written_count,
                    'total_time_s': total_time,
                    'avg_throughput': avg_throughput
                }
            )

            return {
                'written_count': written_count,
                'batch_count': batch_number,
                'total_time_s': total_time,
                'avg_throughput': avg_throughput
            }

        except Exception as e:
            logger.error(
                f"[数据写入] [task_id={task_id}] 写入失败: {e}",
                extra={'task_id': task_id, 'error': str(e)},
                exc_info=True
            )
            raise
```

### 4. Optimizer（参数优化器）

**职责**：
- 参数优化（基于物理自洽性）
- 支持三级优化（全局、泵站、设备）
- 分层降级策略（根据可用数据自动调整优化目标）
- 适用于所有9个缺失指标
- **6项增强功能**（详见文档06）

**核心原理**：

由于**无法获得实际测量值**，采用**物理自洽性优化**方法：
- 不需要实际测量值
- 不需要特性曲线
- 基于物理定律（能量守恒、流量守恒、压力关系等）
- 最小化物理不一致性

**增强功能**（详见 `06-参数优化器增强设计.md`）：

1. **自适应权重调整**：根据数据质量（方差、区分度）自动调整约束权重
2. **分层优化策略**：全局→泵站→设备的继承式优化，下层参数以上层为起点
3. **增量优化**：只使用新增数据，提高优化效率（默认7天）
4. **多目标优化**：使用differential_evolution算法，找到Pareto最优解
5. **参数变化趋势监控**：智能触发优化（参数方差、守恒误差、时间间隔）
6. **跨指标联合优化**：利用指标间的物理关系（能量守恒等）联合优化

**接口定义**：

```python
class UniversalOptimizer:
    """通用参数优化器（共用模块）"""

    def __init__(self):
        logger.info("[参数优化] 初始化完成")

    def optimize(
        self,
        metric_key: str,
        method_id: str,
        optimization_level: str,  # 'global', 'station', 'device'
        station_id: Optional[int] = None,
        device_id: Optional[int] = None,
        start_time: datetime = None,
        end_time: datetime = None,
        task_id: str = None
    ) -> Dict:
        """
        执行参数优化（基于物理自洽性）

        Args:
            metric_key: 指标键
            method_id: 方法ID
            optimization_level: 优化级别
                - 'global': 全局级（station_id=None, device_id=None）
                - 'station': 泵站级（station_id=X, device_id=None）
                - 'device': 设备级（station_id=X, device_id=Y）
            station_id: 泵站ID（泵站级和设备级需要）
            device_id: 设备ID（设备级需要）
            start_time: 开始时间（用于加载历史数据）
            end_time: 结束时间
            task_id: 任务ID（用于日志关联）

        Returns:
            {
                'status': 'success' | 'failed' | 'skipped',
                'optimized_params': {...},
                'improvement': {...},
                'available_constraints': [...]
            }
        """
        logger.info(
            f"[参数优化] [task_id={task_id}] 开始优化 - "
            f"指标: {metric_key}, 方法: {method_id}, 级别: {optimization_level}",
            extra={
                'task_id': task_id,
                'metric_key': metric_key,
                'method_id': method_id,
                'optimization_level': optimization_level
            }
        )

        # 1. 加载所有相关指标的历史数据
        data = self._load_all_metrics_data(
            station_id, device_id, start_time, end_time
        )

        # 2. 加载当前参数
        current_params = shared_services.param_manager.load_parameters(
            metric_key, method_id, station_id, device_id
        )

        # 3. 检查可用约束
        available_constraints = self._check_available_constraints(
            metric_key, data
        )

        # 4. 检查约束数量是否足够
        if len(available_constraints) < 2:
            logger.error(
                f"[参数优化] [task_id={task_id}] 可用约束不足 - "
                f"约束数: {len(available_constraints)}, 最少需要: 2",
                extra={'task_id': task_id}
            )
            return {
                'status': 'failed',
                'reason': '可用约束不足',
                'available_constraints': available_constraints
            }

        # 5. 构建优化目标函数
        def objective(params):
            return self._calculate_physical_inconsistency(
                params, data, metric_key, available_constraints
            )

        # 6. 执行优化
        from scipy.optimize import minimize
        result = minimize(
            objective,
            x0=list(current_params.values()),
            bounds=self._get_param_bounds(metric_key, method_id),
            method='L-BFGS-B'
        )

        optimized_params = dict(zip(current_params.keys(), result.x))

        # 7. 评估优化效果
        improvement = self._evaluate_improvement(
            current_params, optimized_params, data, metric_key
        )

        logger.info(
            f"[参数优化] [task_id={task_id}] 优化完成 - "
            f"改进: {improvement['total_error_reduction']:.2%}",
            extra={
                'task_id': task_id,
                'optimized_params': optimized_params,
                'improvement': improvement
            }
        )

        # 8. 保存优化结果（如果改进显著）
        if improvement['total_error_reduction'] > 0.1:  # 改进超过10%
            self._save_optimized_parameters(
                metric_key, method_id,
                station_id, device_id,
                optimized_params
            )
            return {
                'status': 'success',
                'optimized_params': optimized_params,
                'improvement': improvement,
                'available_constraints': available_constraints
            }
        else:
            logger.warning(
                f"[参数优化] [task_id={task_id}] 优化效果不显著，不应用新参数",
                extra={'task_id': task_id}
            )
            return {
                'status': 'skipped',
                'reason': '优化效果不显著',
                'improvement': improvement
            }
```

### 5. ParameterManager（参数管理器）

**职责**：
- 加载计算参数（三级配置）
- 加载优化参数（三级配置）
- 参数优先级合并（设备 > 泵站 > 全局）

**接口定义**：

```python
class ParameterManager:
    """参数管理器（共用模块）"""

    def load_parameters(
        self,
        metric_key: str,
        method_id: str,
        station_id: int,
        device_id: int
    ) -> Dict[str, Any]:
        """
        加载参数（三级配置）

        优先级：设备级 > 泵站级 > 全局级

        Args:
            metric_key: 指标键
            method_id: 方法ID
            station_id: 泵站ID
            device_id: 设备ID

        Returns:
            合并后的参数字典
        """
        # 1. 单次查询获取所有级别的参数
        query = """
            SELECT
                param_name,
                param_value,
                param_type,
                station_id,
                device_id,
                CASE
                    WHEN device_id IS NOT NULL THEN 3  -- 设备级
                    WHEN station_id IS NOT NULL THEN 2  -- 泵站级
                    ELSE 1                              -- 全局级
                END as priority_level
            FROM calculation_parameters
            WHERE metric_key = %s
              AND method_id = %s
              AND (
                  (station_id IS NULL AND device_id IS NULL) OR  -- 全局
                  (station_id = %s AND device_id IS NULL) OR     -- 泵站
                  (station_id = %s AND device_id = %s)           -- 设备
              )
            ORDER BY priority_level DESC  -- 设备级优先
        """

        rows = self._execute_query(query, [
            metric_key, method_id,
            station_id, station_id, device_id
        ])

        # 2. 按优先级合并参数（高优先级覆盖低优先级）
        params = {}
        for row in reversed(rows):  # 从低优先级到高优先级
            param_name = row['param_name']
            param_value = self._cast_value(row['param_value'], row['param_type'])
            params[param_name] = param_value

        logger.info(
            f"[参数管理] 加载参数完成 - "
            f"指标: {metric_key}, 方法: {method_id}, "
            f"设备: {device_id}, 参数数量: {len(params)}",
            extra={
                'metric_key': metric_key,
                'method_id': method_id,
                'device_id': device_id,
                'param_count': len(params)
            }
        )

        return params

    def _cast_value(self, value: str, param_type: str) -> Any:
        """类型转换"""
        if param_type == 'float':
            return float(value)
        elif param_type == 'int':
            return int(value)
        elif param_type == 'bool':
            return value.lower() in ('true', '1', 'yes')
        else:
            return value
```

        self,
        params: Dict,
        data: Dict,
        metric_key: str,
        available_constraints: List[str]
    ) -> float:
        """
        计算物理不一致性（优化目标函数）

        Args:
            params: 待优化的参数
            data: 历史数据（包含所有相关指标）
            metric_key: 目标指标
            available_constraints: 可用的约束列表

        Returns:
            物理不一致性总误差（越小越好）
        """
        total_error = 0
        weights_sum = 0

        # 第1层：内部一致性
        if 'range_constraint' in available_constraints:
            total_error += 1.0 * self._calculate_range_error(params, data, metric_key)
            weights_sum += 1.0

        if 'non_negative_constraint' in available_constraints:
            total_error += 2.0 * self._calculate_non_negative_error(params, data, metric_key)
            weights_sum += 2.0

        # 第2层：物理关系
        if 'energy_conservation' in available_constraints:
            total_error += 20.0 * self._calculate_energy_error(params, data)
            weights_sum += 20.0

        if 'flow_conservation' in available_constraints:
            total_error += 10.0 * self._calculate_conservation_error(params, data)
            weights_sum += 10.0

        if 'pressure_relation' in available_constraints:
            total_error += 5.0 * self._calculate_pressure_error(params, data)
            weights_sum += 5.0

        # 第3层：相关性
        if 'power_correlation' in available_constraints:
            total_error += 2.0 * self._calculate_power_corr_error(params, data)
            weights_sum += 2.0

        if 'freq_correlation' in available_constraints:
            total_error += 2.0 * self._calculate_freq_corr_error(params, data)
            weights_sum += 2.0

        # 归一化
        if weights_sum > 0:
            return total_error / weights_sum
        else:
            raise ValueError("没有可用的优化约束")

### 1. Pipeline（流水线编排器）

**职责**：定义和执行指标的计算流程

**接口定义**：

```python
class MetricCalculationPipeline(ABC):
    """指标计算流水线基类"""

    def __init__(self, metric_key: str):
        self.metric_key = metric_key
        self.config = self._load_config()

        # 初始化各个阶段
        self.data_loader = self._create_data_loader()
        self.data_filter = self._create_data_filter()
        self.method_selector = self._create_method_selector()
        self.calculator = self._create_calculator()
        self.validator = self._create_validator()

    @abstractmethod
    def _create_data_loader(self) -> 'DataLoader':
        """创建数据加载器"""
        pass

    @abstractmethod
    def _create_data_filter(self) -> 'DataFilter':
        """创建数据过滤器"""
        pass

    @abstractmethod
    def _create_method_selector(self) -> 'MethodSelector':
        """创建方法选择器"""
        pass

    @abstractmethod
    def _create_calculator(self) -> 'Calculator':
        """创建计算执行器"""
        pass

    @abstractmethod
    def _create_validator(self) -> 'Validator':
        """创建结果验证器"""
        pass

    def execute(
        self,
        station_id: int,
        device_id: int,
        start_time: datetime,
        end_time: datetime,
        task_id: str
    ) -> Dict:
        """
        执行计算流水线

        流程：
        1. 数据获取
        2. 数据过滤
        3. 方法选择
        4. 计算执行
        5. 结果验证
        6. 数据写入

        Args:
            station_id: 泵站ID
            device_id: 设备ID
            start_time: 开始时间
            end_time: 结束时间
            task_id: 任务ID（用于日志关联）

        Returns:
            执行结果
        """
        logger.info(
            f"[流水线] [task_id={task_id}] 开始执行 - "
            f"指标: {self.metric_key}, 设备: {device_id}, "
            f"时间: [{start_time}, {end_time})",
            extra={'task_id': task_id, 'metric_key': self.metric_key}
        )

        try:
            # Stage 1: 数据获取
            raw_data = self.data_loader.load(
                station_id, device_id, start_time, end_time, task_id
            )

            # Stage 2: 数据过滤
            filtered_data = self.data_filter.filter(
                raw_data, station_id, device_id, task_id
            )

            # Stage 3: 方法选择
            selected_method = self.method_selector.select(
                filtered_data, station_id, device_id, task_id
            )

            # Stage 4: 计算执行
            results = self.calculator.calculate(
                filtered_data, selected_method,
                station_id, device_id, task_id
            )

            # Stage 5: 结果验证
            validated_results = self.validator.validate(
                results, station_id, device_id, task_id
            )

            # Stage 6: 数据写入
            write_result = shared_services.data_writer.write_batch(
                metric_key=self.metric_key,
                results=validated_results,
                station_id=station_id,
                device_id=device_id,
                task_id=task_id
            )

            logger.info(
                f"[流水线] [task_id={task_id}] 执行完成 - "
                f"写入行数: {write_result['written_count']}",
                extra={'task_id': task_id, 'written_count': write_result['written_count']}
            )

            return {
                'success': True,
                'metric_key': self.metric_key,
                'device_id': device_id,
                'selected_method': selected_method,
                'result_count': len(validated_results),
                'written_count': write_result['written_count']
            }

        except Exception as e:
            logger.error(
                f"[流水线] [task_id={task_id}] 执行失败: {e}",
                extra={'task_id': task_id, 'error': str(e)},
                exc_info=True
            )
            return {
                'success': False,
                'error': str(e)
            }

        """
        过滤数据

        过滤规则：
        1. 移除缺失值（NaN）
        2. 移除负值
        3. 移除异常值（超出合理范围）
        4. 移除停机数据（frequency < 3.0 Hz 或 power < 0.5 kW）
        """
        logger.info(
            f"[数据过滤] [task_id={task_id}] 开始过滤 - 原始行数: {len(data)}",
            extra={'task_id': task_id, 'original_count': len(data)}
        )

        original_count = len(data)

        # 1. 移除缺失值
        data = data.dropna()
        after_nan = len(data)

        # 2. 移除负值
        data = data[(data['main_flow'] >= 0) &
                    (data['power'] >= 0) &
                    (data['frequency'] >= 0)]
        after_negative = len(data)

        # 3. 移除停机数据
        data = data[(data['frequency'] >= 3.0) & (data['power'] >= 0.5)]
        after_threshold = len(data)

        logger.info(
            f"[数据过滤] [task_id={task_id}] 过滤完成 - "
            f"原始: {original_count}, "
            f"移除NaN: {original_count - after_nan}, "
            f"移除负值: {after_nan - after_negative}, "
            f"移除停机: {after_negative - after_threshold}, "
            f"最终: {after_threshold}",
            extra={
                'task_id': task_id,
                'original_count': original_count,
                'final_count': after_threshold
            }
        )

        return data
```

**示例实现（pump_flow_rate）**：

```python
class PumpFlowRateMethodSelector(MethodSelector):
    """pump_flow_rate 方法选择器"""

    # 方法优先级（从高到低）
    METHOD_PRIORITY = [
        ('method_a', 100),  # 功率×频率分摊
        ('method_b', 90),   # 累计流量导数
        ('method_c', 80),   # 单泵直接取总管流量
        ('method_d', 70),   # 功率分摊
        ('method_e', 60),   # 频率分摊
        ('method_f', 50),   # 数据驱动回归
    ]

    def select(
        self,
        data: pd.DataFrame,
        station_id: int,
        device_id: int,
        task_id: str
    ) -> str:
        """
        选择计算方法

        选择逻辑：
        1. 按优先级从高到低检查
        2. 检查依赖数据是否完整
        3. 检查条件是否满足
        4. 返回第一个满足条件的方法
        """
        logger.info(
            f"[方法选择] [task_id={task_id}] 开始选择方法",
            extra={'task_id': task_id}
        )

        for method_id, priority in self.METHOD_PRIORITY:
            if self._check_method_conditions(method_id, data, station_id, device_id):
                logger.info(
                    f"[方法选择] [task_id={task_id}] 选择方法: {method_id} (优先级: {priority})",
                    extra={'task_id': task_id, 'method_id': method_id, 'priority': priority}
                )
                return method_id

        raise ValueError("没有可用的计算方法")

    def _check_method_conditions(
        self,
        method_id: str,
        data: pd.DataFrame,
        station_id: int,
        device_id: int
    ) -> bool:
        """检查方法条件"""
        if method_id == 'method_a':
            # 需要：main_flow, power, frequency
            # 条件：至少2台泵运行
            return self._check_min_running_pumps(station_id, 2)
        elif method_id == 'method_b':
            # 需要：pump_cumulative_flow
            return 'cumulative_flow' in data.columns
        elif method_id == 'method_c':
            # 需要：main_flow
            # 条件：只有1台泵运行
            return self._check_min_running_pumps(station_id, 1)
        # ... 其他方法
        return False
```

## 模块间交互流程

### 完整计算流程

```
用户/定时任务
    ↓
[调度器] schedule_all_metrics()
    ↓
按指标顺序循环（pump_flow_rate → pump_head → ...）
    ↓
[调度器] schedule_single_metric()
    ↓
生成任务列表（按时间窗口和设备分片）
    ↓
并行执行任务（ThreadPoolExecutor）
    ↓
[流水线] execute()
    ├─ [数据获取] load() → 加载依赖数据
    ├─ [数据过滤] filter() → 过滤无效数据
    ├─ [方法选择] select() → 选择计算方法
    ├─ [计算执行] calculate() → 执行计算
    ├─ [结果验证] validate() → 验证结果
    └─ [数据写入] write_batch() → 批量写入
    ↓
等待所有任务完成
    ↓
进入下一个指标
```

### 参数优化流程（独立）

```
用户/定时任务
    ↓
[参数优化器] optimize_metric() 或 optimize_all_metrics()
    ↓
[参数管理器] load_parameters() → 加载当前参数
    ↓
[参数优化器] _load_all_metrics_data() → 加载所有相关指标数据
    ↓
[参数优化器] _check_available_constraints() → 检查可用约束
    ↓
[参数优化器] _calculate_physical_inconsistency() → 计算物理不一致性
    ↓
[scipy.optimize] minimize() → 执行优化
    ↓
[参数优化器] _evaluate_improvement() → 评估优化效果
    ↓
[参数管理器] save_parameters() → 保存优化参数
```

### 数据流示例

```
输入：
- 设备列表: [(14, 105), (14, 106), (15, 201)]
- 时间范围: 2025-09-30 00:00:00 ~ 2025-09-30 02:00:00
- 时间窗口: 1小时

任务分片：
- 任务1: pump_flow_rate, 设备105, [00:00-01:00]
- 任务2: pump_flow_rate, 设备105, [01:00-02:00]
- 任务3: pump_flow_rate, 设备106, [00:00-01:00]
- 任务4: pump_flow_rate, 设备106, [01:00-02:00]
- 任务5: pump_flow_rate, 设备201, [00:00-01:00]
- 任务6: pump_flow_rate, 设备201, [01:00-02:00]

并行执行（max_workers=4）：
- 线程1: 任务1
- 线程2: 任务2
- 线程3: 任务3
- 线程4: 任务4
- （等待线程空闲）
- 线程1: 任务5

等待所有任务完成 → 进入下一个指标（pump_head）
```

**用途**：存储三级参数配置（全局、泵站、设备）

```sql
CREATE TABLE calculation_parameters (
    id SERIAL PRIMARY KEY,
    station_id INT,                  -- NULL=全局, 非NULL=泵站/设备

    created_at TIMESTAMP,
    updated_at TIMESTAMP
);

**使用方式**：
- 全局参数：`station_id=NULL, device_id=NULL`
- 泵站参数：`station_id=X, device_id=NULL`

## 总结

### 核心设计决策

1. **按指标顺序计算**：先完成所有设备的 pump_flow_rate，再进行下一个指标
2. **共用模块全局唯一**：使用单例模式管理 Scheduler、DataWriter、Optimizer
3. **指标专用模块独立实现**：每个指标有自己的 Pipeline、DataLoader、MethodSelector等
4. **三级参数配置**：支持全局、泵站、设备三个级别的参数配置
5. **参数优化独立运行**：不是计算流水线的一部分，通过CLI命令或定时任务触发
6. **渐进式迁移**：先迁移 pump_flow_rate，验证无误后再迁移其他指标

### 预期收益

1. **代码清晰度提升**：
   - 单文件从2659行降低到<600行
   - 模块职责单一，易于理解

2. **可维护性提升**：
   - 添加新指标：只需创建新的指标目录
   - 修改计算逻辑：只需修改对应的指标模块
   - 调试问题：日志清晰，易于定位

3. **可测试性提升**：
   - 每个模块可以独立测试
   - 流水线可以整体测试
   - 测试覆盖率提高

4. **性能提升**：
   - 并行执行（设备间、时间窗口间）
   - 自适应批量大小
   - 减少不必要的数据库查询

5. **灵活性提升**：
   - 三级参数配置
   - 三级参数优化（基于物理自洽性）
   - 支持多种计算方法
