# 调度器执行和数据质量分析 - 研究结果

## 📋 研究发现

### 1. Scheduler使用方式

**类定义**：`app/services/calculation/shared/scheduler.py`

**主要方法**：
```python
scheduler = Scheduler(max_workers=10, enable_adaptive_chunk=True)

# 方法1：执行所有指标（按METRIC_ORDER顺序）
results = scheduler.schedule_all_metrics(
    device_ids=[1, 2, 3, 4, 5, 6],
    start_time=datetime(2025, 10, 22, 8, 0, 0, tzinfo=timezone.utc),
    end_time=datetime(2025, 10, 23, 7, 19, 37, tzinfo=timezone.utc),
    time_chunk_hours=None,  # 使用自适应分片
    metrics=None  # None表示执行所有METRIC_ORDER中的指标
)

# 方法2：执行单个指标
result = scheduler.schedule_single_metric(
    metric_key='pump_flow_rate',
    device_ids=[1, 2, 3, 4, 5, 6],
    start_time=start_time,
    end_time=end_time,
    time_chunk_hours=24
)
```

### 3. 数据时间范围

**实际数据范围**：
- 开始时间：2025-10-22 08:00:00 UTC
- 结束时间：2025-10-23 07:19:37 UTC
- 时长：约23小时
- 设备：1-6（6个泵设备）
- 泵站ID：1

### 4. 执行策略

**指标间串行**：
- 按METRIC_ORDER顺序依次执行
- 先完成所有设备的pump_flow_rate，再执行pump_inlet_pressure

**设备间并行**：
- 同一指标的不同设备并行计算
- 使用ThreadPoolExecutor，max_workers=10

**时间分片**：
- 支持固定分片（time_chunk_hours=24）
- 支持自适应分片（time_chunk_hours=None）

### 5. 返回结果结构

```python
{
    'metric_key': {
        'total_tasks': int,           # 总任务数
        'success_count': int,         # 成功任务数
        'failure_count': int,         # 失败任务数
        'total_points': int,          # 写入记录数
        'total_duration_seconds': float,  # 总耗时
        'avg_duration_per_task_seconds': float,  # 平均任务耗时
        'success_rate': str,          # 成功率
        'results': [TaskResult]       # 详细结果列表
    }
}
```

### 6. 数据质量分析需求

**统计维度**：
1. 每个指标的计算结果数量
2. 数据覆盖率（有效记录数 / 预期记录数）
3. 数据范围（最小值、最大值、平均值、标准差）
4. 异常值和缺失值
5. 不同设备的数据质量差异

**质量评价**：
1. 计算成功率
2. 数据完整性
3. 数据合理性（物理约束）
4. 潜在问题识别
