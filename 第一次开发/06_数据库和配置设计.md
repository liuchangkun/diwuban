## 1. 概述

### 1.1 设计目标

本文档定义特性曲线拟合系统的数据库设计和配置管理方案，包括：

1. **数据库设计**：存储拟合结果、历史版本、评估指标
2. **索引设计**：优化查询性能
3. **JSONB字段结构**：灵活存储复杂数据
4. **配置管理**：集中管理系统参数

### 1.2 数据库表总览

| 表名 | 说明 | 预估数据量 | 优先级 |
|-----|------|-----------|--------|
| `curve_fit_results` | 拟合结果主表 | 100,000行/年 | P0 |
| `curve_fit_params` | 拟合参数表 | 500,000行/年 | P0 |
| `curve_fit_metrics` | 拟合指标表 | 100,000行/年 | P0 |
| `curve_fit_latest` | 最新版本视图 | 3行/设备 | P0 |
| `v_curve_fit_full` | 完整拟合结果视图（三表联合） | - | P0 |
| `curve_fit_history` | 历史评估记录 | 500,000行/年 | P1 |
| `learned_constraints` | 学习约束参数表 | 18行（6设备×3曲线） | P1 |
| `constraint_change_history` | 约束参数变更历史表 | 200行/年 | P1 |

**表说明**：
- **curve_fit_results**：拟合结果主表，存储基本信息、数据信息、元数据
- **curve_fit_params**：拟合参数表，存储拟合系数和方法参数（支持fit/method两种类别）
- **curve_fit_metrics**：拟合指标表，存储评估指标（R²、RMSE、MAE、MAPE）
- **curve_fit_latest**：每个设备每条曲线的最新版本视图
- **v_curve_fit_full**：三表联合的便捷视图，简化常见查询
- **curve_fit_history**：存储历史评估记录，用于版本对比和稳定性分析
- **learned_constraints**：存储从历史数据学习的约束参数，支持自动验证和应用（新增于v2.1，v2.2更新）
- **constraint_change_history**：存储约束参数的变更历史，记录每次学习和应用的详细信息（新增于v2.2）

### 2.1 主表：curve_fit_results

> 🔴 **B5 说明：curve_type 枚举兼容性**

> 新设计采用简化命名（`qh`/`qp`/`qeta`）以便于代码处理。

```sql
-- 版本: v3.1

CREATE TABLE curve_fit_results (

    id SERIAL NOT NULL,

    -- ========== 基本信息 ==========
    -- 🔴 v2.5修复：device_id改为可空，支持泵组曲线（泵组曲线device_id=NULL）
    device_id INTEGER,

    data_end_time TIMESTAMP WITH TIME ZONE,
    data_point_count INTEGER,

    created_by VARCHAR(100),
    status VARCHAR(20) DEFAULT 'active',
    tags TEXT[],
    notes TEXT,

    -- ========== 约束 ==========

COMMENT ON COLUMN curve_fit_results.device_id IS '设备ID';
COMMENT ON COLUMN curve_fit_results.curve_type IS '曲线类型：qh/qp/qeta/heta/peta/qnpsh';

COMMENT ON COLUMN curve_fit_results.method_name IS '拟合方法名称';
COMMENT ON COLUMN curve_fit_results.data_start_time IS '拟合数据起始时间';
COMMENT ON COLUMN curve_fit_results.data_end_time IS '拟合数据结束时间';
COMMENT ON COLUMN curve_fit_results.data_point_count IS '拟合数据点数';
COMMENT ON COLUMN curve_fit_results.data_coverage_rate IS '数据覆盖率（0-1）';
COMMENT ON COLUMN curve_fit_results.physics_validation IS '物理约束验证结果（JSONB）';
COMMENT ON COLUMN curve_fit_results.historical_evaluation IS '历史数据评估结果（JSONB）';
COMMENT ON COLUMN curve_fit_results.normalization_params IS '归一化参数（JSONB）';
```

#### 2.1.3 P2阶段扩展字段【泵组支持】

> **设计原则**：采用向后兼容设计，新增字段全部可空，P0代码无需修改。

**P2扩展DDL（迁移脚本）**：

```sql
-- ============================================================
-- P2阶段扩展：在 curve_fit_results 表中添加泵组支持字段
-- 采用向后兼容设计，不破坏现有数据
-- 版本: v2.5
-- ============================================================

-- ========== 🔴 v2.5修复：修改device_id约束 ==========
-- 允许device_id为空，以支持泵组曲线存储
ALTER TABLE curve_fit_results ALTER COLUMN device_id DROP NOT NULL;

-- ========== 🆕 v2.5新增：curve_points字段 ==========
ALTER TABLE curve_fit_results
    ADD COLUMN IF NOT EXISTS curve_points JSONB;

COMMENT ON COLUMN curve_fit_results.curve_points IS '曲线特征点数据（采样点+关键点）';

-- ========== 新增泵组支持字段 ==========
ALTER TABLE curve_fit_results
    ADD COLUMN IF NOT EXISTS station_id BIGINT,              -- 泵站ID（泵组必填）
    ADD COLUMN IF NOT EXISTS pump_combination BIGINT[],      -- 泵组合数组，如 [1,2,3]
    ADD COLUMN IF NOT EXISTS pump_count INTEGER,             -- 泵数量
    ADD COLUMN IF NOT EXISTS group_type VARCHAR(30),         -- 泵组类型
    ADD COLUMN IF NOT EXISTS base_pump_id BIGINT,            -- 基准泵ID（同构泵组）
    ADD COLUMN IF NOT EXISTS correction_model JSONB;         -- 系统修正系数模型

-- ========== 新增约束 ==========
-- 泵组类型CHECK约束
ALTER TABLE curve_fit_results
    ADD CONSTRAINT chk_results_group_type
        CHECK (group_type IS NULL OR group_type IN (
            'homogeneous', 'heterogeneous', 'mixed', 'composite'
        ));

-- 🔴 v2.5修复：泵组唯一约束（确保同一泵组+曲线类型+版本唯一）
ALTER TABLE curve_fit_results
    ADD CONSTRAINT uq_results_group_curve_version
        UNIQUE(station_id, pump_combination, curve_type, version);

-- 🔴 v2.5修复：单泵/泵组互斥约束（确保二选一）
ALTER TABLE curve_fit_results
    ADD CONSTRAINT chk_results_pump_or_group CHECK (
        (device_id IS NOT NULL AND pump_combination IS NULL) OR
        (device_id IS NULL AND pump_combination IS NOT NULL)
    );

-- ========== 新增索引 ==========
CREATE INDEX IF NOT EXISTS idx_results_station ON curve_fit_results(station_id);
CREATE INDEX IF NOT EXISTS idx_results_pump_combination ON curve_fit_results USING GIN(pump_combination);
CREATE INDEX IF NOT EXISTS idx_results_group_type ON curve_fit_results(group_type);

-- ========== 新增注释 ==========
COMMENT ON COLUMN curve_fit_results.station_id IS 'P2扩展：泵站ID（泵组曲线必填）';
COMMENT ON COLUMN curve_fit_results.pump_combination IS 'P2扩展：泵组合数组，如 [1,2,3]';
COMMENT ON COLUMN curve_fit_results.pump_count IS 'P2扩展：泵数量';
COMMENT ON COLUMN curve_fit_results.group_type IS 'P2扩展：泵组类型（homogeneous/heterogeneous/mixed/composite）';
COMMENT ON COLUMN curve_fit_results.base_pump_id IS 'P2扩展：基准泵ID（同构泵组使用）';
COMMENT ON COLUMN curve_fit_results.correction_model IS 'P2扩展：系统修正系数模型（JSONB）';
```

| 字段名 | 类型 | 约束 | 说明 | 适用场景 |
|-------|------|------|------|---------|
| `curve_points` | JSONB | NULL | 曲线特征点数据 | 所有曲线（🆕 v2.5） |
| `station_id` | BIGINT | NULL | 泵站ID | 泵组曲线必填 |
| `pump_combination` | BIGINT[] | NULL | 泵组合数组 | 泵组曲线必填 |

| `group_type` | VARCHAR(30) | CHECK | 泵组类型 | 泵组曲线 |

**单泵 vs 泵组记录区分**：

| 记录类型 | device_id | station_id | pump_combination | 识别方式 |
|---------|:---------:|:----------:|:----------------:|---------|
| **单泵曲线** | ✅ 必填 | NULL | NULL | `device_id IS NOT NULL AND pump_combination IS NULL` |
| **泵组曲线** | NULL | ✅ 必填 | ✅ 必填 | `pump_combination IS NOT NULL` |

> **🔴 v2.5约束说明**：新增 `chk_results_pump_or_group` 约束确保每条记录要么是单泵曲线（有device_id），要么是泵组曲线（有pump_combination），不允许两者同时存在或同时为空。

### 2.2 参数表：curve_fit_params

#### 2.2.1 完整DDL

```sql
-- ============================================================
-- 表名: curve_fit_params
-- 描述: 曲线拟合参数表（存储拟合系数和方法参数）
-- 创建日期: 2025-01-28
-- 版本: v3.0
-- ============================================================

CREATE TABLE curve_fit_params (
    -- ========== 主键 ==========
    id SERIAL NOT NULL,

    -- ========== 外键关联 ==========
    result_id INTEGER NOT NULL,

    -- ========== 参数信息 ==========
    param_category VARCHAR(50) NOT NULL,
    param_key VARCHAR(100) NOT NULL,
    param_value DOUBLE PRECISION,
    param_text TEXT,

    -- ========== 元数据 ==========
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),

    -- ========== 约束 ==========
    CONSTRAINT pk_curve_fit_params PRIMARY KEY (id),
    CONSTRAINT fk_params_result_id
        FOREIGN KEY (result_id) REFERENCES curve_fit_results(id) ON DELETE CASCADE,
    CONSTRAINT uq_params_result_category_key
        UNIQUE(result_id, param_category, param_key),
    -- 🆕 P2扩展：添加 correction 和 synthesis 类别
    CONSTRAINT chk_params_category
        CHECK (param_category IN ('fit', 'method', 'correction', 'synthesis'))
);

-- ========== 索引 ==========
CREATE INDEX idx_params_result_id ON curve_fit_params(result_id);
CREATE INDEX idx_params_category ON curve_fit_params(param_category);
CREATE INDEX idx_params_key ON curve_fit_params(param_key);

-- ========== 表注释 ==========
COMMENT ON TABLE curve_fit_params IS '曲线拟合参数表（存储拟合系数和方法参数）';
COMMENT ON COLUMN curve_fit_params.id IS '主键ID';
COMMENT ON COLUMN curve_fit_params.result_id IS '外键关联主表curve_fit_results.id';
COMMENT ON COLUMN curve_fit_params.param_category IS '参数类别：fit/method/correction/synthesis';
COMMENT ON COLUMN curve_fit_params.param_key IS '参数名（如a0, a1, a2, degree, lambda等）';
COMMENT ON COLUMN curve_fit_params.param_value IS '数值型参数值';
COMMENT ON COLUMN curve_fit_params.param_text IS '文本型参数值（如字符串配置）';
COMMENT ON COLUMN curve_fit_params.created_at IS '创建时间';
```

#### 2.2.2 字段说明表

#### 2.9.2 特性曲线拟合所需的额定参数

| 参数键（param_key） | 说明 | 单位 | 存储方式 | 是否必需 |
|-------------------|------|------|---------|---------|
| `rated_flow` | 额定流量 | m³/h | 直接存储 | ✅ 必需 |
| `rated_head` | 额定扬程 | m | 直接存储 | ✅ 必需 |
| `rated_power` | 额定功率 | kW | 直接存储 | ✅ 必需 |
| `rated_efficiency` | 额定效率 | - | 计算得出 | ⚠️ 可选（可计算） |

#### 2.9.3 额定参数计算规则

**rated_efficiency（额定效率）计算公式**：

```python
# 公式：η = (ρ * g * Q * H) / (P * 1000)
# 其中：
# - ρ = 1000 kg/m³（水的密度）
# - g = 9.81 m/s²（重力加速度）
# - Q = rated_flow（m³/h）→ 需要转换为 m³/s
# - H = rated_head（m）
# - P = rated_power（kW）

rated_efficiency = (1000 * 9.81 * (rated_flow / 3600) * rated_head) / (rated_power * 1000)
```

**计算参数的存储**：

计算得出的参数应存储到`device_rated_params`表中，以便后续使用：

```sql
INSERT INTO device_rated_params (
    device_id,
    param_key,
    value_numeric,
    unit,
    source,
    created_at
) VALUES (
    1,
    'rated_efficiency',
    0.85,  -- 计算结果
    '-',
    'calculated',  -- 标记为计算得出
    NOW()
);
```

#### 2.9.4 读取额定参数的标准方法

**查询单个设备的所有额定参数**：

```sql
SELECT
    param_key,
    value_numeric,
    unit,
    source
FROM device_rated_params
WHERE device_id = 1
  AND param_key IN ('rated_flow', 'rated_head', 'rated_power', 'rated_efficiency')
  AND (effective_to IS NULL OR effective_to > NOW())
ORDER BY param_key;
```

**查询特定参数**：

```sql
SELECT value_numeric
FROM device_rated_params
WHERE device_id = 1
  AND param_key = 'rated_flow'
  AND (effective_to IS NULL OR effective_to > NOW())
ORDER BY effective_from DESC NULLS FIRST
LIMIT 1;
```

#### 2.9.5 参数缺失处理规则

**强制规则**：
1. ✅ **必须从`device_rated_params`表读取**，不允许使用硬编码或默认值
2. ✅ **参数不存在时必须输出错误日志**，不允许静默失败
3. ✅ **参数不存在时必须抛出异常**，中断拟合流程
4. ❌ **禁止使用任何默认值**（如 `device_params.get('rated_head', 50)`）

**错误日志示例**：


#### 4.1.1 JSONB字段命名规范

**目的**：确保所有JSONB字段的键名命名一致，便于理解和维护。

**命名原则**：

1. **使用蛇形命名法（snake_case）**
   - ✅ 正确：`min_flow_rate`、`max_head`、`learning_rate`
   - ❌ 错误：`minFlowRate`、`MaxHead`、`learning-rate`

2. **使用完整单词，避免缩写**
   - ✅ 正确：`minimum_flow_rate`、`maximum_head`
   - ❌ 错误：`min_flow`、`max_h`
   - ⚠️ 例外：通用缩写可接受（`max`、`min`、`avg`、`std`）

3. **使用物理意义明确的名称**
   - ✅ 正确：`rated_flow_rate`、`rated_head`、`rated_power`
   - ❌ 错误：`q_rated`、`h_rated`、`p_rated`

4. **嵌套对象使用分组**
   - ✅ 正确：`{"constraints": {"flow": {...}, "head": {...}}}`
   - ❌ 错误：`{"flow_constraints": {...}, "head_constraints": {...}}`

5. **数组字段使用复数形式**
   - ✅ 正确：`test_points`、`deviation_values`
   - ❌ 错误：`test_point`、`deviation_value`

6. **布尔字段使用is/has/enable前缀**
   - ✅ 正确：`is_valid`、`has_outliers`、`enable_cache`
   - ❌ 错误：`valid`、`outliers`、`cache`

7. **时间字段使用明确的后缀**
   - ✅ 正确：`created_at`、`updated_at`、`start_time`、`end_time`
   - ❌ 错误：`created`、`updated`、`start`、`end`

### 4.3 historical_evaluation（历史数据评估）

- 按 75%/25% 比例划分为拟合窗口和测试窗口

```python
class CurveFitter:

        if result.rmse > 5.0:  # ❌ 硬编码
            return False
        return True

# ✅ 正确示例：从配置读取
class CurveFitter:
    def __init__(self, config_reader):
        self._config = config_reader

    def validate(self, result):
        min_r_squared = self._config.get('validation.min_r_squared')
        max_rmse = self._config.get('validation.max_rmse')

        if min_r_squared is None:
            raise ParameterMissingError("缺少配置参数: min_r_squared")

        if result.r_squared < min_r_squared:
            return False
        if result.rmse > max_rmse:
            return False
        return True
```

```json
      "description": "系统设计工况"
    }
  },

  "operating_range": {
    "Q_min": 50,
    "Q_max": 300,
    "H_min": 11.0,
    "H_max": 41.6,
    "description": "推荐工作范围（避免气蚀和过载）"

```

**字段说明**：

| 字段 | 类型 | 说明 |
|------|------|------|
| `generated_at` | string | 特征点生成时间（ISO 8601格式） |
| `point_count` | integer | 总点数（采样点 + 关键点） |
| `formula` | string | 曲线公式（便于理解） |
| `sampling_points` | object | 均匀采样点 |
| `sampling_points.count` | integer | 采样点数量（默认20） |
| `sampling_points.Q` | array | 流量数组 |
| `sampling_points.H` | array | 扬程数组（与Q一一对应） |
| `key_points` | object | 关键工况点 |
| `key_points.zero_flow` | object | 零流量点（Q=0） |
| `key_points.rated` | object | 额定工况点 |
| `key_points.bep` | object | 最高效率点（Best Efficiency Point） |
| `key_points.max_flow` | object | 最大流量点（H=0） |
| `key_points.design` | object | 设计工作点 |
| `operating_range` | object | 推荐工作范围 |

**不同曲线类型的curve_points结构**：

```json
// QH曲线（流量-扬程）
{
  "sampling_points": {
    "Q": [...],
    "H": [...]
  },
  "key_points": {
    "zero_flow": {"Q": 0, "H": 42.5},
    "max_flow": {"Q": 350, "H": 0}
  }
}

// QP曲线（流量-功率）
{
  "sampling_points": {
    "Q": [...],
    "P": [...]
  },
  "key_points": {
    "zero_flow": {"Q": 0, "P": 15.0},
    "rated": {"Q": 180, "P": 45.0}
  }
}

// Q-η曲线（流量-效率）
{

    "Q": [...],
    "eta": [...]
  },

```

**使用场景**：

| 场景 | 使用方式 | 优势 |
|------|---------|------|
| **前端绘图** | 直接读取sampling_points | 无需后端计算 |
| **API返回** | 直接返回curve_points | 减少响应时间 |
| **工况标注** | 读取key_points | 关键点直接可用 |
| **范围检查** | 读取operating_range | 快速判断工作点是否合理 |
| **曲线对比** | 比较多条曲线的采样点 | 便于可视化对比 |

### 6.1 创建表和索引（三表分离设计）

```sql
-- ============================================================
-- 迁移脚本草稿: 创建特性曲线拟合三表分离结构
-- 状态: 待转移到 scripts/sql/migrations/048_create_curve_fit_tables.sql
-- 版本: v3.0
-- ============================================================

BEGIN;

-- ========== 1. 创建主表 curve_fit_results ==========
CREATE TABLE IF NOT EXISTS curve_fit_results (
    id SERIAL PRIMARY KEY,
    device_id INTEGER NOT NULL,
    curve_type VARCHAR(50) NOT NULL,
    version VARCHAR(50) NOT NULL,
    method_name VARCHAR(100) NOT NULL,
    data_start_time TIMESTAMP WITH TIME ZONE,
    data_end_time TIMESTAMP WITH TIME ZONE,
    data_point_count INTEGER,
    data_coverage_rate DOUBLE PRECISION,
    physics_validation JSONB,
    historical_evaluation JSONB,
    normalization_params JSONB,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
    created_by VARCHAR(100),
    status VARCHAR(20) DEFAULT 'active',
    tags TEXT[],
    notes TEXT,
    CONSTRAINT uq_results_device_curve_version UNIQUE(device_id, curve_type, version),
    CONSTRAINT chk_results_curve_type CHECK (curve_type IN ('qh', 'qp', 'qeta', 'heta', 'peta', 'qnpsh')),
    CONSTRAINT chk_results_status CHECK (status IN ('active', 'archived', 'deprecated')),
    CONSTRAINT chk_results_coverage_rate CHECK (data_coverage_rate IS NULL OR (data_coverage_rate >= 0 AND data_coverage_rate <= 1))
);

-- 主表索引
CREATE INDEX IF NOT EXISTS idx_results_device_curve ON curve_fit_results(device_id, curve_type);
CREATE INDEX IF NOT EXISTS idx_results_version ON curve_fit_results(version);
CREATE INDEX IF NOT EXISTS idx_results_created_at ON curve_fit_results(created_at DESC);
CREATE INDEX IF NOT EXISTS idx_results_status ON curve_fit_results(status);
CREATE INDEX IF NOT EXISTS idx_results_method ON curve_fit_results(method_name);
CREATE INDEX IF NOT EXISTS idx_results_physics_validation ON curve_fit_results USING GIN (physics_validation);

-- ========== 2. 创建参数表 curve_fit_params ==========
CREATE TABLE IF NOT EXISTS curve_fit_params (
    id SERIAL PRIMARY KEY,
    result_id INTEGER NOT NULL,
    param_category VARCHAR(50) NOT NULL,
    param_key VARCHAR(100) NOT NULL,
    param_value DOUBLE PRECISION,
    param_text TEXT,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
    CONSTRAINT fk_params_result_id FOREIGN KEY (result_id) REFERENCES curve_fit_results(id) ON DELETE CASCADE,
    CONSTRAINT uq_params_result_category_key UNIQUE(result_id, param_category, param_key),
    CONSTRAINT chk_params_category CHECK (param_category IN ('fit', 'method'))
);

-- 参数表索引
CREATE INDEX IF NOT EXISTS idx_params_result_id ON curve_fit_params(result_id);
CREATE INDEX IF NOT EXISTS idx_params_category ON curve_fit_params(param_category);
CREATE INDEX IF NOT EXISTS idx_params_key ON curve_fit_params(param_key);

-- ========== 3. 创建指标表 curve_fit_metrics ==========
CREATE TABLE IF NOT EXISTS curve_fit_metrics (
    id SERIAL PRIMARY KEY,
    result_id INTEGER NOT NULL UNIQUE,
    r_squared DOUBLE PRECISION,
    rmse DOUBLE PRECISION,
    mae DOUBLE PRECISION,
    mape DOUBLE PRECISION,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
    CONSTRAINT fk_metrics_result_id FOREIGN KEY (result_id) REFERENCES curve_fit_results(id) ON DELETE CASCADE,
    CONSTRAINT chk_metrics_r_squared CHECK (r_squared IS NULL OR (r_squared >= 0 AND r_squared <= 1))
);

-- 指标表索引
CREATE INDEX IF NOT EXISTS idx_metrics_result_id ON curve_fit_metrics(result_id);
CREATE INDEX IF NOT EXISTS idx_metrics_r_squared ON curve_fit_metrics(r_squared DESC);

-- ========== 4. 创建历史评估表 curve_fit_history ==========
CREATE TABLE IF NOT EXISTS curve_fit_history (
    id SERIAL PRIMARY KEY,
    result_id INTEGER NOT NULL REFERENCES curve_fit_results(id) ON DELETE CASCADE,
    evaluation_time TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
    test_period_start TIMESTAMP WITH TIME ZONE,
    test_period_end TIMESTAMP WITH TIME ZONE,
    test_point_count INTEGER,
    deviation_stats JSONB,
    pass_rate JSONB,
    segment_evaluation JSONB,
    overall_score DOUBLE PRECISION,
    notes TEXT
);

CREATE INDEX IF NOT EXISTS idx_history_result_id ON curve_fit_history(result_id);
CREATE INDEX IF NOT EXISTS idx_history_eval_time ON curve_fit_history(evaluation_time DESC);

-- ========== 5. 创建最新版本视图 curve_fit_latest ==========
CREATE OR REPLACE VIEW curve_fit_latest AS
WITH ranked AS (
    SELECT
        r.*,
        m.r_squared,
        m.rmse,
        m.mae,
        m.mape,
        ROW_NUMBER() OVER (PARTITION BY r.device_id, r.curve_type ORDER BY r.created_at DESC) as rn
    FROM curve_fit_results r
    LEFT JOIN curve_fit_metrics m ON r.id = m.result_id
    WHERE r.status = 'active'
)
SELECT
    id, device_id, curve_type, version, method_name,
    r_squared, rmse, mae, mape,
    physics_validation, historical_evaluation,
    normalization_params, created_at, status
FROM ranked WHERE rn = 1;

-- ========== 6. 创建完整拟合结果视图 v_curve_fit_full ==========
CREATE OR REPLACE VIEW v_curve_fit_full AS
SELECT
    r.id,
    r.device_id,
    r.curve_type,
    r.version,
    r.method_name,
    r.data_start_time,
    r.data_end_time,
    r.data_point_count,
    r.data_coverage_rate,
    r.physics_validation,
    r.historical_evaluation,
    r.normalization_params,
    r.created_at,
    r.created_by,
    r.status,
    r.tags,
    r.notes,
    m.r_squared,
    m.rmse,
    m.mae,
    m.mape,
    (
        SELECT jsonb_object_agg(p.param_key, p.param_value)
        FROM curve_fit_params p
        WHERE p.result_id = r.id AND p.param_category = 'fit'
    ) AS fit_params,
    (
        SELECT jsonb_object_agg(p.param_key, COALESCE(p.param_value::text, p.param_text))
        FROM curve_fit_params p
        WHERE p.result_id = r.id AND p.param_category = 'method'
    ) AS method_params
FROM curve_fit_results r
LEFT JOIN curve_fit_metrics m ON r.id = m.result_id;

-- ========== 7. 添加表注释 ==========
COMMENT ON TABLE curve_fit_results IS '曲线拟合结果主表（三表分离设计）';
COMMENT ON TABLE curve_fit_params IS '曲线拟合参数表（存储拟合系数和方法参数）';
COMMENT ON TABLE curve_fit_metrics IS '曲线拟合指标表（存储评估指标）';
COMMENT ON VIEW curve_fit_latest IS '每个设备每种曲线的最新活跃版本';
COMMENT ON VIEW v_curve_fit_full IS '三表联合的完整拟合结果视图';

COMMIT;
```

### 6.3 从单表迁移到三表（可选）

如果已有使用 `characteristic_curve_fits` 单表的数据，可使用以下脚本迁移：

```sql
-- ============================================================
-- 数据迁移脚本: 从单表迁移到三表分离
-- 前提: characteristic_curve_fits 表已存在且有数据
-- ============================================================

BEGIN;

-- 1. 迁移主表数据
INSERT INTO curve_fit_results (
    device_id, curve_type, version, method_name,
    data_start_time, data_end_time, data_point_count, data_coverage_rate,
    physics_validation, historical_evaluation, normalization_params,
    created_at, created_by, status, tags, notes
)
SELECT
    device_id, curve_type, version, method_name,
    data_start_time, data_end_time, data_point_count, data_coverage_rate,
    physics_validation, historical_evaluation, normalization_params,
    created_at, created_by, status, tags, notes
FROM characteristic_curve_fits;

-- 2. 迁移指标数据
INSERT INTO curve_fit_metrics (result_id, r_squared, rmse, mae, mape, created_at)
SELECT
    r.id, c.r_squared, c.rmse, c.mae, c.mape, c.created_at
FROM characteristic_curve_fits c
JOIN curve_fit_results r ON c.device_id = r.device_id
    AND c.curve_type = r.curve_type
    AND c.version = r.version;

-- 3. 迁移拟合参数（从JSONB展开）
INSERT INTO curve_fit_params (result_id, param_category, param_key, param_value, created_at)
SELECT
    r.id,
    'fit',
    key,
    value::double precision,
    c.created_at
FROM characteristic_curve_fits c
JOIN curve_fit_results r ON c.device_id = r.device_id
    AND c.curve_type = r.curve_type
    AND c.version = r.version,
LATERAL jsonb_each_text(c.fit_params) AS params(key, value)
WHERE c.fit_params IS NOT NULL;

-- 4. 迁移方法参数（从JSONB展开）
INSERT INTO curve_fit_params (result_id, param_category, param_key, param_text, created_at)
SELECT
    r.id,
    'method',
    key,
    value,
    c.created_at
FROM characteristic_curve_fits c
JOIN curve_fit_results r ON c.device_id = r.device_id
    AND c.curve_type = r.curve_type
    AND c.version = r.version,
LATERAL jsonb_each_text(c.method_params) AS params(key, value)
WHERE c.method_params IS NOT NULL;

COMMIT;
```

## 7. 配置文件设计

### 7.1 配置设计原则

#### 7.1.1 参数存储策略

**核心原则**：曲线拟合的**业务参数**存储在数据库中，**系统配置**复用项目现有配置文件。

| 参数类型 | 存储位置 | 说明 | 示例 |
|---------|---------|------|------|
| **拟合业务参数** | 数据库三表（`curve_fit_results` + `curve_fit_params` + `curve_fit_metrics`） | 可按设备/曲线/方法版本化管理，支持 ParameterOptimizer 动态优化 | 验证阈值、约束范围、方法参数 |
| **系统通用配置** | `configs/*.yaml` | 复用项目现有配置，禁止在曲线模块重复定义 | 数据库连接、日志、时区 |
| **模块特有配置** | `configs/curve_fitting.yaml` | 仅包含曲线拟合模块独有的系统级配置 | 缓存策略、并行控制、监控告警 |

#### 7.1.2 禁止在配置文件中定义的内容

以下参数**必须存储在数据库**，禁止放在配置文件中：

```yaml
# ❌ 错误：这些参数不应出现在配置文件中
curve_fitting:
  qh:
    validation:
      r_squared_min: 0.95      # ❌ 应存储在 method_params JSONB
      monotonicity: "decreasing" # ❌ 应存储在 physics_validation JSONB
    constraints:
      H0_min: 0                # ❌ 应存储在 method_params JSONB
      H0_max: 200              # ❌ 应存储在 method_params JSONB

# ❌ 错误：historical_evaluation 配置不应在静态配置文件中
historical_evaluation:
  deviation_thresholds:        # ❌ 评估策略可能需要动态调整
    within_5_percent: 0.90
```

**这些参数的正确存储位置**：

| 参数 | 存储字段 | 说明 |
|------|---------|------|
| `r_squared_min`, `rmse_max` 等验证阈值 | `method_params` JSONB | 方法级别参数，可版本化 |
| `monotonicity`, `convexity` 等约束 | `physics_validation` JSONB | 物理约束验证结果 |
| `H0_min/max`, `K_min/max` 等边界 | `method_params` JSONB | 边界约束参数 |
| `deviation_thresholds` 等评估配置 | `historical_evaluation` JSONB | 历史评估结果和配置 |
| `recommended_methods` 方法列表 | 由 MethodSelector 动态选择 | 基于数据特征和历史表现 |

#### 7.2.1 现有配置文件清单

项目已在 `configs/` 目录下提供以下配置文件，**曲线拟合模块应直接复用，禁止重复定义**：

| `configs/error_handling.yaml` | 重试策略、熔断器 | 直接复用 |

#### 7.2.2 复用现有配置加载器

项目已提供统一的配置加载器 `app.core.config.loader_new`，**曲线拟合模块应复用，禁止重新实现**：

### 7.4 加载曲线拟合配置

**复用现有配置加载器**，仅需读取曲线拟合特有配置文件：

```python
from pathlib import Path
from typing import Dict, Any
import yaml

from app.core.config.loader_new import load_settings, Settings


def load_curve_fitting_config(
    config_dir: Path = Path("configs")
) -> Dict[str, Any]:
    """
    加载曲线拟合模块配置

    1. 复用项目全局配置（数据库、日志、系统）
    2. 加载曲线拟合特有配置

    Args:
        config_dir: 配置文件目录

        Dict[str, Any]: 曲线拟合配置字典

    curve_fitting_path = config_dir / "curve_fitting.yaml"

    if not curve_fitting_path.exists():
        return _get_default_curve_fitting_config()

    with open(curve_fitting_path, 'r', encoding='utf-8') as f:
        return yaml.safe_load(f) or {}


def _get_default_curve_fitting_config() -> Dict[str, Any]:
    """返回默认的曲线拟合配置"""
    return {
        "cache": {
            "enabled": True,
            "backend": "memory",
            "lru": {"max_size": 1000, "max_memory_mb": 512},
            "ttl": {"curve_result": 3600, "device_params": 86400}
        },
        "parallel": {
            "enabled": True,
            "max_workers": 4,
            "batch_size": 100
        },
        "preprocessing": {
            "min_data_points": 100,
            "max_data_points": 100000
        }
    }


# ============================================================
# 使用示例
# ============================================================

# 1. 加载全局配置（复用现有加载器）
settings: Settings = load_settings(Path("configs"))

# 2. 加载曲线拟合特有配置
```

**ParameterOptimizer 动态优化参数**：

```python
class ParameterOptimizer:
    """参数优化器 - 从数据库读取历史参数并优化"""

    def get_optimized_params(
        self,
        device_id: int,
        curve_type: str,
        method_name: str
    ) -> Dict[str, Any]:
        """
        获取优化后的方法参数

        1. 从数据库加载该设备/曲线/方法的历史最佳参数
        2. 根据历史评估结果动态调整阈值
        3. 返回优化后的参数
        """
        # 查询历史最佳记录
        historical_params = self._load_historical_best(
            device_id, curve_type, method_name
        )

        if historical_params:
            # 基于历史表现优化参数
            return self._optimize_from_history(historical_params)
        else:
            # 首次拟合，使用模块内置默认值
            return self._get_default_params(curve_type, method_name)
```

## 8. 环境变量说明

### 8.1 环境变量使用原则

**核心原则**：曲线拟合模块**复用项目全局环境变量**，不需要单独的 `.env` 文件。

#### 8.1.1 已有的全局环境变量

项目已在 `configs/database.yaml` 等配置文件中定义了所有必要的配置，**禁止通过环境变量覆盖数据库配置**（参见 `app/core/config/loader_new.py` 配置优先级说明）：

| 配置项 | 来源 | 说明 |
|-------|------|------|
| 数据库连接 | `configs/database.yaml` | 仅从 YAML 加载，ENV/CLI 覆盖被禁止 |
| 日志配置 | `configs/logging.yaml` | 仅从 YAML 加载 |
| 系统配置 | `configs/system.yaml` | 仅从 YAML 加载 |

#### 8.1.2 曲线拟合模块不需要环境变量

由于：
1. 数据库配置由项目全局配置管理，禁止 ENV 覆盖
2. 缓存使用内存缓存（禁止 Redis），无需外部服务配置
3. 日志配置由项目全局日志系统管理
4. 曲线拟合的业务参数存储在数据库中

因此，**曲线拟合模块无需定义独立的环境变量或 `.env` 文件**。

### 8.2 特殊情况：开发/测试环境

如果在开发或测试环境中需要临时覆盖配置，可以使用项目全局的 `.env` 文件：

```bash
# 项目根目录 .env（仅开发/测试环境使用）
# 注意：生产环境应使用 configs/*.yaml 配置文件

# 部分 ingest 配置支持 ENV 覆盖（见 loader_new.py 白名单）
INGEST_BATCH_SIZE=5000
INGEST_MAX_WORKERS=4
```

**注意**：数据库配置（`DB_HOST`、`DB_PORT` 等）**不在 ENV 覆盖白名单中**，因此设置这些环境变量不会生效。

### 9.1 数据库性能优化建议

| 优化项 | 建议 | 说明 |
|-------|------|------|
| **分区** | **不需要分区** | 当前数据量（6台设备×6种曲线×每月1版本≈432条/年）单表完全满足需求 |
| **归档** | 定期归档旧版本 | 将deprecated状态的记录移至归档表 |
| **VACUUM** | 定期VACUUM ANALYZE | 保持统计信息准确 |
| **连接池** | 使用连接池 | 避免频繁建立连接（复用项目全局连接池`app/adapters/db/pool.py`） |

> **⚠️ 关于分区的说明**：
> - 当前系统规模（6台设备）不需要分区策略
> - 预计年数据量：6设备 × 6曲线类型 × 12月 = 432条记录/年
> - 即使运行10年，总数据量也仅约4,320条，单表完全满足性能需求
> - 如果未来设备数量扩展到100+台，可考虑按`device_id`范围分区
