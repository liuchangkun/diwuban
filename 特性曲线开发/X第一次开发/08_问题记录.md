## 🆕 新发现问题（2025-12-02 研究分析）

> **背景**：在研究动态运行参数、混合泵组、异构泵组对特性曲线拟合的影响时，发现以下设计缺陷。

### D1. 缺少稳态识别模块 ✅ 已解决

**发现日期**：2025-12-02
**严重程度**：🔴 阻塞
**状态**：✅ 已解决
**解决日期**：2025-12-02
**影响范围**：预处理层、数据提取层

**问题描述**：
设计文档中没有稳态识别模块，无法区分稳态运行数据和过渡态数据。泵启动/停止过程、频率调节过程、负荷突变导致的瞬态数据会被纳入拟合，降低拟合精度。

**解决方案**：
采用**方案A+C组合**（phase字段过滤 + 变化率检测）：
1. **复用现有能力**：`mv_device_running_1s.phase = 1` 过滤启停过渡期
2. **新增变化率检测**：频率0.5Hz/min, 压力2%/min, 流量5%/min
3. **最小稳态持续时间**：5分钟
4. **参数可配置**：存储在数据库配置表

**新增模块**：`SteadyStateDetector`（详见02文档8.4节）

---

#### 📊 现有系统能力分析（2025-12-02）

**已有相关功能**：

1. **`fn_startstop_windows`**（启停窗口识别）：
   - 位置：`scripts/sql/m1/003_fn_startstop_windows.sql`
   - 功能：基于多指标（电流、功率、频率）识别启停/非稳态窗口
   - 参数：`p_ramp_thr`（斜率阈值）、`p_jitter_thr`（抖动阈值）
   - 返回：`win_type`（startup/shutdown/startstop）、时间窗口

2. **`fn_running_state_1s`**（逐秒运行状态）：
   - 位置：`scripts/sql/m1/011_fn_running_state_1s.sql`
   - 功能：从阈值表读取，按秒输出 is_running（滞回+缺报延续）
   - 输出：`is_running`、`composite_z`、`ramp`、`jitter_3s`

3. **`mv_device_running_1s`**（物化视图）：
   - 字段：`running`（0/1）、`phase`（0=停止, 1=运行, 2=启动中, 3=停止中）
   - 当前设计已使用：`running = 1` 过滤非运行数据

4. **`PhysicsBasedOutlierDetector`**（02文档设计）：
   - Layer 3：变化率检测（`|ΔValue/Δt| ≤ max_rate_of_change`）
   - 只检测单点变化率，非稳态窗口识别

**关键差距**：
- ✅ 有启停窗口识别
- ❌ 未集成到特性曲线拟合流程
- ❌ 频率调节过渡期未识别
- ❌ `phase = 2/3` 未被使用

#### 🔧 解决方案对比（5种方案）

##### 方案A：复用 `mv_device_running_1s.phase` 字段 ⭐ 推荐

**原理**：利用现有物化视图的 `phase` 字段过滤启停过渡期

**实现**：
```sql
SELECT ...
FROM fact_measurements fm
JOIN mv_device_running_1s r ON r.device_id = fm.device_id AND r.ts_bucket = fm.ts_bucket
WHERE r.running = 1
  AND r.phase = 1  -- 仅保留稳定运行期，排除 phase=2(启动中) 和 phase=3(停止中)
```

**优点**：
- 零开发成本，直接使用现有字段
- 已有成熟的滞回/缺报延续机制
- 物化视图已预计算，查询高效

**缺点**：
- 只识别启停过渡，不识别频率调节过渡
- `phase` 字段的计算逻辑需要验证准确性
- 依赖物化视图刷新策略

**适用场景**：快速实现，MVP阶段

---

##### 方案B：调用 `fn_startstop_windows` 过滤启停窗口

**原理**：在数据提取时排除启停窗口时段

**实现**：
```python
def filter_startup_shutdown_windows(device_id, start_time, end_time, data):
    # 获取启停窗口
    windows = call_fn_startstop_windows(device_id, start_time, end_time,
                                        ramp_thr=0.5, jitter_thr=0.8,
                                        startup_cooldown=10, shutdown_cooldown=10)

    # 排除窗口内的数据点
    for win in windows:
        data = data[(data['ts_bucket'] < win.start) | (data['ts_bucket'] > win.end)]

    return data
```

**优点**：
- 利用现有成熟算法
- 参数可调（`ramp_thr`、`jitter_thr`）
- 包含冷却期扩展

**缺点**：
- 需要在Python层调用存储过程
- 启停窗口定义可能过于严格
- 不识别频率调节过渡

**适用场景**：需要精确控制启停窗口排除的场景

##### 方案C：变化率窗口法（滑动窗口检测） ⭐ 推荐

**原理**：基于关键指标的变化率识别非稳态窗口

**实现**：
```python
class SteadyStateDetector:
    def __init__(self, config):
        self.freq_rate_threshold = config.get('freq_rate_threshold', 0.5)  # Hz/min
        self.pressure_rate_threshold = config.get('pressure_rate_threshold', 0.02)  # 2%/min
        self.flow_rate_threshold = config.get('flow_rate_threshold', 0.05)  # 5%/min
        self.min_steady_duration = config.get('min_steady_duration', 300)  # 5 min
        self.window_size = config.get('window_size', 60)  # 1 min sliding window

    def detect(self, data: pd.DataFrame) -> pd.DataFrame:
        # 计算滑动窗口变化率
        data['freq_rate'] = data['pump_frequency'].diff().abs() / (1/60)  # Hz/min
        data['pressure_rate'] = data['pump_outlet_pressure'].pct_change().abs() * 60  # %/min
        data['flow_rate'] = data['pump_flow_rate'].pct_change().abs() * 60  # %/min

        # 标记非稳态点
        data['is_transient'] = (
            (data['freq_rate'] > self.freq_rate_threshold) |
            (data['pressure_rate'] > self.pressure_rate_threshold) |
            (data['flow_rate'] > self.flow_rate_threshold)
        )

        # 扩展非稳态窗口（前后各30秒）
        data['is_transient'] = data['is_transient'].rolling(61, center=True).max().fillna(0)

        # 过滤短稳态段
        data['is_steady'] = ~data['is_transient']
        data = self._filter_short_steady_segments(data, self.min_steady_duration)

        return data[data['is_steady']]
```

**优点**：
- 可识别频率调节过渡期
- 参数可配置，存储在数据库
- 逻辑清晰，易于调试
- 可与方案A/B组合使用

**缺点**：
- 需要新开发模块
- 阈值参数需要调优
- 对数据质量敏感（缺失值影响变化率计算）

**适用场景**：生产环境，需要精细控制的场景

**前提条件**：

#### 🔧 解决方案对比（6种方案）

##### 方案A：相似定律归一化（全归一到50Hz）⭐ 推荐

**原理**：使用相似定律将所有运行点归一化到额定频率50Hz

**公式**：
```
Q_50 = Q × (50/f)
H_50 = H × (50/f)²
P_50 = P × (50/f)³
η_50 = η  （效率不随频率变化，近似）
```

**实现位置**：预处理层 `FrequencyNormalizer`

**优点**：
- 物理意义明确，符合泵工程实践
- 输出单一特性曲线，便于存储和使用
- 现有代码已使用类似方法（`pump_speed`计算用频率比例）
- 适用于预测：知道频率后可反向推导实际值

**缺点**：
- 相似定律在低频(<30Hz)时精度下降
- 效率曲线的频率修正需要额外处理（Moody修正）
- 需要额外存储原始频率信息

**适用场景**：标准变频泵（频率30-50Hz范围）

---

##### 方案B：频率分段拟合（多条曲线）

**原理**：按频率区间分别拟合独立曲线

**分段示例**：
```
段1: f ∈ [25, 35) Hz → 曲线1
段2: f ∈ [35, 42) Hz → 曲线2
段3: f ∈ [42, 50] Hz → 曲线3
```

**优点**：
- 避免相似定律的低频误差
- 每段曲线精度高
- 可发现不同频段的泵特性差异

**缺点**：
- 存储复杂度高（每台泵多条曲线）
- 频段边界可能数据不足
- 预测时需要插值或选择最近段
- 曲线切换点可能不连续

**适用场景**：需要高精度、频率跨度大的场景

---

##### 方案C：三维曲面拟合（频率作为第三变量）

**原理**：H = f(Q, freq) 或 P = f(Q, freq)

**模型示例**：
```
H = a₀ + a₁Q + a₂Q² + a₃f + a₄f² + a₅Qf
```

**优点**：
- 一个模型覆盖所有工况
- 可捕捉频率-流量交互效应
- 预测时无需额外转换

**缺点**：
- 模型复杂度高，过拟合风险
- 需要更多数据点（覆盖Q-f二维空间）
- 可视化困难（三维曲面）
- 与传统泵曲线表示方式不兼容

**适用场景**：数据量充足、需要精细建模的场景

---

##### 方案D：不归一化直接拟合（现状）

**原理**：忽略频率差异，直接用所有数据拟合

**优点**：
- 实现最简单
- 适用于软启动泵（频率恒定50Hz）

**缺点**：
- 变频泵拟合结果严重失真
- R²值低、RMSE高
- 预测值不可靠

**适用场景**：仅适用于软启动泵或工频泵

---

##### 方案E：混合策略（根据泵类型自动选择）⭐ 推荐

**原理**：根据 `pump_type` 自动选择处理策略

**逻辑**：
```python
if pump_type == 'soft_start':
    # 软启动泵：直接拟合（方案D）
    pass
elif pump_type == 'variable_frequency':
    freq_std = calculate_frequency_std(data)
    if freq_std < 2.0:
        # 类似工频运行（如设备5）：直接拟合
        pass
    else:
        # 真正变频运行：使用相似定律归一化（方案A）
        data = normalize_by_affinity_laws(data, rated_freq=50)
```

**优点**：
- 兼容所有泵类型
- 利用现有 `dim_devices.pump_type` 字段
- 自动适应实际运行模式
- 实现复杂度适中

**缺点**：
- 需要维护多个处理路径
- 阈值参数需要调优

**适用场景**：混合泵组环境（推荐作为生产方案）

---

##### 方案F：相似定律+残差修正（高精度版）

**原理**：先用相似定律归一化，再用残差模型修正低频误差

**步骤**：
1. 用相似定律归一化到50Hz
2. 拟合基础曲线 H_base = f(Q)
3. 计算残差 ε = H_actual - H_predicted
4. 建立残差修正模型 ε = g(f, Q)
5. 最终预测 H = H_base + ε

**优点**：
- 结合物理模型和数据驱动
- 高精度，适用于全频率范围
- 保留物理可解释性

**缺点**：
- 实现复杂
- 需要更多数据验证
- 计算开销较高

**适用场景**：高精度要求的关键应用

| 特性 | 软启动泵 | 变频泵 | 类工频变频泵 |
|------|---------|--------|------------|
| 运行频率 | 固定50Hz | 25-50Hz变化 | 约50Hz |
| 处理策略 | 直接拟合 | 相似定律归一化 | 直接拟合 |
| 识别条件 | pump_type='soft_start' | pump_type='variable_frequency' 且 freq_std>2 | pump_type='variable_frequency' 且 freq_std<2 |

**详见**：02文档8.5节 `FrequencyNormalizer`、8.6节 `DeviceTypeDetector`

### D7. 场景识别机制缺失 ✅ 已解决

**发现日期**：2025-12-02
**严重程度**：🔴 阻塞
**状态**：✅ 已解决
**解决日期**：2025-12-02
**影响范围**：全流程

**问题描述**：
设计文档没有明确说明如何区分不同的拟合场景：
- 单泵 vs 泵组
- 软启泵 vs 变频泵 vs 类工频变频泵
- 同构泵组 vs 异构泵组 vs 混合泵组

**解决方案**：
新增 `ScenarioDetector`（场景识别器）模块，统一识别拟合场景：

1. **单泵场景识别**（P0阶段）：
   - `SOFT_START_SINGLE`：`pump_type='soft_start'`
   - `VFD_SINGLE`：`pump_type='variable_frequency'` 且 `freq_std > 2`
   - `QUASI_FIXED_FREQ_SINGLE`：`pump_type='variable_frequency'` 且 `freq_std < 2`

2. **泵组场景识别**（P2阶段）：
   - `HOMOGENEOUS_GROUP`：所有泵功率差异 < 10%
   - `HETEROGENEOUS_GROUP`：各泵功率差异 ≥ 10%
   - `MIXED_GROUP`：同时存在变频泵和软启泵
   - `GROUP_COMPOSITE`：请求泵组综合曲线

3. **集成位置**：阶段0.5（时间窗口划分之后、数据提取之前）

**详见**：02文档8.7节 `ScenarioDetector`

## 📝 常见问题和解决方案（FAQ）

### Q1：如何在新建对话后恢复工作进度？

**A**：按照以下步骤恢复：
1. 读取 `特性曲线开发/第一次开发/07_进度跟踪.md` 查看当前进度
2. 读取 `特性曲线开发/第一次开发/01_完整开发计划和跟踪.md` 了解整体计划
3. 读取 `特性曲线开发/第一次开发/08_问题记录.md` 了解已知问题
4. 检查代码实现状态：`app/services/characteristic_curves/`
5. 运行测试验证：`pytest tests/services/characteristic_curves/ -v`
6. 继续下一个任务

### Q2：如何选择合适的拟合方法？

**A**：参考以下文档：
- `特性曲线开发/第一次开发/05_188种方法完整目录.md` - 188种方法分类和选择指南
- `特性曲线开发/第一次开发/05_188种方法完整目录.md#9.4节` - P0核心方法（14种首选方法）
- 根据场景选择：快速拟合、高精度、物理约束、鲁棒性、小数据、外推
- 使用 `MethodSelector.get_recommended_methods()` 获取推荐方法（参考02文档5.3节）

### Q3：如何处理拟合失败的情况？

**A**：按照以下降级策略：
1. 尝试使用更简单的方法（如从三次降级到二次）
2. 调整参数初始值
3. 放宽物理约束（带警告）
4. 使用插值方法作为最后手段
5. 记录失败原因，供后续分析

### Q4：如何验证拟合结果的质量？

**A**：使用以下指标：
- **R²**：>0.90为良好，>0.95为优秀
- **平均相对偏差**：<10%为良好，<5%为优秀
- **通过率**（偏差<5%）：>70%为良好，>85%为优秀
- **物理约束验证**：必须全部通过
- **历史数据评估**：使用测试数据验证

### Q5：如何处理数据质量问题？

**A**：使用预处理层：
1. **数据清洗**：去除异常值、缺失值
2. **归一化**：标准化数据范围
3. **特征工程**：提取有用特征
4. 如果数据质量太差，考虑使用更鲁棒的方法（如机器学习方法）

### Q6：如何优化拟合性能？

**A**：使用以下优化策略：
1. **批处理**：使用 `BatchProcessor` 处理大数据量
2. **缓存**：使用 `CacheManager` 缓存拟合结果
3. **参数优化**：使用 `ParameterOptimizer` 优化参数初始值
4. **并行处理**：对于多设备、多曲线，使用并行处理

### Q7：如何处理物理约束冲突？

**A**：按照以下优先级：
1. **优先满足物理约束**：使用约束优化（Mode 2）
2. **如果无法满足**：使用后验证证（Mode 1）并记录警告
3. **如果仍然冲突**：允许强制拟合（带明显警告），供人工审查
4. **记录冲突原因**：供后续分析和改进

### Q8：如何管理拟合结果的版本？

**A**：使用版本管理机制：
- **版本格式**：YYYYMMDD_HHMMSS（时间戳）
- **存储**：采用三表分离设计（参考06文档第2节）
  - `curve_fit_results` - 拟合结果主表
  - `curve_fit_params` - 拟合参数表
  - `curve_fit_metrics` - 拟合指标表
- **历史保留**：所有版本永久保存
- **版本对比**：使用 `compare-versions` CLI命令对比不同版本（参考01文档3.2节阶段8）
- **回滚**：可以回滚到任意历史版本
