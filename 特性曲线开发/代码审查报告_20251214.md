## 2. 发现的问题

### 2.1 严重问题（需要立即修复）

#### P1-001: 参数命名不一致
- **位置**: `curve_fit_params` 表
- **问题**: result_id=1 使用 `a0,a1,a2`，result_id=8 使用 `a,b,c`
- **影响**: 其他系统加载曲线时无法正确解析参数
- **建议**: 统一使用 `a0,a1,a2...` 命名规范

#### P1-002: pump_characteristic_curves 表空数据
- **位置**: 数据库表
- **问题**: 该表设计存在但无数据，且表结构与代码中 FitResult 不匹配
- **影响**: 可能导致数据存储混乱
- **建议**: 明确该表用途，或清理冗余表

#### P1-003: method_id 与 method_name 混用
- **位置**: `ResultStorage.load()` 方法 (第291-293行)
- **问题**: `method_id=row[4]` 实际使用的是 method_name
- **代码**: 
```python
fit_result = FitResult(
    method_id=row[4],  # method_name作为method_id ← 错误
    method_name=row[4],
```
- **影响**: 从数据库加载的结果 method_id 字段不正确
- **建议**: 在数据库添加 method_id 列，或修正代码逻辑

#### P1-004: 方法注册表无法实例化方法 ❗❗❗
- **位置**: `MethodRegistry.get_method()` 方法 (第188-190行)
- **问题**: 调用 `method_class(method_name=..., method_id=...)` 但方法类的 `__init__` 不接受这些参数
- **影响**: **整个方法注册表无法正常工作**，`get_method()` 始终抛出异常
- **错误信息**: `TypeError: MathPoly2Method.__init__() got an unexpected keyword argument 'method_name'`
- **根因**: 
  - `MethodRegistry.get_method()`: `return method_class(method_name=..., method_id=...)`
  - `MathPoly2Method.__init__(self)`: 无参数版本
- **修复方案**: 
  1. 方案A: 修改所有方法类的 `__init__` 接受参数
  2. 方案B: 修改 `get_method()` 不传递参数，或检查签名

#### P1-005: 流水线调用get_method参数不匹配 ❗❗❗
- **位置**: `CurveFittingPipeline._stage_curve_fit()` (第872行)
- **问题**: 调用 `self._method_registry.get_method(method_id)` 只传了一个参数
- **正确调用**: `get_method(curve_type, method_id)` 需要两个参数
- **影响**: **整个拟合流程无法运行**
- **代码**:
```python
# 错误
method = self._method_registry.get_method(method_id)
# 应该是
method = self._method_registry.get_method(context.curve_type, method_id)
```

#### P1-006: DataExtractor 使用不存在的数据库列
- **位置**: `shared/data_extractor.py` 第110-126行
- **问题**: SQL查询引用 `fm.flow`, `fm.head`, `mv_device_running_1s` 等不存在的列/表
- **数据库结构**: `fact_measurements` 表实际包含 `device_id`, `metric_id`, `value`, `ts_bucket`
- **影响**: **数据提取无法运行**

### 2.2 中等问题（建议修复）

#### P2-001: MathPoly2Method.__init__ 参数不一致
- **位置**: `methods/mathematical/polynomial.py` 第34-36行
- **问题**: `__init__(self)` 无参数，但基类 `BaseMethod.__init__` 需要 `method_name, method_id`
- **代码**:
```python
def __init__(self) -> None:
    super().__init__(method_name="2次多项式", method_id="math_poly_2")
```
- **建议**: 保持一致性，允许外部传入参数

#### P2-002: 约束参数未实际使用
- **位置**: `MathPoly2Method.fit()` 方法
- **问题**: `constraints` 参数接收但未使用
- **代码**:
```python
def fit(self, X, y, constraints=None, **kwargs):
    # constraints 未被使用
    coefficients = np.polyfit(X, y, self.degree)
```
- **影响**: Q-H曲线 a2 应为负数的物理约束未被强制执行
- **建议**: 实现约束拟合或至少验证约束

#### P2-003: 数据清洗器缺少边界检查
- **位置**: `preprocessing/data_cleaner.py`
- **问题**: 物理约束检测方法使用 `rated_head` 但没有处理 Q 轴边界
- **建议**: 添加 Q 轴物理范围检查 (0 < Q < Q_max)

#### P2-004: MAPE 值单位不一致
- **位置**: `curve_fit_metrics` 表
- **问题**: 有些 MAPE=0.0123 (小数形式)，有些 MAPE=2.5 (百分比形式)
- **影响**: 质量评估不准确
- **建议**: 统一 MAPE 存储格式（建议使用小数形式 0.025 = 2.5%）

### 2.3 轻微问题（优化建议）

#### P3-001: 硬编码的质量阈值
- **位置**: `methods/base_method.py` 第29-31行
- **代码**:
```python
R2_EXCELLENT_THRESHOLD: float = 0.99
R2_GOOD_THRESHOLD: float = 0.95
R2_FAIR_THRESHOLD: float = 0.90
```
- **建议**: 从配置文件读取

#### P3-002: 方法注册表硬编码基准数据
- **位置**: `methods/method_registry.py` 第45-69行
- **建议**: 从数据库或配置文件读取基准数据

#### P3-003: 日志中文与英文混用
- **位置**: 多个文件
- **建议**: 统一日志语言风格

#### P3-004: ResultOutput 预测函数重建不稳定
- **位置**: `output/result_output.py` 第128-138行
- **问题**: 根据系数数量硬编码重建预测函数，不支持所有方法
- **代码**:
```python
if len(coeffs) == 3:  # poly2
    return coeffs[0] + coeffs[1]*x + coeffs[2]*x**2
elif len(coeffs) == 4:  # poly3
    ...
```
- **建议**: 使用通用多项式计算或从 FitResult 中获取 predict_func

#### P3-005: 泵组处理器默认返回系统扬程
- **位置**: `pump_group/pump_group_processor.py` 第339行
- **问题**: 查询失败时默认返回 35.0m，但这可能不合适
- **建议**: 抛出异常或从配置读取默认值

## 8. 结论

特性曲线拟合系统的基础架构已经搭建完成，但存在 **6个严重问题** 会导致系统无法运行：

1. 方法注册表与方法类接口不匹配
2. 流水线调用方法注册表参数不正确
3. 数据提取器SQL与数据库结构不匹配
4. 数据库中参数命名不一致
5. method_id 存储和加载逻辑错误
6. pump_characteristic_curves 表与代码不同步

**建议先修复紧急问题，再进行端到端测试。**
