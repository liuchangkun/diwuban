## 1. 功能概述

### 1.1 背景

现有泵组曲线通过**合成曲线**方法获得（从单泵曲线合成），本功能新增**直接拟合**方法，从泵组实测数据直接拟合曲线。

### 1.2 核心设计

```
┌─────────────────────────────────────────────────────────────────┐
│                     泵组曲线获取方式                             │
├─────────────────────────────────────────────────────────────────┤
│  方式A（现有）：合成+修正                                        │
│  ├─ 单泵曲线 → ParallelSynthesizer → 理论曲线                   │
│  ├─ 理论曲线 + SystemCorrectionModel → 修正后曲线               │
│  └─ 优点：灵活，可预测任意组合；缺点：依赖单泵拟合精度           │
│                                                                  │
│  方式B（新增）：直接拟合                                         │
│  ├─ 泵组实测数据 → 按泵组合分组 → GroupCurveFitter              │
│  └─ 优点：真实反映并联损失；缺点：每种组合需足够数据             │
│                                                                  │
│  执行策略（要求4）：                                             │
│  └─ 每次执行同时运行两种方法，自动对比分析，输出推荐             │
└─────────────────────────────────────────────────────────────────┘
```

### 1.3 两种方法对比

| 对比维度 | 合成+修正 | 直接拟合 |
|----------|----------|----------|
| **数据来源** | 单泵P0曲线 + 理论合成 | 泵组历史运行数据 |
| **物理模型** | 并联原理（等扬程流量叠加） | 数据驱动（无预设模型） |
| **系统损失** | 通过修正系数α补偿 | 自然包含在拟合结果中 |
| **适用场景** | 新安装泵站、数据不足 | 有充足运行历史 |
| **预测能力** | 可预测任意泵组合 | 仅支持历史出现过的组合 |
| **精度来源** | 依赖单泵拟合精度 | 依赖运行数据质量 |
| **优势** | 灵活、可扩展 | 真实、无累积误差 |
| **劣势** | 忽略并联损失细节 | 数据覆盖要求高 |

### 1.4 设计要求

| 要求 | 说明 |
|------|------|
| **要求1** | 支持任意数量水泵（1~N台），无硬编码上限 |
| **要求2** | 输出结果明确标识生成方式（direct_fit/synthesis） |
| **要求3** | 5种泵组场景全覆盖 |
| **要求4** | 每次同时执行两种方法，自动对比分析 |

## 2. 直接拟合核心原理

### 2.1 为什么需要按泵组合分组？

**关键认知**：泵组曲线不仅取决于运行台数N，更取决于**具体哪些泵在运行**。

```
示例：某泵站有3台泵（泵1、泵2、泵3）

2台运行时的可能组合：
├─ 组合A：泵1+泵2 → 曲线A（H = f_A(Q)）
├─ 组合B：泵1+泵3 → 曲线B（H = f_B(Q)）
└─ 组合C：泵2+泵3 → 曲线C（H = f_C(Q)）

即使都是2台运行，三条曲线也不同！
原因：
1. 各泵特性可能存在差异（磨损程度、安装位置）
2. 管网阻力分配不同
3. 并联损失不同
```

**分组依据**：`pump_combination_key = ",".join(sorted(running_pump_ids))`

例如：`"1,2"`, `"1,3"`, `"2,3"`, `"1,2,3"` 各自独立拟合。

### 2.2 5种泵组场景分组策略

| 场景 | 直接拟合 | 分组依据 | 说明 |
|------|:-------:|---------|------|
| **HOMOGENEOUS_GROUP** | ✅ | `pump_combination` | 同型号泵仍需按组合分组 |
| **HETEROGENEOUS_GROUP** | ✅ | `pump_combination` | 不同泵组合曲线差异大 |
| **VFD_HETEROGENEOUS_FREQ** | ⚠️ | `pump_combination` + 频率归一化 | 需先归一化后拟合 |
| **MIXED_GROUP** | ✅ | `pump_combination` | VFD+SS组合方式影响曲线 |
| **MIXED_HETEROGENEOUS** | ✅ | `pump_combination` | 同上 |

> ⚠️ **重要**：即使是同构泵组（HOMOGENEOUS），也需要按具体组合分组。
> 因为实际运行中，各泵存在个体差异（磨损、安装等）。

### 2.3 VFD_HETEROGENEOUS_FREQ场景特殊处理

**问题**：同样的泵组合（如泵1+泵2），不同频率下曲线也不同。

**解决方案**：频率归一化到50Hz后拟合，使用时再反归一化。

```python
# ═══════════════════════════════════════════════════════════════
# 相似定律（Pump Affinity Laws）
# ═══════════════════════════════════════════════════════════════
# Q ∝ f      流量与频率成正比
# H ∝ f²     扬程与频率的平方成正比
# P ∝ f³     功率与频率的立方成正比
# ═══════════════════════════════════════════════════════════════
#
# ❗适用条件（v3.1新增）：
#   1. 几何相似：同一台泵或等比缩放的相似泵
#   2. 动力相似：雷诺数Re足够大（渐近自模区），通常Re > 10^5
#   3. 频率范围：一般限制在额定频率的25-120%范围内
#   4. 效率假设：相似工况下效率近似不变（实际会略有下降）
#
# ❗边界情况（精度下降）：
#   - 低频时（f < 30Hz）：溝道损失比例增大，实际扬程低于理论值
#   - 高频时（f > 55Hz）：可能进入汽蚀区
#   - 大范围变频：建议使用分段修正系数
# ═══════════════════════════════════════════════════════════════

# 步骤1：计算功率加权平均频率（v3.4修复：改用实际功率加权）
# 物理意义：大功率泵对泵组特性影响更大，应赋予更高权重
# ⚠️ 使用实际功率P_actual而非额定功率P_rated，反映当前工况贡献
f_weighted = sum(P_actual[pump_id] * f for pump_id, f in pump_frequencies.items()) / sum(P_actual.values())
# 当功率数据缺失时，退化为简单算术平均
if sum(P_actual.values()) <= 0:
    f_weighted = sum(pump_frequencies.values()) / len(pump_frequencies)

# 步骤2：将实测数据归一化到50Hz（用于拟合）
Q_norm = Q_actual * (50.0 / f_weighted)        # Q ∝ f
H_norm = H_actual * (50.0 / f_weighted) ** 2   # H ∝ f²

# 步骤3：使用归一化数据拟合曲线
# H_50Hz = f(Q_50Hz)  → 得到50Hz基准曲线

# 步骤4：使用时反归一化（在线预测）
# 给定实际频率f_actual和目标流量Q_actual：
Q_50Hz = Q_actual * (50.0 / f_actual)     # 归一化流量
H_50Hz = curve_50Hz.predict(Q_50Hz)        # 查50Hz曲线
H_actual = H_50Hz * (f_actual / 50.0) ** 2 # 反归一化扬程
```

**注意**：功率也需要考虑频率修正 `P_actual = P_50Hz * (f/50)³`

## 5. 数据结构详细定义

### 5.1 GroupOperatingPoint（泵组运行工况点）

```python
# 文件：app/services/characteristic_curves/core/data_structures.py

@dataclass
class GroupOperatingPoint:
    """泵组运行工况点
    
    表示某一时刻泵组的运行状态，是直接拟合的基础数据单元。
    
    分组依据：running_pump_ids（排序后转为pump_combination_key）
    拟合输入：Q_total（X轴）、H_system（Y轴）
    """
    # ===== 基本信息 =====
    ts_bucket: datetime           # 时间戳
    station_id: int               # 泵站ID
    
    # ===== 核心工况数据 =====
    Q_total: float                # 总流量 (m³/h) - 拟合X轴
    H_system: float               # 系统扬程 (m) - 拟合Y轴
    P_total: Optional[float] = None  # 总功率 (kW) - 用于Q-P曲线拟合
    eta_total: Optional[float] = None  # 总效率 (0-1) - 用于Q-η曲线拟合（v3.0新增）
    
    # ===== 运行状态 =====
    n_running: int = 0            # 运行台数
    running_pump_ids: Tuple[int, ...] = field(default_factory=tuple)  # 运行泵ID元组（已排序）
    
    # ===== 变频信息（VFD场景必需）=====
    pump_frequencies: Optional[Dict[int, float]] = None  # 各泵频率 {pump_id: freq_Hz}
    avg_frequency: Optional[float] = None  # 平均频率（用于频率归一化）
    
    # ===== 数据质量 =====
    is_steady_state: bool = True  # 是否稳态（非稳态数据应过滤）
    data_quality_score: float = 1.0  # 数据质量评分 (0-1)
    
    @property
    def pump_combination_key(self) -> str:
        """泵组合标识（用于分组）"""
        return ",".join(map(str, sorted(self.running_pump_ids)))
    
    def to_normalized(self, target_freq: float = 50.0) -> 'GroupOperatingPoint':
        """归一化到目标频率（用于VFD_HETEROGENEOUS_FREQ场景）
        
        相似定律：
        - Q ∝ f     流量与频率成正比
        - H ∝ f²    扬程与频率平方成正比
        - P ∝ f³    功率与频率立方成正比
        - η 在相似工况下近似不变，但低频时需要惩罚修正
        
        ⚠️ 效率低频惩罚（v3.4更新，分段修正更符合物理实际）：
        - f < 25Hz：极低频区，机械损失占比显著增大，惩罚系数 k=0.20
        - 25Hz ≤ f < 35Hz：低频区，轻度惩罚，惩罚系数 k=0.10
        - f ≥ 35Hz：正常运行区，效率近似不变
        - f > 50Hz：超频运行，不惩罚（物理上效率可能略升）
        
        惩罚公式：η_corrected = η × (1 - k × (1 - f/50)²)
        
        ⚠️ 物理解释：
        - 低频时泵转速下降，水力效率维持但机械损失（轴承摩擦、密封损耗）
          占总功率比例增加
        - 典型离心泵在25Hz时效率可下降5-10%
        """
        if not self.avg_frequency or self.avg_frequency == target_freq:
            return self
        
        ratio = target_freq / self.avg_frequency
        
        # 效率惩罚计算（分段修正，更符合物理实际 v3.4）
        eta_corrected = self.eta_total
        if self.eta_total is not None:
            f = self.avg_frequency
            if f < 25.0:
                # 极低频惩罚：机械损失占比显著增大
                penalty_factor = 1 - 0.20 * (1 - f / 50.0) ** 2
            elif f < 35.0:
                # 低频轻度惩罚
                penalty_factor = 1 - 0.10 * (1 - f / 50.0) ** 2
            else:
                # 35Hz以上不惩罚（包括超频运行）
                penalty_factor = 1.0
            eta_corrected = self.eta_total * penalty_factor
        
        return GroupOperatingPoint(
            ts_bucket=self.ts_bucket,
            station_id=self.station_id,
            Q_total=self.Q_total * ratio,           # Q ∝ f
            H_system=self.H_system * (ratio ** 2),  # H ∝ f²
            P_total=self.P_total * (ratio ** 3) if self.P_total else None,  # P ∝ f³
            eta_total=eta_corrected,  # 效率含低频惩罚修正
            n_running=self.n_running,
            running_pump_ids=self.running_pump_ids,
            pump_frequencies=self.pump_frequencies,
            avg_frequency=target_freq,  # 归一化后的频率
            is_steady_state=self.is_steady_state,
            data_quality_score=self.data_quality_score
        )
```

## 8. 双方法对比分析详细逻辑

### 8.1 对比原理

```
双方法对比的物理意义：

合成曲线（理论值）：
├─ 基于单泵Q-H曲线的并联叠加原理
├─ 假设：H₁ = H₂ = ... = H_N = H_system
├─ 假设：Q_total = ΣQ_i（无干涉损失）
└─ 通过修正系数α补偿系统损失

直接拟合（实测值）：
├─ 基于泵组历史运行数据
├─ 自然包含：并联干涉损失、管网阻力分配、流量分配不均
└─ 反映真实的泵组特性（非单泵特性的简单叠加）

对比价值：
├─ 差异小（<3%）：合成方法足够精确，可继续使用
├─ 差异中等（3-8%）：存在系统损失，需分析原因
└─ 差异大（>8%）：单泵曲线或合成方法存在问题
```

### 8.2 GroupCurveComparator 详细实现

```python
class GroupCurveComparator:
    """泵组曲线对比分析器
    
    职责：
    1. 量化直接拟合与合成曲线的差异
    2. 根据决策规则推荐最优方法
    3. 生成对比报告用于诊断
    """
    
    def __init__(
        self,
        max_acceptable_diff: float = 0.05,  # 最大可接受差异5%
        min_r2_for_direct_fit: float = 0.90,  # 直接拟合最低R²要求
        min_data_points: int = 100  # 最少数据点
    ):
        self._max_acceptable_diff = max_acceptable_diff
        self._min_r2 = min_r2_for_direct_fit
        self._min_points = min_data_points
    
    def compare(
        self,
        direct_fit: DirectFitResult,
        synthesis_func: Callable[[float], float],
        Q_range: Tuple[float, float],
        n_sample_points: int = 100
    ) -> Dict[str, Any]:
        """
        对比两种方法的曲线
        
        Args:
            direct_fit: 直接拟合结果
            synthesis_func: 合成曲线函数 H = f(Q)
            Q_range: 比较的流量范围
            n_sample_points: 采样点数
        
        Returns:
            {
                'max_diff_h': 最大扬程差 (m),
                'avg_diff_h': 平均扬程差 (m),
                'max_diff_ratio': 最大相对差异,
                'diff_by_region': 分区域差异分析,
                'recommended_method': 推荐方法,
                'recommendation_reason': 推荐理由,
                'confidence': 置信度
            }
        """
        import numpy as np
        
        # 1. 在流量范围内采样
        Q_samples = np.linspace(Q_range[0], Q_range[1], n_sample_points)
        
        diffs = []
        for Q in Q_samples:
            H_direct = direct_fit.predict(Q)
            H_synthesis = synthesis_func(Q)
            
            if H_synthesis > 0:
                diff_ratio = abs(H_direct - H_synthesis) / H_synthesis
                diffs.append({
                    'Q': Q,
                    'H_direct': H_direct,
                    'H_synthesis': H_synthesis,
                    'diff_h': H_direct - H_synthesis,
                    'diff_ratio': diff_ratio
                })
        
        # 2. 计算统计指标
        diff_ratios = [d['diff_ratio'] for d in diffs]
        diff_hs = [abs(d['diff_h']) for d in diffs]
        
        max_diff_ratio = max(diff_ratios)
        avg_diff_ratio = np.mean(diff_ratios)
        max_diff_h = max(diff_hs)
        avg_diff_h = np.mean(diff_hs)
        
        # 3. 分区域分析（低流量、中流量、高流量）
        n_third = len(diffs) // 3
        region_diffs = {
            'low_Q': np.mean([d['diff_ratio'] for d in diffs[:n_third]]),
            'mid_Q': np.mean([d['diff_ratio'] for d in diffs[n_third:2*n_third]]),
            'high_Q': np.mean([d['diff_ratio'] for d in diffs[2*n_third:]])
        }
        
        # 4. 决策推荐
        recommended, reason, confidence = self._determine_recommendation(
            direct_fit, max_diff_ratio, avg_diff_ratio, region_diffs
        )
        
        return {
            'max_diff_h': float(max_diff_h),
            'avg_diff_h': float(avg_diff_h),
            'max_diff_ratio': float(max_diff_ratio),
            'avg_diff_ratio': float(avg_diff_ratio),
            'diff_by_region': region_diffs,
            'sample_diffs': diffs,  # 详细采样数据
            'recommended_method': recommended,
            'recommendation_reason': reason,
            'confidence': confidence
        }
    
    def _determine_recommendation(
        self,
        direct_fit: DirectFitResult,
        max_diff_ratio: float,
        avg_diff_ratio: float,
        region_diffs: Dict[str, float]
    ) -> Tuple[CurveFitMethod, str, float]:
        """
        确定推荐方法
        
        决策规则（优先级从高到低）：
        
        1. 直接拟合数据不足 → 推荐合成
           条件：data_points_used < min_data_points
           
        2. 直接拟合质量差 → 推荐合成
           条件：R² < 0.90
           
        3. 差异很小 → 推荐合成（更灵活）
           条件：avg_diff_ratio < 2%
           理由：差异小时，合成方法可预测未见过的组合
           
        4. 直接拟合质量优秀且差异显著 → 推荐直接拟合
           条件：R² > 0.95 且 data_points > 200 且 avg_diff_ratio > 3%
           理由：直接拟合更真实反映系统特性
           
        5. 区域差异不均匀 → 推荐直接拟合
           条件：max(region_diffs) - min(region_diffs) > 5%
           理由：合成方法在某些区域可能不准
           
        6. 其他情况 → 推荐合成（保守选择）
        """
        # 规则1：数据量不足
        if direct_fit.data_points_used < self._min_points:
            return (
                CurveFitMethod.SYNTHESIS,
                f"直接拟合数据点不足（{direct_fit.data_points_used} < {self._min_points}）",
                0.9
            )
        
        # 规则2：拟合质量差
        if direct_fit.r_squared < self._min_r2:
            return (
                CurveFitMethod.SYNTHESIS,
                f"直接拟合R²过低（{direct_fit.r_squared:.3f} < {self._min_r2}）",
                0.85
            )
        
        # 规则3：差异很小
        if avg_diff_ratio < 0.02:
            return (
                CurveFitMethod.SYNTHESIS,
                f"两种方法差异很小（{avg_diff_ratio:.1%}），合成方法更灵活",
                0.95
            )
        
        # 规则4：直接拟合优秀且差异显著
        if (direct_fit.r_squared > 0.95 and 
            direct_fit.data_points_used > 200 and 
            avg_diff_ratio > 0.03):
            return (
                CurveFitMethod.DIRECT_FIT,
                f"直接拟合质量优秀（R²={direct_fit.r_squared:.3f}，"
                f"数据点={direct_fit.data_points_used}），差异{avg_diff_ratio:.1%}显著",
                0.90
            )
        
        # 规则5：区域差异不均匀
        region_range = max(region_diffs.values()) - min(region_diffs.values())
        if region_range > 0.05:
            worst_region = max(region_diffs, key=region_diffs.get)
            return (
                CurveFitMethod.DIRECT_FIT,
                f"合成方法在{worst_region}区域偏差较大（区域差异范围{region_range:.1%}）",
                0.75
            )
        
        # 规则6：默认推荐合成
        return (
            CurveFitMethod.SYNTHESIS,
            "差异在可接受范围内，推荐使用更灵活的合成方法",
            0.7
        )
```

### 8.3 对比结果解读指南

| 差异程度 | avg_diff_ratio | 可能原因 | 建议动作 |
|---------|:--------------:|---------|----------|
| 极小 | < 2% | 系统损失小，单泵曲线准确 | 继续使用合成方法 |
| 正常 | 2% - 5% | 存在并联损失，属正常范围 | 两种方法均可 |
| 偏大 | 5% - 10% | 管网复杂或单泵曲线偏差 | 优先使用直接拟合 |
| 过大 | > 10% | 单泵曲线或合成逻辑有问题 | 需排查诊断 |

### 8.4 差异过大的诊断流程

```
当 avg_diff_ratio > 10% 时：

1. 检查单泵曲线拟合质量
   └─ 各泵的R²是否都 > 0.95？
   └─ 单泵曲线是否近期更新？

2. 检查数据质量
   └─ 直接拟合的数据是否包含异常工况？
   └─ 是否有传感器故障数据混入？

3. 检查泵组配置
   └─ 泵组合是否与数据提取的分组一致？
   └─ 是否有泵被替换或维修？

4. 检查物理变化
   └─ 管网阻力是否发生变化？
   └─ 泵性能是否退化？
```

## 11. 单泵曲线数据来源

### 11.1 合成+修正方法的单泵曲线来源

**关键问题**：合成+修正方法拟合泵组曲线时，单泵曲线从哪里获取？

**答案**：从数据库 `curve_fit_results` + `curve_fit_params` 表获取最新的拟合结果。

```python
class CurveRegistry:
    """曲线注册表 - 单泵曲线的统一获取接口"""
    
    def load_from_database(self, pump_id: int, curve_type: str) -> CurveEntry:
        """
        从数据库加载单泵曲线
        
        数据来源：
        - curve_fit_results: 拟合元数据（R², RMSE, 拟合时间等）
        - curve_fit_params: 拟合系数（coefficients）
        """
        sql = """
            SELECT cfr.*, array_agg(cfp.param_value ORDER BY cfp.param_order) AS coeffs
            FROM curve_fit_results cfr
            JOIN curve_fit_params cfp ON cfr.id = cfp.result_id
            WHERE cfr.device_id = %(pump_id)s
              AND cfr.curve_type = %(curve_type)s
              AND cfr.is_active = true
            GROUP BY cfr.id
            ORDER BY cfr.fitted_at DESC LIMIT 1
        """
        # ... 加载并返回 CurveEntry
```

## 14. 支持的特性曲线类型

### 14.1 当前支持的曲线类型

| 曲线类型 | 代码标识 | 物理含义 | 合成+修正 | 直接拟合 |
|----------|----------|----------|:---------:|:--------:|
| 流量-扬程曲线 | `qh` | H = f(Q) | ✅ | ✅ |
| 流量-功率曲线 | `qp` | P = f(Q) | ✅ | ✅ |
| 流量-效率曲线 | `qeta` | η = f(Q) | ✅ | ⚠️需限定条件 |

> ⚠️ **Q-η曲线直接拟合的物理问题**（v3.1新增）：
>
> 泵组效率计算公式：
> ```
> η_total = (ρ × g × Q_total × H_system) / P_total
> ```
>
> **问题**：同一Q值下，不同H对应不同η。直接拟合η = f(Q)忽略了H的影响。
>
> **解决方案**：
> 1. **条件限定**：Q-η曲线仅在固定系统曲线（固定H-Q关系）时有效
> 2. **曲面拟合**：改用η = f(Q, H)二元函数拟合（推荐）
> 3. **派生计算**：从qh和qp曲线派生：η(Q) = ρgQH(Q)/P(Q)
>
> **推荐实现**：
> ```python
> # 方案A：派生计算（推荐，物理一致性好）
> def calculate_eta(Q: float, qh_curve, qp_curve) -> float:
>     H = qh_curve(Q)  # 查qh曲线
>     P = qp_curve(Q)  # 查qp曲线
>     return (1000 * 9.81 * (Q/3600) * H) / (P * 1000)  # m³/h→m³/s, kW→W
>
> # 方案B：曲面拟合（数据量充足时）
> def fit_eta_surface(Q_data, H_data, eta_data):
>     # 拟合 η = f(Q, H) 二元多项式
>     from sklearn.preprocessing import PolynomialFeatures
>     from sklearn.linear_model import Ridge
>     X = np.column_stack([Q_data, H_data])
>     poly = PolynomialFeatures(degree=2)
>     X_poly = poly.fit_transform(X)
>     model = Ridge(alpha=0.1).fit(X_poly, eta_data)
>     return model, poly
> ```

### 14.2 可扩展支持的曲线类型

| 曲线类型 | 代码标识 | 物理含义 | 扩展优先级 | 实现难度 |
|----------|----------|----------|:----------:|:--------:|
| 功率-效率曲线 | `peta` | η = f(P) | 高 | 低 |
| 扬程-效率曲线 | `heta` | η = f(H) | 高 | 低 |
| 流量-功率曲线（反向） | `pq` | Q = f(P) | 中 | 中 |
| NPSH曲线 | `npsh` | NPSHr = f(Q) | 低 | 高 |

## 17. 物理问题专题

### 17.1 变频泵组频率归一化处理

```python
class FrequencyNormalizer:
    """频率归一化处理器
    
    相似定律（Pump Affinity Laws）：
    - Q ∝ f      流量与频率成正比
    - H ∝ f²     扬程与频率平方成正比
    - P ∝ f³     功率与频率立方成正比
    - η 不变     效率在相似工况下不变
    
    多泵平均频率处理：
    - 使用加权平均频率（按功率加权）
    - f_avg = Σ(P_i × f_i) / Σ(P_i)
    """
```

### 17.2 泵组合有效性判定

```
判定规则：
1. 运行泵必须是泵站成员
2. 至少1台VFD泵（纯SS泵组不支持）
3. 泵功率匹配（避免大小泵差异过大）
4. 运行台数合理（不超过管网承载能力）
```

预测流程：
1. 选择推荐方法的曲线
2. 给定Q_target，计算H_predicted
3. 验证预测结果在有效范围内

```
处理策略：
- 直接拟合：自动包含各种启停顺序的数据
- 合成方法：假设稳态运行，不考虑启停顺序
- 建议：过滤启停过渡期数据（通常5-10分钟）
```

### 17.6 逆流/倒灌/气蚀异常识别

```python
class AnomalyDetector:
    """泵组运行异常检测器
    
    检测类型：
    1. 逆流：Q < 0（单泵流量为负）
    2. 倒灌：H_system > 各泵出口压力
    3. 气蚀：NPSHa < NPSHr
    4. 抢流：某泵流量远大于其他泵
    """
```

### 17.7 最小运行流量限制

```
物理约束：
- 每台泵需要最小流量以保证冷却和稳定
- 通常为额定流量的10-30%

验证逻辑：Q_per_pump >= Q_rated * 0.15
```

### 17.8 并联泵组抢流现象

```
抢流现象（Flow Stealing）：

产生原因：
1. 泵特性差异：H0或K参数差异大
2. 频率差异：变频泵频率不同
3. 管路阻力：各泵进出口管阻不同
4. 泵磨损：老旧泵效率下降

识别方法：当max(Q_i)/min(Q_i) > 2时预警

处理策略：
1. 直接拟合：数据自然包含抢流影响
2. 合成方法：通过修正系数补偿
3. 控制优化：调整变频泵频率平衡流量
```
