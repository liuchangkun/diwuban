## 1. 术语统一表（重要）

> **⚠️ 强制规则**：所有文档和代码必须使用以下统一术语，禁止混用。

| 统一术语 | 禁止使用 | 说明 |
|---------|---------|------|
| `method_id` | ~~method_name~~（作为ID时） | 方法唯一标识符，如 `math_poly_2` |
| `method_name` | - | 方法显示名称，如 `2次多项式` |
| `coefficients` | ~~fit_params~~, ~~params~~ | 拟合系数数组 |
| `physics_constraints` | ~~constraints~~（单独使用时） | 物理约束参数 |
| `rated_params` | ~~device_params~~ | 设备额定参数（rated_flow, rated_head等） |
| `curve_type` | ~~type~~, ~~fit_type~~ | 曲线类型（qh, qp, qeta等） |
| `fit_result` | ~~result~~（单独使用时） | 拟合结果对象 |
| `validation_result` | ~~validate_result~~ | 验证结果对象 |

**代码示例**：
```python
# ✅ 正确
def fit(self, method_id: str, rated_params: dict) -> FitResult:
    coefficients = self._calculate_coefficients(data)
    return FitResult(method_id=method_id, coefficients=coefficients)

# ❌ 错误
def fit(self, method_name: str, device_params: dict) -> dict:
    fit_params = self._calculate_params(data)
    return {"params": fit_params}
```

## 2. 日志系统通用规范

### 2.1 日志记录器初始化

所有模块必须按照以下方式初始化日志记录器：

```python
import logging
from app.core.logging.setup import log_activity, log_biz, log_sql, log_cache, set_context, clear_context

class ModuleName:
    """模块示例"""
    
    def __init__(self):
        # 标准日志记录器初始化
        self._logger = logging.getLogger(f"{__name__}.{self.__class__.__name__}")
```

### 2.2 日志级别使用规范

| 级别 | 使用场景 | 示例 |
|------|---------|------|
| **DEBUG** | 详细调试信息、中间变量、循环迭代 | 参数验证详情、缓存键哈希、单个约束检查 |
| **INFO** | 关键业务流程节点、阶段开始/完成 | 拟合开始/完成、方法选择结果、保存成功 |
| **WARNING** | 非致命异常、降级处理、配置覆盖 | 验证失败但继续、缓存过期、方法覆盖 |
| **ERROR** | 可恢复错误、业务异常 | 参数验证失败、方法不存在、数据库连接失败 |
| **CRITICAL** | 不可恢复错误、系统级故障 | 核心组件初始化失败、关键配置缺失 |

### 2.3 日志API选择指南

| API | 用途 | 参数示例 |
|-----|------|---------|
| `self._logger.info/debug/error()` | 标准模块日志 | `extra={"extra_data": {...}}` |
| `log_activity(name, params)` | 活动追踪（上下文管理器） | `with log_activity("拟合", params={...}):` |
| `log_biz(action, status, detail)` | 业务操作审计 | `log_biz("曲线拟合", "成功", {...})` |
| `log_sql(sql, params, duration_ms, rows)` | 数据库操作 | `log_sql("SELECT...", (1,), 50, 10)` |
| `log_cache(op, key, hit, duration_ms)` | 缓存操作 | `log_cache("get", "abc123", True, 0.5)` |
| `set_context(trace_id, device_id)` | 设置追踪上下文 | `set_context(trace_id="xxx", device_id=1)` |
| `clear_context()` | 清除追踪上下文 | 在finally块中调用 |

### 2.4 日志内容强制要求

| 字段 | 要求级别 | 说明 |
|------|---------|------|
| **设备ID** | 强制 | 所有涉及设备的日志必须包含 |
| **曲线类型** | 强制 | qh/qp/qeta |
| **拟合方法ID** | 强制 | 方法唯一标识 |
| **拟合方法名称** | 强制 | 方法显示名称（中文） |
| **追踪ID** | 强制（流程入口） | 用于关联整个流程的日志 |
| **耗时ms** | 建议 | 性能监控 |
| **数据量** | 建议 | 数据行数、条目数 |
| **错误详情** | 强制（错误日志） | 错误类型、错误信息、堆栈位置 |

### 2.5 日志级别一致性检查清单

**代码审查时必须检查以下日志级别使用是否正确：**

| 场景 | 正确级别 | 常见错误 |
|------|---------|---------|
| 拟合开始/完成 | INFO | ❌ 使用DEBUG（关键节点应可见） |
| 参数验证失败 | ERROR | ❌ 使用WARNING（应阻止流程） |
| 缓存未命中 | DEBUG | ❌ 使用WARNING（正常情况） |
| 方法回退 | WARNING | ❌ 使用INFO（降级需关注） |
| 数据库连接失败 | ERROR | ❌ 使用WARNING（需立即处理） |
| 约束验证通过 | DEBUG | ❌ 使用INFO（过于频繁） |
| 批处理进度 | INFO | ✅ 每10%或每设备一条 |
| 单个数据点处理 | DEBUG | ❌ 使用INFO（过于频繁） |

**日志级别选择决策树**：

```
是否影响业务流程？
├── 是 → 是否可恢复？
│       ├── 是 → ERROR
│       └── 否 → CRITICAL
└── 否 → 是否需要运维关注？
        ├── 是 → WARNING
        └── 否 → 是否是关键业务节点？
                ├── 是 → INFO
                └── 否 → DEBUG
```

### 2.6 extra_data格式规范

所有日志的 `extra_data` 必须遵循以下结构：

```python
extra={"extra_data": {
    # 强制字段（业务相关日志）
    "设备ID": device_id,
    "曲线类型": curve_type,
    "拟合方法ID": method_id,
    "拟合方法名称": method_name,

    # 追踪字段（流程入口）
    "追踪ID": trace_id,

    # 业务字段（根据场景）
    "输入数据": {
        "总行数": len(data),
        "列名": list(data.columns),
        "时间范围": {...}
    },

    # 结果字段
    "执行结果": "成功/失败",
    "耗时ms": duration_ms,

    # 错误字段（仅错误日志）
    "错误类型": type(e).__name__,
    "错误信息": str(e),
    "错误位置": traceback.format_exc().split('\n')[-3]
}}
```

## 4. 系统配置常量

> **⚠️ 强制规则**：以下常量是系统全局配置，所有模块必须引用而非硬编码。

### 4.1 数据质量阈值

| 常量名 | 值 | 说明 | 定义位置 |
|--------|------|------|----------|
| `MIN_DATA_POINTS` | 50 | 拟合最小数据点数，少于此值拒绝拟合 | `02_方法层.md` |
| `MIN_EXTRACTION_POINTS` | 100 | 数据提取建议点数，用于数据提取阶段 | `04_曲线模块/*.md` |
| `MIN_VALIDATION_POINTS` | 50 | 验收标准最小点数，用于质量验收 | `10_质量标准/01_验收标准.md` |
| `R2_EXCELLENT_THRESHOLD` | 0.99 | R² 优秀质量阈值 | `02_方法层.md` |
| `R2_GOOD_THRESHOLD` | 0.95 | R² 良好质量阈值 | `02_方法层.md` |
| `R2_FAIR_THRESHOLD` | 0.90 | R² 合格质量阈值 | `02_方法层.md` |

**数据点数量说明**：
- **MIN_DATA_POINTS (50点)**: 拟合方法的最小要求，少于此值拒绝拟合。这是核心阈值，平衡了数据质量和可用性。
- **MIN_EXTRACTION_POINTS (100点)**: 数据提取阶段的建议值，确保有足够的数据进行筛选和清洗。
- **MIN_VALIDATION_POINTS (50点)**: 验收标准，与MIN_DATA_POINTS保持一致。

**使用场景**：
- 数据提取阶段：使用MIN_EXTRACTION_POINTS作为目标，尽量提取更多数据
- 拟合执行阶段：使用MIN_DATA_POINTS验证数据量，少于50点拒绝拟合
- 质量验收阶段：使用MIN_VALIDATION_POINTS作为验收标准

**代码使用示例**：
```python
from app.services.characteristic_curves.methods.base_method import (
    MIN_DATA_POINTS,
    R2_EXCELLENT_THRESHOLD,
    R2_GOOD_THRESHOLD,
    R2_FAIR_THRESHOLD
)

def validate_data_quality(data: np.ndarray, r_squared: float) -> str:
    """验证数据质量"""
    if len(data) < MIN_DATA_POINTS:
        return "insufficient_data"

    if r_squared >= R2_EXCELLENT_THRESHOLD:
        return "excellent"
    elif r_squared >= R2_GOOD_THRESHOLD:
        return "good"
    elif r_squared >= R2_FAIR_THRESHOLD:
        return "fair"
    else:
        return "poor"
```

### 4.2 metric_key枚举定义（v2.6新增）

> **⚠️ 强制规则**：所有数据查询必须使用以下标准metric_key值

**metric_key定义**：用于从`dim_metric_config`表查询`metric_id`，再从`fact_measurements`表查询实际数据。

#### 4.2.1 核心指标

| metric_key | 说明 | 单位 | 用途 |
|-----------|------|------|------|
| `pump_flow_rate` | 泵流量 | m³/h | QH/QP/QEta曲线 |
| `pump_head` | 泵扬程 | m | QH曲线 |
| `pump_power` | 泵功率 | kW | QP曲线 |
| `pump_efficiency` | 泵效率 | % (0-100) | QEta曲线 |
| `pump_frequency` | 泵频率 | Hz | 变频泵控制 |
| `pump_current` | 泵电流 | A | 功率计算 |
| `pump_voltage` | 泵电压 | V | 功率计算 |

#### 4.2.2 系统指标

| metric_key | 说明 | 单位 | 用途 |
|-----------|------|------|------|
| `main_pipeline_outlet_pressure` | 主管出口压力 | MPa | 系统扬程计算 |
| `main_pipeline_inlet_pressure` | 主管入口压力 | MPa | 系统扬程计算 |
| `main_pipeline_flow_rate` | 主管流量 | m³/h | 泵组流量验证 |
| `water_level_inlet` | 进水池水位 | m | 吸程计算 |
| `water_level_outlet` | 出水池水位 | m | 扬程计算 |

#### 4.2.3 查询示例

```python
# 查询流量数据
sql = """
    SELECT ts_bucket, AVG(value) as Q
    FROM fact_measurements
    WHERE device_id = %(device_id)s
      AND metric_id = (
          SELECT id FROM dim_metric_config
          WHERE metric_key = 'pump_flow_rate'
      )
      AND ts_bucket BETWEEN %(start_time)s AND %(end_time)s
    GROUP BY ts_bucket
    ORDER BY ts_bucket
"""

# 查询扬程数据
sql = """
    SELECT ts_bucket, AVG(value) as H
    FROM fact_measurements
    WHERE device_id = %(device_id)s
      AND metric_id = (
          SELECT id FROM dim_metric_config
          WHERE metric_key = 'pump_head'
      )
      AND ts_bucket BETWEEN %(start_time)s AND %(end_time)s
    GROUP BY ts_bucket
    ORDER BY ts_bucket
"""
```

#### 4.2.4 映射关系说明

**数据流**：
1. 应用层使用`metric_key`（字符串标识符）
2. 通过`dim_metric_config`表查询对应的`metric_id`（整数ID）
3. 使用`metric_id`从`fact_measurements`表查询实际测量数据

**优势**：
- 解耦应用层和数据库层
- 支持metric_key的灵活扩展
- 便于多租户和多设备类型支持

### 5.3 数据获取示例

```python
# ✅ 正确：通过metric_key获取指标数据
from app.adapters.db.pool import get_connection

def get_pump_frequency(device_id: int) -> float:
    """获取泵的当前频率"""
    sql = """
        SELECT fm.value AS frequency
        FROM fact_measurements fm
        WHERE fm.device_id = %(device_id)s
          AND fm.metric_id = (
              SELECT id FROM dim_metric_config
              WHERE metric_key = 'pump_frequency'
          )
        ORDER BY fm.ts_raw DESC
        LIMIT 1
    """
    with get_connection() as conn:
        result = conn.execute(sql, {'device_id': device_id}).fetchone()
        if result:
            return float(result['frequency'])
    raise DataNotFoundError(f"设备 {device_id} 无频率数据")
```
