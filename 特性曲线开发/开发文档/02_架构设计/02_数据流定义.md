## 1. 流程阶段定义（16阶段）

本系统采用 **16阶段** 流程（P0: 13阶段 + P2: 3阶段）：

### 1.1 P0阶段（单泵曲线）

| 阶段 | 名称 | 模块 | 输入 | 输出 | 执行类型 | 优先级 |
|:----:|------|------|------|------|:--------:|:------:|
| **1** | 时间窗口划分 | TimeWindowSplitter | device_id, curve_type | TimeWindowSplitResult | 必须 | P0 |
| **2** | 场景识别 | ScenarioDetector | device_id, 设备参数 | Scenario枚举 | **条件** | P0 |
| **3** | 数据提取 | DataExtractor | device_id, 时间窗口 | raw_data (DataFrame) | 必须 | P0 |
| **4** | 数据预处理 | DataCleaner | raw_data | cleaned_data | 必须 | P0 |
| **5** | 稳态识别 | SteadyStateDetector | cleaned_data | steady_state_data | **条件** | P0 |
| **6** | 约束计算 | Constraints | data, device_params | constraints_dict | 必须 | P0 |
| **7** | 频率归一化 | FrequencyNormalizer | data, frequency | normalized_data | **条件** | P0 |
| **8** | 数据归一化 | Normalizer | data, constraints | normalized_data, norm_params | 必须 | P0 |
| **9** | 方法选择 | MethodRegistry | curve_type, data_characteristics | method_id | 必须 | P0 |
| **10** | 曲线拟合 | BaseMethod.fit() | X, y, constraints | MethodResult | 必须 | P0 |
| **11** | 结果验证 | Validator | method_result, constraints | ValidationResult | 必须 | P0 |
| **12** | 历史评估 | HistoricalDataEvaluator | predict_func, test_window | EvaluationReport | **条件** | P0 |
| **13** | 存储结果 | ResultStorage | FitResult | version | 必须 | P0 |

**关键参数说明**【v3.12补充：问题013】：

**TimeWindowSplitResult 结构定义**：
```python
@dataclass
class TimeWindowSplitResult:
    """时间窗口划分结果"""
    fit_window: Tuple[datetime, datetime]    # 训练窗口（起止时间）
    test_window: Tuple[datetime, datetime]   # 测试窗口（起止时间）
    can_evaluate: bool                       # 是否可以执行历史评估
    fit_point_count: int                     # 训练窗口数据点数
    test_point_count: int                    # 测试窗口数据点数
```

**时间窗口划分策略**：
- **默认比例**：75% fit_window（训练） / 25% test_window（测试）
- **最小数据量要求**：
  - fit_window ≥ 200点（拟合最小要求）
  - test_window ≥ 50点（评估最小要求）
- **时间连续性**：test_window 紧接在 fit_window 之后，无重叠
- **can_evaluate 判断条件**：
  - test_point_count ≥ 50 且
  - test_window 时间跨度 ≥ 24小时

**示例**：
```python
# 输入：time_range = (2024-01-01 00:00:00, 2024-01-31 23:59:59)
# 输出：
result = TimeWindowSplitResult(
    fit_window=(datetime(2024, 1, 1, 0, 0, 0), datetime(2024, 1, 24, 5, 59, 59)),  # 75%
    test_window=(datetime(2024, 1, 24, 6, 0, 0), datetime(2024, 1, 31, 23, 59, 59)), # 25%
    can_evaluate=True,
    fit_point_count=3456,
    test_point_count=1152
)
```

**阶段12执行条件**：
- 仅在 `TimeWindowSplitResult.can_evaluate=True` 时执行
- 如果 `can_evaluate=False`，跳过阶段12，直接进入阶段13

### 1.2 P2阶段（泵组曲线）

| 阶段 | 名称 | 模块 | 输入 | 输出 | 执行类型 | 优先级 |
|:----:|------|------|------|------|:--------:|:------:|
| **14** | 泵组类型识别 | PumpGroupProcessor.identify_group_type() | pump_infos | GroupProcessingStrategy | **条件** | P2 |
| **15** | 并联合成 | ParallelSynthesizer.synthesize_*() | 单泵曲线, N, H_system | SynthesisResult | 必须 | P2 |
| **16** | 修正系数学习 | SystemCorrectionModel.fit() | 运行数据 | correction_model | 必须 | P2 |

**P2阶段入口条件**【v3.11修复：问题261】：
- 输入为 `station_id + pump_combination` 而非 `device_id`
- 所有单泵曲线已完成P0阶段拟合
- P2阶段复用P0的方法选择和拟合逻辑

**P2阶段入口验证**：
在执行阶段14之前，必须验证以下条件：
1. **单泵曲线完整性验证**：
   - 查询 `curve_fit_results` 表，确认 `pump_combination` 中的每个 `device_id` 都有对应的曲线记录
   - 验证曲线类型：至少需要 `qh` 曲线，可选 `qp`、`qeta` 曲线
   - 验证曲线状态：`status = 'active'`
2. **曲线质量验证**：
   - 验证 R² ≥ 0.90（最低质量要求）
   - 验证物理约束满足度
3. **失败处理**：
   - 如果任何单泵曲线缺失或质量不合格，抛出 `PumpGroupProcessingError`
   - 错误信息应明确指出哪些泵的曲线有问题

**条件执行说明**：
- **阶段2**：根据配置决定是否执行场景识别
- **阶段5**：当数据包含非稳态运行数据时执行
- **阶段7**：仅当 `pump_type='variable_frequency'` 且 `freq_std > 2.0` 时执行
- **阶段12**：仅当 `time_split.can_evaluate=True` 时执行

## 4. 场景枚举定义（权威）

```python
from enum import Enum

class Scenario(str, Enum):
    """泵运行场景枚举"""
    # P0 单泵场景
    SOFT_START_SINGLE = "soft_start_single"           # 软启泵单泵
    VFD_SINGLE = "vfd_single"                         # 变频泵单泵（频率变化大）
    QUASI_FIXED_FREQ_SINGLE = "quasi_fixed_freq_single"  # 类工频变频泵单泵

    # P2 泵组场景（枚举值与06_数据结构.md中的GroupProcessingStrategy保持一致）
    HOMOGENEOUS_GROUP = "homogeneous"              # 同构泵组（功率差异<10%，频率差异<2%）
    HETEROGENEOUS_GROUP = "heterogeneous"          # 异构泵组（功率差异≥10%）
    VFD_HETEROGENEOUS_FREQ = "vfd_hetero_freq"     # VFD频率异构（频率差异≥2%）
    MIXED_GROUP = "mixed"                          # 混合泵组（VFD+SS，功率差异<10%）
    MIXED_HETEROGENEOUS = "mixed_heterogeneous"    # 混合异构泵组（VFD+SS，功率差异≥10%）
    GROUP_COMPOSITE = "group_composite"            # 泵组综合曲线
```

### 4.1 业务场景与枚举值映射表【v2.5新增】

> **说明**：本节明确业务需求中的场景描述与系统枚举值的对应关系。

| 业务场景描述 | 系统枚举值 | 识别条件 | 典型案例 |
|-------------|-----------|---------|---------|
| **同构全变频泵组** | `HOMOGENEOUS_GROUP` | 纯VFD，功率差异<10%，频率差异<2% | 3台相同型号的55kW变频泵并联 |
| **异构全变频泵组** | `HETEROGENEOUS_GROUP` | 纯VFD，功率差异≥10% | 1台55kW + 2台75kW变频泵并联 |
| **异构全变频泵组（频率差异）** | `VFD_HETEROGENEOUS_FREQ` | 纯VFD，功率差异<10%，频率差异≥2% | 3台相同型号泵，但运行频率分别为45Hz、50Hz、48Hz |
| **混合泵组** | `MIXED_GROUP` | VFD+SS混合，功率差异<10% | 2台75kW变频泵 + 1台75kW软启泵 |
| **异构混合泵组** | `MIXED_HETEROGENEOUS` | VFD+SS混合，功率差异≥10% | 1台55kW变频泵 + 2台75kW软启泵 |

**注意事项**：
1. **"并联台数优化"不是场景类型**，而是一种功能，体现为N-Q、N-P、N-η曲线
2. 场景识别在**阶段14**执行，由 `PumpGroupProcessor.identify_group_type()` 完成
3. 识别顺序：先判断控制类型（纯VFD/混合）→ 再判断功率差异 → 最后判断频率差异
4. 边界值（如恰好10%功率差异）归入**更复杂**的场景（如 HETEROGENEOUS 而非 HOMOGENEOUS）

### 5.3 异常处理说明【v3.11修复：问题271、问题274】

**阶段3数据提取失败处理**：
- **异常类型**：`DataExtractionError`（错误码：CF009）
- **触发条件**：
  - 数据库查询失败
  - 提取的数据为空（数据点数 < min_data_points）
  - 数据格式不符合要求
- **处理策略**：
  - ❌ 不使用空数据或默认数据降级
  - ✅ 抛出异常，记录详细错误原因（device_id、curve_type、时间范围）
  - ✅ 终止当前拟合流程
- **详见**：`03_核心模块/03_共用层.md` 异常定义

**P2阶段单泵曲线缺失处理**：
- **异常类型**：`PumpGroupProcessingError`（错误码：CF015）
- **触发条件**：
  - pump_combination中任何device_id的曲线缺失
  - 曲线质量不合格（R² < 0.90）
  - 曲线状态非active
- **处理策略**：
  - ✅ 在阶段14入口验证时抛出异常
  - ✅ 错误信息明确指出哪些泵的曲线有问题
  - ❌ 不触发P0重新拟合（需要外部调度）
  - ❌ 不跳过缺失的泵（保证数据完整性）

**其他关键异常**：
- **阶段10拟合失败**：抛出`FittingError`，不自动重试（由外部调度决定）
- **阶段11验证失败**：抛出`ValidationError`，记录验证失败原因
- **阶段16修正模型训练失败**：抛出`CorrectionModelTrainingError`，拒绝存储

**数据库连接失败处理**【v3.11修复：问题276】：
- **异常类型**：`DatabaseConnectionError`
- **触发条件**：
  - 阶段3数据提取时数据库连接失败
  - 阶段13存储结果时数据库连接失败
- **处理策略**：
  - ✅ 连接池自动重试（最多3次，指数退避）
  - ✅ 重试失败后抛出DatabaseConnectionError异常
  - ✅ 记录详细错误日志（连接参数、错误信息、重试次数）
  - ❌ 不使用降级存储（如本地文件）
- **实现**：连接池已实现自动重试机制（app/adapters/db/pool.py）

### 6.2 P2精度目标表（v2.4更新）

| 泵组类型 | 适用泵类型 | 识别条件 | 处理策略 | R² 目标 | RMSE 目标 |
|---------|-----------|---------|---------|:-------:|:---------:|
| `HOMOGENEOUS_GROUP` | 纯VFD | 功率差异<10% 且 频率差异<2% | 基准泵曲线 × N + 修正 | > 0.96 | < 2.0m |
| `HETEROGENEOUS_GROUP` | 纯VFD | 功率差异 ≥ 10% | 各泵独立曲线 + 合成 + 修正 | > 0.94 | < 3.0m |
| `VFD_HETEROGENEOUS_FREQ` | 纯VFD | 频率差异 ≥ 2% | 各泵反归一化 + 流量叠加 + 修正 | > 0.96 | < 2.0m |
| `MIXED_GROUP` | VFD+SS | 功率差异 < 10% | 分类处理 + 分类合成 + 修正 | > 0.92 | < 4.0m |
| `MIXED_HETEROGENEOUS` | VFD+SS | 功率差异 ≥ 10% | 分类处理 + 加权合成 + 修正 | > 0.90 | < 5.0m |

> ⚠️ **业务约束**：纯SS泵组不支持（软启泵必须与变频泵混合使用才能实现流量调节）

### 6.4 泵组场景处理矩阵（v2.4更新）
