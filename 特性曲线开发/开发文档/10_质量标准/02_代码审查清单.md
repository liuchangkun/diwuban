## 1. 代码风格

### 1.1 命名规范

| 类型 | 规范 | 示例 |
|------|------|------|
| 类名 | PascalCase | `CurveFittingPipeline` |
| 函数名 | snake_case | `calculate_metrics` |
| 变量名 | snake_case | `fit_result` |
| 常量 | UPPER_SNAKE_CASE | `MAX_ITERATIONS` |
| 私有属性 | 前缀下划线 | `_model` |

### 1.2 审查检查项

- [ ] 命名是否清晰表达意图
- [ ] 是否遵循项目命名规范
- [ ] 是否使用统一术语（参见术语表）
- [ ] 禁止使用的术语是否被使用

**禁止的命名**:
```python
# ❌ 禁止
method_name  # 作为ID时应使用 method_id
fit_params   # 应使用 coefficients
constraints  # 单独使用时应使用 physics_constraints
```

## 2. 类型安全

### 2.1 类型注解要求

- [ ] 所有公共函数必须有类型注解
- [ ] 返回值类型必须明确
- [ ] 复杂类型使用TypedDict或Literal

**正确示例**:
```python
from typing import Literal, Optional, Dict, Any

CurveType = Literal['qh', 'qp', 'qeta']

def fit(
    self,
    device_id: int,
    curve_type: CurveType,
    start_time: datetime,
    end_time: datetime,
    methods: Optional[List[str]] = None
) -> FitResult:
    ...
```

### 2.2 审查检查项

- [ ] 函数签名是否有完整类型注解
- [ ] 是否使用Literal限制字符串值
- [ ] 是否使用TypedDict定义复杂字典结构
- [ ] 可选参数是否使用Optional

## 3. 错误处理

### 3.1 异常规范

| 异常类型 | 使用场景 |
|---------|---------|
| `ValueError` | 参数值无效 |
| `DataNotFoundError` | 数据不存在 |
| `DataNotSufficientError` | 数据量不足 |
| `FittingError` | 拟合失败 |
| `ValidationError` | 验证失败 |

### 3.2 审查检查项

- [ ] 是否捕获了可能的异常
- [ ] 是否使用了正确的异常类型
- [ ] 异常信息是否包含有用的调试信息
- [ ] 是否有日志记录异常

**正确示例**:
```python
try:
    result = method.fit(X, y)
except Exception as e:
    self._logger.error(f"拟合失败: device={device_id}, method={method_id}, error={e}")
    raise FittingError(f"设备{device_id}的{curve_type}曲线拟合失败: {e}")
```

## 4. 数据库操作

### 4.1 连接管理规范

- [ ] 使用 `get_connection()` 上下文管理器
- [ ] 禁止创建新的连接池
- [ ] 禁止使用SQLAlchemy ORM

**正确示例**:
```python
from app.adapters.db.pool import get_connection

def save(self, result: FitResult) -> str:
    with get_connection() as conn:
        with conn.cursor() as cursor:
            cursor.execute(sql, params)
            conn.commit()
```

### 4.2 审查检查项

- [ ] 是否使用get_connection()获取连接
- [ ] 是否正确处理事务（commit/rollback）
- [ ] 是否使用参数化查询（防SQL注入）
- [ ] 是否正确关闭cursor

## 5. 性能考虑

### 5.1 审查检查项

- [ ] 是否避免在循环中执行数据库查询
- [ ] 是否使用批量操作替代单条操作
- [ ] 大数据量是否使用分页/流式处理
- [ ] 是否避免不必要的数据复制
- [ ] 是否使用缓存（适当场景）

### 5.2 NumPy/Pandas最佳实践

- [ ] 是否使用向量化操作替代循环
- [ ] 是否避免DataFrame.append()
- [ ] 是否使用适当的数据类型

---

## 6. 安全规范

### 6.1 审查检查项

- [ ] 数据库操作是否使用参数化查询
- [ ] 是否验证用户输入
- [ ] 敏感信息是否被日志记录
- [ ] 是否有硬编码的密码/密钥

### 6.2 日志规范

**禁止记录**:
- 数据库密码
- API密钥
- 用户敏感数据

**必须记录**:
- 操作开始/结束
- 异常信息
- 关键业务决策

## 7. 审查流程

### 7.1 审查前自检

开发者提交PR前必须完成:

- [ ] 代码通过本地测试
- [ ] 代码通过lint检查
- [ ] 添加/更新了相关测试
- [ ] 更新了相关文档

### 7.2 审查重点

| 优先级 | 检查项 |
|--------|--------|
| P0 | 功能正确性 |
| P0 | 安全问题 |
| P0 | 数据库操作规范 |
| P1 | 类型安全 |
| P1 | 错误处理 |
| P2 | 代码风格 |
| P2 | 性能优化 |

### 7.3 审查结论

| 结论 | 说明 |
|------|------|
| ✅ Approved | 可以合并 |
| 🔄 Request Changes | 需要修改 |
| 💬 Comment | 仅评论，不阻塞 |
